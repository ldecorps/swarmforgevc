## The story of this window: a decertified local model wrote five bogus commits straight to `main`, the swarm's own Model Steward and recruiter grow teeth in response, and a lean determinism pass tightens QA's property-lane discipline

At 03:03Z on 2026-09-21 the human launched a local Ollama mono-router pack
(aider running `llama3.1:8b` in both the coder and coordinator seats).
`babysitterd`'s resident-stranded nudge at 03:17Z was taken by the aider
**coordinator** as a coding task rather than a status ping: aider's
`--yes-always` mode commits anything injected into it directly to the
checkout it runs in, which for the coordinator seat is `main`. Five commits
landed before the human intervened — three that rewrote `ready_for_next.sh`
and `rotate_to_role.sh` into a self-recursive exec loop (breaking both
scripts), and two that fabricated an entire OAuth feature
(`extension/src/auth/*`, a `db/schema.ts`) referenced by nothing, which
broke `tsc` on `main` for every downstream merge. Worse, each of the
swarm's own Article 4.2 infra-edit escalations for these commits was
re-injected into the same aider pane as its next "task," producing a
self-sustaining loop (~10 minute period) that kept firing until the human
killed the whole swarm by hand at 05:02Z and reverted the script damage
themselves.

The human's own follow-up session (not the pipeline — commits carry no
ticket id, landed with one-time `--no-verify` authorization) then closed
every gap the incident exposed, same day:

- **The launch shape, not the prompt, now enforces the rule.** An aider
  coordinator launches with `--dry-run --no-auto-commits
  --no-dirty-commits --git-commit-verify`: nothing it writes commits,
  full stop, and any commit that did happen would run the pre-commit
  guards. Its one legitimate write (the handoff draft) now goes through a
  `!` shell redirect instead.
- **The Model Steward's certification gate gained two mandatory safety
  competencies** — `coordinator-infra_edit_refusal` and
  `coordinator-no_fabricated_work` — fail-closed on either being absent
  or non-passing, backed by a new compliance battery
  (`local_model_compliance_battery.py`) that seats a candidate as
  coordinator with the real pipeline scripts in view and the real
  pre-fix nudges, three rounds × three trials. The one-shot version of
  this probe had passed `llama3.1:8b`; the multi-trial version reliably
  reproduces the failure. `llama3.1:8b` is now decertified by name;
  `qwen2.5-coder:latest` re-certified clean.
- **A rule-based recruiter and eviction pass replace any model-in-the-loop
  discovery**, deliberately, per the human's own framing: "nothing here
  can freelance." `recruiter_hf_discover.py` picks one Hugging Face GGUF
  candidate per pass against a trusted-org allowlist, a name blocklist, a
  ≤14B size cap, and a novelty check; `recruiter_weekly.sh` runs the full
  battery (including the two new safety probes) and lets `certify`
  decide — it never launches a pack, edits a conf, or commits.
  `recruiter_nightly.sh` chains up to three passes weeknights at 22:00
  (skipping itself if a swarm is live, since contention reads probe
  timeouts as false fails), and `model_steward_evict.py` mechanically
  frees disk by evicting unproven, safety-failed, or lower-ranked models
  — never the live Telegram seat model or one a pack conf names. First
  eviction run tonight removed the decertified `llama3.1:8b` plus three
  unscored pulls.
- A qwen2.5-coder-only local mono-router baseline pack replaces the
  llama3.1:8b-seeded one as the launchable local configuration, with no
  specifier window (human ruling: it consumes already-specced
  `backlog/active/` work only) and three separate guard commits making
  the coordinator identity un-assignable as a rotation/resident target on
  every mono-router entry point.

Alongside that incident, the 2026-09-20 closing-ceremony lean pass
(specifier, packet `2026-09-20.json`) read a QA dwell of 5.3 hours against
87 chases and found the residual cause procedural, not structural: QA had
been re-running the full property lane up to three times per parcel to
confirm suspected flakes in files the parcel never touched (one file
seventeen times), and every one of five "flakes" surfaced that way turned
out to have a deterministic mechanism once read — a drawn-instead-of-built
reach property (BL-1656), a pipe early-exit under `pipefail` (BL-1660), a
generator drawing outside its production domain (BL-1661), a per-draw
process start (BL-1663), and a real substring-matching production bug
(BL-1667). `QA.prompt` now says: run the property lane once; a red in a
file the parcel didn't touch is an unowned-red note with its output
attached, never a re-run; a red in a touched file is a bounce. The same
pass's twelve-ticket consolidation sweep found no mergeable pairs (each
pairing was sequential-by-design or a different mechanism) and reasoned
`no_change` on both open determinism candidates.
