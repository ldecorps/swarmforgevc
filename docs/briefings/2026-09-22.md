## The story of this window: three separate holes in the land step get found and closed the same day, the closing ceremony learns to finish itself in one sleep, and the cursor-bridge module-load census keeps growing as each landed slice reveals the next

Three independent land-step integrity bugs surfaced and were fixed within
hours of each other on 2026-09-21, none related to the aider-coordinator
incident that dominated yesterday's briefing:

- **BL-1671** — `check_merge_deletion.sh` read the working tree instead of
  the staged index, so an unstaged deletion of a tracked path on the
  shared master checkout (a seat's `rm`, or the tracked
  `handoff-draft.txt` every master-resident send consumes) refused the
  daemon's diverged reconcile. It tripped the main-sync deadlock latch
  twice on 2026-09-21 before the `--cached` fix landed.
- **BL-1678** — a `LAND_CLEAN` land pushes QA's *whole* branch tip and the
  land step only judges path-sharing siblings, so an unapproved forward
  riding the same branch on unrelated paths ships unreviewed. This is how
  BL-1640's already-bounced forward reached `origin/main` at 12:42 under
  BL-1666's land (375 `into QA` merges on main's first parent since
  08-22 share this exposure). Interim fixed in `QA.prompt`: every land is
  now a tip-pure landing commit pushed by sha, never `HEAD:main`.
- **BL-1683** — `merge_drop_guard_lib.bb` judged a dropped hunk by path
  string with no rename detection, so an ordinary backlog promotion
  (`git mv paused → active` + one status line) read as the whole file
  being dropped whenever the received branch still held the paused copy.
  This refused the documenter's own BL-1467 forward outright (128 lines
  of BL-1680's YAML, on a day with 14 promotions). Interim: an empty
  revert carrying git's own "This reverts commit \<sha\>." line satisfies
  the guard.

Separately, **BL-1640** closed a standing gap in the closing ceremony:
`finish_shift_run_closing_ceremony` previously ticked the ceremony CLI
once and left the rest of the sequence to the daemon's later sweeps — on
an afternoon bedtime those sweeps' deadlines were already hours stale. It
now loops the ceremony to `phase:done` itself, with deadlines relative to
the sleep's own start time and a hard grace ceiling that stops the stack
and says so if the ceremony overruns. This lands the same day the human
corrected the separate "drain the seats" semantics bug (`handoff_lib.bb`'s
`resolve-dequeueable-candidates` now checks the pause/ceremony freeze
before a role claims its *own* next queued item, not just before the
daemon delivers a new one) — together they close two different ways a
bedtime freeze was leaking work past its boundary.

The cursor-bridge module-load-budget saga (`stepHandlerModuleLoadBudget`,
opened by BL-1658) kept compounding this window: landing BL-1658 pinned a
fifteen-file eager-requirer population, which immediately handed the
standing-red row to **BL-1685** (fourteen *more* eager requirers outside
that population, the whole 286-module bridge graph), which handed it to
**BL-1687** (seventeen more, invisible to both prior text censuses —
`path.join`-built paths and module-scope object-literal requires). Each

findings from inside the same BL-1658 parcel became their own tickets:
BL-1680 (an acceptance fixture fakes the model catalogue as `qwen3:14b`
while the real code path reads the live env, which every session actually
sets to `qwen2.5-coder:latest`) and BL-1681 (two of BL-696's feature
scenarios asserting page literals removed eight weeks ago by two later,
unrelated tickets — red and unrun the whole time).
