Not blocking anything right now (ordinary commits keep landing fine on top,
same as yesterday), but worth a human `git rebase --continue`/`--abort`
whenever convenient — see Flagged #1.

**Finding #2 (resolved this shift): a ticket's code shipped through the
pipeline riding as an unreviewed ancestor of a different ticket's branch.**
Human-directed ambulance mode fast-tracked BL-907 then BL-908 (the two
browsable-knowledge-screen Bubble slices) through the pipeline
sequentially. When BL-908 reached QA, QA independently discovered (and the
documenter had separately surfaced the same finding minutes earlier) that
**BL-825** — an unrelated ticket promoted earlier the same shift, whose
coder commit was never explicitly forwarded — had its single commit
sitting as an ancestor of BL-908's branch the whole time. Architect's and
hardener's BL-908 passes never actually reviewed BL-825's files (confirmed:
architect's scan predated BL-825's files entering the branch). Had BL-908
merged, BL-825's code would have shipped to `main` having skipped both
required gates. **QA held BL-908 without merging** rather than approve on
"looks clean." The coordinator redirected ambulance to BL-825 (its forward
handoff to cleaner had, in fact, already been sent — it was just sitting
held by ambulance the whole time, so no new dispatch was needed), let it
run its own architect → hardener → documenter → QA pass, and closed it
clean at 03:32. Ambulance then moved to BL-829 per the specifier's
independently-confirmed sequencing (BL-825 → BL-829 → resume BL-908).
Net: zero code defects found, but a real gate-integrity gap — a ticket's
work can silently ride along in another ticket's branch with no handoff of
its own, and nothing structural currently catches that except a role
happening to notice. Worth a specifier ticket if it recurs (see Flagged
#2).
