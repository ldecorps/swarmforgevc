## The period's dominant story: reconcile/reset destruction, now ticketed as BL-1288

`git reflog` shows 20 `reset: moving to origin/main` events across
2026-08-29/30 — the same `master_main_reconcile` behavior that drove prior
briefings' BL-1214 narrative. Root cause was isolated today: the shared
push-before-reset primitive (`rematch-with-push-first!`,
`master_main_reconcile_lib.bb:745`) treats *every* failed push as genuine
divergence and resets, when a push can also fail for reasons that have
nothing to do with divergence (unreachable remote, missing credential,
network drop) — and it discards the push's own `:error` string, the one
thing that could tell the two apart. All three production call sites
already use the shared BL-1198 primitive, so this is not a wiring gap; it's
a classification bug inside behavior that is fully wired and still firing.

Specced today as **BL-1288** (defect, severity high — a live fault that
destroys committed work and blinds the signal meant to prevent it, but not
critical since every loss so far has been recoverable from the reflog).
`human_approval: pending` — it needs a human tap on one open direction
question (escalate vs. silently hold-and-retry-later on a non-rejection
push failure) before a coder can pick it up. Recorded on the ticket that it
