What the project is. SwarmForge VC is a VS Code extension that fronts SwarmForge, a tmux-based multi-agent coding swarm. It launches the swarm on a target repo, shows every agent live, tracks each ticket through the pipeline and lands the result. It drives SwarmForge from outside (its ./swarm wrapper, tmux, the .swarmforge/ state folder) and never reimplements it. The swarm builds this repo itself. Bubble is the Android phone app. The PWA is a static backlog dashboard; the live holistic UI is the authenticated control surface.

Repo map. extension/ holds the TypeScript extension, its tools and tests. swarmforge/ holds the babashka and shell pipeline scripts, the role prompts, and the constitution under swarmforge/constitution/articles/. specs/features/ holds the Gherkin acceptance contracts and specs/pipeline/steps/ their step handlers. backlog/ holds the tickets in paused/, active/, done/ and hold/, with review evidence in backlog/evidence/. docs/ holds how-to, reference and explanation pages. android/ is Bubble; pwa/ is the dashboard.

The pipeline. A ticket flows specifier, coder, cleaner, architect, hardener, documenter, QA, and each ticket names only the stages its change needs. Roles pass work on with swarm_handoff.sh through mailboxes. QA is the last gate and queues an approved commit for the lander daemon, which lands it on main. The coordinator controls intake, promotes paused tickets under a depth cap, and moves a landed ticket to done/.

Local-model seats read only their compact cards under swarmforge/roles/local-model/ (loop.note plus the role's .note), never the full role prompt unless the card sends them there. When a role prompt's how-to-act path changes, the matching .note must change in the same land, and a prompt_engine_test_runner pin should name the new path so the card cannot drift again.

The rules that matter most. The specifier writes specs and the constitution, never code. Every ticket has Gherkin acceptance scenarios and must be small and testable. The gates are unit, acceptance and property tests, mutation testing for TypeScript, CRAP at or under 6, and coverage. A test failing on main is a standing red: it is fixed at once by a hotfix with a review ticket after it, or it gets an owner in backlog/standing-reds.tsv, and QA approves nothing while a red has no owner. Defects carry a severity, and critical and high ones jump the queue. A consolidation never drops a sentence a human wrote.
