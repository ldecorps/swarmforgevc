  root a live process created... only when the pid... is dead or is the
  sweeping process itself") — **stated reason, no new property test**.
  This is `sweepStaleTmpDirs`'s own existing contract, already
  coder-authored and property-tested by BL-1623

  root is removed iff its recorded pid is this process's own or not
  alive"). This parcel does not modify `sweepStaleTmpDirs` at all - it
  adds four MORE callers of the unmodified, already-proven helper. Adding
  a second property test asserting the identical claim about the identical
  unmodified function would not encode anything this parcel changed; the
  claim over the FOUR NEW CALL SITES specifically (each one now delegates
  correctly, with no leftover direct `readdirSync(os.tmpdir())`) is what
  this ticket's own acceptance scenario 01 (drives the real helper against
  a live-peer-survives / dead-pid-reaped pair) and scenario 03 (reads each
  migrated file's own source and asserts it calls `sweepStaleTmpDirs` and
  never lists the temp dir directly, literal or aliased) discharge
  directly - the same posture BL-1450's evidence used for a change to an
  existing property file's own reach-math shape, not a new pure module.
