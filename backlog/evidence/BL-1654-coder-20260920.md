# BL-1654 coder evidence

## What was built

`specs/features/BL-1308-an-unlanded-sibling-on-a-second-parent-is-invisible.feature`
scenario 03 ("A replay tip carries no path from a ticket the report did
not name") asserted a premise BL-1389 (06f1babcaf, 2026-09-04) already
closed: that an unlanded sibling's untagged path could ride the replay tip
unattributed. Since BL-1389, the land step excludes such a path outright
and prints `EXCLUDED_SIBLING_PATH <path> <ticket>` for it, so the
scenario's own "did a foreign path really ride the tip" premise check
fails first, red on main since 2026-09-04 (BL-1006's shape: the successor
that closed the gap never retired the scenario built to catch it).

- Scenario 03 retired (deleted, not reworded), its comment naming why and
  when, and naming the replacement.
- A new scenario ("03b") added in its place, on the SAME `second-parent`
  fixture shape scenario 02 already builds (no new fixture, per the
  ticket's own "How"): asserts the replay tip adds only the cited
  ticket's own path(s) (each attributed solely to `BL-9001` via the
  fixture's own attribution oracle), and that both of the sibling's
  untagged files (`sib_a.txt`, `sib_b.txt` - the fixture CLI's own fixed
  literals) are named on their own `EXCLUDED_SIBLING_PATH ... BL-9002`
  line and never in `replayAdded`. Comment names BL-1389 so the lineage
  stays greppable from the feature file alone.
- Feature narrative re-tensed: the paragraph stating the pre-BL-1389 gap
  in present tense now states it as the historical shape BL-1389 closed,
  while leaving the sibling-DETECTOR narrative (scenarios 01/02/04,
  unaffected by BL-1389) exactly as it was.
- Step handler (`bl1308SiblingDetectorCoversReplaySteps.js`): the old
  scenario 03's Then step (`the ticket that path is attributed to is
  named in the report`) removed; two new Then steps added. **Found while
  writing them**: the fixture CLI's own `attribution` map is built ONLY
  from `replayAdded` paths (it diffs the replay tip against origin/main,
  then attributes each ADDED path) - an excluded path is never in that
  map by construction, not because nothing was excluded. Deriving the
  sibling's paths from `attribution` therefore silently asserted nothing
  (empty set, vacuous pass) - caught by running the acceptance suite
  before considering this done, not by inspection alone. Fixed by using
  the fixture's own fixed literals (`sib_a.txt`/`sib_b.txt`, the same
  literal `SIBLING`/`CITED_TICKET` this file already hardcodes for this
  fixture) instead.
