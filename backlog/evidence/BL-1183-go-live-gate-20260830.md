# BL-1183 — the BoB go-live gate

Coder, 2026-08-30.

## The instruction

> Human: do not run live day-long production trials until telemetry and
> performance-assessing tools can decide outrank/tie/lose.

So a production trial that cannot be adjudicated does not merely fail to be
useful — it refuses to arm.

## What "ready" means, and why it is derived rather than invented

The checklist is decided from what BL-1182's `decide` actually needs, not from
a separate list that could drift from it:

- **Telemetry** is a role-matrix score for BOTH models. Without both, `decide`
  falls through its unscored clause and reverts on absent evidence — it never
  compares anything, so the trial would seat a non-permanent model for a day
  and learn nothing.
- **An assessor** is battery / scorecard / bake-off evidence behind those
  scores: `model_steward_lib/battery-or-scorecard-evidence?`, the same
  predicate `ranking-authority-tier` already uses to decide which evidence may
  outrank which. A score with no such citation is somebody's opinion, and an
  opinion cannot adjudicate a day of production.

Deriving it this way means the gate cannot pass a pairing the lifecycle would
then be unable to judge — the two would have to disagree, and they read the
same registry through the same predicates.

## Fail-closed, and it names the gap

`go-live-checklist` reports ready only when it can positively see all four
facts. An unreadable registry, an absent role matrix and a candidate nobody has
scored all produce a NAMED gap rather than a pass.

`go-live-refusal` returns one string carrying every gap, so a caller cannot
accidentally report the verdict without the reasons — a refusal that said only
"not ready" would cost the operator the same search as having no gate.

Each gap names which model it is about and which half it is:

```
trial refused: the BoB go-live checklist is not satisfied -
  trial-comparison telemetry: no recorded score for the candidate cerebras/trial-model;
  performance assessor: no battery/scorecard/bake-off evidence for the permanent anthropic/perm-model
```

## Where the gate sits

In `run-trial-nominate`, BEFORE anything is armed or seated — the trial start
path the ticket names. BL-1182's `nominate` is untouched, and so are its lib
tests: the gate is a check the CLI performs first, not a change to the
lifecycle's own contract.

`trial go-live --role <role> <provider>/<model>` reads the checklist without
seating anything, which is qa_e2e step 3's "checklist is readable offline".

## The invariants (BL-654)

`swarmforge/scripts/test/bl1183_go_live_gate_property_runner.bb`, seeded LCG.

The space is four independent facts — each model scored, each model assessed —
so it is enumerated rather than sampled: sixteen combinations drawn uniformly,
with floors on the fully-ready case and on each individual gap (measured: 22
fully ready, 201 / 210 unscored, 102 / 95 unassessed). Evidence strings are
drawn from BOTH sides of the assessor predicate, because that predicate is what
decides "assessed" and a generator producing only one kind would never cross
the boundary.

Invariant 1 is stated as an EQUIVALENCE, so both directions are checked every
draw: a gate that refused everything would satisfy the refusal half and be
useless, and one that allowed everything would satisfy nothing.

Invariant 2 checks three things per unready draw — there is a named gap, every
gap names its model and its half, and the refusal text carries all of them —
plus that the gap named is the one actually missing, so a checklist that always
reported the same gap could not pass.

**Non-vacuity, both by breaking the code and running:**

| break | result |
|---|---|
| the assessor half of the checklist is dropped | P1 FAILS |
| the refusal reports the verdict without the reasons | P2 FAILS |

Restored; ALL PASS at 400 runs each.

## A spec defect surfaced, not worked around

`required_wiring` row 1 reads:

```
BoB trial start path::go-live checklist::telemetry + assessor readiness
```

The PATH segment is prose, not a file path. `pre_qa_gate_lib.bb` reads the path
and substring-matches the pattern with no expansion step, so this row can never
match and will hard-block the documenter's forward to QA on a wiring-absent
refusal — the BL-874 shape, and exactly the defect this ticket's own sibling
BL-1182 had fixed in its notes before minting.

Surfaced to the specifier by note (priority 00) rather than edited here: the
row is the specifier's to write, and guessing at what it meant to anchor would
be the consolidation this constitution forbids. The anchor it plainly wants
exists and is real — `swarmforge/scripts/model_steward_cli.bb::go-live` (the
gate in the trial start path) and
`swarmforge/scripts/model_steward_trial_lib.bb::go-live-checklist` — if the
specifier wants a suggestion.

Row 2 (`specs/pipeline/steps/index.js::bl1183BobGoLiveGateSteps`) is real and
satisfied.
