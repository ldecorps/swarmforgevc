## D1 — NPE when a cap flag is omitted

`probe!`'s own destructuring has no `:or` default for `fix-turns-limit`/
`max-ticks`/`wall-clock-seconds`, so an omitted CLI flag flows through as
an explicit `nil` value, and `probe!` always forwards these three keys
into `run-fixture!` EXPLICITLY (even when nil) — `run-fixture!`'s own
`:or` map never fires for a present-but-nil key, so the nil reached
`(* wall-clock-seconds 1000)` / `(min max-ticks ...)` and NPE'd.

Fix: `run-fixture!` now coalesces with `(or x default)` at the top of its
body — the ONE place, per the remediation pointer — using new named
constants `default-max-ticks` (400) and `default-wall-clock-seconds`
(900), replacing the dead `:or` map entirely. Verified both omission
shapes from QA's own repro (no cap flags at all; `--wall-clock-seconds 8`
alone) run to a real outcome, never an NPE.

## D2 — the turn cap counted poll ticks, not model turns

`effective-max-ticks = min(max-ticks, 5 + wall-clock-seconds*1000/50ms)`
let a small/default `max-ticks` (400) silently override a much larger
`wall-clock-seconds` (900): 400 raw 50ms poll ticks = 20s, so a hung seat
was mislabeled `"turn cap"` at ~20-23s regardless of the wall-clock
budget requested, and the documented 900s wall clock never bound
anything.

Fix: added `drive-until-capped!`, `run-fixture!`'s own outer loop over
`local-parcel-driver-lib/drive-tick!` (BL-1697's real, unmodified
per-cycle primitive — never `drive-to-end!`, whose `max-ticks` is the
raw-poll-tick count this bug came from). It stops the moment
`fixTurnsUsed` (a REAL model turn) reaches `max-ticks`, or the driver
reaches a terminal state, or a `safety-ticks` ceiling — sized against
`wall-clock-seconds` ONLY, never `max-ticks` — expires (a backstop against
an abandoned background future, never the thing that actually stops a
slow-but-real run). `outcome-of` now reports `"turn cap"` only when real
turns taken reached `max-ticks`; every other non-terminal, non-escalated
exit is `"wall-clock cap"`.

Verified: a hung seat with `max-ticks 5` (tiny) and `wall-clock-seconds 3`
now runs the full ~3s (not ~250ms) and reports `"wall-clock cap"`, 0
turns. A `never`-committing stand-in with `max-ticks 1` and
`wall-clock-seconds 30` now stops after exactly 1 real turn (~2.5s),
reporting `"turn cap"` — a real, previously-impossible outcome.

## D3 — scorecard/summary fields, model id, llm-history survival

- Added `resolve-model-id` (GETs `<endpoint>/models`, matches the
  requested id byte-identical or with a `:latest` tag appended; falls
  back to the raw argument on any read failure). `probe!` resolves once
  and uses the resolved id for every scorecard, the summary, the evidence
  filename, and the real aider launch. Verified against the real local
  endpoint: `qwen3-14b` → `qwen3-14b:latest`; an unmatched name falls
  back unchanged.
- Added `:turns` (`fixTurnsUsed` from the final driver state) to every
  scorecard.
- `--llm-history-file` now points at an absolute path OUTSIDE the
  throwaway root (computed before launch, never `.probe-llm.log` inside
  root, which `run-fixture!`'s own `finally` deletes) — `nil` for a
  stand-in run. `:llmHistoryPath` added to every scorecard; the summary
  text now names it and the turn count per fixture.
