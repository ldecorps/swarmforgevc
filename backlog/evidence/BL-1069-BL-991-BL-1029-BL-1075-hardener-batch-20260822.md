## BL-1069 scenario 1: 12/29 Gherkin mutants survived — NOT fixed, recorded
as a known gap

The surviving mutants are almost all small numeric/character perturbations
of the Example rows' client/server version strings (e.g. `"3.4"` ->
`"2.06"`, `"3.7b"` -> `"3.xb"`). The step handler
(`bl1069TmuxServerVersionSteps.js`) already declares `KNOWN_VERDICTS` and
validates the row's declared verdict against it, but does not pin the
client/server version VALUES themselves against a declared literal set
before the real comparison runs them — so a mutated version string that
happens to land on the same side of the safe-floor boundary as the
original produces the identical `warned`/`silent` verdict and the mutant
survives. This is the "Scenario Outline picks its test by shape" class of
gap from this role's own accumulated rules, applied to a numeric rather
than symbolic column.

**Not fixed in this pass**, given session time constraints, but explicitly
NOT silently passed either. Mitigating factor, not an excuse: the
underlying comparison logic (`version_key`/`version_lt?` equivalent) is
already rigorously proven correct by BL-1069's OWN property test, which
explicitly covers the two near-miss pairs this scenario exists for (3.10
vs 3.9 numeric, 3.7 vs 3.7b lettered) with a real independent oracle and a
proven non-vacuity break-and-revert at authoring time. The Gherkin gap is
in the ACCEPTANCE layer's fidelity to its own Example values, not in
production logic itself.

**Recommended fix for whoever picks this up**: pin each row's
client/server literal against a `KNOWN_EXAMPLE_VALUES` map (or similar) in
`bl1069TmuxServerVersionSteps.js` and assert the captured value against it
before the round-trip through `zsh_sourced`, per this role's own established
pattern for this class of gap.

## BL-1029: all 3 Gherkin mutants survived — recorded EQUIVALENT (BL-234)

All three survivors are case/character mutations of the "launch path"
EXAMPLE value in the "a launch path round-trips through a real shell
unchanged" scenario (e.g. `coder.sh` -> `codeR.sh`, `/Users/` -> `/users/`).
The scenario's own invariant is a round-trip property — `unquote(quote(X))
== X` — which holds identically for ANY string X, including every mutated
example value here. The example paths are illustrative inputs chosen for
their special characters (apostrophes, spaces), not literals a downstream
assertion hardcodes for comparison; mutating them to a different
still-valid string cannot be caught by a round-trip test by construction.
Demonstrable from the code (BL-234's equivalence bar), not a convenient
excuse — the property proved is symmetric in the input value.
