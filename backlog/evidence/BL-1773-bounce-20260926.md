## Ruling

A file named `<landed parcel file name><suffix>`, for a suffix in
handoff_lib's `sidecar-suffixes` registry, is part of the landed parcel and
does not block. A sidecar named for any other file (another parcel's, or an
orphan) still blocks, as does every other shape the ticket already listed.
Reuse the registry, never restate it. The invariant is restated over files:
"The re-point never resets a tree whose in_process holds anything beyond ONE
git_handoff naming the landed ticket plus that same file's
handoff_lib-registered sidecars."

Why the narrow reading and not "ignore every sidecar": the guard exists to
refuse a reset while anything might be in flight, and fail-closed is its
posture. A sidecar whose parcel is not the landed one is a surprise worth a
skip. The skip never fails the land (BL-1438).
