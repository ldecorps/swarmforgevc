# BL-1400 — coder pass, 2026-09-05

## What changed

`extension/src/tools/check-feature-handler-registration.ts` — the tree builder,
which is where the defect always was:

- `CheckIo` gains `listTree(relativeDir)`: every file at or below a
  repo-relative directory, as paths relative to it. `createFsIo` implements it
  with `readdirSync({ recursive: true, withFileTypes: true })`.
- `readTree` fills `stepFiles` from `listTree(STEPS_DIR)` (sorted, `.js` only)
  instead of a flat `listDir`, so a handler in a subdirectory is IN the tree and
  the assessor's existing `isDiscovered` predicate refuses it with no change to
  the pure check at all.
- `lib/` is excluded from `stepFiles` at the same point. It is already reported
  as `libFiles`, and admitting a helper whose name happens to start with a
  ticket id would turn a legitimate nested helper into an `unregistered-handler`
  offender — invariant 2's failure shape. `libFiles` is now recursive too, so a
  helper nested inside `lib/` is still a lib file.

No change to `featureHandlerRegistrationCheck.ts`, its predicate, or the shell
guard: the subdirectory branch was correct and simply unreachable.

## Invariants (BL-654)

`extension/test/bl1400NestedHandlerIsSeen.property.test.js`, `npm run
test:properties` only:

1. **A handler at any depth is in the tree and refused, naming both.** The
   generator CONSTRUCTS the nesting — it draws a depth 0..3 and builds the path
   — rather than hoping a nested case appears. Depth 0 (the passing placement)
   is drawn alongside, so the property distinguishes pass from refusal instead
   of asserting one shape twice. Reach asserted: `[0,1,2,3]` must all appear or
   the property fails.
2. **A lib helper is never an offender.** The helper is named for the SAME
   ticket the feature declares — the exact file a ticket-keyed check would
   mistake for that feature's handler — at the top of `lib/` and nested inside
   it, both required by the handler and required by nothing. Reach asserted over
   all six combinations.

**Non-vacuity, run and reverted.** Restoring the flat `listDir` in `readTree`
turns property 1 red (property 2 stays green — a different defect). Admitting
`lib/` into `stepFiles` turns property 2 red (property 1 stays green). Each
property fails against its own defect and only its own.
