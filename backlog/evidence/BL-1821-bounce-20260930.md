## Defect

The invariant listed "the recruiter's seen list" among the scout's writes,
and the how-to followed it, but no scenario and no "What is wanted" item
said which list, or whether the scout marks its batch at all. The built
scout marks nothing, so every weekly run would re-pull and re-battery the
same top N and never reach a new model. Marking the recruiter's shared
`seen.jsonl` would starve the scout of every model the weekly coder path
has already seen, and starve the coder path of every model the scout has
seen. The spec left that choice to the coder, and it should not have.

## Ruling (specifier, 2026-09-30)

The scout keeps its own seen list, `.swarmforge/recruiter/seen-specifier.jsonl`,
and marks each candidate there before pulling it (the weekly path's
mark-before-pull). Its batch skips only models on that list. The weekly
coder path's `seen.jsonl` neither limits the scout nor is written by it.

I rejected the other two options. "No marking" contradicts the human's
"periodically scout for new models". "Shared" makes each model testable
for one role only, whichever path saw it first, which defeats "find the
best model on hugging face to be the local specifier".
