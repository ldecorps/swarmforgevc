# BL-1877 coder evidence (2026-10-02)

Ruling A: a commit runs only the property files its staged change
reaches; the whole lane runs only when the reach cannot be computed.

## What changed

- `swarmforge/scripts/property_suite_reach.js` (new): computes reach as a
  static reverse require-graph closure over `extension/out/**/*.js` and
  `extension/test/**/*.property.test.js`. Tried `vitest related` first
  (the ticket's own "one way" suggestion) and it returns no related
  files for this codebase - verified empirically:
  `npx vitest related out/tools/vitest-worker-memory-budget.js --config
  vitest.properties.config.mjs --run` -> "No test files found". The
  property files load `extension/out` via `require()`/`createRequire`,
  and Vite's import analysis (what `related` walks) does not trace plain
  CommonJS `require()` calls, so that route was abandoned for a static
  scan instead.
  - A staged `extension/src/X.ts` maps to `extension/out/X.js`; if that
    compiled file does not exist on disk, reach is reported as
    uncomputable (`WHOLE_LANE`) - compile has not produced what the
    graph needs.
  - A staged `*.property.test.js` is reached directly.
  - Output: `WHOLE_LANE` on uncomputable reach, or zero or more
    `test/...property.test.js` lines (relative to `extension/`) - zero
    lines is a confident "reaches nothing", distinct from `WHOLE_LANE`.
- `swarmforge/scripts/check_property_suite_drift.sh`: calls the reach
  script on the already-collected `TRIGGER_PATHS` right where it used to
  unconditionally log `"run"` and start the default suite.
  - `REACH_MODE=none` (reaches nothing): logs
    `skip-no-reach` and exits 0 without starting a suite process at all.
  - `REACH_MODE=files`: logs `run (reached: ...)` and runs
    `npx vitest run --config vitest.properties.config.mjs <files>` (or,
    under test injection, the injected command with the reached files
    appended as trailing args - the same "append extra trailing args"
    shape `run_rerun_for_file` already uses for its own `bl1407-rerun`
    sentinel, so a fixture's recording command can observe what it was
    asked to run).
  - `REACH_MODE=whole` (uncomputable, including `node` missing from
    PATH or the reach script itself erroring): unchanged behaviour -
    `run_default_suite` / the injected command with no extra args.
  - The allowlist, reconcile-import skip, override env, refusal log and
    BL-1407 re-run-alone seam are all untouched; they operate on whatever
    subset actually ran, same as before.
- `specs/pipeline/steps/bl1877CommitRunsReachedPropertyFilesSteps.js`
  (new): the feature's handler, discovered from its own file (BL-1371).
  Builds a throwaway git repo under `/tmp` per scenario (`trackedTmpRoot`,
  BL-1390's own-`.git` proof via `git rev-parse --git-common-dir` before
  any mutating git command), with its own copy of the guard, the libs it
  sources, and `property_suite_reach.js` (SCRIPT_DIR resolution needs
  them side by side), plus a recording suite command that appends its
  own `"$@"` to a file.

## Review against the invariant

"A property file the staged change reaches is never skipped at the
commit; when the guard cannot compute the reach it runs the whole lane."
`resolve_reach`'s three-way split (`none`/`files`/`whole`) is exhaustive
and fails closed: any reach-script failure (missing `node`, non-zero
exit, an exception inside the script) falls through to `whole`, never to
`none` or a partial file list. The only way a property file is excluded
from an actual run is `REACH_MODE=files` with that file absent from the
computed set, which is exactly the scenarios test (two property files
import a changed module -> both and only both are named).
