## What changed

**`swarmforge/scripts/shell_quote_lib.bb`** is new and is the one place a
launch path becomes a shell word. It exposes `shell-quote-single` (the POSIX
close-escape-reopen form) and `launch-command`, which is what every site calls.

Deliberately a **command builder**, not just the quoting primitive: the `zsh `
prefix and the quoting are one decision, and splitting them is how a site ends
up with the prefix right and the quoting wrong. No site now writes `"zsh "` at
all — the enumeration in scenario 02 finds exactly one construction site in the
whole production tree, and it is the helper.

BL-1018's private `shell-quote-single` in `single_role_repair_lib.bb` is
**removed**, not duplicated — the ticket is explicit that leaving a second copy
behind is not acceptable. That lib now loads the shared one.

The helper is pure string construction with no subprocess, which matters
because `handoffd.bb` loads it: `daemon_cycle_guard_lib_test_runner`'s closure
gate forbids any subprocess path inside that closure outside the one
chokepoint. Gate re-run and green.

## Verified by round trip, never by text

Every assertion that matters hands the constructed argument to a REAL shell
and compares what comes back, byte for byte, to what went in. That shape is
part of the ask for a reason: this defect already survived BL-1018's own
property runner behind a `str/includes?` check on the raw path, which passes
whether the escaping is correct or broken.

`swarmforge/scripts/test/shell_quote_lib_test_runner.bb` round-trips eight path
shapes — apostrophe, spaces, `$`, backslash, `;&|`, backticks, double quotes,
an embedded newline — and keeps the pre-fix construction as a NEGATIVE control,
asserting it really does fail in a shell. A test that has never seen the broken
shape fail is a coverage counter.
