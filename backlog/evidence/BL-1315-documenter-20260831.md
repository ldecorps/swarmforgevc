## What changed (user/operator-visible)

`land_step_lib.bb`'s `own-paths` (the tip-pure replay content BL-1241's
remedy builds) no longer bases the path set on a ticket-tagged merge's
first-parent `:delivered` diff. That base was BL-1308's stated residual and
was wrong in both directions on the same live machinery: over-inclusion
(2026-08-30, BL-1307 over BL-1300 — an unlanded sibling's second-parent
content entered the tip under the forwarded ticket's name) and
under-inclusion (2026-08-31, BL-1298 over BL-1303 — the landed ticket's own
content, having reached the branch before its own tagged merge via a
sibling's passenger ride, was absent from the first-parent diff and
dropped from the tip).

`own-paths` now bases the set on the full `origin/main..commit` diff (the
new `full-delivered-paths`, a two-tree diff, not a per-commit walk) and
excludes a path only on positive attribution to a still-unlanded sibling
and no other ticket (the new `path-attributing-commits` /
`path-owner-tickets`) — never the landed ticket's own paths, and never a
path touched by even one untagged commit in range (the hardener's
invariant-1 rework: an untagged touch used to be invisible to attribution,
so a path shared between an unlanded sibling's tagged commit and a later
untagged own-chain commit read as fully sibling-owned and was wrongly
dropped). An unreadable attribution refuses the land rather than silently
narrowing the tip, naming the specific path or diff `own-paths` could not
read (invariant 2) — `land-plan`'s `:escalate` reason now surfaces that
text instead of the old generic "could not compute own paths to replay".

`land_step_cli.bb` itself is untouched (confirmed: no diff against
`origin/main`) — `LAND_CLEAN` / `LAND_REPLAY <branch> <new-commit>` /
`LAND_ESCALATE` output shape is unchanged, only the tip contents and
escalate-reason specificity changed. `entangled-siblings` /
`unlanded-siblings` (BL-1308's detector, BL-1272's landed-sibling
discriminator) are unaffected.
