## Mutant D was a real gap — fixed, not explained away

Scenario 16 asserted only that the id read `(unattributed)`, never which
COMMIT was shown alongside it. The code has an explicit, commented
preference ("preferring HEAD's ... when it exists") for exactly this case
— both sides genuinely have a commit for the path here (HEAD's own
introducing commit, and the incoming side's deleting commit), so this is
not a hard-to-reach branch, it was simply never asserted on.

commits with the guard's own abbreviation format (`git rev-parse --short`,
matching `git log --format=%h` — the fixture's usual `--short=10` doesn't
match the guard's own output length, confirmed by a first false-negative
attempt before fixing the format) and assert the diagnostic names HEAD's
commit specifically, never the incoming side's. Re-ran mutant D against the
strengthened scenario: now fails correctly. Restored the source file
