# BL-1343 — coder pass (2026-09-02)

Critical defect: the land step subtracted a landing ticket's own paths from
its own replay and then reported the empty set in the same words a completed
land produces. Three QA-approved parcels were held off main.

## The fix

One change, in `swarmforge/scripts/land_step_lib.bb::own-paths`: the loop now
carries the paths it excluded together with the siblings they were credited
to, and at the end distinguishes the two empty sets that previously looked
identical.

- **Nothing delivered** (the tip IS origin/main) → `{:paths [] :warning nil}`,
  a real answer: nothing left to replay.
- **Paths delivered, every one subtracted** → `{:paths nil :warning "..."}`,
  a refusal naming the landing ticket, each excluded path and the sibling it
  was credited to.

`land-plan` already escalates on a nil `:paths`, and `land_step_cli.bb`
already turns that into `LAND_ESCALATE` + exit 1, so the refusal reaches the
operator without a second code path.

Chosen deliberately from the two the ticket offered ("a richer attribution
walk, a guard at the empty-set boundary, or both is the implementer's call"):
the guard at the boundary. It makes the failure impossible to mistake for a
completion, which is the invariant, without touching the attribution walk that
BL-1272's fail-closed sibling rule depends on.

## Rework on the architect's bounce D1 (2026-09-02)

**The finding was right.** `filesArb` drew each commit's credit independently
and uniformly over three values, so the all-sibling corner - the whole defect -
arrived with P ≈ 0.12 per case. Over `numRuns: 25` that left each test with a
~4.6% chance of failing on its own coverage floor, and the architect measured
1 spurious red in 6 runs. The file's own header claimed the opposite discipline
while implementing exactly the freely-drawn generator it warned about.

**Fix: the corner is reached by construction, not by draw.** The shape is no
longer generated. Each of the three shapes - every path credited to a sibling,
a genuinely mixed set, none credited to a sibling - gets its OWN property run
(`for (const shape of SHAPES) fc.assert(...)`), and only the file set inside a
shape is generated. `creditsFor` then constructs credits to match, with 'mixed'
forced to contain at least one sibling AND at least one survivor - something an
independent draw could not guarantee either. Every floor assertion now holds
because every shape ran, not because a draw was lucky. `numRuns` is 9 per shape
(27 cases total, up from 25), so breadth did not shrink.

The header comment that stated the discipline is re-tensed to describe what the
file now does, and records D1 so the next reader knows why it is shaped this
way.

**Verified**: the property file ran green **14 consecutive times** (8 + 6),
against the ~1-in-6 red the bounce measured. Non-vacuity re-confirmed after the
rewrite: disabling the guard in `land_step_lib.bb` still fails BOTH invariants.
`bb .../land_step_lib_test_runner.bb` ALL PASS and the acceptance feature is
6/6 after restoring the parcel the bounce reverted.

No production code changed in this rework - the defect was in the test's own
generator, exactly as the bounce said.
