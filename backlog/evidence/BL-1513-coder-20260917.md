# BL-1513 — coder pass, 2026-09-17

## The fix

`swarmforge/scripts/route_backlog_to_coder.sh`: `MSG` is now composed from
`TICKET_ID` (already resolved a few lines earlier for BL-1097's own
dispatch-trail check) as `Work <id>: read backlog/active/<id>-*.yaml`, and
moved to right after `TICKET_ID` is resolved — before the dispatch-trail
read and, critically, before the `assigned_to` rewrite — so a refusal
touches nothing (same "before anything is written or rewritten" posture
BL-1097 already established there). The `${MSG:0:80}` truncation branch is
replaced with a refusal: non-zero exit (1), stderr naming both the
80-character limit and `${#MSG}`, nothing queued. Every ticket id the
swarm mints stays comfortably under the limit (composed length is
`35 + 2*len(id)`; the threshold is `len(id) <= 22`), so this is a no-op
for every live ticket and a loud refusal only for a pathological id.

Two doc/comment references that quoted the old message shape now quote
the new one: `done_with_current_task.bb`'s BL-1422 section comment, and
`docs/how-to/BL-652-done-with-current-arg-rejection.md`. Explicitly listed
in the ticket's own "## What changes" (not a documenter callout), and
tightly coupled to the exact wording chosen here, so fixed in this same
parcel rather than left for a guess.

## Acceptance

`specs/features/BL-1513-the-router-note-is-never-cut.feature` was already
authored by the specifier at mint (`28f6302d32`) — this pass adds only
`bl1513RouterNoteFitsSteps.js` (BL-233/BL-1371). Drives the REAL
`route_backlog_to_coder.sh` and `dispatch_trail_cli.bb` against a fresh
fixture git repo per scenario, the same shape `bl1415LostDispatchSteps.js`
already uses. One wrinkle worth recording for whoever touches this fixture
next: `SWARMFORGE_SKIP_DAEMON=1` (the router's own default when the env
var is left unset) or `SWARMFORGE_SKIP_SYNC_INJECT=1` both leave the note
sitting in the coordinator's `outbox/` forever in a fixture with no live
daemon — genuinely undelivered, not just "delivery not yet observed" — so
neither lets a test read the delivered note's exact content. The fix:
`SWARMFORGE_SKIP_DAEMON=0` explicitly (never left to the router's own
default) plus a FAKE `.swarmforge/tmux-socket` file (any content — no real
tmux session needed, since `handoff_inject_lib.bb`'s `deliver-parcel!`
writes the recipient's target file before attempting the tmux wake
notification, which then fails harmlessly, exactly as it does in every
other fixture in this suite that never sets up a real socket).

## BL-654: the two declared invariants

`swarmforge/scripts/test/bl1513_router_note_fits_property_runner.bb`:

- Invariant 1 ("delivered byte-for-byte as composed... refused with the
  limit and its length named... nothing is queued... never shortens"): the
  domain is one integer parameter (ticket-id length) with a single hard
  threshold at 22/23, so this covers every length immediately around it
  (21-24) plus representative far points on both sides (1, 5, 10, 30),
  crossed with two real ticket-id prefixes (BL, GH) — 16 real
  `route_backlog_to_coder.sh` invocations against a fresh fixture each,
  asserting either a byte-exact delivered message or a refusal naming both
  80 and the exact composed length, with nothing queued. (An earlier draft
  swept every length 1-30 exhaustively — 60 trials, ~2 minutes — narrowed
  to this boundary-plus-far-points set once BL-1541's "seconds" target
  made that cost visible; still a real cross-check via the actual script,
  never a hoped-for sample.)
- Invariant 2 ("keeps the verb-first Work \<ticket-id\> form... parsers
  read it... and notes already on record in the old shape stay
  readable"): for 10 ids across the same length/prefix set, the REAL
  parser (`chase-sweep-lib/dispatch-trail-ticket-id`) recovers the exact
  id from both the NEW message shape and a hand-built OLD-shape message —
  the backward-compatibility half this ticket must not break, checked
  without needing the router at all.

Proven non-vacuous by hand before committing: reverting
`route_backlog_to_coder.sh` to its pre-fix composition (`BASENAME`, cut to
80) fails 16 of 16 invariant-1 checks — every "fits" case desyncs from the
basename-vs-id difference, every "refuse" case never refuses at all
(cut and sent instead); reverted before landing.
