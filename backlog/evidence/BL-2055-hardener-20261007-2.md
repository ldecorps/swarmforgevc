# BL-2055 — hardener pass 2 (QA bounce D1), 2026-10-07

QA bounce (`0150e7173f`, D1, blamed hardener): the shell launch script's
own copy of the sidecar-suffix list (`__bl2055_held_name`'s `case`
pattern in `swarmforge.sh`) had no BL-897 agreement test against
`handoff_lib.bb`'s canonical `sidecar-suffixes` — only the Babashka
guard's copy (`local_model_repeat_guard.bb`) had one, in
`test_bl1971_local_model_repeat_guard.sh`. A third, independent copy with
no agreement test could drift silently: a fifth sidecar suffix added to
`handoff_lib.bb` later would make the guard correctly skip it while the
shell script's launch loop still read it as a held parcel's name.

## Fix

Added to `swarmforge/scripts/test/test_bl1991_local_seat_restart_launch.sh`,
right after the existing `case_text` extraction (the same awk-extracted
real script text every other case in this file already drives): grep the
extracted text for the sidecar `case` pattern line itself (never a
hand-retyped copy — a future edit to the real line is what this test
reads), pull out each `*.suffix` token, sort, and compare against
`handoff_lib.bb`'s own `sidecar-suffixes` (loaded and sorted via `bb -e`,
the identical mechanism `test_bl1971` already uses for the guard's copy).

Confirmed the test actually discriminates, not merely greps for
presence: hand-edited a throwaway copy of `swarmforge.sh` to add a fifth,
fake suffix (`*.extra-suffix`) to the case pattern and re-ran the test —
failed immediately, naming both sorted lists for the mismatch. Restored
and diffed clean before trusting the real run.
