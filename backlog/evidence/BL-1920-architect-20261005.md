- Answering the two questions this ticket's description poses to the
  architect pass:
  - **Is "ends on a NO_TASK tool result" the right guard, or can a
    wake-nudge-NO_TASK cycle still repeat faster than handoffd's chase
    cadence?** The nudge is structurally bounded to at most one extra
    upstream call per `_complete` invocation (one synchronous `if
    needs_nudge(...)` branch, no loop) — it cannot itself retry or spin.
    Across separate wakes, `needs_nudge` returns False whenever the
    request's last message is a NO_TASK tool result (the seat just asked
    and got told there is nothing) or the reply text itself says NO_TASK,
    so the one case that would otherwise repeat — wake, call
    ready_for_next.sh, get NO_TASK, model restates that — never earns a
    nudge in the first place. The shim also rewrites at most one tool call
    per turn (`calls = calls[:1]`), so the request's last message is
    reliably the single most recent tool result, not one of several with
    NO_TASK buried earlier — the guard's "last message" check doesn't miss
    a parallel-call case because there isn't one. No repeat-faster-than-chase
    scenario found.
  - **Is a text heuristic acceptable here, or should the trigger be
    structural?** The *safety* property (never nudge while idle) is
    structural, not heuristic — it depends only on message role/content
    shape, not on wording. The *trigger* (recognizing an announcement) is
    necessarily heuristic: there is no structural signal in a chat
    completion that distinguishes "I'll run the tool" from a genuine final
    answer other than reading the text, and the three-hotfix history here
    (plain announce, then "let's", each caught only after a live
    counterexample) shows the heuristic needing iteration. That is an
    acceptable trade because the heuristic only ever adds a call
    (false positives cost one wasted nudge round-trip, bounded to one);
    it never suppresses a needed one in a way that regresses correctness,
    and the structural NO_TASK guard is what actually protects against
    runaway loops. Acceptable as designed.
