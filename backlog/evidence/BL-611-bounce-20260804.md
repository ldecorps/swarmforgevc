## D2 — acceptance step handler mutates real host state and can hang

- **Failing command**: `bash specs/pipeline/scripts/run_acceptance.sh specs/features/BL-611-deterministic-babysitterd-managed-by-swarm-lifecycle.feature`
  (no env override — this is the command QA's own role prompt specifies)
- **Commit**: `fd66ec3170`
- **First error excerpt**: the run never returns. Process tree confirmed via
  `ps`: `node cli.js` → `node --test ...generated.test.js` → `bash
  start_ancillary_services.sh` → `bash install_freshness_cron.sh` → `crontab -`,
  all sitting at 0.0% CPU, unchanged, for 8+ minutes. Isolated repro:
  `crontab -l` returns instantly; `printf '...' | crontab -` (the write path
  `install_freshness_cron.sh` uses) hangs indefinitely on this host and never
  returns even after 2 minutes — consistent with a macOS permission-consent
  gate that never resolves headlessly.
- **Failure class**: acceptance
- **Expected vs observed**: Expected the acceptance suite for a daemon-lifecycle
  ticket to run against disposable fixture roots only, per the Design And
  Testability rule ("redirect live paths through env seams; missing seam = add
  one in the same parcel"). Observed `runStartAncillary()`'s `ancillarySkipEnv()`
  (`specs/pipeline/steps/bl611BabysitterdLifecycleSteps.js:97-105`) sets
  `SWARMFORGE_SKIP_OPERATOR/FRONT_DESK/ONBOARDER/TUNNEL/RESIDENT_SPY_TUNNEL` but
  not `SWARMFORGE_SKIP_FRESHNESS_CRON` — so every call to the real
  `start_ancillary_services.sh` also invokes the real `install_freshness_cron.sh`,
  which mutates the *actual host's* system crontab (not the disposable fixture
  root) as a side effect, and hangs the whole acceptance run indefinitely on any
  host where a crontab write is not instantaneous. I re-ran with
  `SWARMFORGE_SKIP_FRESHNESS_CRON=1` exported manually to get past this and
  complete the rest of verification (see D1); no crontab pollution occurred
  (confirmed via `crontab -l` before/after — the write never landed, it just
  hung and was killed).
- **Blamed role**: coder (same file/function as D1).
- **Remediation pointer**: add `SWARMFORGE_SKIP_FRESHNESS_CRON: '1'` to
  `ancillarySkipEnv()` in `specs/pipeline/steps/bl611BabysitterdLifecycleSteps.js:97-105`,
  alongside the five skips already there.
