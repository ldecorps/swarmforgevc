## The fix

Both call sites in `bridgeServer.ts` (`mirrorLetsTalkTurnToBubble`'s main
turn mirror, and `choicePollMirrorTarget`'s poll-destination resolution)
resolved their topic via `bubbleMirrorTopicForPath` — the ordinary-Bubble
resolver, which deliberately returns `undefined` when unbound. Both now go
through a new `letsTalkMirrorTopicForPath` sibling that calls the already-
exported `effectiveLetsTalkMirrorTopicId` instead. `effectiveBubbleMirrorTopicId`
and `bubbleMirrorTopicForPath` themselves are untouched — invariant 2 forbids
widening them, so the diff never touches their bodies, only which resolver
the Let's Talk call sites reach for.

The choice-poll site is not named in the ticket's description but is the
same bug shape one function up the call chain: `mirrorLetsTalkChoicePollToBubble`
runs only after the main mirror already succeeded (i.e. only when a
destination topic was found), so leaving it on the old resolver would have
kept the poll silently dropped in the unbound case even after this fix —
same file, same immediate caller, zero added surface. Confirmed against the
original BL-709 landing (`9e713ac6c2`): that commit independently switched
both call sites the same way; this pass restores that shape.
