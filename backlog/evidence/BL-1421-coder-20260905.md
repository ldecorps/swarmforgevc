# BL-1421 — coder pass, 2026-09-05

The post-QA branch sweep's `:surfaced` (already-told) record reset on
every newly landed commit, so a role that stayed behind was told again on
every one of the 103 commits main landed on 2026-09-05 — 539 "branch
behind: dirty worktree - merge up" notes and tmux wakes across six roles
in one day. `decide-role` also read `dirty?` before `in-process?`, so a
role mid-parcel (dirty by definition — its own uncommitted work) was
classed as a resolvable dirty-worktree wake instead of in-process-work,
the one class the human's BL-1361 ruling never wakes for. This session
lived through the resulting flood directly while implementing BL-1407,
BL-1416, and BL-1422.

## Declared invariants (BL-654)

All three have a coder-authored, non-vacuous property test (four
properties total — P1 alone turned out insufficient for one aspect of
invariant 1, see P1b below), each shown to fail against a deliberately
broken implementation (verified live, then restored — `diff` against a
pre-break backup confirmed byte-identical restoration every time):

- **Invariant 1** (one standing surfacing per (role, reason); a newer
  landed sha alone never re-tells) — **P1**: an arbitrary sequence of
  ticks replayed through the real `sweep!` must produce the IDENTICAL
  per-tick tell/no-tell pattern as an independent reference state
  machine. Broken by flipping `surface-already-recorded?`'s
  `(not caught-up-to-told?)` to plain `caught-up-to-told?`: 475/500 cases
  failed. **P1b** (added after auditing P1's own coverage): P1's mocked
  `:caught-up-to-told?` ignores the `told-sha` argument it's handed, so a
  broken `record-surface!` upsert (plain `conj`, leaving stale duplicate
  entries) does not change P1's tell pattern at all and passed clean
  against that mutant — a real vacuity gap, caught by design review before
  claiming the property proven. P1b targets `record-surface!` directly:
  after N successive re-surfacings of the same (role,reason), exactly one
  entry must exist, naming the LAST landed-sha. Broken by reverting the
  upsert to plain `conj`: 420/500 cases failed (every one with 2+
  re-surfacings).
- **Invariant 2** (in-process work is surfaced as in-process-work, never
  woken) — **P2**: broken by reverting `decide-role`'s precedence swap:
  179/500 cases failed (every one with `in-process?=true` and
  `dirty?=true`, the ticket's own "mid-parcel is dirty by definition"
  case).
- **Invariant 3** (BL-1361 unchanged: one unreachable mailbox withholds
  nothing from the others) — **P3**: broken by removing the `try/catch`
  around `tell!` in `sweep!`: the property runner itself CRASHED with the
  injected exception propagating out of `reduce` (the failure mode the
  invariant exists to prevent, made directly visible rather than merely
  asserted false).

**Reachability floors**: all four coverage buckets (P1 sequences over 5
ticks, P1 sequences containing a re-catch-up tell, P2 dirty=true cases, P3
sequences with at least one throwing role) measured 263-455 out of 500 —
all well above the 50 (runs/10) floor.
