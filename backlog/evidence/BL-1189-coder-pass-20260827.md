# BL-1189 coder pass — 2026-08-27

## Summary

Live Screen could paint the same ticket as primary working on several role
tiles at once (BL-600 on Coordinator, Cleaner, Architect, and Documenter
simultaneously during a bookkeep-close cascade). Two independent fixes:

1. **Invariant 1** — `resolveResidentHeldTicketMeta` (`residentPaneSpy.ts`)
   now only reports a ticket as primary working when it is genuinely still
   in `backlog/active/`. A closed ticket's stale, never-cleared in_process
   claim file used to still read as "working now" because
   `lookupBacklogItemById` searches every folder including `done/`; a new
   `isTicketActive` check gates on the `active/` folder specifically.
2. **Invariant 2** — new pure `dedupePrimaryWorkingTicket(claimedTicketIds,
   meta)` (`residentPaneSpy.ts`), threaded through `tryCaptureRolePane`'s
   new `claimedTicketIds` parameter and `captureLiveScreenPanes`'s one
   `Set` shared across all tiles in a capture: the first role (in
   `LIVE_SCREEN_ROLE_ORDER`) to claim a ticket in one capture keeps it;
   any later role reporting the same ticket has it demoted-or-omitted.

## Key paths

- `extension/src/concierge/residentPaneSpy.ts` — `isTicketActive`,

## Design notes

- "Stale mailbox residue" (acceptance scenarios 03/04) is modeled as a
  handoff sitting in a role's `inbox/completed/`, never `inbox/in_process/`
  — `resolveResidentHeldTicketMeta` only ever reads `in_process`, so this is
  invisible to it by construction; no separate staleness signal was needed
  for those two scenarios beyond the invariant-1/2 fixes above.
- Did not implement literal pane-text-based tie-breaking ("prefer pane
  truth when claims disagree", How #4) — that directive is explicitly
  marked "direction, not mandate" in the ticket. The shipped tie-break is
  deterministic first-claimed-in-`LIVE_SCREEN_ROLE_ORDER`-wins, which
  satisfies both declared invariants and the acceptance scenarios as
  written; a pane-text corroboration pass would be a reasonable follow-up
  but is not required by anything this ticket declares as testable.
