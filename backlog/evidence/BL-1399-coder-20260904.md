## A second arm the ticket did not see — and how it is handled

`FRESHNESS_REQUIRED` alone does **not** make the test green. The guard has a
second check with **no seam**: it walks its own `$SCRIPT_DIR` for
`*_supervisor.bb` and refuses any it cannot find a conf row for. With the
registry seam in place the fixture still failed, now naming
`bridge_headless_supervisor` — a refusal the ticket's author could not have
seen, because the `babysitterd` arm fails first and the guard exits on the
first failure.

Handled inside the ticket's outcome rather than by widening the guard: the
fixture's conf now carries a row per supervisor **derived from the same glob
the guard walks** (never a list written in the test — BL-1398's lesson, one
ticket old), and each of those rows gets a fresh heartbeat in the fixture so
the daemon is healthy and the watchdog takes no action on it. Only handoffd's
age varies, so every BL-1012 assertion still reads handoffd's behaviour alone.
**No guard, checker or live conf file was changed** — asserted by e2e check 4,
which diffs all four live files.

A `spec-gap` note (priority `00`) goes to the specifier with this, so the
ticket's "How" record matches what the fix actually required.
