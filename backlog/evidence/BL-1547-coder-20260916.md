# BL-1547 — coder evidence, 2026-09-16

## The fix

`landed_ticket_lib.bb` (BL-992's own freshest-ref reader) gains:

- `ticket-yaml-at-ref-in` (private): `ticket-yaml-at-ref`'s existing body,
  generalized to an arbitrary backlog subpath instead of the hardcoded
  `backlog/active`. `ticket-yaml-at-ref` itself is unchanged in signature
  and behavior (delegates to the new helper with `"backlog/active"`).
- `ticket-lanes-at-ref` (public): every backlog lane (`:active` `:paused`
  `:hold` `:done`) whose tree at a given ref contains a ticket's own YAML
  (`id:` field match, never a filename glob) — `backlog/done`'s git-grep
  pathspec covers the whole subtree, so a ticket nested by milestone
  (`backlog/done/M8/BL-....yaml`) is found exactly like an unnested one.
- `ticket-closed?` (public): true only when a ticket is found under
  `backlog/done` and under no other lane, resolved from the FIRST of
  `declaration-refs` (main/origin-main, freshest first per BL-992/BL-891)
  that finds the ticket in some lane at all. A ref finding it nowhere
  falls through to the next ref rather than concluding either way from
  silence; no ref ever resolving it (absent everywhere, or every ref
  unreadable) answers `false` — the fail-closed default per this ticket's
  own constraint.

`task_scope_gate_lib.bb`'s `foreign-scope-findings` (BL-1192, pure)
gains an optional 4th argument, `closed-ticket-ids` — a plain set the
impure caller passes in, so the function itself makes no git call (kept
as the BL-654 property target the ticket's own "How" section asks for).
A path whose basename resolves to an id in that set is excluded from the
findings, alongside the existing task-id and BL-1276 declared-path
exclusions. The 2-arity and 3-arity call shapes are preserved unchanged
(default `nil` closed-ticket-ids), so no existing caller needed updating.

`findings-for-git-handoff` (the one impure entry point) now computes,
for every distinct foreign candidate id found among the changed paths
(never the task's own id, already excluded earlier in the same `for`),
whether `landed-ticket-lib/ticket-closed?` says it is closed, and passes
that set into `foreign-scope-findings`. The task's own ticket is never
queried for closure at all — the exclusion happens before the candidate
set is even built.

## Declared invariant (BL-654)

> "A foreign-scope finding names a ticket that is OPEN: its YAML read
> under backlog/active, paused or hold on the freshest ref, or not found
> at all. A basename whose ticket is read under backlog/done on that ref
> is never a finding."

Coder-authored first, in
`swarmforge/scripts/test/bl1547_closed_ticket_not_foreign_property_runner.bb`
(not a suite-manifest member — a property runner has its own lane, per
`suite_inventory_lib.bb`'s own `test-file?`/`check` comment, same as
BL-1276's own `task_scope_gate_acceptance_exemption_property_runner.bb`).
Drives `foreign-scope-findings`'s pure 4th argument directly (300 runs):
every generated foreign id is independently marked closed or open, given
1-2 paths of varying recognised shape (feature/yaml/how-to) so the
exemption is proven to travel with the ID, not the path or the shape;
asserts a closed id contributes no finding from ANY of its paths, an open
id contributes a finding for EVERY one of its paths, and the total finding
count is exactly the sum of open ids' own path counts. A second, smaller
pass confirms the 3-arity call and the 4-arity call with `nil`/`#{}`
closed-ticket-ids agree byte-for-byte (backward compatibility). Reach
floors asserted, not hoped for (closed-id cases: 100+, open-id cases:
100+, multi-path-same-id cases: 30+ — all comfortably cleared at 300
runs).

The git-backed half of the invariant (which lane a ticket is REALLY filed
under, on the freshest ref) is deliberately NOT re-tested inside this
property — that is `landed_ticket_lib.bb`'s own job
(`ticket-lanes-at-ref`/`ticket-closed?`), exercised against real git
fixtures in `task_scope_gate_lib_test_runner.bb` instead (mkdtemp, own
origin, per BL-1390). Splitting the two keeps the property fast and pure
and the git-fixture tests focused on the one thing they alone can prove.

**Non-vacuity, proven by hand**: with the `(not (contains? closed-set
id))` clause deleted from `foreign-scope-findings`, the property fails
immediately — every closed-id case reports a spurious finding, and the
total-count assertion mismatches. Restored before committing; full
`ALL PASS` output above is from the restored file.
