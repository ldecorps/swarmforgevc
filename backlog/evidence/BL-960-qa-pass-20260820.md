## G9 — direct verification of the fail-open contract

The operator disabled this hook on 2026-08-19 (`3bac496ec`) with the condition: *"Re-enable ONLY once the wrapper is parse-checked (`bash -n`) with fail-open to the untouched original."* Because approving this ticket re-arms a hook that rewrites every Bash command the whole swarm issues — including QA's own — the contract was exercised directly against the shapes from the original incident:

| Input shape | Result |
|---|---|
| heredoc containing literal parens (**the incident case**) | wrapper BUILT, `bash -n` **parses** |
| bare literal parens (`echo (not a subshell)`) | **FAIL-OPEN** → caller hands back the byte-untouched original |
| unterminated quote | **FAIL-OPEN** → byte-untouched original |
| plain command | BUILT, parses |
| pipeline | BUILT, parses |
| `;`-sequence | BUILT, parses |

Every wrapper that is built parses; everything that cannot be safely wrapped fails open to the original with no narration. `safe-wrapper-command` returns `nil` on a failed gate, and `wrapper-parses?` catches exceptions to `false`, so a parse gate that THROWS also fails open — the failure mode is "leave the command alone", never "hand Claude Code something unparseable".
