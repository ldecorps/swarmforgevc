# BL-1660 coder evidence

## The fix

`swarmforge/scripts/local_ollama_pack_shape_lib.sh`'s `bl1142_pack_config`
fed `printf` into an `awk` program that called `exit` at the first
matching line. Under `set -o pipefail`, once awk is scheduled between two
of printf's writes it has already closed its stdin, so printf's next
write dies of SIGPIPE (141) and `set -e` fails the caller - deterministic
once the body is larger than the pipe buffer (64 KiB on this host), and
occasionally sighted even on small bodies under load (the property lane's
own flaky sightings this shift). Fixed by reading the whole input every
run and taking the first match via a flag variable, printed once at
`END`, so awk never closes its stdin early regardless of body size or
scheduling:

```
awk -v k="$key" '$1=="config" && $2==k && !f { v=$3; f=1 } END { if (f) print v }'
```

Every existing output is unchanged - still the first matching line, still
empty when none match. `bl1142_window_count` already read its whole input
and was never at risk.

## Test case 07 - a fresh subprocess is load-bearing

Calling `bl1142_classify_pack_shape` directly inside
`local_ollama_pack_shape_test_runner.sh`'s own already-running shell
(after cases 01-06 had already run) did NOT reliably reproduce the race
against the deliberately-broken library - 20/20 clean, a false pass. The
same body, run through a fresh `bash -c` matching the ticket's own
reproduction shape (`bash -c 'set -euo pipefail; source lib;
bl1142_classify_pack_shape "$(cat)"'`, body on stdin), reliably reproduced
it 20/20. Case 07 spawns that fresh subprocess rather than calling the
function inline.

## Declared invariant (BL-654)

"Every pipeline in local_ollama_pack_shape_lib.sh consumes its whole
input on the reading side - no early exit while a producer may still be
writing - so the classifier's exit status is 0 for every well-formed body
of any size, under any scheduling."

A new, separate property test,
`extension/test/bl1660PackConfigNoEarlyExit.property.test.js`, encodes
this - deliberately not touching
`bl1142LocalOllamaPackShape.property.test.js` per this ticket's own
constraint (that file's `classify()` is the pre-existing consumer proving
the fix, not to be edited). Reachability floor: the generator draws
`windowLines` from `[6000, 30000]`; at 12 bytes per `window seat\n` line
every draw produces a body of 72,000-360,012 bytes, always past the 64
KiB pipe buffer - by construction, not by hope. Each run spawns a fresh
`bash -c` (the ticket's reproduction shape) so the pipe is real. Shown
non-vacuous above (fails on the very first draw against the broken
awk-exit form).
