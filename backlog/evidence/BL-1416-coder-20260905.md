## Declared invariants (BL-654)

All three have a coder-authored, non-vacuous property test in this parcel,
each shown to fail against a deliberately broken implementation (verified
live, then restored — `diff` against a pre-break backup confirmed
byte-identical restoration):

- **Invariant 1** (a busy pane is never classified auth-dead) — P1 broken
  by making the busy branch of `decide-auth-observation` return a fresh
  `{:attempts 0 :alerted false}` instead of the prior state unchanged (the
  "reset instead of untouched" bug): 458/500 generated cases failed
  (every one whose prior state wasn't already the zero state).
- **Invariant 2** (only performed respawns are counted) — P2 broken by
  making `resolve-committed-state` always return `(:state decision)`
  (ignoring `performed?` — the exact pre-BL-1416 bug): 357/500 generated
  cases failed (every one containing at least one skipped respawn).
- **Invariant 3** (the persist alert names the matched line + performed
  count) — P3 broken by dropping the matched-line branch from
  `format-alert-reason`: 374/500 generated cases failed (every one with a
  non-nil matched line).

**Reachability floors**: all four coverage buckets (P1 non-zero prior
attempts, P2 some-skipped, P2 all-performed, P3 nil-line) measured well
above the `runs/10` (50) floor — 401/425/75/116 respectively.
