## D1 — CLEARED: a failed commit no longer leaves anything of this run staged

**Reproduced first, exactly as the send-back described**, with real
temp git repositories and a real refusing `pre-commit` hook — not a thrown
mock. The three new tests in `extension/test/boyScoutRunCommitIndex.test.js`
failed against the bounced code with precisely the states the architect
recorded:

```
expected [' M src/a.ts']      actual ['M  src/a.ts']
expected ['?? src/new.ts']    actual ['A  src/new.ts']
expected []                   actual ['AD src/new.ts', 'MM src/a.ts']
```

**The fix, in `extension/src/tools/boyScoutRun/commit.ts`.** Both halves of the
architect's remediation, because each closes a different half of the defect:

1. **Staging is now the narrowest thing that makes the partial commit
   possible.** `commitEdits` first asks `git ls-files -z -- <paths>` which of
   its paths git already tracks, and stages ONLY the ones it does not. A
   tracked path goes straight into `git commit -- <path>`, whose temporary
   index cannot diverge the real one — so for the common case (a cleanup
   editing existing files) there is now no staging to leave behind at all.
2. **Whatever it did stage, it takes back on failure.** On either a failed
   `git add` (which can stage some paths before failing on another) or a failed
   `git commit`, `git reset --quiet -- <the paths this function staged>` runs
   before the throw. Scoped to those paths deliberately: a blanket
   `git reset -- <all paths>` would throw away staging the operator had done
   themselves on a tracked path before the run.

An unstage that itself fails is appended to the thrown message as a WARNING
rather than replacing it — the commit failure is the reason the operator
needs, and a leaked index entry is something they also need to know; neither
may hide the other.

**Tests added (all failed before the fix, except where noted):**

- `boyScoutRunCommitIndex.test.js` (new file, 4 tests), real temp repos, reads
  `git status --porcelain` so both columns — staged and unstaged — are
  asserted, never file content alone:
  - a failed commit over an EDITED tracked file leaves ` M`, not `M `/`MM`
  - a failed commit over a CREATED file leaves `??`, not `A `/`AD`
  - a whole `boyScoutRun` whose commit throws leaves `git status --porcelain`
    EMPTY — the index back as well as the tree, which is the send-back's
    actual ask
  - (passed before the fix too, and kept as its regression guard) a SUCCEEDING
    commit still commits exactly the run's paths and leaves the operator's own
    unrelated staged work staged and uncommitted — the failure mode a naive
    `git reset` fix would have introduced
- `boyScoutRun.test.js`: the existing argv test updated for the new command
  sequence (it asserted the exact spawn list, which deliberately changed), plus
  four new ones — a tracked path is never staged; a failed commit unstages
  exactly what it staged and nothing else; a failed unstage is reported
  alongside the commit failure; an `ls-files` that fails falls back to staging
  everything and can still take it all back.

never threw, so invariant 1's "never partially applied" had never reached the
one path that writes, passes its gates, and then cannot commit.

came back.
