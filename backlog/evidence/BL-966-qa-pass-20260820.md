## G2 — the invariant measured against the live repository, not a fixture

This defect was directly observable in QA's own session: **every `swarm_handoff.sh` call all night printed `WARNING: Active backlog depth exceeded (active=7, max=3)`**, and QA escalated it more than once as a backlog-over-cap problem. It was not one. The cap was 7 the whole time; the CLI resolved `3` from a worktree because linked worktrees carry no `.swarmforge/`, so the identity fallback produced a different governance constant per checkout — silently, which is the fail-open this ticket names.

After the fix, both checkouts agree:

```
master checkout : 7
QA worktree     : 7
```

That is the invariant's exact claim ("two checkouts of the same repo can never disagree silently"), verified on the repository the swarm is actually running in rather than a temp fixture.

## Observation — pre-existing stderr noise on a scratch root (NOT a BL-966 defect)

Invariant 3 says "only the new stderr fall-through notice may appear" on a plain temp dir. In practice a second message also appears there:

```
effective_backlog_depth_cli: throttle-recommendation refresh failed, exit=1
Error: Cannot find module '<root>/extension/out/tools/emit-throttle-recommendation.js'
```

Attributed before judging: `git diff HEAD^1 HEAD -- effective_backlog_depth_cli.bb` shows **no** change to that call in this parcel, and `git log -S` places its introduction at `79f3f6b0e` (**BL-432**). It fires only when the CLI runs against a root that has no built `extension/out`, which a scratch fixture never has. It is pre-existing, unrelated to this change, and this parcel neither adds nor worsens it — so it is recorded here rather than raised as a defect against BL-966. Worth a separate look by whoever owns BL-432's throttle loop: a missing optional refresh printing a raw Node stack trace is noisy for something that is meant to degrade gracefully.
