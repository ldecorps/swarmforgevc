## Invariants — verified in the actual code

1. **No commit reaches main carrying a Babashka script that fails SCI
   analysis.** `analyse_one()` discriminates on babashka's own error banner
   (`^-+ Error|Unable to resolve symbol|Could not resolve symbol|Could not
   find namespace`), never the exit code — correctly avoids the false-refuse
   the coder's own evidence documents finding against `hardening_debt_ledger_read.bb`
   (a CLI that exits non-zero on no-args but loaded fine). `set -uo pipefail`,
   no `set -e`, each file's status captured independently (BL-1242/BL-1252).
2. **`handoffd.bb` is booted, not merely analysed.** `boot_handoffd()` runs
   the real daemon against a per-invocation mkdtemp fixture with
   `--sweep-once`, and — this is the part I checked most carefully — the
   banner check (`(( banner ))`) is evaluated and short-circuits to failure
   *before* any reliance on output content, so babashka echoing the source
   of a broken `sweep-once done` marker inside its own `Context:` error block
   (the false-green the coder's evidence describes finding and fixing) cannot
   pass. Confirmed live: `--sweep-once` only ever writes "sweep-once done"
   via `log!`, which spits to a file, never to stdout — so the fallback
   `grep -q 'sweep-once done' <<<"$out"` on the non-banner/non-zero-rc path
   is effectively dead code in normal operation, but this makes the guard
   *more* conservative (any unexplained non-zero exit refuses), never less —
   not a defect.
3. **Verdict follows the tree under test, not the checker's worktree.**
   `changed_bb_files()` reads `git_clean -C "$TREE_ROOT" show ... HEAD`, and
   `analyse_one`/`boot_handoffd` both `cd` into the tree's own
   `$SCRIPTS_DIR` (symlinked into the boot fixture) before loading — a
   script that `load-file`s siblings picks up the tree's siblings. The
   `git_clean` wrapper scrubs the full `GIT_*` env before every git call in
   this script, closing the leaked-`GIT_DIR` hazard that would otherwise
   invert this invariant on the land-replay path (the exact incident class
   already seen twice this session in unrelated tickets).
