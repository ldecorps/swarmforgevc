## Invariant 1: a bounced commit never approves a path on its own

A path whose last incoming touch is bounced is imported only when a later
commit of the same ticket on the incoming side is approved and carries the
identical blob.

- The predicate enforces this: `bounce_superseded_by` returns 1 (bounce
  stands) unless a same-ticket later commit on the ancestry path is itself
  approved; the guard then imports the path only if the staged blob matches
  the incoming parent blob (`git diff --cached "$merge_head" -- "$f"` empty).
- Live: `bash swarmforge/scripts/is_qa_ancestor.sh a0b390f7e0` prints

## Invariant 2: one ticket's approval never imports another ticket's path (BL-1096)

- `bounce_superseded_by` extracts the ticket id from the bounced commit's
  subject (`^(BL|GH)-[0-9]+`) and only considers candidates whose subject
  matches `^${ticket}([^0-9]|$)` — a different ticket's approval can never
  supersede.
- Guard suite case "bounced-then-fixed: a different ticket's approval never
  covers the bounced commit's path" passes: the merge is refused and the
  bounced path is named.
- Store suite case "a different ticket's approved descendant does not
  supersede a bounce" passes: exit 1, the bounce still stands.
- The guard's per-path anchor (BL-1096) is unchanged: each path is still
  anchored on its own last incoming commit, never the merge tip.

## Cost on a long ancestry path

- The supersession scan is bounded: `git rev-list --ancestry-path
  "$FULL_SHA..$base" | head -n 200` per base (swarmforge-QA, origin/main,
  each lander-queued tip). 200 commits is the same bound 8f2643f123's
  carrier used on the guard's single incoming-side path; a bounced-then-
  fixed parcel's fix descends directly from its first try, so the
  superseding commit sits a handful of commits up, far inside the bound.
- The per-candidate verdict runs in a subshell, so a long path costs at
  most 200 subshell invocations of `answer_one` per base, and only for
  commits whose subject carries the same ticket id — the subject grep
  filters before the subshell runs.
- The guard itself no longer walks the ancestry path at all: it calls the
  predicate once per staged path, and the predicate's supersession scan is
  the only walk. No second definition, no second walk (BL-925 invariant 2).
