## D1 (BL-964) — the gate carried 3 hand-written needles for an 11-seam mechanism

The guard's needle list is the three retired names the 2026-08-20 incident exposed. But `swarm_ensure.bb` reads **eleven** `SWARM_ENSURE_*` seams:

```
BABYSITTERD_CMD  CURSOR_BRIDGE_CMD  EXTENSION_BOUNCE_CMD  EXTENSION_CHECK_CMD
FRONT_DESK_CMD   OPERATOR_CMD       RC_CAPTURE_CMD        RC_CMDLINE_CMD
RC_NOTIFY_CMD    RC_SESSION_DEAD_WAIT_SECONDS             SUPERVISOR_CMD
```

So the gate covered **3 of 11**. Measured against the received commit, **8 of 9** retired spellings went unflagged — `SWARMFORGE_ENSURE_BABYSITTERD_CMD`, `…CURSOR_BRIDGE_CMD`, `…FRONT_DESK_CMD`, `…OPERATOR_CMD`, `…RC_*` — each carrying the **identical** silent failure the ticket describes: the fake is ignored, the real command runs, and the test still passes. The roster was the incident's names, not the mechanism's, which is the one-at-a-time patching the ticket exists to end.

**Fix**: the needles are now DERIVED from `swarm_ensure.bb`'s own reads (`SWARM_ENSURE_X_CMD` → `SWARMFORGE_ENSURE_X`), the same read-the-other-side's-literal method BL-948's parity gate uses. A twelfth seam is covered the day it is added, with no edit here. Two safety properties came with it:

- **union with the historical floor** — deriving can extend the gate but never shrink it below the three names known to have caused a real incident;
- **an empty derivation raises** rather than yielding an empty needle set, which would make the gate pass every file while looking green. That is the one failure a gate must never have.

**After**: 11 needles, **0 of 9 missed**, real tree still 0 violations. Pinned by 4 new tests (8 total, was 4): every seam in the `.bb` has a gated retired spelling; a non-incident seam's retired spelling is flagged; the floor survives; an empty derivation throws.

## D2 (BL-962) — `offender-row` had no unit coverage, and "non-merge commits are untouched" was unpinned

Hand-authored sweep (BL-638 fallback — the BL-962 feature has no `Scenario Outline`, so the BL-113 gate is `inapplicable`, and `.bb` has no wired mutation tool): six single-edit mutants over the parcel's own changed behaviour. **5 killed, 1 SURVIVED.**

The survivor deleted `offender-row`'s `(not (commit-is-merge? sha))` branch, sending non-merge commits through parent adjudication too. Nothing failed, because `offender-row` had **zero** unit references.

**It is not an equivalent mutant, and I checked rather than assuming.** On the happy path it agrees by accident: `merge-non-first-parents` drops the first two fields of `rev-list --parents`, so a non-merge commit yields `[]`, `parents` is empty, and nothing is exempted. But that call is a git subprocess returning `nil` on failure, which `merge-parent-facts` turns into `{:ok? false}` and `offender-row` into `::adjudication-failed` — failing the **whole sweep** closed. So the mutant converts an ordinary non-merge offender into a total sweep failure whenever that extra git call fails, and "non-merge commits untouched" is the ticket's own constraint.

Killed by pinning the property directly: with adjudication stubbed to FAIL, a non-merge commit must still report its offending paths — because it must never consult adjudication at all. A companion test drives the same stub from the merge side, where failing closed IS correct. **Re-run: 6/6 killed.**

## Independently re-verified: the architect's D1 bounce on BL-962 is genuinely closed

Pass 1 bounced BL-962 because the structural gate was **vacuous** — it stripped string contents before scanning, and in Babashka a git subcommand can only ever appear as a string literal, so a rival ancestry predicate passed unnoticed. Rather than take the pass-2 verdict on trust, I planted the exact rival shape into `babysitter_check.bb`:

```clojure
(defn rival-ancestor? [a b]
  (zero? (:exit (process/sh "git" "merge-base" "--is-ancestor" a b))))
```

Result: `FAIL no second ancestry predicate: merge-base/--is-ancestor never appears in babysitter_check.bb's code, string arguments included` — and ALL PASS again once restored. The gate is non-vacuous.
