# BL-1573 — coder evidence, 2026-09-16

## The fix

`chase_sweep_lib.bb`'s `dispatch-gap-note-message` now leads with the
router's own verb-first `Work` marker, the same fix BL-1223 applied to
the sibling `unassigned-active-note-message`:

```
Work BL-217: read file in backlog/active - auto-routed by the sweep, no HEAD
```

(76 characters, under `dispatch-gap-note-max-length` = 80.)
`dispatch-trail-ticket-id` now answers `BL-217` for `{:task nil :message
(dispatch-gap-note-message "BL-217")}` (was `nil` on main), so the
fallback note itself counts as a dispatch trail and the next sweep does
not re-detect the gap. `dispatch-trail-ticket-id`,
`spec-work-ticket-id-pattern`, `read-active-items`, and `handoffd.bb` are
unchanged, per the ticket's own constraint.

## One necessary addition beyond the ticket's named file list

`specs/pipeline/steps/dispatchGapSteps.js`'s `listQueuedAutoroutesFor`
(BL-222's own acceptance step handler, unrelated ticket) matched a queued
fallback note via `^message: <id>` - a bare-leading-id pattern that no
longer matches the new verb-first text. Running its own test file
(`specs/pipeline/test/steps/dispatchGapSteps.test.js`, which the ticket
does name) after updating the fixture text to the new message format
failed 3 of 18 cases for exactly this reason. Widened the regex to
`^message: (?:Work )?<id>` so it recognizes both the legacy bare form and
the new verb-first form - the qa_e2e_procedure's own step 6 names this
test file as needing to stay green, and it cannot without this one-line
change. Not in the ticket's own "Not in scope" exclusion list (which
names `dispatch-trail-ticket-id`, `spec-work-ticket-id-pattern`,
`read-active-items`, `handoffd.bb`, and `test_*.sh` specifically) and not
a design choice - purely a mechanical consequence of the approved message
change, recorded here for visibility since it is not in the ticket's own
predicted diff list.
