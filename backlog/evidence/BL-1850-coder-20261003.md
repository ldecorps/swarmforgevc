## Change
- `swarmforge/scripts/local_seat_settings_snapshot_lib.bb` (pure):
  - `parse-show-parameters` turns Ollama `/api/show`'s text into a map: numbers as numbers,
    quoted strings unquoted, a repeated `stop` as a vector.
  - `pick-provider-entry`: the seat worktree's `modelProviders.openai` list replaces the user
    list when it carries one, per QA's BL-1838 reading.
  - `drop-credentials` works recursively through maps and lists, keyed by `credential-key?`:
    any key naming an API key, a token, a secret or a password.
  - `parse-nvidia-smi` parses the name, enforced limit and default limit.
  - `fingerprint` is sha256 over a canonical, key-sorted JSON of the row minus `at`;
    `finish-row` stamps it.
- `swarmforge/scripts/local_seat_settings_snapshot_cli.bb` takes `<root> --seat --model
  --endpoint-url --card --worktree [--qwen-home] [--nvidia-smi] [--qwen-bin]`.
  - It asks Ollama (`/api/version` and `/api/show`; a `/v1` suffix on the endpoint is stripped),
    `nvidia-smi` and `qwen --version` in parallel. Each is bounded at 1.5 s under a shared 2.3 s
    deadline, and a silent source is recorded as `"unknown"`.
  - It reads qwen's user and workspace settings, and the card's path, bytes and sha256. It
    appends one JSON row to `.swarmforge/local-agent/seat-settings/<seat>.jsonl`.
  - Every failure is logged to stderr, including a non-zero exit, unusable output, a partial
    Ollama answer, a missing card and an unwritable record. It always exits 0.
- `swarmforge.sh` `write_role_launch_script`: for `local-model` seats only, the generated launch
  script's `local_model_guard` gains the snapshot line, so it runs on every start and respawn,
  before `launch_body` starts qwen.
  - The line is `bb '<seat worktree>/swarmforge/scripts/local_seat_settings_snapshot_cli.bb'
    '<root>' --seat '<role>' --model '<--model>' --endpoint-url '<lm_url>' --card '<the seat's
    card, role_prompt_card_path>' --worktree '<seat worktree>' >/dev/null
    2>>'.swarmforge/launch/<role>.seat-settings.log' || true`.
  - This is the required_wiring anchor.

## Invariants (BL-654, coder first authorship)
`extension/test/bl1850SeatSettingsSnapshot.property.test.js` (`npm run test:properties` only):
- **Invariant 1** draws a failure mode per source:
  - Ollama: ok, hang, refused, 500, or malformed;
  - nvidia-smi: ok, hang, missing, exit 1, or garbage;
  - qwen: ok, hang, or missing;
  - settings: valid or malformed; card: present or missing; record directory: writable or not.
  The CLI must exit 0 within 3 s and log on stderr whenever anything failed. Fixed examples pin
  the all-hang worst case, the unwritable record, a clean run, and each single failure on its own
  (so another source's log cannot stand in).
  - The property found a gap: an `nvidia-smi` exiting 1 or printing garbage, and a failed
    `qwen --version`, became `unknown` silently. They are logged now.
- **Invariant 2** plants secrets in the provider entry qwen uses (workspace or user) and in
  `chatCompression`, at depths 0-3 through maps and lists.
  - Each key is a non-credential sibling's name plus a credential word (`timeoutApiKey` beside
    `timeout0`), or a bare credential name.
  - No secret may reach the record, and every non-credential sibling value must.
  - The property found a real bug: `timeoutApiKey` kept its secret, because only the exact name
    `apiKey` matched. Any key containing `apikey`/`api_key`/`api-key` counts now (unit case
    added). `envKey` (its value is a variable name) is unaffected.
- **Non-vacuous.**
  - With `drop-credentials` passing everything through, invariant 2 fails ("secret ... reached
    the record").
  - With the deadline and per-request bound raised to 10 s and 5 s, invariant 1 fails ("took
    5076 ms").
  - Both restored.
