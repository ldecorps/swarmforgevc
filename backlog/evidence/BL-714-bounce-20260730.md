# BL-714 — documenter send-back: `required_wiring` unsatisfiable by design

- **Date**: 2026-07-30
- **Reported by**: documenter (`note`, priority 00, to specifier + coordinator)
- **Blamed role**: specifier (the field was written at mint time)
- **Failure class**: spec-gap
- **Ticket**: BL-714 — hardening gates blocked repo-wide
- **Disposition**: spec amended on `main`; parcel not bounced — the documenter
  still holds it and continues after merging `main`.

## D1 — every `required_wiring` entry asserted the state the ticket removes

`swarmforge/scripts/pre_qa_gate_lib.bb` implements `required_wiring` as a
**presence** assertion: for each `path::pattern` entry it reads `path` at the
cited commit and fails unless the content *contains* `pattern` (a missing file
is also a violation).

BL-714's five entries all named the pre-fix state:

| entry | pattern asserted | after the fix |
|---|---|---|
| `node_modules/.vite/vitest/…/results.json` | `tracked-cache` | file removed from the index → "not found at cited commit"; the literal `tracked-cache` never appeared in a vitest results blob either, so the entry could not pass at *any* commit |
| the four `telegramCursorBridge*.test.js` files | `mkdtemp` | the fix replaces `fs.mkdtempSync` with the shared `mkTmpDir` helper → `mkdtemp` gone → violation |

Verified against `main` at report time — all four D2 files contain `mkdtemp`
and none contains `helpers/tmpDir`:

```
telegramCursorBridgeExpedite   main: mkdtemp=1 tmpDir-helper=0
telegramCursorBridgeLogs       main: mkdtemp=1 tmpDir-helper=0
telegramCursorBridgeRedeploy   main: mkdtemp=1 tmpDir-helper=0
telegramCursorBridgeUpdate     main: mkdtemp=1 tmpDir-helper=0
```

So the field **passed before the fix and failed after it** — the exact inverse
of what a wiring gate is for. The documenter's note said "2 entries"; the true
count is all five.

## Remediation applied

- D2 (four entries): pattern `mkdtemp` → `helpers/tmpDir`, which is what a
  migrated file must contain (`require('./helpers/tmpDir')`).
- D1 (one entry): **dropped**. "This blob is no longer tracked" is a deletion
  and has no presence form; `required_wiring` cannot express it. It is already
  carried by the ticket's invariant 1 and by the real gate,
  `extension/test/onboarderRenameNoResidualFacilitator.test.js`. The `git rm
  --cached` work stays in scope in the description — only the unexpressible
  gate entry is removed.

## Blocked checks

None. This was a spec-field defect, reviewable by reading the gate
implementation against the ticket; no check was blocked behind it.

## Note for future tickets

`required_wiring` can only assert that something **exists**. A ticket whose
value is a *removal* must express that through an invariant plus a guard test,
never through a `required_wiring` entry.
