## Which other BL-680 literals are one formatting edit away from the same red
The handler reads the prompt with `\s+` collapsed to one space (`readNormalizedDoc`), so a **line
wrap** inside a quoted phrase can never cause this red. A backtick, bold marker, case change or
punctuation change inside a literal can. Each of the 16 literals was located in the live prompt
and its surroundings read:
- **One backtick away**: these phrases name a YAML field or path in plain words, the same shape
  as the `depends_on` red:
  - "A merged result still fits the slice size envelope" (the field is `slice_size_envelope`).
  - "a ticket in the active backlog is never consolidated" (`backlog/active/`).
  - "sweep every open intake and every paused ticket in that epic's orbit" (`paused`).
- **One bold-marker edit away**: these phrases sit at the edge of a `**...**` run:
  - "Epic-top-priority consolidation pass" (the bold closes after the full stop, outside the
    literal).
  - "The one hard constraint on consolidating" (the bold opens just before "The").
  Either breaks only if a marker moves inside the phrase.
- **Case and punctuation sensitive** (sentence-initial capitals and an inner comma): "Several
  intakes...", "One intake...", "The intake archives once, pointing at...", "Correct any...",
  "Record the consolidation...", and "merge overlaps, split oversized slices, and retire
  superseded ones". A reword that keeps the meaning but changes the capital or the comma turns
  them red.
- The rest of the literals are mid-sentence plain prose: "the resulting ticket lists every source
  intake", "each source intake archives with a pointer to that ticket", "states which part...",
  "each resulting ticket records...", "every operator directive quoted...". They are exposed only
  to a reword.
