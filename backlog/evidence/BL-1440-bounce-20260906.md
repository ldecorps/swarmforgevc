   Two more properties in the same file fail the same way (invariant 2 "expensive guard runs iff cheap all pass", invariant 3 "unexpected failure names as error"), all with the newly-added tier-1 guard reported at unexpected status 127 (command not found) inside the property's synthetic guard-fixture directory.
4. **Failure class**: `unit`.
5. **Expected vs observed**: Expected `npm run test:properties` green (this ticket's own change is a new commit guard, not a change to this file). Observed 3/5 properties in this file failing, reproduced identically across two independent full-suite runs on a quiet host (load avg ~1.9), so this is deterministic, not a resource-contention flake.

**Root cause**: `run_commit_guards.sh` (this parcel's own change, `swarmforge/scripts/run_commit_guards.sh`) adds `run_guard check_constitution_doc_citations.sh` to the tier-1 cheap chain. `bl1252CommitGuardAggregationInvariants.property.test.js` models that same chain via a hand-enumerated `INDEX_GUARDS` array (lines 24-42) that a synthetic fixture stubs one file per entry for. The new guard is not in that array, so the property test's fixture never stubs it; the real `run_commit_guards.sh` then tries to exec a guard script that doesn't exist in the fixture dir, hits "command not found" (exit 127), and the property's model (which doesn't know this guard exists) disagrees with the runner's actual (correct) behavior.

The test file's own comment at the `check_handler_module_graph.sh` entry states this exact failure mode outright: *"This list is hand-enumerated, so a guard added to the chain and not added here is left unstubbed by the fixture: the runner then reports it missing on every plan, and these properties fail against a chain that is behaving correctly."* Three prior tickets that added tier-1 guards (BL-1303, BL-1385, BL-1395, BL-1428, per the surrounding comments) each added their guard's filename to `INDEX_GUARDS` when they landed. BL-1440 is the first to skip that step.

**Remediation pointer**: add `'check_constitution_doc_citations.sh'` to `INDEX_GUARDS` in
`extension/test/bl1252CommitGuardAggregationInvariants.property.test.js` (around line 40, following the existing BL-1428 entry's comment style), in the same coder pass that wires the guard into `run_commit_guards.sh`. Owning role: **coder** — this is the same commit that adds the guard call to the shared chain; the property test's own comment names exactly the discipline that commit needed to follow.
