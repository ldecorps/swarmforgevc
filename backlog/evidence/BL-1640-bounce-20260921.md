   whenever the caller's CWD differs from `--target`, because
   `night-closing-ceremony-run.ts`'s `main()` resolves the default conf path as
   `path.join(projectRoot, 'swarmforge', 'swarmforge.conf')` where `projectRoot`
   comes from `resolveCliMainWorktreeContext()` → `resolveProjectRoot(process.cwd())`
   — CWD-derived, not `--target`-derived (`extension/src/tools/night-closing-ceremony-run.ts:521-527`,

   (this parcel's own new loop, `swarmforge/scripts/finish_shift_lib.sh`) calls
   `node "$cli" --target "$root" --sleep-path finish-shift` with no `--conf`, so it
   inherits this bug on every tick.

**Root-cause note (git-verified, not speculation):** the bare
`--target "$root" --sleep-path finish-shift` invocation line predates this parcel
(BL-1393); `git diff origin/main HEAD -- swarmforge/scripts/finish_shift_lib.sh`
shows this parcel only wraps that same line in a loop, never adding `--conf`. The
omission was harmless before this parcel: the daemon's own overnight ticks always
run with CWD already equal to the repo root, and the pre-BL-1640 code let the
daemon drive every tick after the first. This parcel is what makes the sleep path
itself responsible for every tick's deadline arithmetic AND makes that arithmetic
depend on `swarmforge.conf`'s configured budgets for the first time — so the
pre-existing CWD-fragility is now load-bearing and silently wrong exactly the kind
of way this ticket exists to eliminate (BL-1640's own "What is wrong" section is
about a silently-unmet ceremony contract). The one known production caller
(`wait_for_expedite_then_bedtime.sh`) happens to `cd "$ROOT"` before calling
`./finish-shift`, so this is not visibly on fire in production today — but the
ticket's own qa_e2e text calls for testing via an explicit target-path precisely
because that is the contract `--target` is supposed to honor, and it does not.

**Blamed role**: coder. **Remediation pointer**:
`swarmforge/scripts/finish_shift_lib.sh`, `finish_shift_run_closing_ceremony` — pass
`--conf "$root/swarmforge/swarmforge.conf"` explicitly to every `node "$cli"` call
in the loop (matching the shell test's own successful `tick_at` pattern in
`swarmforge/scripts/test/test_bl1640_sleep_runs_ceremony_to_done.sh`), so the
budgets read never depend on the caller's CWD. (A deeper fix — making
`night-closing-ceremony-run.ts`'s own `--conf` default resolve from `root`
rather than `projectRoot` — is also reasonable but touches
`resolveCliMainWorktreeContext`/`resolveProjectRoot`, shared by other CLIs
(`swarm-metrics.ts`, `generate-backlog-dashboard.ts`, `generate-docs-tree.ts`);
out of this parcel's stated scope unless the coder judges it the cleaner fix.)
