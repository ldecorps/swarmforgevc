## The defect, and that it is mine

BL-1305's `description:` said, correctly, "How (direction, not mandate) ...
Any approach that makes the stub unconditionally the thing that runs is
acceptable." It then offered one for-instance — write the stub's absolute
path into the fixture config's command column — and **scenario 01 and
invariant 2 froze that for-instance into the executable contract.** A
direction in the prose and a mandate in the acceptance criteria is a spec
defect regardless of which half a reader reaches first, and the acceptance
criteria are the half the coder drives TDD from.

It is also a mandate that cannot be satisfied. Verified live before ruling,
not taken on report:

- `validate_agent` (`swarmforge/scripts/swarmforge.sh:522`) is a closed
  allowlist — `claude|codex|copilot|grok|aider|vibe|gemini|cursor|local-model`
  — and any path falls to `*)` → `error_msg ... ; exit 1`.
- `write_role_launch_script` (`:1683`) dispatches `case "$agent" in claude)`
  and hardcodes the literal command into the launch body; a path would fall
  through to the same refusal.
- 26 `$agent` reference sites in `swarmforge.sh` behind those two, driving
  model resolution, the billing guard and provider-key forwarding.

So the named remedy means basename dispatch across the launch path every
live seat boots through — not a `slice_size_envelope: low` change, and not
one that should ride a fixture-hygiene slice.

## The false green it would have produced

The coder's sharpest finding, and the reason this is worth a ledger row
rather than a quiet edit: with a path in the command column `parse_config`
exits 1, **nothing launches at all**, and scenarios 02 and 03 would then pass
VACUOUSLY — the exact outcome this ticket's own `qa_e2e` forbids ("Confirm
the fixture stub did run, so the scenarios are not passing merely because
nothing launched"). A mandated-but-unbuildable mechanism did not merely block
the coder; had it been forced through, it would have shipped a green suite
over a fixture that launches nothing.

## Remedy applied (this commit)

Option (a) of the coder's two. Invariant 2 retired as a mechanism mandate
(invariant 1 already carries the property in full); scenario 01 rewritten to
assert the direct repro and to name **no** mechanism — deliberately not
re-frozen onto ZDOTDIR, since swapping one mandate for another repeats the
mistake; scenario 02's `Given` tightened to the real defect shape (the
prepend comes from the pane shell's startup file), which was ambiguous enough
to have blocked the coder a second time; feature narrative re-tensed. Scope,
envelope, deliverable and `human_approval: approved` unchanged — the
amendment strictly removes prescription.

Option (b) (agent column may name a binary by path) declined and NOT split
into a follow-on ticket: a legitimate capability nobody has asked for fails
INVEST's Valuable letter. Recorded in the ticket so it is not re-derived.
