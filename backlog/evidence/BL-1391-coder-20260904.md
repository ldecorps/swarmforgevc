## Two fixture traps worth the next reader's time

1. **Appending to opposite ends of a large file is not a code conflict.** The
   first draft of scenario 3 appended a line to `push_sweep_lib.bb` on both
   sides; git merged that cleanly, so the conflict set was the ticket alone and
   the run read as "the resolver resolved a code conflict" when no code path
   was ever conflicted. It now rewrites the SAME line on both sides.
2. **A `REPO_ROOT` one level short fails silently.** `cd "$SCRIPT_DIR/../.."`
   from `swarmforge/scripts/test` lands on `swarmforge/`, so every `cp` from it
   failed and the fixture had no scripts directory at all — the reason scenario
   3 had no code file. The copy is now checked, as the seed commits are.
