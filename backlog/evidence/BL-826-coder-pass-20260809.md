## Invariants (BL-654)

1. *"No path arms the microphone while Bubble's own audio can still reach it:
   every re-arm route ... passes the same quiet-tail gate, with no bypass."*
   — **stated reason, no property test**. This invariant quantifies over
   `TalkEngine.kt`'s call-site wiring, not over a pure function's input
   domain. `TalkEngine` holds `android.os.Handler`/`Looper` and `Context` in
   its own fields and constructor, placing it on the device-adjacent side of
   the Testability Boundary — Bubble line (same boundary BL-769 drew); a
   property test would need Robolectric or a real device to exercise it,
   both deliberately not adopted. Verified instead by direct code reading
   (required_wiring above, re-derived fresh this pass, not taken on the prior
   landing's word) and, end-to-end, by the manual device procedure recorded
   in the ticket's `verification:` block, which QA runs on a paired phone —
   the only way to observe whether Bubble's own speaker output can reach its
   own mic on real hardware.
2. *"The gate always resolves: for every input it either arms the mic or
   records why it will not, within a bounded ceiling..."* — already encoded
   as a coder-authored property test,
   `HandsFreeReArmGatePropertyTest.kt::every input resolves to Arm within the
   active-playback ceiling, never an unbounded wait` (500 randomized inputs,
   asserts every `NotYet` recommends a strictly-later, in-ceiling recheck and
   every path eventually arms). Confirmed non-vacuous: the companion test `a
   gate without a ceiling clamp would fail the resolves-within-ceiling
   property` runs the same random-walk loop against a deliberately
   ceiling-less decision function and asserts it fails to arm — proving the
   property test can fail, not just pass by construction.
