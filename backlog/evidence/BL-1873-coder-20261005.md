## What changed
- `reworkObservatorySource.ts`: a closed ticket counts as reworked only when
  `bounce_count` > 0 on its ticket YAML (read via the existing per-ticket
  YAML scan, no second parser), or an evidence file whose basename contains
  `bounce` (evidence filename matching narrowed from "names the ticket" to
  "names the ticket AND says bounce"). Routine pass evidence (`-QA-`,
  `-architect-`, ...) no longer counts.
- `loadCompletedTicketRecords` takes an optional `sinceMs`; when passed, the
  `backlog/` git-log walk (`runGitLog`'s new `sinceIso`, `git log --since`)
  is scoped to that instant, and the per-ticket YAML read is skipped
  entirely for any ticket whose close lands outside the scoped window
  (`yamlMetaByTicket`'s new `wantedTicketIds` filter).
- New `deriveCloseDates` (gitHistoryAdapter.ts): a close date keyed only on
  the ticket's arrival under `backlog/done/`, unlike `deriveTicketLifecycles`
  which also requires seeing the spec's original arrival - needed because a
  ticket's promotion can predate a scoped window while its close lands
  inside it.
- `rework-observatory.ts`'s `runObservatory` now passes `baselineStartMs` as
  `sinceMs` - nothing before it can land in either of the two trailing
  windows.
- BL-430's feature gains scenarios 07 (Scenario Outline, 3 examples: pass
  evidence only / bounce_count / bounce-named evidence) and 08 (history
  walk itself, not a derived aggregate, is scoped), with their step handlers
  in `bl430ReworkObservatorySteps.js`. Scenarios 01-06 untouched.
