## A zsh word-splitting bug found and fixed during verification

First draft passed `${context_length:+--context-length "$context_length"}`
directly as one array element in the `bb ...` invocation. zsh does not
word-split an unquoted parameter expansion the way bash does (confirmed:
`foo --a ${x:+--flag "$x"} --b` arrives at `foo` as 3 args, not 4 - `--flag
"$x"` lands as ONE token). The CLI's own `opt-value` then never found a
literal `"--context-length"` element, so the context-length fallback
silently never worked. Fixed the same way `check_local_model_seat_windows`
already passes `--context-length "${SWARMFORGE_OLLAMA_CONTEXT_LENGTH:-}"`
unconditionally (blank when unset, `--role` likewise) - no conditional
expansion, so no word-splitting risk. Caught by a direct `zsh -f -c
"source swarmforge.sh; write_local_model_qwen_settings ..."` smoke test
before it ever reached the acceptance/property layers.

A second bug the same smoke-testing found: the acceptance step handler's
first draft used `spawnSync` for the CLI invocation while the fake Ollama
server ran in the SAME node process - `spawnSync` blocks the event loop
for the whole child's lifetime, so the server could never actually answer
the child's curl request. Fixed by switching to async `spawn` (a Promise
resolved on `close`), the same shape BL-1801's own step handler already
uses for exactly this reason.

## Invariant check

One declared invariant: "A local-model seat's qwen context budget equals
the window its model is served with, or the swarm's configured context
length when Ollama reports none; never a value only the operator's
~/.qwen/settings.json holds." `resolve-window`'s own signature (served-
window, context-length-str -> window-or-nil) structurally proves the
"never a value only ~/.qwen holds" half - it has no parameter through
which `~/.qwen` could reach it. The precedence half (served wins over
whatever context-length says; context-length only when served is unknown;
nil - never fabricated - when neither resolves) is
`bl1838_qwen_provider_window_property_runner.bb`
(`extension/test/bl1838QwenProviderWindow.property.test.js`'s thin
wrapper), four categories chosen by construction each iteration (never
independent coin flips), 200 runs, all four reached (measured: 50/50/50/50
at the default run count). Non-vacuity proven at authoring: swapping the
`or`'s argument order (context-length would wrongly win over a known
served window) fails category 1 immediately; restored and re-verified
green.
