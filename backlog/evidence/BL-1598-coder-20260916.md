# BL-1598 — coder evidence, 2026-09-16

## The fix

`extension/src/tools/check-suite-file-budget.ts` gains a committed-register
decision table on top of BL-378's existing over/under-budget check:

- `parseRegisterRows(text)` — the standing-red register's own TSV shape
  (BL-1428): 5 tab-separated columns (file, ticket, first_seen,
  measured_ms, note), `#`-comment and blank lines skipped.
- `openTicketIds(backlogDir)` — ticket ids with a `*.yaml` file directly
  under `backlogDir/paused` or `backlogDir/active` (mirrors
  `qa_hold_lib.bb`'s own `open-ticket-ids-for`).
- `checkFileDurationBudget(durations, budgetMs, register = [], openTickets = new Set())`
  now returns `{ passed, verdict, offenders, staleRows, unownedRows, registeredPoles }`:
  - over budget, no row → `offenders` (`new-pole`, refused) — **identical**
    to the pre-BL-1598 behavior when `register` is omitted/empty (invariant 1).
  - over budget, row present, ticket open, not stale → `registeredPoles`
    (`ok`, reported, not refused).
  - a row's ticket is not open → `unownedRows` (`unowned-row`, refused),
    regardless of the file's current duration.
  - a row's file now measures under 80% of budget → `staleRows`
    (`stale-row`, refused, naming the row that should leave).
  - `passed` is false iff `offenders`/`staleRows`/`unownedRows` is
    non-empty; `registeredPoles` never blocks.
- `extractFileDurations(report, projectRoot?)` — unchanged when
  `projectRoot` is omitted (existing tests, existing callers); when given,
  relativizes vitest's real **absolute** `r.name` path (confirmed by
  inspecting a live `.vitest-report.json`: entries are full filesystem
  paths, not the `test/foo.test.js` shorthand this module's OWN test
  fixtures use) against `projectRoot`, matching `backlog/suite-poles.tsv`'s
  committed, portable file column (`extension/test/...`).
- `runGuardAgainstReport(reportPath, registerPath?)` / `printGuardReport` /
  `formatGuardReport` — the ONE decision + ONE report format, used
  identically by `main()` (the standalone CLI) and by
  `recordTestDuration.js` (the in-process live consumer), so the two never
  compute or print two different answers for the same run.

`extension/scripts/recordTestDuration.js`: the guard is now called
**in-process** via `runGuardAgainstReport`/`printGuardReport` (mirroring
this same file's existing in-process use of
`check-suite-duration-budget.js`) rather than spawned a second time as a
subprocess whose stdout would need parsing back. `REGISTER_PATH =
path.join(ROOT_DIR, '..', 'backlog', 'suite-poles.tsv')` is the literal
wiring anchor (`required_wiring`). `pole_ms`/`work_ms` are computed from
the same `durations` the guard already extracted (max / sum); `new_offenders`
= `guardVerdict.offenders.length`; `budget_verdict` = `guardVerdict.verdict`.

`extension/scripts/testDurationRecorderLib.js`'s `buildRecord` gains the
four fields (`pole_ms`, `work_ms`, `new_offenders`, `budget_verdict`) as
direct pass-throughs; `result` (the TEST outcome) is unchanged and
independent of `budget_verdict` (scenario 02). Updated its own existing
unit test's exact-shape `deepEqual` expectations for the new fields (it
previously asserted the OLD 4-field shape exactly) and added one new test
pinning result/budget_verdict independence.

`backlog/suite-poles.tsv` — the nine files/measured_ms from the ticket's
own table, verbatim (`69900, 65300, 36600, 36300, 23600, 14600, 10600,
8500, 7300`), all owned by `BL-791` (open under `backlog/paused/`).

## Declared invariants (BL-654)

- **Invariant 1** ("a file over budget with no register row always fails
  exactly as BL-378 did") — coder-authored, non-vacuous property test:
  `extension/test/bl1598SuitePoleRegister.property.test.js`, two
  properties over `checkFileDurationBudget` (pure injection, BL-1541
  shape): one with an arbitrary register that never covers the offending
  file, one with no register at all (the literal pre-BL-1598 shape).
  Non-vacuity: hardcoding `passed` to `true` inside the guard (the gate
  waving every new pole through — the exact defect this invariant exists
  to catch) fails both properties immediately; reverted and reconfirmed
  green.
- **Invariant 2** ("no test is removed to satisfy the gate") — a
  repo-history/process claim (comparing the recorder's counted test-file
  total across a git commit boundary), not a pure-module property; per
  BL-654 this is a stated reason rather than a test. This parcel deletes
  no test file (`git diff --stat` for this commit shows only the touched
  files above, no `.test.js` removed), and `listTestFiles`'s own mechanism
  (glob `*.test.js` under `extension/test`) is unchanged.
