  check, same stderr line on the "not live" branch — BL-1253 scenario 04's
  observable behavior is unchanged) and now additionally exports
  `CURSOR_BRIDGE_INBOUND_QUEUE_SOURCE=auto` right after its own decision.
- `cursor_bridge_supervisor.bb` only gains one forwarded env var
  (`CURSOR_BRIDGE_INBOUND_QUEUE_SOURCE`) in its child-env vector.
- `shouldUseCursorBridgeInboundQueue`: when `CURSOR_BRIDGE_INBOUND_QUEUE_SOURCE`
  trims to exactly `'auto'`, the flag read is forced to `undefined` (so the
  live per-poll feeder check decides); any other value — unset, `'operator'`,
  or an empty string — leaves `flag` as the raw
  `CURSOR_BRIDGE_INBOUND_QUEUE` value, so an explicit `0` or `1` still
  forces its mode exactly as before. Verified by reading the three new
  test cases plus the pre-existing explicit-flag tests, all of which pass
  below.
