## D1 (HIGH) — a legitimate role verdict failed the run

The run ended `ticket: failed`.

The documenter returned **`forward`** — a real, documented outcome in this repo, and
the *correct* one for an internal change with nothing user-facing to document. The
driver's dispatch knew only `pass` and `bounce`, with everything else falling
through to failure. So a role doing exactly the right thing failed the ticket.

**Why no earlier gate caught it:** the fixture stage runner only ever emitted `pass`
or `bounce`. The seam encoded the driver author's assumption about role vocabulary
rather than the roles' actual vocabulary. A green 21/21 was measuring agreement
between two things I wrote, not agreement with the system.

Fixed by moving the vocabulary into the lib as data:

```clojure
advance-verdicts  #{:pass :forward :approved}
bounce-verdicts   #{:bounce :send-back :sendback}
```

`classify-verdict` **fails closed** — an unrecognised verdict stops the run loudly
rather than being guessed into `:advance`, because guessing would silently skip a
gate. Ten assertions, plus three CLI cases: `forward` advances, `approved`
advances, and an unknown verdict fails without reaching `done/`.

## D2 (LOW) — 3 seconds burned per stage, with the fix in the warning text

Every stage's `stderr.log`:

```
Warning: no stdin data received in 3s, proceeding without it.
If piping from a slow command, redirect stdin explicitly: < /dev/null to skip
```

`claude -p` waited for stdin that never came, on all seven stages. Fixed by opening
stdin from `/dev/null`.

## D3 (MEDIUM) — my own mutation tooling destroyed uncommitted work, twice

Both `expedite_mutation_sweep.sh` and `expedite_prove_nonvacuity.sh` restored the
mutated lib with `git checkout -- "$LIB"` — i.e. to **HEAD**, not to what they
found. Running either with an uncommitted fix in the lib silently reverted it.

It happened twice during this stage, and both times it presented as **37 unrelated
CLI failures and 19 acceptance failures**, which is exactly how much time a
misleading symptom costs. A tool that mutates a file must restore what it found,
not what git remembers.

Both now back up the working copy to a temp file and restore from that. Verified:
the lib's md5 is unchanged across a full run of both.

Worth naming that the first fix covered only the sweep. The prover had the same
line, and the same-shaped bug is rarely alone — the second instance cost another
full gate sweep to find.
