# BL-775 coder pass

## What was built

Bubble's Live page ships as remote HTML in the UI bundle, per the human's
2026-08-06 "flip BL-775 to remote" ruling — not a rewrite, an extraction:

- **One renderer (invariant 1, required_wiring).** The entire Live Screen
  document — markup, style, script — now lives in
  `residentSpyUiHtml.ts::renderLiveScreenBody`. `getResidentSpyUiHtml()`
  (the existing Mini App route) becomes a thin wrapper over it.
  `bubbleLiveUiHtml.ts` (new) exposes `getBubbleLiveUiHtml()` — also a thin
  wrapper over the same function — and `isBubbleLivePath` for `/live`.
  `getBubbleLiveUiHtml() === getResidentSpyUiHtml()` always, by
  construction (asserted directly in
  `test/bl775BubbleLiveScreenShell.test.js` and by the acceptance
  scenario "both surfaces come from one renderer").
- **Registered in the bundle (required_wiring).** `letsTalkRoutes.ts` gains
  `bubbleLivePage` (id `live`, entryPath `live`, order 1) and
  `mergeBubbleLiveIntoUiBundleManifest`, wired into `bridgeServer.ts`'s
  existing merge chain (`/lets-talk/ui-bundle.json`) and its pre-auth HTML
  shell dispatch (`/live`), following the health/host/operator-docs
  pattern exactly.
- **Invariant 3 (failure reason, not a bare status).** This was a real gap,
  not inherited: `residentPaneLive.ts`'s `tryCaptureRolePane` returned
  bare `undefined` on a failed tmux capture, and the client's `refresh()`
  discarded the bridge's own JSON error body behind `throw new Error('HTTP
  ' + r.status)`. Fixed at both ends:
  - `tryCaptureRolePane` now returns a discriminated
    `{ok:true,snapshot} | {ok:false,reason}` (`captureLiveScreenPanes`'s
    own failure path threads `reason` into `unavailablePane(reason)`;
    `captureResidentPaneLive`/`captureCoordinatorPaneLive`, which only ever
    read truthiness, are unaffected — verified by their own existing
    tests, unchanged).
  - The per-pane render (`renderPane`, and the fullscreen
    `syncFullscreenContent`) now shows `pane.reason` when present, instead
    of only the generic `(pane not reachable)`.
  - `refresh()`'s fetch failure path now reads the bridge's own JSON
    `{error: ...}` body (or `r.statusText`) into the HTTP error message,
    and the aggregate offline banner shows that reason (`lastFetchErrorReason`)
    ahead of the idle default.
  - The idle-vs-broken scenario (05): the banner's default text changed
    from the alarming "Live panes unavailable — swarm agents may be down."
    to "Swarm is idle - no live panes right now." — a quiet swarm now
    reads as quiet.
- **Invariant 2 (read-only)** holds by construction and is checked
  directly: the shared renderer's script contains no `POST` at all, only
  the two existing preference `PUT`s (font size, ticket-strip-collapse),
  neither of which mutates swarm state. Verified by grepping the served
  HTML for the bridge's actual swarm-mutating write-route paths
  (`/gate-answer`, `/telegram-inbound`, `/reply-ack`,
  `/paused-pager/expedite`, `/paused-pager/approve`, `/catch-up/mark-read`,
  `/epic-reorder/move`, `/epic-reorder/make-top`,
  `/epic-reorder/topic-make-top`) in both the acceptance scenario and by
  direct source inspection.

## Invariant encoding (BL-654)

All three declared invariants have executable coverage, none needed a
stated-reason exemption:

1. One renderer — `getBubbleLiveUiHtml() === getResidentSpyUiHtml()`
   equality assertion (`bl775BubbleLiveScreenShell.test.js`) plus the
   acceptance scenario driving both real routes.
2. Read-only — no `POST` anywhere in the served script (grep, both unit
   and acceptance); the two `PUT`s are preference-only.
3. Reason-not-bare-code — `residentPaneLive.test.js`'s two new cases
   (`tryCaptureRolePane` failing with a tmux stderr reason, and with an
   empty-output reason) plus the acceptance scenario's real fake-tmux
   failure driven through the real jsdom-rendered page.

No property-test file was added for these: none of the three invariants
quantifies over a meaningfully large input space beyond what the unit and
acceptance cases above already cover exhaustively (the renderer takes no
arguments; the read-only check is a fixed grep; the reason-threading has
exactly two failure shapes, both covered).

## Unowned red found while working this ticket (standing-red rule)

`specs/features/BL-829-bubble-remote-page-pager.feature`, scenario "a
malformed page list rejects the whole manifest", fails on `main`. Root
cause: `bridgeServer.ts`'s built-in-page merge chain
(health/host/operator-docs, now also `live`) always runs after the
operator manifest resolves, even when that resolution fell back to
`pages: []` on a malformed operator list — so "no page from it is offered
to the shell" was never true once any built-in page existed. Confirmed
PRE-EXISTING and unrelated to this parcel: `git stash push -u` (reverting
every BL-775 change), recompiled, re-ran the feature — same single
failure with BL-775 entirely absent; `git stash pop`, recompiled,
continued unaffected. No row in `backlog/standing-reds.tsv` and no ticket
found naming it. Filed as an `unowned-red` `note` (priority 00) to the
specifier and coordinator.
