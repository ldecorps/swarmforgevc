## Three decisions worth the reviewer's eye

**The field list is not a second copy of the constitution.** The ticket is
explicit that restating Article 4.4's fields would drift (BL-897). The list
lives once in `ARTICLE_44_ITEM_FIELDS`, and a unit test PARSES
`swarmforge/roles/QA.prompt` and asserts the five numbered fields there are
exactly the five the tool carries. Reword the prompt and that test fails, which
is the point — BL-897's own remedy shape (a constant mirrored across a boundary
needs a test asserting both literals agree). Runtime-parsing the prompt was the
alternative and was rejected: a tool that stops working when a prompt is
reflowed is worse than one that fails a test.

**The collision form is the corpus's, not invented.** Two forms exist on disk:
`-pass2-` before the date, and `-<date>-2.md` after it. The tool emits the
second (`BL-1166-qa-bounce-20260827-2.md`, `BL-1204-architect-bounce-20260828-2.md`)
because a tool can generate it deterministically without knowing what the
second pass MEANT, which the `pass2` qualifier implies.

**Committing exactly one path is load-bearing, not tidiness.** An approval
authorizes only its ticket's work (BL-506), so `git add -- <path>` and
`git commit -- <path>`, never `-A`. Every test and every property runs against
a deliberately DIRTY tree and asserts it is still dirty afterwards.
