# BL-1229 — coder pass, 2026-09-05

## What was wrong

`landPilotedTicket`'s `deps` contract is a plain TypeScript interface; the
15 test files that build a `deps` object by hand do so as JS object
literals, so nothing ever compares the two. BL-757 added
`checkOrphanedAuthoredDocs` as a required member with an unconditional
call site and no test stub was updated — measured 2026-08-28: 10 files,
22 crashing assertions. This ticket's own human ruling (2026-08-28) took
"the stronger line": connect the contract to the stubs so the NEXT
widening costs one clear failure, not one crash per file — and firmly:
"a missing deps member must not be filled in with a silent default."

BL-1221 (this same day, this same session) already repaired the 15
files' own hand-rolled stubs so `checkOrphanedAuthoredDocs` specifically
is supplied everywhere — that ticket was explicit that it left the
*structural* connection out of scope ("A guard that checks every required
deps member is present in the stub factories would close the class...
named in out_of_scope so it is a decision, not an oversight"). This
ticket builds exactly that connection.

## A genuine, non-vacuity-driven finding

P1's first draft (omit any one required member, assert the run always
throws) failed on `assessMultiworktreeFixture` with a REAL land verdict
instead of a throw — not a bug in the property, a real fact about
`pilotAcceptanceGate.ts`'s own `requireMultiworktreeFixture`: that member
is required by the TYPE but only INVOKED at runtime when
`isLifecycleTeardownTicket` returns true; a non-teardown ticket (every
base fixture here) never reaches the call at all, so omitting it is
invisible on that path. Fixed by setting `isLifecycleTeardownTicket: () =>
true` only for that one member's generated case (documented inline,
non-vacuously found and recorded, not assumed).

## Declared invariants (BL-654)

**Invariant 1** ("A test-built deps stub that does not satisfy the full
landPilotedTicket contract fails loudly; a missing member is never
silently defaulted.") — **P1**: iterates EVERY real required member
(20, extracted from the live interface, not a hand-kept duplicate list)
explicitly — satisfied by construction, matching this codebase's own
established fix for exactly this class of coverage gap (a bare
`fc.constantFrom` sample over 20 items missed one in 60 draws during
authoring; the loop-over-every-member + `fc.constant` shape closes that
for good) — and asserts omitting it from an otherwise-complete stub
always throws, never lands. A generator-reach assertion confirms every
required member was actually drawn.

**Invariant 2** ("Adding a member to the deps contract produces one
failure naming that member, regardless of how many test files build a
stub.") — **P2**: randomizes 1-4 synthetic member names (guaranteed not
to collide with any real member) appended to a SIMULATED widened
interface body, and asserts the completeness check reports EXACTLY that
many missing members, each correctly named — regardless of count, and
never touching any of the 15 real caller files (the shared stub is the
only thing checked).

**Non-vacuity**, each mutation run for real and restored byte-identical
(confirmed via `diff` against a pre-break backup):
- P1: disabling the omission (`delete incomplete[member]` commented out)
  failed on the very first generated case — "readAcceptanceDeclaration
  did not throw - got a land verdict instead" — proving the property
  actually exercises a missing member, not merely that some promise
  settles.
- P2: inverting the missing-member filter (`supplied.has(name)` instead
  of `!supplied.has(name)`) failed immediately — "expected 1, got 20" —
  proving the property is sensitive to the actual missing-member
  computation.

**Reachability**: P1 covers all 20 real required members by construction
(never sampled); P2's 20 runs each draw 1-4 unique synthetic names,
exercising every count in that range.
