# BL-1353 — cleaner pass, 2026-09-05

## What was found

The specifier's priority-00 amendment (merged onto `main` at `98454ae8c4`,
folded into this worktree ahead of the coder's forward) rewrote scenario 03 of
`specs/features/BL-1353-task-arrived-is-not-an-escalation.feature` from
"evaluates whether to hibernate" / "does not hibernate" to "evaluates whether
to relaunch" / "relaunches", and added a `Given the swarm is hibernated with a
drained backlog` step — correcting the factual error the coder had already
flagged (fresh coordinator mail is the BL-310 relaunch UP-trigger, not an input
to the hibernate DOWN-trigger).

The coder's step handler
(`specs/pipeline/steps/bl1353TaskArrivedIsNotAnEscalationSteps.js`) was
written against the pre-amendment wording and did not travel with the spec
edit — running the acceptance suite showed scenario 03 failing with "no step
handler matched" for the new `Given` line, since the two `When`/`Then`
patterns it still defined (`evaluates whether to hibernate`,
`does not hibernate`) no longer matched the feature text at all.

This is exactly the BL-233 contract required_wiring names: "step text changed,
so the acceptance handler must follow in the same parcel." It reached the
cleaner unfixed because the specifier's amendment merged into this branch
ahead of the coder's own forward, so the coder's commit predates the wording
it needed to match.

## Fix

- Added a step for `the swarm is hibernated with a drained backlog` (records
  scenario premises; the actual `:already-hibernated? true
  :backlog-drained? true` values are already passed to the real
  `should-relaunch?` call, so this step is a no-op state marker matching the
  Given/When/Then shape).
- Renamed the `When` handler regex from `evaluates whether to hibernate` to
  `evaluates whether to relaunch`.
- Renamed the `Then` handler regex from `it observes fresh coordinator mail
  and does not hibernate` to `it observes fresh coordinator mail and
  relaunches`. Assertions unchanged — they already asserted the relaunch
  direction (`s.relaunches === 'true'`), only the doc-comment framing in the
  regex name was stale.

No behavior in `operator_lib.bb` / `operator_runtime.bb` changed.
