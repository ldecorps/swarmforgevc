## One real gap found and closed

`assertParcelDoesNotEditReviewedSources` had **zero direct test coverage**
before this pass. It is only called from the six family files
(bl1113/1115/1116/1117/1136/1323), where it runs against THIS repository's
real git history — and `origin/main..HEAD` frequently contains no commit
naming the ticket at all (the early-return path), so the function's
substantive assertion could go untested indefinitely without anyone
noticing. Both mutants against it (`--first-parent` dropped, `includes()`
inverted) survived the existing suite for exactly this reason.

Added 4 tests to `extension/test/bl1356StampOffHelper.test.js` against a
real git fixture repo (`gitFixture()`, built with `mkTmpDir` + real `git`
spawns): no commit naming the ticket in range (returns empty, no throw), a
commit naming the ticket that leaves the reviewed path alone (no throw), a
commit naming the ticket that touches the reviewed path (throws, names the
path), and a merge case for `--first-parent` specifically.

**The merge case caught a wrong assumption of my own, corrected before
landing.** My first draft expected a merge naming the ticket, whose SECOND
parent (a side branch) touches the reviewed path, to be EXCLUDED by
`--first-parent` — reasoning by analogy from BL-1354's sibling detector,
which excludes merges entirely from a ticket's own line changes. That
analogy does not hold here. Measured directly before trusting either
direction: `git show <merge>` with no diff option defaults to a COMBINED
diff, which shows nothing for a clean two-way merge (no divergence to
report); `--first-parent` instead diffs the merge result against its FIRST
parent alone, which DOES show the reviewed path as changed, because
relative to main-before-the-merge the content changed — the same fact
BL-1354's own investigation names ("a merge's first-parent diff is
everything its second parent brought in"). So `--first-parent` here is the
STRONGER, more cautious check (a review parcel whose merge silently carries
in someone else's edit to a reviewed path is still flagged), and dropping
it is a real weakening — the combined diff would let it through silently.
Fixed the test to assert `throws`, not `doesNotThrow`, with the reasoning
recorded inline; it discriminates the mutant either way once written
correctly.
