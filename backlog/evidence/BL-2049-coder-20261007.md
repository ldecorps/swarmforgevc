## The reach selector

`swarmforge/scripts/property_runner_reach_lib.bb` / `property_runner_reach.bb`
— the same lib/CLI pair shape as `bb_load_closure_lib.bb`/`bb_load_closure_cli.bb`.
`bb property_runner_reach.bb <scripts-dir> <changed-path>...` prints, one
per line sorted, the `*_property_runner.{bb,sh,js}` file names in
`<scripts-dir>/test` that any changed path (relative to the repository
root, `<scripts-dir>/../..`) reaches:

1. P is R itself.
2. R is a `.bb` and P is a `.bb` in R's load-file closure.
3. R's own text contains P's file name.

Closure computation follows the ticket's own "How" exactly: a runner R's
OWN direct deps (`bb-load-closure-lib/direct-load-file-deps` on R's raw
text) are resolved against R's OWN directory (`scripts-dir/test`) first,
converted to paths relative to `scripts-dir`, and ONLY THEN walked with
`compute-closure` rooted at `scripts-dir` — calling `compute-closure`
directly on R itself was explicitly ruled out (it resolves every
dependency against ONE fixed root, so from `scripts-dir` it cannot follow
a dep written as `"../a.bb"`, and from `scripts-dir/test` it would list
`a.bb`'s own deps but never walk them, since `a.bb`'s OWN load-file forms
are themselves relative to `scripts-dir`, not `scripts-dir/test`).

Invariant 1 (fail-open): the whole rule-1/2/3 check for one
(runner, path) pair is wrapped in ONE `try`/`catch` returning `true` on
any exception — an unreadable runner or a closure computation that
throws is reported reached, never silently dropped.

Invariant 2 (union): `reached-runners` filters paths to those under
`scripts-dir` first, then checks each runner against each relevant path
independently and unions the results — literally, not via any combined
shortcut that could drop one path's own contribution.

## The front-end flag

`swarmforge/scripts/test/run_property_runners.sh --changed-from <ref>
[dir]`: computes `git diff --name-only <ref>...HEAD` in the repository
holding `dir`, passes those paths to `property_runner_reach.bb
<dir/..>`, and narrows the existing `find`-based population listing to
exactly the reached names before handing it to `run_recorded_lane.sh` —
the listing, ordering and interpreter-dispatch-by-extension are
untouched. When nothing is reached it prints `no property runner reached
since <ref>` and exits 0 without invoking the lane runner at all.

## Step handler

`specs/pipeline/steps/bl2049PropertyRunnerReachSteps.js` (new, per
`required_wiring`) builds the Background's fixture (`trackedTmpRoot`,
BL-1390) and drives BOTH the real selector CLI (scenario 01) and the
real front-end script (scenario 02, a genuine git fixture proven by
`rev-parse --git-common-dir` before committing), reading "exactly the
runners" that ran from a log each fixture runner (babashka scripts that
`spit` their own name, then exit a code read from an env var) appends to.

One bug caught by the acceptance run itself: the fixture's own
"mark a file as changed" step first OVERWROTE the changed file with
arbitrary non-Clojure text, which is harmless for scenario 01 (the
selector only ever `slurp`s text, never evaluates it) but crashed runner
x on a bare unresolvable symbol the moment scenario 02 actually
LOAD-FILED `b.bb` for real, before it ever reached its own log-append
line — read as "nothing ran" rather than the real cause. Fixed by
appending a valid Clojure comment line (`; changed <timestamp>`) instead
of replacing the file's content.

## Invariants (BL-654)

New file
`extension/test/bl2049PropertyRunnerReachInvariants.property.test.js`,
both coder-authored, driving the real `property_runner_reach.bb` CLI
against real mkdtemp fixtures:

1. Invariant 1: a runner made unreadable (`chmod 000`) is always reported
   reached for a changed path that is neither the runner's own path (so
   rule 1's cheap string-equality check cannot be what passes it) nor
   anything the runner's text could name. 15 runs.
2. Invariant 2: N (2–4) independent runners, each reached by exactly one
   of N non-overlapping changed paths, plus one runner reached by none;
   calling the selector with all N paths together must equal the union
   of calling it with each path alone, and the untouched runner must
   never appear either way. 60 runs, floor 10 on each of n=2/3/4.

**Non-vacuity, proven by hand, reverted before this commit**: (a) changed
the fail-open `catch` to return `false` — invariant 1 failed exactly as
expected; (b) changed `reached-runners` to consider only the first
relevant changed path (`(take 1 (filter ...))`) — invariant 2 failed
exactly as expected, missing the second runner from the union. Both
restored from a backup; `git diff` shows only the real implementation.
