# BL-1354 — CODER PASS, 20260903

## The hypothesis, confirmed before building (as the ticket asked)

Ran the REAL detector against BL-1332's cited tip `6fd46b37c3` and listed, per
sibling, which attributed paths' blobs differ from `origin/main`:

- Every PRIVATE path of every named sibling was byte-identical (`SAME`).
- The only differing paths were files several tickets touch:
  `docs/reference/Specification.MD`, `docs/index.md`, and cross-ticket backlog
  yaml/topics.

So the shared path is the cause, and the tip-pure REPLAY is not: `sibling-landed?`
is content equality, never ancestry, and a replayed sibling's private content
compares equal. The specifier's diagnosis correction holds; QA's original
reading does not.

Two further causes surfaced only by running it, neither visible from reading:

1. **Intermediate lines.** A line one of a sibling's own commits added and a
   LATER commit rewrote is not part of what the tip would land. Demanding it on
   `origin/main` reports a landed sibling as unlanded — measured on BL-1271,
   where a superseded `abandoned_commits:` line was the sole miss.
2. **Merge commits inflate attribution.** A merge authors no lines; its
   first-parent diff is everything its second parent brought in, whoever wrote
   it. The landing ticket BL-1332's OWN unlanded lines were charged that way to
   sibling BL-1341 and made it read unlanded — the same confusion, one door up.

## What changed (`swarmforge/scripts/land_step_lib.bb`)

`sibling-landed?`'s public shape is untouched (`{:paths :complete?
:same-content?}`), and so are `attribution-complete?` and every fail-closed row.
What changed is what `landed-siblings` injects as `same-content?`: a
per-SIBLING, line-scoped verdict instead of whole-blob equality.

- `diff-line-changes` — pure parse of a unified diff into per-path
  `{:added :removed}`. `--- `/`+++ ` are read as headers only outside a hunk (a
  removed content line can itself begin `--- `).
- `commit-line-changes` / `sibling-own-line-changes` — the sibling's own lines,
  merged across its own non-merge commits. `nil` (unread) propagates; merges are
  skipped, so a path credited to the sibling only through a merge yields `{}` —
  a real answer, not an unread one.
- `sibling-path-verdict` — pure, three-valued: `:landed`, `:unlanded`, or
  `:vacuous` (the sibling has nothing left to land at that path, so the path is
  silent rather than an obstacle). Scored against what SURVIVES at the tip.
- `landed-siblings` drops the `:vacuous` paths and hands the rest to
  `sibling-landed?`, whose existing empty-paths row then fails closed — so a
  sibling with nothing but vacuous paths still reports unlanded. Silence is
  never scored as evidence (invariant 1).
