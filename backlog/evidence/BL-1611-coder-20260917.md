# BL-1611 — coder evidence, 2026-09-17

## What changed

`swarmforge/scripts/ready_for_next.bb`'s `has-in-process-parcel?`
(pre-turn worktree-drift guard, BL-1195) read the role's `in_process` box
through the flat reader (`handoff-lib/my-handoff-files`), which never
descends into a batch role's `in_process/batch_<stamp>_<seq>/`
directories. A batch role (cleaner, hardender) mid-work therefore always
read as holding nothing, and its own uncommitted WIP was refused as
`WORKTREE_DRIFT_DETECTED` (hardender hit this on BL-1599, 2026-09-16).
One-line fix: swap in `handoff-lib/handoff-files-with-batches` (BL-1313,
pre-existing) in its place. `worktree_drift_lib.bb`, the master-resident
exemption, and BL-1515's branch-identity guard are all untouched.

## Declared invariant (BL-654)

> "For every roster shape, the drift guard's in-process input is true
> exactly when a git_handoff or note parcel exists anywhere under the
> role's in_process box, at the top level or inside a batch_ directory."

Encoded as a coder-authored property test pinning
`handoff-lib/handoff-files-with-batches` (the exact function
`has-in-process-parcel?` now wires to — testing it directly is not an
option, since loading `ready_for_next.bb` as a library runs its own
top-level guards, including a `System/exit`, against whatever git-root
this process resolves against):

- `swarmforge/scripts/test/bl1611_drift_guard_in_process_property_runner.bb`
  — seeded RNG (seed 1611), 150 runs, generates random `in_process` trees
  (0-2 top-level `.handoff` files, 0-3 `batch_*` directories each holding
  0-2 parcels, optional noise files/dirs) and asserts the reader's
  existence boolean matches the generated ground truth. Generator-reach
  asserted: every named roster-shape row (nothing at all, a top-level
  parcel, a batch directory with a parcel, a batch directory that stays
  empty) is confirmed drawn, not merely hoped for.
- Non-vacuousness built into the runner: a deliberately-broken flat
  reader is shown to wrongly report "nothing held" for a batch-only
  parcel, then the real reader is shown to report it correctly — this is
  the exact bug class BL-1611 exists to fix.
- `extension/test/bl1611DriftGuardInProcessInvariant.property.test.js` —
  thin Vitest wrapper (`spawnSync('bb', [RUNNER])`), the BL-654 "runs only
  via `npm run test:properties`" placement.
