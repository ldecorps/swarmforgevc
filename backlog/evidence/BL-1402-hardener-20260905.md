## atomicWrite.js — scoped Stryker run (10 mutants, all equivalent)

Isolated via `vitest.bl1402.stryker.config.mjs` (the vitest.bl1081/bl1365/
bl1383.stryker.config.mjs precedent — avoids the standing Stryker-sandbox
reds elsewhere in the suite without touching the shared vitest.config.mjs).

19 mutants total, 9 killed, 10 survived. All 10 survivors are on the
`typeof content === 'string'` branch guard and the explicit
`{ encoding: 'utf8', flag: 'a' }` options object — and every one is a
genuine equivalent, confirmed empirically against this Node version's own
`fs` API defaulting behavior (not reasoned, tested):

| survivor | mutant | proof |
|---|---|---|
| `if (typeof content === 'string')` → `if (false)` / `!== 'string'` / `=== ""` | branch always taken/inverted | `fs.writeFileSync(path, buffer, 'utf8')` — Node ignores the encoding arg entirely when content is a Buffer (confirmed: identical bytes with/without it); `fs.writeFileSync(path, string)` with no encoding arg defaults to `'utf8'` already — so BOTH branches produce byte-identical output for every content type this function accepts |
| `fs.writeFileSync(tmp, content, 'utf8')` → `..., "")` | encoding `''` instead of `'utf8'` | empirically confirmed: `fs.writeFileSync(p, s, '')` then `fs.writeFileSync(p, s, 'utf8')` on the SAME multi-byte Unicode string (`日本語 emoji 🎉 café`) produce byte-identical output — Node resolves an empty/falsy encoding string to its own `'utf8'` default, not an error |
| `{ encoding: 'utf8', flag: 'a' }` → `{}` | empty options object | confirmed: `fs.appendFileSync(p, s, {})` produces the exact same result as the explicit object — Node's OWN documented default for `appendFileSync` options is `{encoding:'utf8', flag:'a'}`, i.e. identical to what this code specifies explicitly |
| `{ encoding: 'utf8', ... }` → `{ encoding: "", ... }` | empty encoding in options | same defaulting as above |
| `{ ..., flag: 'a' }` → `{ ..., flag: "" }` | empty flag in options | confirmed: `flag: ''` behaves as `flag: 'a'` (append), NOT a throw or a different mode - verified against a REAL discriminator first (`flag: 'w'` genuinely truncates instead of appending, proving the test methodology can tell flags apart when they really differ) |

None of these are "hard to test" — they are provably unobservable through
Node's own `fs` API for every input this function's type signature admits
(`string \| Buffer`). The explicit encoding/flag values are defensive/
self-documenting (spelling out the intended behavior rather than relying on
an unstated default that could differ across runtimes), which is worth
keeping — not a simplification target for this pass (cleaner-domain, and
even then the current form reads clearer, not just shorter).
