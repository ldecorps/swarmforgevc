# BL-1420 — coder pass, 2026-09-05

## What was wanted

BL-784's registry guard (`daemon_log_freshness_registry_guard.sh`) runs
before every `daemon_log_freshness_check.sh` invocation and refuses when
(a) a daemon named in `FRESHNESS_REQUIRED` has no conf row, or (b) any
live `*_supervisor.bb` script has no conf row - the second arm has no
seam, it always walks the real scripts directory. Three fixtures written
before BL-784 pointed only `FRESHNESS_CONF` at a one-row conf and never
set `FRESHNESS_REQUIRED`, so the guard's own first arm alone already
refused them ("daemon 'babysitterd' has no row"): BL-1011's feature was
0/8, BL-1012's 0/9, and the bl1011 attribution property runner span
`:continue true` past the refusal into an empty announce, so its four
properties held vacuously over zero violations.

## What landed

- **`extension/test/helpers/freshnessFixture.js`** (new): `supervisorNames(scriptsDir)`
  (the same `*_supervisor.bb` glob the guard walks, injectable so a test
  can point it at a scratch directory) and `writeGuardSatisfyingRows(...)`
  (one conf row + a fresh heartbeat log per name the glob finds, plus the
  `FRESHNESS_REQUIRED` registry) - the shared derivation the ticket's
  "How" asked for, so the two JS step handlers never each hand-mirror the
  guard's own glob a second time (BL-1398's lesson).
- **`specs/pipeline/steps/bl1011FreshnessAlarmNamesSwarmAndReasonSteps.js`**:
  `makeRoot()` now calls `writeGuardSatisfyingRows` (requiring `handoffd`
  only, pinned at `PINNED_EPOCH`); `runChecker()` sets `FRESHNESS_REQUIRED`.
- **`specs/pipeline/steps/bl1012FreshnessSelfInflictedIncidentsSteps.js`**:
  same shape, pinned at `NOW`.
- **`swarmforge/scripts/test/bl1011_freshness_attribution_property_runner.bb`**:
  a Clojure-side `supervisor-names`/`write-guard-satisfying-rows!` (the
  same glob via `fs/glob`, no cross-language sharing attempted - the
  ticket's own "How" says the bb runner derives from the same glob in
  Clojure, not that it shares code with the JS helper); `build-checkout!`
  calls it. `run-checker!` now checks `(:exit result)` explicitly instead
  of swallowing everything via bare `:continue true`: `{:ok? true
  :announced ... :incidents ...}` on a clean exit, `{:ok? false :stderr
  ...}` otherwise. The main loop reports a non-zero exit as a failed run
  ("P-checker (the checker must exit 0)") naming the stderr, and
  evaluates NONE of P1-P4 or the coverage counters over that run - never
  folding a refusal into an empty, vacuously-passing observation.
- Neither the guard, the checker, nor any live conf file was touched
  (`git diff` against both is empty).

## Declared invariants

1. **Every fixture derives its supervisor rows from the same glob the
   guard walks; no hand-written list.** `supervisorNames`/`supervisor-names`
   are the ONLY place either language enumerates `*_supervisor.bb` files;
   both the JS helper and the bb runner accept an injectable
   `scriptsDir`/`scripts-dir`, and BL-1420's own scenario 04 (3 rows, one
   per fixture) proves each fixture's row count follows an INJECTED
   scratch directory's count rather than a number baked in at authoring
   time.
2. **A harness never turns an unexpected checker exit into an
   observation.** The bb runner's `run-checker!` now returns `{:ok?
   false ...}` on non-zero exit, and the main loop reports it as a failed
   run instead of evaluating P1-P4 over an empty announce - demonstrated
   directly by mutation (see Non-vacuity) and by BL-1420's own scenario 03
   (a fixture whose registry names a daemon its conf lacks fails naming
   the guard's own refusal line, with nothing appended to the announce
   file).
3. **The guard, the checker and the live conf files are untouched.**
   `git diff HEAD -- swarmforge/scripts/daemon_log_freshness_registry_guard.sh
   swarmforge/scripts/daemon_log_freshness_check.sh` and `git status
   --short swarmforge/scripts/daemon_log_freshness*.conf` are both empty
   at this commit.
