## What was actually still broken: the gate was not wired in at all

The ticket's own acceptance was **red 3 of 4** on arrival, and running it
found two distinct causes.

### D1 — the production call site is missing from `swarm_handoff.bb`

`grep -n unregistered swarmforge/scripts/swarm_handoff.bb` returned
**nothing**. The lib, its unit runner, its property runner, the step handler,
the driver and the manifest row all survived; the 21 lines that actually call
the gate did not.

Cause, traced: `9a77c98bac` (`Revert "Merge documenter BL-1240 0ca3bc03c0
into QA"`), the correct BL-490 revert of QA's bounce, removed the whole
parcel — including three hunks in `swarm_handoff.bb`. The rework that
answered the bounces re-landed everything **except** those hunks. A partial
resurrection: every artefact present, the wiring absent, so invariant 1 ("a
parcel that adds a test file without a manifest row does not move to the next
stage") was false in the live send path while every unit and property check
still passed.

Note this is exactly the blind spot the ticket's own 2026-08-30 amendment
records: the production call site was verified by hand at the time
(`swarm_handoff.bb:426`) and deliberately given **no** `required_wiring`
entry. Nothing gated it, so nothing noticed when the revert took it out.

Restored verbatim from `9a77c98bac`'s own reverse diff — the load-file, the
gate block in the `let`, and the refusal-message arm — so the chain reads as
it did before the revert, in the same position relative to the BL-1192
task-scope gate.

### D2 — the acceptance driver made one send, and the self-audit gate ate it

`specs/pipeline/steps/lib/bl1240UnregisteredTestGateCli.sh` invoked
`swarm_handoff.bb` once. The self-audit challenge (Article 2.3) consumes the
**first** valid invocation of any `git_handoff` draft — it prints
`AUDIT_REQUIRED` / `HANDOFF_NOT_QUEUED` and returns before the gate chain is
reached — so all three handoff scenarios were asserting against the challenge
rather than against any gate. The driver now answers the challenge the way a
real agent does (re-invoke with an identical draft) and reports the second
call's verdict; if no challenge is raised, the first call's verdict stands.

This is why the acceptance did not catch D1 on its own: it could not reach
the gate chain at all.
