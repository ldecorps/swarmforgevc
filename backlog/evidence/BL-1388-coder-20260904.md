## A measured contradiction in the ticket — and in one scenario

The ticket's "How" offers two ways to make a handler undiscoverable: name it
without the suffix, **or** nest it under `specs/pipeline/steps/`. The feature
file turns both into a Scenario Outline row. **The nested row is not a refusal
case in the guard as it stands**, measured rather than reasoned:

`check-feature-handler-registration.ts`'s `readTree` fills `stepFiles` from
`listDir(STEPS_DIR)` — **non-recursive**. A nested file is therefore never in
`stepFiles`; no handler declares the feature's ticket; `collectUnregisteredHandlers`
sees `own.length === 0` and skips. Driving it end to end confirms it: the tree
guards return `[]` for a feature whose only handler is nested. (Arguably a real
hole in the guard — a feature can reach `main` with its only handler parked in
a subdirectory — but the guard's own behaviour is explicitly out of scope here,
so it is reported, not fixed.)

So the fixture asserts only the suffix case, which genuinely refuses, and says
in a comment why the nested one is absent. **A priority-00 spec-gap note went
to the specifier** (2026-09-04 20:21Z): the outline row needs retiring or
replacing (BL-1006: retire, never reword). Per Article 4.4 a spec gap leaves by
note, never a parcel — so **this parcel is not forwarded until that row is
amended**: its acceptance run is 3 pass / 2 fail, and the two failures are that
row alone.
