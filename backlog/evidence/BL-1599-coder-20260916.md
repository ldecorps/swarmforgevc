# BL-1599 — coder, 2026-09-16

## What was wrong

`check-suite-duration-budget.ts` holds the wall-clock 10s target
(`SUITE_DURATION_BUDGET_MS`) and, by architect-reviewed design (BL-445),
only surfaces an over-budget run rather than refusing, because wall
jitters with host load. It has read over budget since July with no line
that actually refuses. The epic's 2026-08-22 profile found the operator's
13s ceiling unreachable by cutting poles alone and put slice C on hold
for a host-budget/lane-composition decision, delegated to the specifier
on 2026-09-16 (coordinator note 008676).

## The decision (specifier, recorded on BL-791)

Summed per-file WORK, because it is fork-independent and stable: 533.8s
(2026-08-22, 460 files, 1 fork, macOS) -> 546.1s (2026-09-16, 622 files,
9 forks, WSL) while wall moved 689s -> 72s over the same span. Budget
550000 ms, 10 percent tolerance, ratchet down only. Host budget and lane
composition (fork pool, `npm test` as the unit lane) unchanged.

## The fix

- `check-suite-duration-budget.ts`: `SUITE_WORK_BUDGET_MS = 550000`,
  `SUITE_WORK_TOLERANCE = 0.10`, `OPERATOR_WALL_CEILING_MS = 13000`.
  `classifySuiteWork(workMs, budgetMs, tolerance)` returns `ok` at or
  under budget, `over-tolerance` up to `budget * 1.1` (passes, prints the
  margin), else `over-budget` (refuses). `deriveExpectedWallMs(workMs,
  forks, poleMs)` = `max(poleMs, workMs / forks)`, floored at 1 fork.
  `buildSuiteWorkVerdict`/`formatSuiteWorkVerdict` compose the two and
  print work, forks, slowest file, derived wall and the distance to the
  13000ms ceiling on every run.
- `extension/scripts/recordTestDuration.js`: the live consumer. Resolves
  the real fork count through the SAME `resolveVitestWorkerPool`
  composition `vitest.config.mjs` itself calls (same environment inputs -
  `SWARMFORGE_PACK`, `SWARMFORGE_ROTATION`, platform, RAM, free-cores
  ceiling), prints the verdict line, folds an `over-budget` verdict into
  the script's own exit code via `computeFinalExitCode`'s new third
  argument (still loses to a real test failure), and records
  `work_budget_verdict` on the row beside BL-1598's `budget_verdict`.
- `SUITE_DURATION_BUDGET_MS` (10000) and `PER_FILE_DURATION_BUDGET_MS`
  (7000, `check-suite-file-budget.ts`) are untouched - verified by diff
  below.
