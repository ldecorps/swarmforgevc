## What changed

`swarmforge/scripts/land_main_publish.sh` — the only landing step QA.prompt
makes mandatory — now consults the finished detector before it advises
anything:

- The `--decide-only` decision is computed into `DECISION` and printed LAST, so
  a refusal never has push advice already on stdout ahead of it.
- `ENTANGLED_SIBLING_BLOCK` plus one `entangled-sibling: <id> …` line per
  unlanded ticket, then a line naming the remedy (BL-1241's tip-pure replay).
  A caller keys off the literal marker, never prose.
- Documented exit status **3** on refusal, `0` otherwise (`2` stays the usage
  error), recorded in the script's own header.
- The guard cannot abort the script. It runs under `set -euo pipefail`, so the
  detector is invoked inside a command substitution with `|| true`
  (Guardrails, BL-1242/BL-1252) — a refusal is an ordinary exit and never
  leaves the land lock held. Asserted, not assumed: unit row 04 checks the lock
  directory is absent after a refusal.

Fail-open (invariant 2) covers every input the step cannot read: no tip sha, no
`land_step_lib.bb` on disk, a tip whose subject names no ticket, an unreadable
range against origin/main (`:warning` set), or a detector that errors. Only a
POSITIVE finding refuses.
