# BL-1686: a fixture proves its root before git init, and no shell test sweeps a live sibling's TMPROOT — coder

## What changed

1. `swarmforge/scripts/test/test_bl1378_expedite_close_guard.sh`, `mk_fixture()`:
   `prove_root "$root"` now runs BEFORE `git -C "$root" init -q -b main`
   (previously one line after it — BL-1516's own patch, cd638f1c6f). Since
   `git rev-parse --git-common-dir` fails on a path with no `.git` yet,
   `prove_root`'s git-common-dir-check branch now `return 0`s (pass) rather
   than `exit 1` (refuse) when that check fails "not a git repository" —
   the STRING check (root under `$TMPROOT`) is the only proof available
   before a repository exists, and "no `.git` yet" cannot itself indicate
   a wrongly-rooted EXISTING repo (that failure mode needs a foreign repo
   already there). Verified empirically in scratch before touching the
   real file: a fresh under-TMPROOT dir with no `.git` passes, the same
   dir after `git init` still passes, and an empty-string root (the exact
   BL-1378/BL-1516 race) is still refused by the string check alone,
   unaffected.
2. Audited the two fixtures in `test_bl1374_sync_merge_passengers.sh`
   (`mk_autofix`, `mk_entangled`) — both already call `prove_root` before
   any mutating git command; no change needed there, confirmed by reading
   the source (lines 71/93, both before their own `git init`).
3. New shared helper `sweep_stale_prefix_roots` in
   `swarmforge/scripts/test/lib/tmp_cleanup.sh`: a pid-scoped, zombie-aware
   replacement for the blind BL-971 startup sweep
   `rm -rf "${TMPDIR:-/tmp}/${PREFIX}".* 2>/dev/null || true`. It parses
   the pid segment out of each root's own name and removes a root only
   when that pid is not alive — liveness is `kill -0` AND NOT a zombie
   (checked via `ps -o stat=`, BL-1647's own idiom, reused verbatim from
   `finish_shift_lib.sh`'s `_finish_shift_pid_is_zombie`; stock bash 3.2
   has no `/proc`). A root with no parseable pid segment is left alone.
4. All five files named in the ticket's census now `source lib/tmp_cleanup.sh`,
   call `sweep_stale_prefix_roots "$PREFIX"` instead of the blind glob, and
   embed the owning pid in their own root names (`${PREFIX}.$$.XXXXXX`, or
   `${PREFIX}$$.XXXXXX` for `bl1363_close_ticket_property_runner.sh` whose
   `PREFIX` already ends in `-`):
   `test_suite_baseline_cli.sh`, `test_bl1376_expedite_branch_handover.sh`,
   `bl1363_close_ticket_property_runner.sh`,
   `test_bl1374_sync_merge_passengers.sh`,
   `test_bl1378_expedite_close_guard.sh`.
5. Regression section 09 added to `test_bl1378_expedite_close_guard.sh`:
   creates a TMPROOT, removes it, calls the real `mk_fixture` from an
   empty scratch cwd, and asserts both the refusal text and that the
   scratch cwd holds no `.git` afterward — pinning the ORDER fix, not just
   `prove_root`'s own behaviour (already covered by sections 07/08).
6. `specs/features/BL-1686-...feature` (pre-minted by the specifier) driven
   by a new `specs/pipeline/steps/bl1686FixtureProofBeforeInitSteps.js`,
   which shells out to a new
   `specs/pipeline/steps/lib/bl1686FixtureProofBeforeInitCli.sh` — extracts
   `prove_root`/`mk_fixture` from the real bl1378 file by source position
   (never retyped) for scenario 01, sources the real `sweep_stale_prefix_roots`
   and reads each real file's own `PREFIX` constant for scenario 02's
   Outline (all five census files), and greps for the blind idiom for
   scenario 03.
