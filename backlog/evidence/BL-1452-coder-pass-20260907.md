## The fix

One shared predicate, `extension/src/tools/backlogTicketId.ts`:

```ts
export const BACKLOG_TICKET_ID_PATTERN = /^(BL|GH)-\d+$/i;
export function isBacklogTicketId(value: string | undefined): value is string { ... }
```

Both `required_wiring` sites now delegate to it:

- `bounceArgsCore.ts` — removed the private `TICKET_PATTERN = /^BL-\d+$/i` and
  `isValidTicket`; `validatedCoreFields` calls `isBacklogTicketId(ticket)`
  directly. This is the shared core `recordBounceArgs.ts` (record-bounce.js,
  BL-635) and `recordQaBounceArgs.ts` (record-qa-bounce.js, BL-608) both
  import, so both recorders pick up GH acceptance from one edit.
- `qa-sibling-check.ts` — same removal; all four call sites
  (`parseStatusArgs`, `hasValidDeferFields`, `parseClearArgs`) now call
  `isBacklogTicketId`.

`record-bounce-correction.ts` (BL-990, the third recorder the ticket's "How"
section named) was checked and left untouched: `parseArgs` there only checks
`isNonBlank(flags['--ticket'])` — no pattern validation exists to route, so
there is nothing for this predicate to replace.

Per the ticket's "How" section, `swarmMetrics.ts`'s unanchored
`TICKET_ID_PATTERN` (`/^(BL|GH)-?(\d+)/i`, prefix-matches a task name) was
**not** touched or reused — the new predicate is anchored (`$`) and is a
different contract (validates a whole id, not a task-name prefix).

## Acceptance handler design note

`is_qa_ancestor.sh`'s bounce-token check
(`match_bounce_token`/`answer_one`) runs **before** any ancestry-of-
`swarmforge-QA` check, so scenario 01's fixture does not need a real
`swarmforge-QA` ref/branch to reach the `bounced:` stderr line — a plain
fixture repo with the ticket, a commit, and a `record-bounce.js` call is
sufficient. Confirmed by reading the script directly (`match_bounce_token`
returns 1 with the `bounced: ... (recorded as ...) - a bounced parcel never
reads as approved (BL-952)` line before `answer_one` reaches the ancestry
branch).
