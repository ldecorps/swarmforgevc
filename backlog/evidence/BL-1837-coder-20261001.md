# BL-1837 — coder bounce fix, 2026-10-01

QA bounce (commit 4526c4c133, D1 in `backlog/evidence/BL-1837-QA-20261001.md`):
`handoff_lib.bb`'s `prompt-file-path` kept the bare `@` role name, so a
respawn/rotation (`recompose-role-prompt!`, called from `respawn-self!` and
`rotate-resident-to!`) recomposed the dead pre-fix `coder@iq3.md` instead of
the card the launch script actually reads (`coder-iq3.md`).

## Fix

- `swarmforge/scripts/handoff_lib.bb` `prompt-file-path`: now 2-arity,
  `(prompt-file-path role-name agent)` maps every `@` to `-` for
  `agent = "local-model"`, exactly as `swarmforge.sh`'s
  `role_prompt_card_path` does. The 1-arity form keeps the old unmapped
  behaviour (agent unknown).
- `recompose-role-prompt!` now resolves the path with the role's agent
  (`load-role-info`, i.e. `roles.tsv` — not the metadata sidecar, which
  lives AT that same path and can't be read first to find it).
- `swarmforge/scripts/respawn_bootstrap_lib.bb`'s own `prompt-file-path` is
  left unmapped on purpose, with a comment: it is reachable only through
  `argv-for-role` / `run-respawn-bootstrap!`, and `bootstrap-steps`
  (`agent_runtime_lib.bb`) returns no steps at all for an `:embedded`
  bootstrap-style agent — `local-model`'s own capability entry — so a wrong
  path there is never read. Aligning it would be a second copy of the same
  mapping with no behaviour change.

## Tests added (`swarmforge/scripts/test/handoff_lib_test_runner.bb`)
