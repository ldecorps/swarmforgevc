## A design note on scenario 02 ("every line is accepted")

`swarmforge.sh`'s `parse_config` has two DIFFERENT failure shapes: a
per-line syntax rejection (`Invalid config line N: ...`, inside the read
loop) and a separate POST-loop structural check (`No windows defined in
<file>`, once the whole file has been read with zero window lines).
The installed `swarmforge.conf` is deliberately metadata-only
(`tooling_root`/`swarm_name`, no window lines - it is read for those
config lines by other tools, never launched bare) and legitimately
fails the second check while passing the first perfectly. The
acceptance step handler asserts specifically that neither file produces
an `Invalid config line` error (and that `mono-router.conf`, which DOES
carry window lines, parses all the way through with no error at all) -
matching the scenario's own title, "the installed engine accepts every
LINE", not "swarmforge.conf launches a full pack on its own".

## Invariant check

Three declared invariants, all exercised directly by the acceptance
feature above:

1. "The engine, hooks, pack and conf a target receives all come from
   one checkout at one recorded commit." - `install_starter_kit.bb`
   derives `checkout-root` from its OWN file location (never a second,
   independently-configurable source) and stamps that same root's
   `git rev-parse HEAD` into the written conf (scenario 04).
2. "An install never writes into a target that already holds a
   swarmforge/ tree; it refuses and leaves every file byte-identical."
   - checked before any copy (scenario 07's byte-identical hash
   comparison).
3. "No file that describes swarmforgevc itself ... is copied into a
   target." - `generic-articles` is an explicit allowlist (never a
   directory copy of the whole `constitution/articles/` tree), and the
   role prompts come only from `starter-kit/roles/`, never
   `swarmforge/roles/` (scenario 03).

No separate property test: each invariant names a small, fixed set of
paths (the exact file list above) - an exhaustive check the acceptance
scenarios already give directly, not a space a generator would add
coverage over.
