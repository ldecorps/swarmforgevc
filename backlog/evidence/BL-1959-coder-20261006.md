  for the coordinator's own index (always the last-registered role) on a
  pack declaring `config coordinator_mode deterministic` (`$COORDINATOR_MODE`,

  `provision_coordinator` runs). Placed beside `is_sequential_dormant`,
  same style.
- Wired at the three launch-loop sites the ticket named that create a
  session, a launch script, or a terminal window for a role: the
  `create_role_session` loop, the `launch_role` loop, and the terminal
  window-opening loop — each now also skips when

  and `prepare_handoff_dirs` (mailbox directories, keyed off the full
  `ROLES` array with no dormancy/seatless check) are untouched — the row

  sequential_dormant "$i" || continue`) needed no change: `is_sequential_
  dormant` is already always false for the coordinator's index (it is
  "never dormant... reserved infrastructure" by existing design), so that
  loop already skips the coordinator on every pack, before and after this
  ticket.
- New step handler `bl1959DeterministicPackLaunchKeepsTheCoordinatorRowSteps.js`
  (auto-discovered per BL-1371 — `specs/pipeline/steps/index.js` globs

  (same `ZSH_EVAL_CONTEXT` toplevel-guard convention as test_coordinator_
  provisioned_infrastructure.sh/test_rotation_sequential_pack.sh — no real
  top-level launch, no reimplementation): `parse_config` (which calls
  `provision_coordinator` internally), `write_roles_file`,
  `prepare_handoff_dirs`, then the exact guard shape each real loop uses
  (`is_sequential_dormant || is_coordinator_seatless`) gating the REAL
  `create_role_session` (against a throwaway, project-private tmux socket
  — BL-367's `resolve_swarm_socket.bb`, sourced unconditionally at the top
  of swarmforge.sh) and the REAL `write_role_launch_script`. The for-loop/
  continue shape is boilerplate; the gating predicates and the session/

  `fs.mkdtempSync` goes through `trackedTmpRoot` (`./lib/fixtureReaper`);
