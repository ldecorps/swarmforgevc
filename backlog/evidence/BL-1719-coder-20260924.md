## Scope judgment call: two caller files beyond the ticket's own list

The ticket's Scope lists `handoff_lib.bb` only, with "FIRM: the fix is in
the one shared resolver both delivery paths call, never two copies." That
FIRM clause is about the DECISION algorithm never being duplicated - it
does not, and given the invariant's own text ("a recipient with no
session gets no wake... on every delivery path"), cannot mean zero
callers ever change. `resolve-wake-session` returning `nil` accomplishes
nothing on its own: `agent-runtime-inject/notify-agent!` has no upfront
"does this session exist" check of its own - given a genuinely missing
session it retries, times out, and THROWS ("tmux send submit failed"),
which is worse than the current bug, not a fix. Achieving "skipped and
logged, naming the missing session" (the feature's own Then step) requires
the two real send-attempt call sites to check for `nil` themselves, before
ever reaching that injection machinery:

- **`swarmforge/scripts/handoffd.bb`** ("the handoff daemon"): `notify!`
  checks `(nil? wake-sess)` first; on nil, logs `wake-skip-no-session
  <configured-session>` to `handoffd.log` and returns without touching
  tmux at all. This is the ONLY call site of `handoffd/notify!` in the
  whole file (`chase-poke-and-notify!`'s `send-wake-up!`, itself the
  chase sweep's own wake attempt for a just-arrived OR retried parcel) -
  every OTHER `wake-session` call in this file is a read (busy-probe,
  epoch check, resident-target? classification), unaffected by this
  ticket and untouched.
- **`swarmforge/scripts/handoff_inject_lib.bb`** ("the sender's own
  send"): `notify-delivered-recipient!` (private, called from exactly one
  place - `write-parcel-to-recipients!`, `deliver-parcel!`'s own inner
  loop) checks `(nil? wake-sess)` BEFORE the dedup/busy checks - on nil,
  logs `deliver-notify-skip-no-session <recipient> <configured-session>`
  and records an `outcome=skip` row in `inject-traffic.log` naming the
  recipient's OWN configured session (never another role's - the exact
  census the ticket's own qa_e2e_procedure step 3 counts), never calling
  `notify!` at all.

Both touches are the minimal "check the shared resolver's answer, skip
and log" wiring the ticket's own two named delivery paths require - the
remap/skip DECISION itself lives exclusively in `resolve-wake-session`,
called unchanged from both sites.

   yet load-filed (SCI analyzes a `defn`'s body eagerly at definition

   still referenced a namespace conditionally loaded only for the OTHER
   branch. Fixed by load-filing BOTH `handoff_inject_lib.bb` and
   `handoffd.bb` unconditionally, at the top level, before the `case`
   dispatch - the same fix shape as #1, applied to my own new file.

   was typed" difference.** The shell test's first pane-text snapshot,
   taken immediately after `tmux new-session`, raced the shell's own
   prompt print - a 1-second settle before the "before" snapshot fixed
   it; not a defect in the code under test.
4. **The delivered inbox filename carries a `_for_<recipient>` suffix**,
   not the outbox's own bare filename - the shell test's own inbox-arrival
   check uses a glob, not an exact name.
