## Declared invariant (BL-654)

- **"No control-socket fixture path can exceed swarm_socket_lib.bb's length
  limit on any supported OS, whatever that OS uses as its temp base."**
  This is already fully executable-encoded, not newly needed here:
  `mkSocketFixtureRoot` (`specs/pipeline/steps/lib/socketFixtureRoot.js`)
  hardcodes its root to `SHORT_FIXTURE_BASE = '/tmp'` and never reads
  `os.tmpdir()` at all — the OS's own temp base is structurally irrelevant
  to the resulting path, which is exactly why adopting it (rather than
  patching the two call sites' prefixes) closes the invariant for every
  future adopter too. The pre-existing, coder-authored
  `extension/test/bl948SocketFixtureInvariants.property.test.js`'s third
  test ("a fresh root leaves the worst-case socket path within the guard
  limit, with margin") already measures exactly this claim against the
  real limit; it is unmodified by this parcel and re-verified green above
  (3/3). This ticket does not touch the helper — it adopts it — so no new
  property test is written; writing one would restate the same assertion
  against the same unchanged function, which is exactly the duplication
  the engineering rules ask touched code to avoid. Acceptance scenario 03
  additionally measures the two files THIS ticket actually converts,
  closing the gap between "the helper is safe" and "these two adopters are
  now built from it."
