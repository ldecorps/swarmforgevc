## Invariant 1 — property test added

> "land-plan over origin/main..commit still considers every commit in the
> full ancestry (never --first-parent alone, never parcel-own-base alone);
> a sibling absorbed before the parcel's last hop still forces LAND_REPLAY
> exactly as BL-1461 requires."

New file:
`swarmforge/scripts/test/bl1806_land_plan_fat_tip_detection_property_runner.bb`.

QA's remediation pointer named the exact gap: the acceptance feature's own
scenario 02 places its sibling ONLY on the first-parent line, so a
regressed `--first-parent`-only walk would still pass it — it does not
discriminate. `land_step_lib_test_runner.bb:589` (BL-1308) is a fixed unit
precedent for one second-parent-only sibling; the new property runner
generalizes it against the REAL `land-plan` (never a reimplementation): a
randomized number of siblings (0-2 each), independently placed EITHER on
the first-parent line OR exclusively inside a merged side branch (a
forward merge whose subject names the landing ticket — the exact shape a
cleaner/architect/hardener/documenter hop produces), interleaved in a
seed-shuffled order with 0-3 untagged filler merges so the tip carries real
merge-DAG shape and the `*commit-meta*` preload BL-1806 introduced
(`range-commit-meta`, bound by `land-plan` as `*commit-meta*`) is genuinely
exercised, not bypassed by a single-merge fixture.

- Traced `range-commit-meta` and `ancestry-commits` by hand first: both
  walk `git log`/`git rev-list base..commit` with no `--first-parent`

## Invariant 2 — stated reason, no property test

> "On a fixture whose full ancestry is at least one thousand commits and
> whose first-parent ancestry is under twenty, land-plan returns a verdict
> in under ten seconds of wall clock."

executable encoding: this invariant quantifies over wall-clock time on a

fixture shape (≥1000 full / <20 first-parent ancestry) — the same posture
BL-1431's own invariant 2 (`BL-1431-coder-20260905.md`) recorded for an
analogous case in this same file.
