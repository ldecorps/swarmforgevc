## What was wrong, and the fix

`test_bl1388_land_step_guard_fixture.sh` has been red on main since BL-1388
landed on 2026-09-04. Its step 4 (`git diff main -- land_step_lib_test_runner.bb`,
requiring a NON-EMPTY diff) was BL-1388's own qa_e2e item 4 - meaningful
only while that parcel was unlanded - frozen into a standing assertion.
Since the shell manifest's `standing` rows are no role's lane, nothing
noticed for thirteen days.

- Deleted the `# -- 4.` block entirely (steps 1, 2, 3, 5 byte-identical,
  headers unrenumbered per the ticket's own direction).
- Added a loud precondition at the top of the shell test: a fresh tree
  with no compiled `extension/out/tools/check-feature-handler-registration.js`
  now fails at once, naming the missing build and `npm run compile`,
  before any runner assertion runs - the second finding (a fresh clone
  otherwise fails eight runner cases as if the land step were wrong,
  because the tree-guard fixture's `check_feature_handler_registration.sh`
  execs that compiled file and refuses with no build present).
- New census script `test_standing_shell_tests_never_diff_main.sh`,
  registered `standing` in `suite-manifest.tsv` (`bb suite_inventory_cli.bb`
  confirms the tree and manifest agree: 524 files, 520 standing, 4
  excluded).
