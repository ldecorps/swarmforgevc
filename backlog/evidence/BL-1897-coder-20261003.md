## Change (test side only, no extension/src)
- `extension/test/helpers/gitEnvGuard.js`:
  - `ceilingDirectoriesWith(current, dirs)` (pure) appends to a colon-separated
    `GIT_CEILING_DIRECTORIES`. It keeps the existing entries first and drops empties and
    repeats, so it is idempotent.
  - `ceilGitDiscoveryAtTmpdir(tmpdir = os.tmpdir())` (impure) adds the tmpdir and its real path
    to `process.env.GIT_CEILING_DIRECTORIES`.
  - Git discovery from a fixture under TMPDIR now stops before it climbs into TMPDIR, so a TMPDIR
    inside a checkout no longer makes every fixture part of that checkout's work tree. A fixture
    that runs `git init` itself is still found.
- `extension/test/helpers/gitEnvGuardSetup.js` calls it at module load. That setupFile already
  runs for every test file in BOTH lanes (`vitest.config.mjs` and `vitest.properties.config.mjs`,
  BL-1196's strip). So it covers mkTmpDir, mkSharedTmpDir, mkProcessTmpDir and any raw
  `os.tmpdir()` user at once, and every spawned git inherits it.
  - Why there and not `tmpDir.js`: tmpDir.js is loaded only by files that require it, while the
    setupFile runs before every file. The setupFile is also where the test process's git-env
    policy already lives.
  - The env-restore guard is unaffected: the value is set before each test's snapshot and is
    idempotent across files (isolate:false).
- `tmp/BL-1867-tmpdir/`: all 29 files removed from the repository (`git ls-files tmp` is empty).
  `/tmp/` is in the root `.gitignore` (line 24).

  symlink, and deep TMPDIR.

- **Checked and recorded.** Dropping only the real path still passes, because git resolves
  ceiling symlinks itself. The comments say so; the real path is kept so the ceiling does not
  depend on that.
