# BL-1469 — hardener bounce, 2026-09-07

## D1: the open-slot nudge's evaluate-ctx never threads `:today`, so a
`not_before`-gated candidate is silently invisible to the not_before gate
on that path — named, counted and escalated exactly as BL-1468 was

**Failing command**: N/A — a wiring gap, not a failing test. Verified by
direct call, `bb` REPL against the live source:

```
(load-file "swarmforge/scripts/chase_sweep_lib.bb")
(load-file "swarmforge/scripts/promotion_gates_lib.bb")
(def content "id: BL-9999\nstatus: todo\nhuman_approval: approved\nnot_before: 2099-01-01\n")
(def candidates [{:file "x.yaml" :content content}])
(def ctx {:active-count 0 :max-depth 5 :active-epics nil :done-ids #{}})
(chase-sweep-lib/nudge-eligible-candidates candidates ctx)
;; => [{:file "x.yaml" :content "...not_before: 2099-01-01\n"}]   -- WRONG: still eligible
(chase-sweep-lib/nudge-eligible-candidates candidates (assoc ctx :today "2026-09-07"))
;; => []   -- correct, once :today is threaded
```

**Commit tested**: `ec344c16e2` (this hardening worktree's tip, architect's
`fdf850f2f3` merged in — the coder's own `48aeb5c5e5`).

**First error excerpt**: N/A (see the REPL transcript above — the defect
is an omission, not an exception).

**Failure class**: `wiring-gap` — the same class Article 4.4 / the
hardener's own standing lesson names ("A default-arg signature change
hides unwired call sites behind a green suite", BL-900): `evaluate`'s new
`:today` argument defaults to `nil` when a caller's context map omits it,
`not-before-refusal` then has `today-date` come back `nil` from
`parse-iso-date`, and `(and today-date ...)` short-circuits to no
refusal — every existing test and the whole suite stays green, because
nothing throws and no existing fixture supplies a `not_before`-bearing
candidate to this path.

**Expected vs observed**: Expected — every promotion-adjacent decision
that consults the shared `promotion-gates-lib/evaluate` chain treats a
future `not_before` exactly as `evaluate` itself does (this is the design
BL-963's own docstring states outright: "a candidate the chain refuses
for any reason … is invisible to every one of [naming, counting toward
fire, and escalation state] … inherited for free through the chain").
Observed — `swarmforge/scripts/handoffd.bb`'s `open-slot-nudge-sweep!`
(line ~2077) builds its `evaluate-ctx` for
`chase-sweep-lib/nudge-eligible-candidates` with `:active-count
:max-depth :active-epics :done-ids` only, no `:today`. `not_before` is
the FIRST gate that needs a piece of caller-supplied evaluation context
the pre-existing gates never did (every other gate's inputs come from
`content` itself or ticket state, never wall-clock context), so this is
the first time "inherited for free" silently breaks: a
`not_before`-gated candidate is treated by the nudge sweep as fully
eligible — named as the top open-slot candidate, counted toward the
nudge's fire decision, and accruing BL-798 escalation state — while the
real promotion path (`promote_and_route_next.sh` → the CLI, which DOES
resolve and thread `:today`) correctly refuses it.

**Why this matters for this exact ticket**: this is not merely inherited
debt — it reopens a live version of the BL-1468 incident this ticket
exists to close. BL-1468 was promoted by "the batch promotion after an
approval sweep" (this ticket's own `description`); the open-slot nudge is
the human-facing signal that drives exactly that kind of sweep/approval
action. A `not_before`-gated ticket, un-gated on this path, gets named
and escalated to a human as ready, inviting the same premature approval
→ promotion sequence BL-1468 lived through, and BL-963's own existing
property test (`bl963_nudge_gate_chain_property_runner.bb`, Invariant 1)
would have caught this immediately had its fixtures ever drawn a
`not_before` candidate — they don't, because the invariant predates this
gate.

## Remediation (direction, not mandate)

Thread `:today` (the CLI's own `today-utc` pattern —
`(str (java.time.LocalDate/now java.time.ZoneOffset/UTC))`, or an
equivalent already resolved once per sweep tick) into the `evaluate-ctx`
map `handoffd.bb`'s `open-slot-nudge-sweep!` builds before calling
`chase-sweep-lib/nudge-eligible-candidates`, mirroring the CLI's own "one
resolve per call, threaded through every `evaluate` site" discipline
(never re-resolved inside `chase_sweep_lib.bb`'s pure functions, per
BL-1390's no-real-clock-in-any-test posture already extended to the
library layer by this same ticket). Extend
`bl963_nudge_gate_chain_property_runner.bb` (or a new BL-1469-scoped
fixture) with a `not_before`-in-the-future candidate drawn at the top
rank, asserting it is excluded from `nudge-eligible-candidates`'s result,
never named, and never accrues escalation state — the same three-surface
shape Invariant 1 already asserts for every other gate.

Blamed role: **coder** (the ticket's own "How" direction named the three
CLI call sites and `promote_and_route_next.sh` explicitly but never
`chase_sweep_lib.bb`/`handoffd.bb`'s nudge sweep, and the coder's own
evidence claims "verified non-vacuous by hand" without this path; cleaner
and architect's own NONE passes also missed it — Article 4.4 places the
fix with the coder as the originating implementer of the new `:today`
argument).
