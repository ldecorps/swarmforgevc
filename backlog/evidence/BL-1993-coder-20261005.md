## Code review: `swarmforge/scripts/local_model_tool_call_shim.py`

Read the full diff of `418b0a4ab3` against its parent.

- `BAD_TOOL_CALL_RETRIES = 2` — module constant, matches the ticket's
  "up to `BAD_TOOL_CALL_RETRIES` = 2 retries".
- `is_bad_tool_call(status, payload)`:
  - `status < 500` → `False` immediately, so 2xx/3xx/4xx are never retried,
    even if their body happens to contain the phrase.
  - otherwise the body is stringified (`payload` if already a `str`, else
    `json.dumps(payload)`) and matched for the exact phrase
    `"invalid tool call arguments"` — the one llama-server emits for an
    unparseable tool call. No other error text matches, so every other
    error passes through unchanged. Matches the description's "a 5xx whose
    body says 'invalid tool call arguments', nothing else".
- `_complete`: after the first upstream call,
  `while is_bad_tool_call(status, payload) and retries < BAD_TOOL_CALL_RETRIES`
  re-sends the *same* `upstream_request` and counts `retries`. The loop
  exits after at most 2 retries (1 + 2 = 3 upstream calls total) and then
  falls through to the normal path: a 200 gets rewritten/nudged as before;
  a non-200 (including a persistent 500) is returned to the client
  unchanged. Matches "up to `BAD_TOOL_CALL_RETRIES` = 2 retries of the same
  request in `_complete`".
- The chat log line gains `bad_call_retries=N` only when `retries` is
  non-zero (`+ (f" bad_call_retries={retries}" if retries else "")`), so
  ordinary requests' log lines are byte-identical to before. Matches "the
  chat log line gains `bad_call_retries=N`".
- Nothing else in the file was touched by the hotfix (23 insertions, 0
  deletions in the shim).

## Invariant check

Declared invariant: "The shim retries only an upstream failure caused by a
tool call llama-server could not parse, at most `BAD_TOOL_CALL_RETRIES`
times, and passes every other error through unchanged."

- "only ... could not parse": `is_bad_tool_call` matches one exact phrase
  on one exact status class (5xx) — verified in code and pinned by
  `test_only_a_parse_failure_counts`.
- "at most `BAD_TOOL_CALL_RETRIES` times": the `while` loop's
  `retries < BAD_TOOL_CALL_RETRIES` bound — verified in code and pinned by
  `test_a_bad_tool_call_that_persists_still_returns_the_error` asserting
  exactly `1 + BAD_TOOL_CALL_RETRIES` upstream calls.
- "passes every other error through unchanged": the loop condition is false
  for every non-matching status/body, so the first response is returned as
  is — verified in code and pinned by the same two tests (the 500 that
  persists is returned; the 200 path is untouched).

The invariant is executable and is covered by the hotfix's own unit tests
in the same commit; no separate property test is required.
