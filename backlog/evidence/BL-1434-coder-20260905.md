# BL-1434 — coder pass, 2026-09-05

## What was wanted

`extension/test/hostActivityFeed.property.test.js` (BL-833) was a bare
node script - forty trials over a mulberry32 PRNG, `node:assert` checks,
`process.exit(1)` on failure, no `test(`/`it(`/`describe(` at all. Under
`vitest.properties.config.mjs` this collects with no suite found, so the
property has been red since it was allowlisted 2026-08-27 and its
assertions have never run under the suite. The standing-red register
attributed the row to BL-1206 (a mis-attribution the architect caught);
BL-1206 has since landed (`backlog/done/M8/BL-1206-...yaml`) without
touching this file, so the row would read unowned - the architect's
finding this ticket exists to close.

## What landed

- **`extension/test/hostActivityFeed.property.test.js`**: the forty
  trials are now one `test(...)` block (vitest `globals: true`, no
  import needed, matching every sibling property file). Each of the
  original checks (active status, bound respected, no invented line, the
  suffix matches emitted, quiet after end) is a `node:assert/strict`
  assertion inside the test body - a failure is now a red vitest run, not
  a `process.exit` the runner never sees.
- Same file, **`installInjectedHookIfRequested`**: gated behind
  `process.env.BL1434_INJECT_INVENTED_LINE === '1'` (unset in every
  ordinary run), installs an append hook via the module's own
  pre-existing `__setHostActivityAppendHookForTests` test seam that
  appends one extra line nobody recorded - used only by acceptance
  scenario 03, never active in the normal pass. `__resetHostActivityFeedForTests()`
  clears any hook, so it is (re-)installed after every reset inside the
  trial loop.
- **`backlog/standing-reds.tsv`** / **`swarmforge/scripts/property_suite_standing_allowlist.tsv`**:
  the file's row removed from both, in this same commit (BL-1428's rule -
  a land that turns the test green removes its rows, no row survives).
- **`specs/pipeline/steps/bl1434HostActivityFeedPropertyRegistersSteps.js`**
  (new): drives the real file through the real properties config via
  `npx vitest run ... --reporter=json`, parsing the JSON report rather
  than grepping for `test(` (per the ticket's own direction) - scenario 01
  reads `numTotalTests`, scenario 02 reads `numFailedTests`, scenario 03
  reads the actual `failureMessages` for the "invented line" text (via the
  env-var injection above), scenario 04 reads the two TSVs directly.

## Regression found and fixed (collateral: BL-1175's own property-guard test)

The pre-commit `check_property_suite_drift.sh` gate refused this commit:
`test/bl1175PropertySuiteStandingRedsInvariants.property.test.js` failed
alone. That file's invariant 1 asserted the allowlist inventory is always
non-empty (`inventory.length > 0`) - true until BL-1434 removed the LAST
remaining row, legitimately emptying it (every prior row had already been
fixed or reassigned per the file's own comment history: BL-1428 25->20,
BL-1430 ->18, ..., BL-1434 ->0). Invariant 2 also read
`readInventory()[0].file` to borrow a real allowlisted filename for its
own guard-script exercise, which now throws on an empty array.

Fixed in `extension/test/bl1175PropertySuiteStandingRedsInvariants.property.test.js`
(not `extension/src`, so invariant 3 is unaffected):
- Invariant 1: dropped the non-empty requirement - the structural
  per-row checks (still enforced over however many rows remain) were
  always the real invariant per the file's own BL-1430 comment; zero rows
  is a valid, and the best possible, outcome.
- Invariant 2: since the real `check_property_suite_drift.sh` resolves
  its allowlist TSV path relative to its OWN script directory (never an
  env var or argument), it can no longer borrow a real filename from the
  now-empty live allowlist. Added `mkIsolatedGuard()`: copies the guard
  script and its three sourced libs into a temp directory alongside a
  SYNTHETIC allowlist row, and runs that isolated copy instead - the same
  code path, but never reading or touching the live project's own
  allowlist file (BL-1390's "never mutate the live checkout" lesson,
  applied to a config file rather than a git operation).

Verified: `bl1175PropertySuiteStandingRedsInvariants.property.test.js`
3/3 pass solo; full `npm run test:properties` exit code 0 (all files,
~280s).
