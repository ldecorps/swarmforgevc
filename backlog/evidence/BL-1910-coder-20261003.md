## Change
- `extension/scripts/testDurationRecorderLib.js` (the lib every sandbox copies beside the
  recorder, so no new file is needed in bl1761's fixture or a Stryker sandbox):
  - `groupRunExitCode` and `groupRunFailure` are pure.
  - The process-group runner runs when the lib is invoked with `--run-in-own-group <timeoutMs>
    <graceMs> <cmd> ...`. It spawns `detached` (its own session and process group). On timeout
    it TERMs the whole group (`kill(-pgid)`) and KILLs it after the grace.
  - However the leader ends, it returns only once `kill(-pgid, 0)` says the group is empty
    (natural exit within the grace, then TERM, then KILL, bounded).
  - Exits: 124 on timeout, the leader's own code otherwise, 125 for a signal it did not send.
  - Plain Node, no setsid binary and no GNU timeout flags, so it works on macOS bash 3.2 hosts.
- `extension/scripts/recordTestDuration.js` `confirmPoleAlone(file, { timeoutMs })`:
  - It runs vitest through the runner via `spawnSync(process.execPath, [lib, ...])`.
  - `timeoutMs` is the seam; the default is still three per-file budgets.
  - A timeout returns `{failed: 'confirmation timed out after <ms>ms; its process group was
    killed'}`. The `{ms}`/`{failed}` contract and the guard's single retry are unchanged.
  - An outer `spawnSync` bound only catches a hung runner.
- Handler `specs/pipeline/steps/bl1910ConfirmationLeavesNoProcessSteps.js`:
  - It drives the real `confirmPoleAlone` in-process, with the fixture test in a tracked mkdtemp
    outside `extension/test/`.
  - The scenario sets a unique marker in this process's environment for the length of the call
    only. Every process the confirmation starts inherits it, and none may carry it when the call
    returns (`/proc/*/environ`, or `ps eww` on macOS).

## Invariant (BL-654, coder first authorship)
`extension/test/bl1910ConfirmationLeavesNoProcess.property.test.js` (`npm run test:properties`
only, Linux):
- **What each draw does.** It builds a process tree under the runner, as confirmPoleAlone starts
  it. The leader exits with a code, hangs past the timeout, or kills itself. It has up to 3
  children, which may ignore TERM, may start a grandchild, and may exit at once (orphaning the
  grandchild).
- **Assertions.** No marked process is alive when the runner returns, and the exit code matches.
  Two closing calls of the REAL `confirmPoleAlone` (timing out, and finishing) assert the same.
- **Reach.** Every leader outcome, a TERM-ignoring child, and an orphaned grandchild.
- **Stated limit.** A descendant that calls `setsid()` leaves the group. Vitest's pool forks
  plain children, so no process a confirmation starts does that.
- **Non-vacuous.** With `signalGroup` addressing the leader's pid instead of `-pgid`, and the
  drain skipped, it fails with "left alive after the runner returned", and so do the two
  runner unit tests and feature scenario 01 ("processes marked ... outlived the confirmation").
  Restored, and the leftovers from those runs (mine) killed.
