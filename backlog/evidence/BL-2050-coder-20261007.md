# BL-2050 — coder evidence (2026-10-07)

`forward-completion-decision` (`forward_evidence_lib.bb`) takes two new
keys, `qa-stage?` and `committed?`, and returns a new `:refuse-committed`
when a non-QA-stage role has committed for the parcel's ticket since
dequeue with no forward yet evidenced - checked BEFORE the reason clause,
so a stated `--no-op` reason can no longer read as cover for finished,
unforwarded work. A caller that omits the two new keys (the batch path)
gets exactly today's answers, proven by a dedicated no-key sweep below.

`forward-gate!` (`done_with_current_task.bb`) now computes `committed?`
via a new `newest-sha-naming-ticket-since` (the existing
`git-log-names-ticket-since?` refactored to return the SHA instead of a
bare boolean, so both readers share one git-log invocation rather than
drifting into two) and `qa-stage?` via the existing
`forward-evidence-lib/qa-stage?`, passes both through, and on
`:refuse-committed` fails with `NOT_A_NO_OP: <ticket> has commit <sha>
since this parcel was queued` / `Send a git_handoff for <ticket> naming
<sha>.` - never mentioning `--no-op`.

## Invariant (BL-654)

"A role other than QA never completes a forwarding git_handoff with a
reason once it has committed for that ticket since the parcel was queued,
unless a git_handoff naming the ticket was queued." — **coder-authored
property test**, new file
`swarmforge/scripts/test/bl2050_forward_gate_committed_property_runner.bb`.
An exhaustive 128-state sweep (every `{forwarding? master-resident?
evidenced? qa-note-evidenced? qa-stage? committed? reason}` combination)
plus a 32-state sweep with `committed?`/`qa-stage?` omitted entirely
(the batch-path shape), both checked against an oracle derived fresh from
the invariant's own English text (a priority-ordered flag list resolved by
`some`, not the implementation's `cond`) rather than copied from the
source. Reach is complete by construction (every state enumerated, not
sampled).

**Non-vacuity proven by hand before this commit**: temporarily replaced
the new clause's condition with `false` in `forward_evidence_lib.bb`,
re-ran the property runner — 4 states mismatched exactly where expected
(every `committed?=true, qa-stage?=false, evidenced?=false` combination
across `qa-note-evidenced?`/`reason`) — then restored the real
implementation from a backup and re-ran clean. The working tree carries
only the restored, correct file; the broken intermediate was never
committed.

Real-fixture, through-the-real-script coverage of the same invariant (the
actual `done_with_current.sh` refusing/completing) lives in the acceptance
feature itself, driven by the new step handler — the property runner above
is the pure decision's own proof, not a second copy of that IO.
