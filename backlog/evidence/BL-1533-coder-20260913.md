# BL-1533 coder evidence — 2026-09-13

## What changed

- `extension/test/helpers/signedTrendSeries.js` (new): `signedSeriesArb(sign)`
  — a fast-check arbitrary yielding a trendable series (2..8 points) whose
  final two points give `computeTrend` the requested direction (`up`,
  `down`, or `flat`) on every draw, since `computeTrend` derives direction
  from only the last two points. Earlier points are drawn freely and never
  affect direction. Exported so the property test's constructed sign runs
  and the BL-1533 step handler's direct sampling (scenario 02) draw from
  the same generator.
- `extension/test/bl604TrendAnalysisInvariants.property.test.js`:
  invariant 1's existing length-bucket loop is untouched. Added a second
  loop, once per sign in `['up', 'down']`, running `SIGN_FLOOR` (10) draws
  of `signedSeriesArb(sign)` each — each draw is guaranteed by construction
  to land in `coverage.up` / `coverage.down`, so the existing
  `assertReachFloor(coverage, ['up', 'down'], SIGN_FLOOR, ...)` call is met
  every run rather than merely usually met. Each draw also re-asserts the
  invariant's own claim (a single-series `buildTrendAnalysis` +
  `renderTrendAnalysisSection` pass renders exactly one bullet whose
  parsed direction/delta/current/prior match `computeTrend` directly).
  Prints `BL-1533 invariant 1 reach: {...}` before the floor assertions so
  the acceptance run can read the counts from the run itself.
- `specs/pipeline/steps/bl1533SignedSeriesReachSteps.js` (new): scenarios
  01/03 drive the real property file under the real properties config
  (spawnSync from `extension/`, reading its own printed reach line).
  Scenario 02 drives the real generator and the real compiled
  `computeTrend` directly — the generator itself is sampled in a child
  `node` process run with `cwd: extension/` (fast-check and
  `test/helpers/signedTrendSeries.js` resolve only from
  `extension/node_modules`/`extension/test`, not from this file's own
  location under `specs/pipeline/steps/`), never a reimplementation of
  either.

`extension/src/metrics/trend.ts` and `trendAnalysis.ts`,
`property_suite_standing_allowlist.tsv`, and BL-604's own feature/handler
are untouched (confirmed via `git status --short`).
