## Two reproduction techniques tried and rejected before the one that worked

1. First draft: `sleep 300 & Z_PID=$!; kill -9 "$Z_PID"` inside a `$(...)`
   finishing in ~0.2s, then poll `ps -o stat=` for up to 1s. Never once
   observed a zombie in this environment — bash itself services a
   just-killed background child's job-control status opportunistically
   between commands, even with no explicit `wait`, apparently often
   before the next `ps` poll fires.
2. Second draft: a dedicated `bash -c '...; kill -9 "$c"; sleep 2'`
   helper process as the killed pid's own direct parent, blocked in a
   plain `sleep` syscall for 2s. Still never observed a zombie — the
   same opportunistic reaping appears to apply even to a shell that is
   nominally "blocked" in `sleep`.
3. What worked: a `python3 -c` helper. Python installs no implicit
   job-control reaping at all; a forked, killed child stays a zombie
   until the parent explicitly calls `os.waitpid()` or exits — fully
   deterministic, no polling/timing luck required. Both
   `test_finish_shift_lib.sh`'s case 09 and the acceptance handler use
   this same technique.

## A real bug found and fixed during (2): `set -e` + `pipefail` on a
   legitimately-failing external command

`stat="$(ps -o stat= -p "$Z_PID" 2>/dev/null | tr -d '[:space:]')"` — once
the target pid was FULLY gone (not a zombie, genuinely reaped), `ps`
itself exits non-zero. With `pipefail`, the pipeline's own exit status is
`ps`'s (the last command with a NON-zero exit takes precedence over a
later successful one, not the reverse - confirmed by tracing this exact
failure with `bash -x`), and under `set -e` a bare `var=$(...)` assignment
with a non-zero result aborts the whole script. This silently killed the
test after case 08 with no test 09 output at all until traced. Fixed with
`|| true` on the pipeline (test file) and on `_finish_shift_pid_is_zombie`'s
own `ps` call (production file — the SAME hazard is real there too: a pid
that fully exits between `_finish_shift_pidfile_alive`'s `kill -0` check
and this one is a legitimate race under the real `./finish-shift`'s own
active `set -euo pipefail`, and must never crash the whole bedtime run).
