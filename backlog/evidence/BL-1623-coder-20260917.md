# BL-1623 — coder evidence, 2026-09-17

## What changed

Seven property test files each carried their own blind `for (const entry
of fs.readdirSync(os.tmpdir())) { if (entry.startsWith(PREFIX)) rmSync(...)
}` module-load sweep, removing every entry sharing its prefix regardless
of who made it. Two live instances of the same file (a concurrent lane, a
guard re-run, a solo re-run) meant the later one's sweep deleted the
earlier one's live fixtures mid-test - QA's BL-1609 pass hit this exactly
on `bl1309LandDecideEntanglementInvariants`: its own just-written,
just-committed sibling ticket file read back as "no backlog ticket file
found" because a concurrent instance's sweep had removed the whole root.

Fix (BL-1287's fixture-tunnel rule, applied to temp roots):
- `extension/test/helpers/tmpDir.js` gains `sweepStaleTmpDirs({ prefix,
  dir, isPidAlive })`: removes an entry under `dir` (default
  `os.tmpdir()`) matching `<prefix><pid>-...` only when `pid` is this
  process's own (before it has written) or not alive - never a live
  peer's. The zombie-aware liveness probe (`defaultIsPidAlive`/
  `isZombiePid`, BL-984's original) is LIFTED here from
  `propertyLaneFixtureRunner.js`, which now imports it from tmpDir.js
  instead of carrying its own copy (the ticket's own "never a second copy
  of the zombie probe").
- Each of the seven files: roots now build as
  `` `${FIXTURE_PREFIX}${process.pid}-...` ``; the local blind sweep
  function's body becomes one line, `sweepStaleTmpDirs({ prefix:
  FIXTURE_PREFIX })`; nothing else in any of the seven changes (no
  assertion touched). `bl1343ReplayNeverDropsOwnPathInvariants` builds its
  roots through `checkoutSeededRepo(prefix)` (a `sharedRepoFixture.js`
  wrapper over `mkTmpDir`) rather than calling `mkTmpDir` directly - same
  migration, applied at its own call site.
- `extension/test/helpers/blindTmpDirSweepFinder.js`: the one place "does
  this property file still blindly list the whole temp dir" is decided -
  shared by the unit-lane guard and the acceptance step handler, per
  BL-1422/BL-233's own "one decision, one place" precedent.
- `extension/test/blindTmpDirSweepGuard.test.js` (unit lane, `npm test`,
  no call site - discovered by the `*.test.js` glob): names any
  `*.property.test.js` under `extension/test/` that still calls
  `readdirSync(os.tmpdir())` directly; on this tree, names none, and
  confirms the seven named files are all present (the census pin).

## Declared invariants (BL-654)

Both encoded directly against the real `sweepStaleTmpDirs` in
`extension/test/bl1623ScopedTmpDirSweepInvariants.property.test.js`
(`isPidAlive` injected - a fake pid never collides with a real one the
host might reuse mid-run, and the property is about the helper's own
removal decision given a liveness answer, not the OS pid table):

1. "A fixture sweep never removes a temp root a live run owns... " - for
   generated populations mixing this-process-own/alive/dead/no-pid-shape
   roots (0-12 entries), the removed set matches exactly: own and dead are
   removed, alive and no-pid-shape survive. Generator-reach asserted for
   all four shapes.
2. "A run that died without trapping anything still has its roots cleared
   by the next run's sweep... " - encoded as the AGGREGATE claim distinct
   from invariant 1's per-root decision: for 0-10 accumulated dead-owner
   roots (simulating that many past crashed runs, never swept between
   them), ONE sweep call clears ALL of them in a single pass - never
   partial, never needing N calls for N generations. Reach forced via a
   weighted arbitrary (0 and >=5 each guaranteed weight) after an
   unweighted `fc.integer(0,10)` missed drawing 0 in an early run -
   BL-654's own "an asserted reachability floor, never a hoped-for one."

Non-vacuousness: a `brokenAlwaysRemove` helper (ignores pid entirely, the
exact pre-fix bug class) is shown to wrongly remove a live peer's root;
the real helper is then shown to leave it alone. Additionally verified by
hand before finalizing: patching the real `sweepStaleTmpDirs` to `if
(true)` (always remove) failed invariant 1 and the dedicated
non-vacuousness test (2/3 failing) while invariant 2 still passed
(correctly - "remove everything" trivially satisfies "clear every dead
one"); restored, 3/3 green again.
