## Invariants — verified directly in the code
1. **Scope is the ONE shared classifier, with a path-component boundary.**
   Read `process_table_lib.bb:148-188` end to end. The new
   `path-boundary-after?` helper requires the character following a path
   match to be a real boundary (`/`, whitespace, a quote, or end-of-string);
   `cmd-names-path?` applies it to every occurrence in the command line
   (not just the first), and the cwd arm accepts equality or a boundary
   immediately after the prefix. This is exactly the amendment's literal
   wording, applied to both arms. `worktree_stray_lib.bb:54` delegates to
   `process-table-lib/project-scoped-process?` with `[root]` as the sole
   scope path — since callers always pass a single absolute worktree root
   (not a relative fragment), a START-boundary collision (an unrelated path
   coincidentally ending in the same suffix) is not realistically
   exploitable here; the boundary fix correctly targets the actual observed
   hazard (a shorter root as a literal prefix of a longer sibling root).
2. **Reaping is by process group, never by pid.** `check_worktree_strays.bb`'s
   `reap!` computes `own-pgid` (this process's own group) and explicitly
   separates it from `others` before sending `kill -- -<pgid>` — a stray
   sharing the caller's own group is reported, never signalled, closing the
   "kill -- -<pgid> killed the caller" defect the coder's own evidence
   describes finding and fixing.
3. **A stray is a refusal, not a warning.** Confirmed in the e2e: "a stray
   makes the check FAIL - a refusal, not a warning" passes, and the CLI's
   own exit-code contract matches.
