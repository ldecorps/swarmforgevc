# BL-1704 — coder pass, 2026-09-26 (QA bounce D1 fix)

## What was wrong

Scenario 03 example 1 ("is no longer running") killed only the stand-in
`ollama serve`-titled process, leaving its `ollama runner`-titled child
alive and orphaned. That child then reads to the LIVE swarm's own real
ghost janitor (BL-1705/BL-1726, running on this host regardless of any
test) exactly like a genuinely leaked runner - no matching live server
nearby - and the janitor reaped it within seconds (QA evidence
`.swarmforge/daemon/orphan-janitor-audit.log:
reaped-ollama-ghost pid=15580 cmd=ollama runner age_ms=5164`), collapsing
the scenario's own "no process was signalled" assertion by a real
collision, not by anything the stop-path code did.

## What changed

- `extension/test/helpers/ollamaStopPathsFixture.js`: new
  `killServerAndRunner()` kills the stand-in server AND its runner child
  together - no server-less "ollama runner" is ever left alive for the
  real janitor to find. Corrected the `spawnServerWithRunnerChild` comment
  that had misattributed this exact failure mode to a "WSL2 kernel/session
  reparenting quirk" (per QA's own remediation pointer).
- `specs/pipeline/steps/bl1704OllamaStopPathsSteps.js`: scenario 03
  example 1 now calls `killServerAndRunner()` and asserts "no process was
  signalled" against a fresh untitled process
  (`fixture.startUnrelatedProcess()`) instead of the (now also
  deliberately dead) runner. Example 2 ("now belongs to...") is unchanged
  - it never touches the runner, so the runner-liveness check still
  applies there.
