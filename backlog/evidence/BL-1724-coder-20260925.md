## What was built (already committed as 6115b50174, this session forwards it)

`extension/test/bl1652HandoffdRespawnReadingsWiring.test.js`: the file's
seven cases used to each call `loadHandoffdAndRun`, starting a fresh `bb`

that one `bb` run and stopped after it in `afterAll` — unchanged.

## Declared invariant — no property test, stated reason

Ticket invariant: "One run of the file starts exactly one bb process that
loads handoffd.bb, whatever the number of cases."

This quantifies over the TEST FILE'S OWN process structure, not a pure
testable module's input/output space — there is no generator input to
vary; the call count is fixed by construction (one `execFileSync('bb', ...)`
call site, in `runAllCases`, invoked once from `beforeAll`, regardless of
how many cases are passed to it). A property test needs an input space to
explore; "how many bb processes get spawned" has none here — it is a
structural fact, not a behavior over generated values. Per the Invariants
section's exception (quantifies over process rather than a pure testable
module), this is covered by:
- construction: single call site, single call, verified by
  `grep -c "execFileSync('bb'" test/bl1652HandoffdRespawnReadingsWiring.test.js`
  → 1 (the ticket's own QA procedure step 3).
- the timing evidence itself: 1.02-1.6s across runs vs. 8-9.6s before —
  consistent with one process, not seven, and would regress visibly (back
  toward the old per-case duration) if a case reintroduced its own `bb`
  call.

## A real regression caught by the property lane, fixed this session

`npm run test:properties` (run once before forwarding, per role prompt)
failed: `test/bl1280MkdtempMigrationInvariants.property.test.js` > invariant
1 flagged the three fixture roots this file's `beforeAll` now creates
directly (`root`, `laneWorktree`, `quietWorktree` — lines 86/95/98) as
allocated via `mkTmpDir`, whose sweep is a per-TEST `afterEach` (tmpDir.js).
Every one of the file's seven `test`s reads results derived from those
roots, so a root swept after the first test left the rest referencing a
removed directory in principle (masked in a solo run since the sweep only
matters once other tests genuinely re-touch the filesystem, but flagged
correctly as a structural hazard: the pre-BL-1724 file had no beforeAll
fixture at all, only per-case scripts, so this hazard did not exist before
BL-1724 moved them there — a genuine BL-1724 regression, not pre-existing).

Fix: switched those three call sites to `mkSharedTmpDir` (the beforeAll
sibling, swept once per FILE by the global `afterAll` in
`tmpDirSetup.js`) — the established pattern (`bl1279FrontDeskFixtureClosure.property.test.js`
already uses it this way). The `scriptFile` mkTmpDir call inside
`runAllCases` (not lexically inside `beforeAll`, consumed synchronously,
never referenced by any `test`) is untouched — correctly scoped as-is.
