## Scope note: the shell side's glob order vs the bb side's explicit sort

`local_model_repeat_guard.bb`'s `in-process-handoff-name` explicitly
`sort`s the remaining (non-sidecar) names before taking the first;
`swarmforge.sh`'s new `__bl2055_held_name` iterates the `in_process`
glob in filesystem order with no sort and returns on the first
non-sidecar match. These would disagree only if `in_process` ever held
TWO OR MORE real (non-sidecar) handoff files at once for the SAME
task-mode role — a shape neither the ticket's invariants, the coder's
property test generator (`hasHeld` is a boolean: zero or exactly one
real handoff, never two), nor this pass's own check exercises, because
it is not a reachable state for a task-mode role's `in_process` (BL-1871:
one parcel line, one file). Recorded as an observation, not a defect —
chasing an unreachable shape would be scope the ticket does not ask for.
