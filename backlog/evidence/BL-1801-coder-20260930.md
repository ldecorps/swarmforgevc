## What changed

- `swarmforge/scripts/local_model_window_gate_lib.bb` (new, pure):
  `estimate-tokens` (ceil((composed-chars + overhead-chars) / 3)) and
  `window-outcome` ({:window :estimate-tokens :override? :role :model} ->
  {:decision :proceed|:warn|:refuse :message}) - refuse only when the
  window is known and the estimate exceeds it and no override is set;
  warn when the window is unknown, or known and the estimate is over
  half of it, or an override let an over-window seat through; proceed
  otherwise.
- `swarmforge/scripts/local_model_window_gate_cli.bb` (new): gathers the
  facts - `served-window` POSTs `/api/show` on the running Ollama's
  NATIVE endpoint (strips the `/v1` the seat's own launch uses) and
  parses the `parameters` text blob's `num_ctx` line; falls back to
  `--context-length` when Ollama reports none, else the window is
  unknown. Prints `WARN: <message>` (exit 0) or `REFUSE: <message>`
  (exit 1); silent on proceed.
- `swarmforge/scripts/swarmforge.sh`: `check_local_model_seat_windows`,
  called once right after `ensure_ollama_ancillary_for_launch` and
  before `check_primacy` (inside the same `ZSH_EVAL_CONTEXT ==
  "toplevel"` guard every other launch-sequence call already sits in -
  confirmed by reading it: a test that only `source`s this file, as
  every existing fixture harness in this tree already does, never runs
  this call unless it invokes the function directly, exactly like
  `write_role_launch_script`). Loops `AGENTS[]`; for each `local-model`
  seat, extracts `--model` from `EXTRA_CLI_ARGS[i]`, composes the seat's
  prompt via the real `prompt_engine_cli.bb compose` (identical call
  shape to `write_agent_instruction_file`), and calls the gate CLI. A
  pack with no local-model seat composes nothing and calls the CLI
  never.

## A note on the acceptance's own design choice

`prompt_engine_lib.bb`'s `repo-root` is derived from that file's own
on-disk location and has no override seam (verified: no `--target` flag,
no env var) - a throwaway fixture root can never make the REAL
`prompt_engine_cli.bb compose` produce an exact character count without
editing this repo's own `swarmforge/roles/local-model/coder.note`, which
no test may do. Scenarios 01-04 (about the DECISION over a stated
composed-character count) therefore drive `local_model_window_gate_cli.bb`
directly against a synthetic fixture prompt file of the exact stated
size - the ticket's own scenario note ("fixture prompt files") already
anticipates this. Scenario 05 (about the LOOP over `AGENTS[]` finding no
local-model seat) drives the real `check_local_model_seat_windows`
function instead, sourced from the real `swarmforge.sh` exactly as
BL-1793's own harness does, since that is the one behaviour the CLI
alone cannot demonstrate.

Verification above): invariant 1 (never launches past a KNOWN window
without the override, and says so) is scenarios 01/02/04; invariant 2

finite set of named branches, not a space a generator would add
coverage over.
