# BL-1795 — coder pass, 2026-09-29

## What landed

`land_step_lib.bb`'s replay loop (`replay!`) checks, for each stray
candidate BEFORE the cherry-pick is even attempted: is this stray commit
an ancestor of any commit its own closed owner's `abandoned_commits:`
names? If so, it is recorded superseded — `{:sha :sibling :paths
:superseded? true :reason "ancestor-of-owner-abandoned"}` — and the pick
is never attempted at all.

The check runs BEFORE the pick (not inside `stray-superseded-verdict`,
which only ever sees a real CONFLICT) because a removed draft applies
CLEAN — no conflict for the existing grounds to ever catch, and it would
silently re-add lines the owner's own later commit dropped.

New pure function `ancestor-of-owner-abandoned?` (root, origin-main, sha,
owner): reads `ticket-abandoned-commits` (never a second reader) and
checks `git merge-base --is-ancestor sha <entry>` for each recorded
entry. An entry the ancestry check cannot resolve (ambiguous or unknown
10-hex prefix) answers non-zero and is simply skipped — fail-closed to
today's handling, never counted as a match.

`land_step_cli.bb`'s existing `LAND_STRAY_SUPERSEDED <sha> <paths>
<reason>` line already reads `:reason` generically from any
`:superseded? true` stray-landed entry — no CLI change was needed.

## Declared invariants (BL-654)

- **Invariant 1** ("A stray is recorded superseded on the owner-land
  ground only when it is an ancestor of a commit that its own closed
  owner's abandoned_commits names; any other closed-owner commit keeps
  today's handling.") — **P1**
  (`bl1795_owner_land_superseded_stray_property_runner.bb`): builds a
  randomized DAG (a 1-4-commit chain of the owner's own work, 1-3 of
  those recorded as abandoned_commits, 0-2 distractor commits on unrelated
  branches naming the same owner) and asserts
  `ancestor-of-owner-abandoned?`'s answer for EVERY candidate matches
  ground truth (`git merge-base --is-ancestor` against each recorded
  entry directly, computed independently). Non-vacuous: broken by
  hardcoding the function to always return `true` — failed on every
  generated case with at least one non-ancestor candidate (a distractor,
  or a chain commit after the recorded abandoned index).
- **Invariant 2** ("The ground never changes what lands: a stray
  superseded this way is never cherry-picked, and the replay branch's
  tree is byte-identical to its tree before the stray was considered.") —
  **P2**, a DIFFERENTIAL property against the REAL `land-plan`: for a
  randomized (rewrites/removes) action, `land-plan` runs TWICE — once
  with the superseded draft present in history (an ancestor of the role
  branch), once with it artificially ABSENT (the role branch starts
  straight from the rewrite/removal, no draft commit anywhere) — and
  asserts the two resulting replay trees are byte-identical. Non-vacuous:
  broken by disabling the new gate (always attempting the pick regardless
  of `ancestor-of-owner-abandoned?`'s answer) — failed on every
  `rewrites?=true` case (the with-draft run escalated instead of
  completing, since the pick now genuinely conflicts and no PRE-EXISTING
  ground independently covers this fixture shape — confirmed by hand: the
  fixture's own "landed copy" commit is deliberately UNTAGGED, so grounds
  (b)/(c) cannot coincidentally supersede it first); `removes?=false`
  cases stayed green (that shape never reaches a conflict at all, with or
  without this ticket's fix, since the draft's own content nets to
  nothing once retracted by itself).

**Reachability**: 40 runs each. P1's generator covers chain lengths 1-4,
0-2 distractors, 1-3 abandoned entries. P2: both `rewrites?` and
`removes?` well exercised (a boolean generator over 40 runs).
