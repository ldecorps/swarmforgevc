  own comment — literal-substring matching, matching the ticket's own grep,
  is what's correct here.)

## Invariant (BL-654)

The ticket's one declared invariant ("every step handler that calls
`mkSocketFixtureRoot(` requires it from `./lib/socketFixtureRoot`") is
encoded as an executable check, but as BL-1575 feature scenario 03 in the
acceptance lane rather than a `*.property.test.js` vitest file. Reason: the
invariant quantifies over the actual, non-generated set of step-handler
files on disk — a fixed structural census, not a property over a generated
input space — so a generative property-test harness has nothing to
generate; the ticket itself specifies this exact check as an acceptance
scenario (already authored by the specifier), and this parcel's step
handler is that scenario's one required implementation. No production
module (extension/src) is touched, so there is no vitest-covered surface
for a `test:properties` file to sit alongside.
