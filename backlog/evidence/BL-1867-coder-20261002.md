# BL-1867 — coder pass, 2026-10-02

## What was wrong (confirmed)

`extension/test/helpers/sharedRepoFixture.js`'s `templateIsHealthy` ran
`git config core.worktree` through `execFileSync`; on the common case (key
unset) git exits 1 and `execFileSync` throws, so the catch returned `false`
("unhealthy") on every call. `seedTemplateOnce` then re-seeded AND zeroed
`seedings` every time, so `seedCount()` always read 1 regardless of how many
templates a process actually created. Separately, each template was removed
only via `mkProcessTmpDir`'s `process.once('exit')`, which a vitest fork
worker recycled/killed by the pool never fires.

## Fix

- `readCoreWorktree`/`templateIsHealthy`: only exit 1 with empty stdout
  (the key simply unset) reads as "no key" (healthy); any other failure
  shape is still unhealthy. Verified manually: 3 checkouts via
  `checkoutSeededRepo` now cost exactly 1 seeding (previously 3, one per
  call, each silently re-seeding).
- `seedTemplateOnce`: no longer zeroes `seedings` on a genuine re-seed, so
  the counter reports the true cumulative count. Verified: 1 checkout, a
  forced-unhealthy template (`git config core.worktree /nonexistent`), then
  another checkout → `seedCount()` reports 2.
- The template's directory name now carries its own creating process's pid
  (`bl1039-seed-template-<pid>-<random>`, via `mkProcessTmpDir`), the one
  shape `tmpDir.js`'s existing `sweepStaleTmpDirs` (BL-971/BL-1385/BL-1390's
  owner-aware sweep) can target.
- New `extension/test/helpers/bl1039TemplateGlobalTeardown.js`, wired as
  `globalSetup` in both `vitest.config.mjs` and
  `vitest.properties.config.mjs`: its returned teardown runs once, in the
  MAIN vitest process, after every worker has finished, and sweeps every
  `bl1039-seed-template-` entry whose owning pid is no longer alive. The
  naming shape it targets (`<prefix><pid>-<random>`) cannot match the
  pre-existing leaked templates (a bare mkdtemp random suffix with no
  embedded pid) — this sweeps only what this fix's own naming convention
  produces, never the ~445k already-leaked ones (out of scope, a one-time
  host cleanup for the human per the ticket's own notes).
