## A finding along the way (not itself a defect - noted for whoever next builds a sandbox fixture)

Building scenario 02, a plain sandbox (symlinking only `node_modules` and
`vitest.config.mjs`, matching BL-1761's own fixture) failed with `Cannot
find module '<sandbox>/test/helpers/tmpDirSetup.js'` before any test in the
file ran. Vite resolves `test.setupFiles`' relative paths against its own
root (`process.cwd()` here), never against the dereferenced REAL location
of a symlinked config file - so `vitest.config.mjs`'s four setup files
must themselves exist under whatever root actually FED it. Symlinking
`test/helpers/` (a whole dir, one entry) into the sandbox fixed it; scoped
here to a manual mkdtemp step, since scenario 02 is not built through
`confirmPoleAlone` (whose OWN spawn happens to reach the identical shape,
proven separately: a plain CLI invocation with `confirmPoleAlone`'s exact
`--dir`/`cwd` args, but WITHOUT this project's own `recordTestDuration.js`
wrapper, hits the identical missing-module failure on BL-1761's own
trivial fixture too - `confirmPoleAlone` never surfaces it because it
reports a measured duration from the report entry regardless of that
entry's pass/fail status, which is correct for ITS purpose - a
suite-duration-pole confirmation, not a correctness check - and out of
this ticket's scope to touch).

No production code changed beyond the two Scope config files
(`stryker.config.json`, the new `vitest.stryker.config.mjs`) and the two
Scope test files.
