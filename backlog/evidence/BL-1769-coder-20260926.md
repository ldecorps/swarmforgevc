## Fix

`failingFilesFromRow` (unit/properties branch) now parses from
`rawOutputByCheckId.get(row.id)` - the check's WHOLE stdout+stderr,
captured by `composeQaGatherReport`'s existing `onRawOutcome` seam (the
same one `parseRegisterOutput` already uses for the register check,
BL-1554 architect bounce D1) - never `row.excerpt`, the last
`EXCERPT_MAX_CHARS` (4000) characters kept for the human-facing report.
No second `runFn` call; the exactly-once-per-check sequencing invariant
is untouched.

`buildRegisterJoin` now tracks, per row, whether `failingFilesFromRow`
named anything. A row that is `ran`, non-zero exit, and unit/properties,
that names nothing, contributes one `{ file: <check id>, join:
'unidentified' }` entry instead of contributing nothing - `file` reused
as a placeholder holding the check id (`'unit'` / `'properties'`), per
the ticket's own "or a `file` placeholder" option. `RegisterJoinKind`
gained `'unidentified'`.
