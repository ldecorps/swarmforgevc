# BL-1413 — coder pass, 2026-09-05

The freshness check's `heartbeat_age_secs` (`daemon_log_freshness_check.sh`)
now reads a daemon's log in text mode (`grep -aE`, `LC_ALL=C`) and falls back
past a torn/unparseable newest line to the next parseable one, so a single
crash-time NUL byte can no longer make five healthy supervisors look six
days stale.

## How this parcel avoids the registry-guard trap

`daemon_log_freshness_registry_guard.sh` (called unconditionally at the top
of the real checker) does two checks: every name in the required registry
has a conf row, AND every real `*_supervisor.bb` script file on disk has a
conf row. The second check is not parameterized by `FRESHNESS_CONF` at all —
it always scans `$SCRIPT_DIR/*_supervisor.bb` against whatever conf is
loaded. A scoped/minimal conf can satisfy the first check but never the
second. This parcel's shell tests and step handlers therefore always use the
SHIPPED `daemon_log_freshness.conf`/`_required.conf` (no `FRESHNESS_CONF`/
`FRESHNESS_REQUIRED` override), giving every daemon this ticket does not
care about a fresh heartbeat (`babysitterd`) or simply no pid file
(every `*_supervisor` row not under test, which BL-784's own skip already
excludes from ever being measured).

## Declared invariants (BL-654)

Both have a coder-authored, non-vacuous property test in this parcel,
each shown to fail against a deliberately broken implementation and then
restored:

- **Invariant 1** (measured age is NOW minus the newest heartbeat line's
  timestamp, whatever bytes the file carries) — broken by reverting
  `grep -aE` to `grep -E`: the property failed with the classic symptom,
  `no-heartbeat-line`/sentinel age instead of the real one, on every run
  whose noise was a NUL byte. Separately broken by disabling the fallback
  walk (checking only the newest matching line): failed specifically on
  every `:torn-after` draw (`unparseable-timestamp` instead of the older
  parseable line's real age). **Reachability floors**: the generator must
  hit all four noise placements (`none`, NUL before, NUL after, a torn line
  forcing the fallback) and both threshold sides at least a few times each;
  40 runs measured 8/11/8/13 across the four noise kinds and 20/20
  fresh/stale.
- **Invariant 2** (never restarts/announces within threshold; an
  unparseable line is skipped, never a false sentinel while a newer
  parseable heartbeat exists) — the SAME two breaks above also fail this
  invariant's assertions (a fresh-but-NUL-truncated log gets falsely
  restarted; a torn-newest log with a fresh fallback line gets falsely
  restarted), proving the two invariants are genuinely coupled through the
  same function rather than independently vacuous.
