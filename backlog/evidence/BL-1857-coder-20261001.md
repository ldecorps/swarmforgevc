# BL-1857 — coder pass, 2026-10-01

## What was built

- `swarmforge/scripts/land_step_lib.bb`:
  - New private predicate `untagged-commit-lands-no-line?` — true when
    every non-blank line a commit `c` adds to `path` is either already in
    `origin-main`'s copy of `path` or absent from the landing commit's own
    copy of `path`. Reuses the existing `commit-line-changes` (first-parent
    added/removed line sets) and `blob-lines` (set of lines a rev holds at
    a path) helpers — no new git-shelling primitive.
  - `path-owner-tickets`'s attribution reduce: a non-merge, non-revert
    commit whose subject names **no** ticket (untagged) AND satisfies the
    predicate above is now left out of the path's attribution entirely —
    neither an owner nor an untagged touch — the same exclusion BL-1472
    already gives a recognized `Revert "..."` commit, reached by content
    instead of by subject (BL-972's rule: a gate decides on evidence, never
    a subject alone). A **tagged** commit is never excluded this way, even
    if its content happens to match — only untagged commits are in scope,
    per the ticket's own invariant.
  - `path-owner-tickets` now also returns `:untagged-commits` (the specific
    commit shas that kept `:any-untagged? true`), and the BL-1830 shared-
    own-path refusal message now names them (`"...and untagged commit(s)
    <sha...> touch it..."`) instead of only the path and the siblings —
    the ticket's "the refusal names which commit kept it untagged" bullet.
  - BL-1830's own invariant (a land never publishes an unlanded sibling's
    line on a shared path) is untouched: the new exclusion only ever
    REMOVES a commit from consideration, never adds one, and never changes
    which lines `shared-own-path-rebuild` keeps once a path proceeds to
    rebuild.
- `swarmforge/scripts/test/land_step_lib_test_runner.bb`: three new BL-1857
  unit cases, one per outline row, built on the same `bl1830-manifest`
  fixture the existing BL-1830/D1 tests already use:
  1. restore to origin/main's content, then a reapply — no refusal, clean
     rebuild excluding the sibling.
  2. a line added then removed again before the landing commit — no
     refusal, clean rebuild excluding the sibling.
  3. a line that survives into the landing copy and origin/main lacks —
     still refuses by name (the exact BL-1830 D1 fixture, re-asserted
     under the BL-1857 label since it is this ticket's own outline row
     too).
- `specs/pipeline/steps/bl1857UntaggedCommitLandsNoLineSteps.js` (new) and
  `specs/pipeline/steps/lib/bl1857UntaggedCommitLandsNoLineCli.bb` (new):
  the acceptance driver, built the same way
  `bl1830SharedOwnPathSteps.js`/`bl1830SharedOwnPathCli.bb` already are —
  every scenario drives the REAL `land_step_cli.bb` over a REAL git
  repository with a REAL origin/main ref, never the pure
  `land_step_lib.bb` functions directly, so the acceptance suite cannot
  disagree with what the CLI QA actually runs. `KNOWN_VALUES` maps the
  outline's three `untagged change` texts to three explicit fixture
  shapes (`restore`, `add-remove`, `add-keep`); `outcome` is asserted by
  exact match against the two outline strings (never a passthrough).

## Invariants (ticket's `invariants:` list, BL-654 coder-first authorship)

1. "An untagged commit is left out of a shared path's attribution only
   when no line it added to that path is in the landing commit's copy and
   absent from origin/main's copy; every other untagged touch still
   refuses by name." Encoded by the acceptance scenario's three outline
   rows (KNOWN_VALUES above), the three new unit cases in
   `land_step_lib_test_runner.bb`, **and** a new coder-authored property
   test: `extension/test/bl1857UntaggedCommitLandsNoLineInvariants.property.test.js`
   (`npm run test:properties`). Three cells by construction — `restore-excluded`
   (an untagged commit that only undoes the landing ticket's own just-added
   lines, adding nothing of its own — predicate holds vacuously),
   `add-remove-excluded` (an untagged add immediately cancelled by a later
   untagged remove — net contribution nothing), `add-keep-refuses` (an
   untagged commit's added line survives into the landing copy and
   origin/main lacks it — still refuses by name, row 3, same construction
   BL-1830's own `untagged-touch-escalates` cell already uses). Generator
   reach asserted via `assertReachFloor`/`runsPerCell`, same helpers
   BL-1830's property test uses. **Non-vacuous, verified by hand**: forced
   `untagged-commit-lands-no-line?` to unconditionally return `false`
   (`(and false (when-let ...))`), reran the property — it failed on the
   first `restore-excluded` case with the expected refusal instead of
   `null`; reverted the break (clean diff afterward, confirmed via `git
   diff` showing no `BREAK-TEST` marker), reran green.
2. "A land never publishes an unlanded sibling's line on a shared path
   (BL-1830's invariant, unchanged)." Verified by rerunning BL-1830's own
   feature (`specs/features/BL-1830-a-land-never-publishes-a-siblings-lines-in-a-shared-own-path.feature`,
   3/3 ok, unchanged), its own unit fixtures (`land_step_lib_test_runner.bb`,
   ALL PASS) and its own property test
   (`bl1830SharedOwnPathLineExclusionInvariants.property.test.js`, green) —
   no assertion in any of the three moved.
