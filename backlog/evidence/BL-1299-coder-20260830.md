## What changed

`swarm_handoff.bb`'s reverse-hop math moved into a new
`swarmforge/scripts/reverse_hop_lib.bb`, and `pack-role-names`,
`last-pack-role?`, `role-propagation` and `reverse-roles` now delegate to it.
There is exactly ONE implementation: the pre-fix tree had the selection
written twice (see "Pre-existing defect found" below), which is how the
defect came to be asserted as correct.

`pipeline-roles` drops a roles.tsv row when it is the coordinator OR when it
is **master-resident**, and master-residency is READ FROM THE TABLE — the
human's 2026-08-30 ruling ("derive master-resident from roles.tsv, not
hardcode"). The derivation is column 2, the worktree NAME, against the pair
of sentinels swarmforge.sh itself treats as "no dedicated worktree":

    # swarmforge.sh parse_config, and again in prepare_worktrees
    if [[ "$worktree" == "none" || "$worktree" == "master" ]]; then
      worktree_path="$WORKING_DIR"

Column 3 (the absolute path) carries the same fact and would be an equally
valid derivation; column 2 is used because comparing it needs no path
normalisation — a symlinked or trailing-slash root would make a string path
comparison silently miss, and a missed row reinstates the defect.

`coordinator-row?` is kept explicitly even though `provision_coordinator`
(swarmforge.sh:937, the only coordinator registration in the tree) always
registers it with worktree `master` and so is already covered. It costs one
predicate and keeps the pre-BL-1299 exclusion true of a coordinator row that
ever declared a real worktree.

## Declared invariants (ticket `invariants:`) — both executably encoded

`swarmforge/scripts/test/bl1299_reverse_hop_property_runner.bb`, 500 runs over
GENERATED roles tables (not the live one), since residency is a property of
the row.

1. *No reverse copy is ever addressed to a master-resident role* — asserted
   for every generated table × every sender × `back-one`/`back-all`/declared
   mode; plus no sender addresses itself and no duplicate recipients.
2. *Changing the reverse-recipient set never moves the terminal stamp* —
   two ways: against an INDEPENDENT oracle that recomputes the terminal role
   by a different route, and metamorphically (make an earlier role
   master-resident; the recipient set must shrink by exactly that role while
   `last-pipeline-role` is unchanged).

**Generator reach is asserted, not hoped for.** The runner fails if any of
five reach floors (runs/4) is missed, so the properties cannot pass vacuously:

    REACH any-master-resident          482  (floor 125)
    REACH non-obvious-master-resident  454  (floor 125)   <- NOT specifier/coordinator
    REACH deep-pipeline                386  (floor 125)
    REACH non-empty-reverse           2832  (floor 125)
    REACH terminal-metamorphic         464  (floor 125)

`non-obvious-master-resident` is the floor that matters: it counts runs where
an ORDINARY pipeline role was master-resident purely by its row, the state a
hardcoded name list would get wrong.
