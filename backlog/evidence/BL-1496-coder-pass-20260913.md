discipline) before any check runs — invariant 2.

`promote_and_route_next.sh`, `promotion_gates_cli.bb` and the libs are
untouched (`git diff --stat` on those paths is empty), matching the
`human_approval`'s FIRM constraint.

## A second, deeper rot the closure fix uncovered

Fixing the load-time crash surfaced a **second, independent** failure:
`promote_and_route_next.sh` gained a fail-closed deprecator freshness gate
(BL-1173, 2026-08-27) that this fixture's disposable root has no
`extension/out/tools/deprecate-check.js` for, so every case now HOLD-failed
closed instead of exercising the integrity-refusal behaviour under test —
the exact masking BL-1480 already found and fixed for its own two sibling
fixtures, three weeks after this fixture predates BL-1173. Fixed the same
way BL-1480 did: `write_deprecate_check_allow_stub` (already-shipped
`lib/deprecate_check_allow_stub.sh`), called in `mk_root` before the
fixture's initial commit and staged into it (`git add ... extension`) so it
reads as fixture setup, not drift, against the "index left exactly as it
found it" assertions the later cases make. No change to
`promote_and_route_next.sh`'s own gate logic — test-fixture parcel only.
