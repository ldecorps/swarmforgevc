## Gap found and fixed

The salvage's `eventsSincePreviousRun` treated "no previous run at all"
(the first run on record) and "a previous run that exists but carries no
`foldedLineCounts`" (a run recorded before this field existed) identically
- both folded the WHOLE ledger. The ticket's own "What is wanted" section
is explicit these are different: the first case folds everything (correct,
scenario 04), but the second must start from that prior run's
`windowEnd`/`deliveredAt` day instead - "never the whole ledger". The
salvage's own test
(`eventsSincePreviousRun with a pre-BL-1967 cursor-less run folds the
whole ledger`) had locked in the wrong behavior with a single-event
fixture that could not distinguish the two cases.

Fixed `eventsSincePreviousRun` to treat a cursor-less-but-real previous
run as a day-boundary approximation: every file strictly before that
run's windowEnd/deliveredAt day is skipped entirely (never the whole
ledger again); that boundary day's own file is refolded from its start
(it may re-see the few events that day's prior run already folded - the
ticket's own accepted approximation, since a run from before this field
existed has no real per-line position to recover); every later day is
unaffected either way. Rewrote the test to actually distinguish
before/boundary-day/after events, and added a second test for the
deliveredAt-only fallback (no windowEnd at all).
