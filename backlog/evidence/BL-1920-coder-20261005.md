**What the ticket says:** `history_without_call_prose` drops the text of
every assistant turn in the request that carries `tool_calls`, before the
request goes to Ollama. The reply qwen shows on the pane keeps its text.
Each log line gains `history_stripped=<n>`.

**Review:**
- `history_without_call_prose` (shim line 228): iterates `request["messages"]`,
  and for every message with `role == "assistant"`, a non-empty
  `tool_calls` list, and a non-empty `content`, replaces `content` with
  `""` and increments `stripped`. Returns the modified request and the
  count. The function operates on the *request* (what goes to Ollama), not
  on the *reply* (what qwen shows on the pane) — the reply side is
  untouched, as the ticket requires.
- `_complete` (shim line 615): calls `history_without_call_prose(clamped)`
  before `_call_upstream`, and logs `history_stripped={stripped}`.
- Test `test_history_reaches_ollama_without_text_beside_calls` (test line
  376): posts a request with an assistant turn carrying both content

  Ollama has `content == ""`. Passes.
- Test `test_a_compaction_reaches_ollama_with_the_chats_stripped_history`
  (test line 432): the compaction path also strips. Passes.

## 0eb5958ab6: a reply that announces an action is asked once more

**What the ticket says:** `needs_nudge`, `nudged_request`, `merge_nudged`,
and `_complete` (one completion: history stripped, text calls rewritten,
at most one nudge). A reply with no tool call whose text announces an
action is asked once more with "Call the tool now. Reply with the tool
call only."; the call it gets joins the original text. The NO_TASK guard
is the declared invariant: never when the request ends on a tool result
reading NO_TASK or the reply says NO_TASK. Log lines gain
`nudge=none|ok|no-call`.

**Review:**
- `needs_nudge` (shim line 262): returns False when the completion has
  tool_calls or finish_reason is not stop/None. Returns False when the
  text is empty, contains "NO_TASK", or matches neither `_ANNOUNCE` nor
  `_ASKS_USER`. Returns False when the last message in the request is a
  tool result containing "NO_TASK". This is the invariant: the shim never
  nudges a request whose last message is a tool result reading NO_TASK,
  nor a reply that says NO_TASK.
- `nudged_request` (shim line 285): appends the announcement as an
  assistant message and the nudge text as a user message.
- `merge_nudged` (shim line 291): takes the nudged reply's tool_calls and
  joins them onto the original reply's message (keeping the original
  text). Returns the original unchanged when the nudge got no call.
- `_complete` (shim line 615): after the first completion, calls
  `needs_nudge`; if true, makes exactly one more upstream call with
  `nudged_request`, then `merge_nudged`. The nudge variable is set to
  "ok" or "no-call" and logged. At most one nudge per completion.
- Test `test_an_announcement_after_a_wake_is_nudged` (test line 144):
  "I will now run..." and "Let me run it." both nudged. Passes.
- Test `test_an_idle_seat_is_never_nudged` (test line 171): a request
  ending on a NO_TASK tool result is not nudged even with an announcement
  reply; a reply saying "NO_TASK. I will wait..." is not nudged. Passes.
- Test `test_the_nudged_call_joins_the_original_text` (test line 185):
  the merged reply keeps the original text and gains the nudged call.
  Passes.
- Test `test_an_announcement_is_nudged_once_into_a_call` (test line 386,
  live shim): exactly 2 upstream calls (original + nudge), the second
  ending on the NUDGE text. Passes.

**Verdict: stands.**

## 59a376845a (was BL-1923): "Let's ..." is an announcement too

**What the ticket says:** `_ANNOUNCE` also matches "let's" (straight or
curly apostrophe) and "let us", with the same sentence-or-line-start
anchor, so a mid-word "outlet's" is not a trigger. Nothing else changed.

**Review:**
- `_ANNOUNCE` (shim line 250): the regex includes `let['’]s` and
  `let\s+us` in the alternation, anchored by
  `(?i)(?:^|[.!?:]\s+|\n)\s*` (sentence or line start). A mid-word
  "outlet's" does not match because the anchor requires start-of-string,
  a sentence-ending punctuation mark, or a newline before the word.
- Test `test_a_lets_plan_is_nudged` (test line 148): three replies from
  the seat's own words are nudged ("Let's commit the changes first...",
  "Let's add the entry.", "Let us run the tests."); "The outlet's tests
  passed." is not nudged. Passes.
- The NO_TASK guard, the one-nudge limit, and the merge are unchanged from
  0eb5958ab6 (verified in the review above).

**Verdict: stands.**
