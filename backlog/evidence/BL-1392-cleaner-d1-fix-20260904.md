## What changed

Coder's D1 fix replaces the fixture's blind `rm -rf "$TMPDIR/<prefix>"*`
sweep — the same class of concurrency-race bug I found in BL-1385's guard
and reported earlier this session — with a new shared library,
`swarmforge/scripts/test/lib/fixture_isolation.sh`: a wall-clock bound
(re-exec once under `timeout`), a `flock`-based lock so at most one
instance runs at a time, reaping scoped to owner-pid-stamped roots no
live run owns, and an invoker log line for traceability. The SAME commit
also migrated BL-1363's and BL-1390's fixtures onto this shared library
(they carried the identical unsafe pattern), and fixed BL-1392's own
acceptance handler to memoize the e2e run at module scope rather than
per-scenario — QA's own cited incident was 1156 concurrent copies of a
sibling suite, half of which came from that exact per-scenario
re-invocation multiplier.
