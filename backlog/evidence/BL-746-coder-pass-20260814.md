## Invariants (BL-654)

**Invariant 1** — "Every stop-path assertion in
`test_lifecycle_script_scope.sh` is made against stdout/stderr/exit status
produced by executing the real repo-root `stop-swarm.sh`; no stop-path
scenario derives its expected output from a reimplementation of the
script's branching."

Stated reason, no executable encoding: this is a claim about the TEST
SUITE'S OWN SOURCE SHAPE (does a given assertion's expected value come from
running the real script, or from a parallel `if/else` re-deriving its
logic?) — a property over the code's structure, not over program behavior
across generated inputs. It quantifies over prose/process (has anyone
written a reimplementation?), not a pure testable module, per BL-654's own
carve-out. Enforced instead by the qa_e2e_procedure's own step 5
("Reimplementation audit"), confirmed by hand this pass: grepping the
rewritten stop-path blocks (`test_lifecycle_script_scope.sh` lines
~126-215) finds no `if stack_survivor_scan; then ... else ...` branch of
its own — every assertion reads `$BL746_RC`/`$BL746_OUT` from a real
`bash "$STOP_FIX/stop-swarm.sh" "$STOP_FIX"` invocation. The only surviving
direct `source .../stack_survivor_scan.sh` uses in the file remain the
scanner unit cases (04a/05a/04b), which this ticket's own notes say are not
the reimplementation being removed.

**Invariant 2** — "stop-swarm.sh reports its success line only when every
refuse gate passes (no survivor found AND the pipeline kill exited zero);
on any refuse the success line is absent and the exit status is non-zero."

Encoded in `bl746_stop_swarm_refuse_gate_property_runner.js`, EXHAUSTIVE
over 3 survivor shapes (none, babysitterd, Operator) x 3 `kill_rc` values
(0, 1, 7) = 9 real fixture combinations, each an actual spawned
`stop-swarm.sh` (never mocked), checked against an independent oracle
(`oracleShouldSucceed`, a fresh restatement built without reading
stop-swarm.sh's own source). `npm`/vitest has no bearing here — this is a
bash script, not TypeScript; per the engineering article's Babashka/
Clojure carve-out precedent, and following
`bl886_vitest_orphan_reaper_supervisor_property_runner.js`'s own
established shape for a small, fully-enumerable, real-process-driven
domain, this file is itself the enforced gate.

Non-vacuity proven by hand this pass, not merely asserted: ran the property
runner against `stop-swarm.sh` with the `kill_rc` refuse block
(lines 91-94) deliberately removed (a scratch edit, never committed — the
same regression this ticket's own qa_e2e_procedure step 3 describes).
Result: 4 failures, both a SOUNDNESS violation (exit 0 when a refuse
condition held) and a LOUDNESS violation (success line printed anyway) for
both `killRc: 1` and `killRc: 7`; the `survivor` cases were unaffected
(correctly — that gate was untouched). Reverted
(`git status --short stop-swarm.sh` confirmed byte-identical after), then
re-ran clean: `ALL PROPERTIES HOLD`, 9/9.
