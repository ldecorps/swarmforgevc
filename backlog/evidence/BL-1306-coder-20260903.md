# BL-1306 — coder pass (2026-09-03)

The two-call self-audit stored its challenge under the ROUTED recipient and
looked it up under the DRAFTED one, so any forward that `required_stages`
routing rewrote deleted its own standing challenge at the top of every
invocation. The sender got `AUDIT_REQUIRED` forever: Article 2.3's own
instruction — re-audit, re-invoke byte-identically — became a loop, and an idle
re-invocation loop is what the handoff daemon halts the whole swarm for.

## The fix: one construction, after routing

`invocation-fingerprint` no longer builds a key beside `audit-candidate`; it is
**derived from it** (`(dissoc (audit-candidate …) :version)`). Two independent
constructions of "the same" key is the defect itself, so the fix removes one of
them rather than patching it to agree. The call site moved inside the `let`
that computes `routed`, and passes the same post-routing recipients and the
same canonical commit the store uses.

That also closes the second split basis the ticket flagged as "worth a look":
`:commit` was read raw for the lookup and canonical for the store. It happened
to agree — the ticket said so — but agreement by accident is what the invariant
forbids, and deriving the key makes it structural rather than lucky.

`:version` is dropped because the lookup compares only the keys it carries and a
stored candidate's version does not identify an invocation.

## One fixture hazard found and fixed while here (worth downstream attention)

My first version of these acceptance handlers swept stale fixture roots by
prefix at module load. Scenarios run concurrently and the module can be loaded
more than once per run, so an unguarded prefix sweep deletes a sibling
scenario's LIVE root — a flake that reads as a missing file rather than as a
sweep. The sweep is now age-guarded (older than 10 minutes) in all four handlers
I have added this session (BL-1306, BL-1332, BL-1323, BL-1343), which keeps
BL-971's "sweep before the run, because a killed run traps nothing" while making
it concurrency-safe.

## A real finding from my own property test, before any reviewer saw it

The first version of invariant's edited-draft case drew the replacement
priority from `{'50','10','00'}` — and `50` is the draft's own value, so that
"edit" was a no-op, the draft was byte-identical, and the helper correctly
queued it. The property failed against correct code: the generator's fault, not
the helper's. Fixed by drawing only values that differ from the draft's own
priority. Recorded rather than quietly corrected, because a property that can
fail against correct code is as much a defect as one that passes against broken
code — and this one would have reached a reviewer as a false red.

The same pass also moved the fixture root from a raw `fs.mkdtempSync` to the
shared `mkTmpDir` helper, which BL-1280's guard requires (the raw call is
exempt in exactly three paths, and a test file is not one of them).
