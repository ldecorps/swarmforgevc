## A real fixture-construction bug found while writing the acceptance handler

The `.swarmforge/` directory is gitignored in the REAL repo (its own
top-level `.gitignore`, line 4) specifically so land-lock/land-repoint-log/
in_process bookkeeping never registers as an "uncommitted change". My
first fixture draft omitted this, so a genuinely clean worktree scenario
falsely produced `LAND_REPOINT_SKIPPED an uncommitted change` - the fixture
itself was dirty (an untracked `.swarmforge/` directory left over from
building it), not the re-point logic. Fixed by seeding the fixture with the
same `.gitignore` entry the real repo carries, in both the acceptance
fixture and the property runner's `mk-repo`. Confirmed the in_process check
is unaffected either way: `post-land-repoint!` lists that directory
directly via `fs/list-dir`, never through `git status`.
