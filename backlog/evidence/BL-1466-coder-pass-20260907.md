## The fix

`land_step_lib.bb`:

- **`bounce-records-for`** — every bounce record naming a ticket, across
  `.swarmforge/bounces/*.jsonl`, newest `:at` first; `nil` (fail closed)
  when any file could not be parsed, `[]` (a real "never bounced") when
  the directory is absent or empty. A file already renamed with the live
  store's own `.corrupt-quarantine` suffix is excluded by construction
  (no longer matches `*.jsonl`), not re-detected as corruption here.
- **`git-is-ancestor?`** — `true`/`false` on a clean `git merge-base
  --is-ancestor` read (exit 0/1), `nil` (undeterminable, fail closed) on
  anything else.
- **`bounce-blocking-state`** — composes the two: `nil` when nothing
  changes BL-1375's own answer (no record; the bounced commit no longer
  reachable from the tip - a rebuild off main, or superseded some other
  way); `{:state :bounced :blocking? true :reason "..."}` naming the
  ticket, its bounce date and commit, when the bounced commit is still
  reachable from the tip and no later handoff for the sibling cites a
  descendant of it; `{:state :unreadable :blocking? true :reason "..."}`
  when the store or the ancestry check itself could not be read.
- **`own-paths`'s `approval-fn`** (the one place both it and
  `blocking-siblings` read a sibling's state, per the ticket's own "How"):
  now composes `ticket-approval-state` with `bounce-blocking-state` -
  BL-1375's own blocking states pass through unchanged; an otherwise
  non-blocking (approved/absent) sibling is re-checked against the bounce
  store and overridden to `:bounced` when applicable.

"Re-fixed" reuses `salvage-lib/latest-item-handoffs` +
`salvage-lib/header-field` (both already public, already loaded
transitively via `task-scope-gate-lib`) rather than a third parser of the
handoff archive - the exact "How" direction.
