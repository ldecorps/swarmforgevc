# BL-1911 — coder evidence (2026-10-07)

Ruling B: each turn, `searchRepoForQuestion` (new `extension/src/tools/localSeatRepoRead.ts`)
resolves a ticket id in the question to its backlog YAML, and a path-shaped
token to that file's text, read-only and bounded to the target repository,
never a secret. `runLocalSeatTurn` calls it once, before the one completion
call, via an injectable `searchRepo` seam (default: the real search scoped
to `deps.targetPath`).

## The byte cap — which, and why

`REPO_READ_MAX_BYTES = 4000`. BL-1682's briefing (the seat's system prompt)
runs to about 465 words, ~3000 bytes by design — a local window truncates,
so the briefing itself is already kept short. The repo-read half of the
prompt is capped at roughly the same order of magnitude as the briefing
(4000 vs ~3000) rather than a larger bound, so one over-long match cannot
drown out the briefing or crowd out the question text and the model's own
reply budget on this CPU-only host. `searchRepoForQuestion` takes `maxBytes`
as a parameter (defaulting to the constant) specifically so the unit test
`caps the returned context at the byte bound` can prove the truncation
behaviour at a small bound without constructing a 4000-byte fixture.

## Invariants (BL-654)

1. "The seat reads only inside its target repository, never a secret or
   credential file, and writes nothing." — **coder-authored property test**,
   `extension/test/bl1911LocalSeatRepoReadInvariants.property.test.js`
   ("invariant 1"). Built over a real filesystem (not mocked): six
   candidates constructed by hand (a normal ticket read, a normal path
   read, the three named secret conventions, one traversal escape),
   asserted non-vacuously (each candidate actually reached, reach floor 15
   per candidate via `assertReachFloor`), plus a before/after tree
   snapshot proving nothing was written.
2. "Every request the seat sends to the model carries text it read this
   turn, or says plainly that the repository could not be read." —
   **coder-authored property test**, same file, "invariant 2". Pure over
   `buildPromptWithRepoContext`, the one function that decides what reaches
   the model, crossed with arbitrary question text (`fc.string()`) over the
   three real read outcomes (found something, found nothing, could not
   read), reach floor 25 per outcome.
3. "Routing is unchanged: Cursor keeps the Host topic and the front desk,
   and the seat takes turns only in its own topic." — **stated reason, not
   a new test in this parcel**: this is BL-1235's own invariant 1
   (`extension/test/bl1235LocalQwenSeatInvariants.property.test.js`),
   already encoded against the exact same `decideLocalSeatTurn` this
   parcel does not touch (confirmed: `git diff` of this parcel contains no
   change to `decideLocalSeatTurn` or its routing). First authorship of
   this invariant belongs to BL-1235, not this ticket; re-declaring it here
   does not create a new first-authorship obligation, and a second,
   identical property test in this parcel would duplicate BL-1235's own
   without exercising anything this parcel changed. The existing test's
   continued pass is reconfirmed below, and acceptance scenario 04
   (`the seat still takes turns only in its own topic`) exercises the same
   boundary end to end through this ticket's own fixture.
