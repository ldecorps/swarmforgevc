# BL-1221 — coder pass, 2026-09-05

## What was wrong

BL-757 added `checkOrphanedAuthoredDocs: () => OrphanDocsLandCheckOutcome`
as a REQUIRED member of `landPilotedTicket`'s `deps` interface
(`pilotAcceptanceGate.ts:254`) with an unconditional call at line 624
(`const orphanDocsCheck = deps.checkOrphanedAuthoredDocs();`). Production
supplies it correctly (`pilot-acceptance-gate.ts:221`). No test stub was
ever updated — `grep -rn checkOrphanedAuthoredDocs extension/test/`
returned nothing — so every test file that hand-builds a `deps` object and
calls `landPilotedTicket` threw `deps.checkOrphanedAuthoredDocs is not a
function` before reaching its own assertions. No compile step catches
this: the contract is a TypeScript interface, the stubs are plain-JS
object literals in `.test.js` files, so `tsc` never compares the two.

## Recount: 15 files, not 16

The ticket's own title/count (16) was measured by grepping for the bare
string `landPilotedTicket` under `extension/test/`, which also matches two
files that merely MENTION the name (in a comment or a required_wiring-
style string), never construct a `deps` stub, and were never at risk:
`multiworktreeAcceptanceFixture.test.js` and `pilotAcceptanceGateCli.test.js`
(confirmed: neither contains a `landPilotedTicket(` CALL, and
`pilotAcceptanceGateCli.test.js` builds no `deps` object at all — it
drives the CLI wrapper, whose own acceptance feature covers it
separately, per that file's own comment). Two independent, precise
methods converge on the same **15**: `grep -rl "landPilotedTicket(" ` and
`grep -rl "checkShellEntryPointDrive:"` (a member every real stub already
supplies) name the identical file set. All 15 are fixed here; the
"16" in the ticket's own title is the same class of stale-measurement
drift this session's other tickets (BL-1289, BL-1428) each hit and
corrected against the live grep rather than the mint-time count.

## What landed

Each of the 15 files' own local `mkDeps`/inline `deps` object(s) gains:

    checkOrphanedAuthoredDocs: () => ({ checked: true, docsTouched: false }),

— the benign "no orphans" default the ticket's own description asks for,
placed alongside the other `check*` stub members. No shared cross-file
factory was introduced: every one of the 15 already keeps its OWN local
stub function (no pre-existing shared helper to extend), and the ticket's
own "How" section only prefers a shared factory when the stubs are
"near-identical" AND a factory does not "distort what individual tests
are asserting" — 15 independent local edits, each a single added line, is
the smaller and safer change here. Files with more than one deps-
construction site in the same file (`crossFileDuplicationCheck.test.js`,
`pilotScopedCrapCheck.test.js`, `pilotAcceptanceGate.test.js`) get the
line at every site; two files with the member wrapped across multiple
physical lines (`pilotAcceptanceGate.property.test.js`,
`unreachableStepHandlerCheck.property.test.js`) and one whose OTHER two
sites are override-only calls into its own base factory
(`shellEntryPointDriveCheck.test.js`, fixed at its one base definition)
were handled individually rather than by the same regex pass.
