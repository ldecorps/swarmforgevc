## What changed

`resolveConfirmedFile(file, rootDir, repoRootDir)` from `confirmPoleAlone`'s
inline `path.isAbsolute(file) ? file : path.join(REPO_ROOT_DIR, file)`. A
leading `"extension/"` segment on a relative `file` now resolves against
`rootDir` itself (which under a Stryker sandbox already IS the extension
root, per BL-1066) rather than `repoRootDir` (one directory further up,
which has an `extension/` child only in a real checkout, never inside a
sandbox). Every other relative path still resolves against `repoRootDir`
unchanged; an absolute path still passes through unchanged. Exported
alongside `confirmPoleAlone`.

the real `confirmPoleAlone` against a real on-disk fixture shaped like a
Stryker sandbox (recordTestDuration.js copied, never symlinked, so its own
`__dirname`/`ROOT_DIR` resolve inside the fixture; `testDurationRecorderLib.js`,
`out/`, `node_modules/`, and `vitest.config.mjs` symlinked in unchanged) for
scenario 01, and the same real function unmodified from the real checkout
for scenario 02.

New: `extension/test/bl1761ConfirmPoleAloneSandboxInvariant.property.test.js`
— coder-authored property test (BL-654) encoding the ticket's declared
invariant ("A repo-root-relative test path and its absolute equivalent
resolve to the same file, in the real checkout and inside a Stryker
sandbox"). Generator reach: crosses both the 'real' shape (rootDir's own
basename is "extension") and the 'sandbox' shape (rootDir stands in for
the extension root under an arbitrary name, its parent has no "extension"
child) against real on-disk fixtures, asserting the relative and absolute
forms resolve to the same existing file in both. Non-vacuity confirmed
twice: reverting `resolveConfirmedFile`'s extension/-prefix carve-out
failed this property immediately on the 'sandbox' case (resolved to a
nonexistent `<repoRootDir>/extension/test/<name>.test.js`), and separately
failed acceptance scenario 01 the same way — restored byte-identical
afterward both times.

`confirmPoleAloneOutcomeShapes.test.js` (BL-1721): unchanged, still green —
this ticket's FIRM constraint (no skipping/excluding/sandbox-detecting the
test that exposed the bug) is met by fixing the function it calls, not the
test itself.
