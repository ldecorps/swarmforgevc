# BL-2088 coder evidence — 2026-10-09

## Review of hotfix 01e77eaef2

Reviewed `git show 01e77eaef2` against the five invariants in the ticket.

### Invariant 1: isInFlightEmpty true when every live role's inbox/in_process is empty, even when inbox/new still holds mail

`telegramPipelineDrain.ts` adds `isInFlightEmpty(targetPath)` which calls
`resolveLiveRoles`, `buildRoleInboxes`, and `scanInProcess` for each role.
It returns `roleInboxes.every(({ inProcessDir }) => scanInProcess(inProcessDir).length === 0)`.
`inbox/new` is never consulted. **Confirmed.**

### Invariant 2: isInFlightEmpty false when any live role holds an in_process parcel

Same function: `every(...)` returns false as soon as one role's
`scanInProcess(inProcessDir).length !== 0`. **Confirmed.**

### Invariant 3: wait_in_flight_drain.sh prints drained when in_process is empty, forced when timeout elapses with in_process still occupied

`wait_in_flight_drain.sh` polls `isInFlightEmpty(root)` in a loop. On true it
prints `drained` and exits 0. On timeout it prints `forced` and exits 1.
Fixture test `test_wait_in_flight_drain.sh` exercises both paths. **Confirmed.**

### Invariant 4: wait_for_expedite_then_bedtime.sh arms the intake freeze, waits for expedite, runs the in-flight drain, then calls ./finish-shift — never before the drain returns drained or forced

The rewritten `wait_for_expedite_then_bedtime.sh` calls
`shift_close_freeze_intake.sh` (if not already armed), waits for any
in-flight expedite process to exit, then runs `wait_in_flight_drain.sh`,
and only after that returns (drained or forced) calls `./finish-shift`.
**Confirmed.**

### Invariant 5: shift_close_freeze_intake.sh writes control-pause active with an untilMs and pre-consumes the day's cooldown window marker so apply-cooldown-pause does not double-pause at shift end

`shift_close_freeze_intake.sh` writes `control-pause.json` with
`active: true` and an `untilMs` set to the next local 09:00. It also writes
`cooldown-window.json` with the day's 17:00 window-start ms so that
`apply-cooldown-pause` sees the window already consumed and does not
re-freeze. **Confirmed.**

### finish-shift not reimplemented

The hotfix only changes the wait that precedes `./finish-shift`.
`finish-shift` itself (BL-762) is untouched. **Confirmed.**
