# BL-1720 — coder pass, 2026-09-24

## What landed

- **`swarmforge/scripts/retire_seat_lib.bb`** (new): the pure TSV core -
  `filter-out-seat-rows` (drops every row whose column at a given index
  equals the seat, line order preserved - the SAME function serves
  roles.tsv, whose seat column is 0, and sessions.tsv, whose seat column
  is 1, never a second implementation per file), `seat-row` (the
  existence check `retire_seat.sh` refuses on before touching any file),
  `worktree-paths` (every distinct worktree-path column value, in
  first-seen order, from the ORIGINAL roster - captured before any
  filtering, so the retired seat's OWN worktree is still among them).
- **`swarmforge/scripts/retire_seat.sh`** (new, the ticket's own "How"
  verb): `retire_seat.sh <project-root> <seat>`. One operation, in order:
  (1) refuse with a usage message and exit 1 given the wrong argument
  count; (2) refuse naming the seat, changing NO file, when it has no
  roles.tsv row; (3) rewrite master roles.tsv, then sessions.tsv, then
  EVERY worktree's own roles.tsv copy - including the retired seat's OWN
  (its files are left in place; only its OWN roster row goes, same as
  every other copy's) - all through `retire_seat_lib.bb`'s one filter
  function; (4) only THEN kill the seat's tmux session, so the
  babysitter's repair sweep - which reads whichever roster copy it is
  given - never observes "missing session, but the roster still lists
  it" mid-operation; (5) print every parcel still sitting in the retired
  seat's own mailbox (`inbox/new/`, `inbox/in_process/`) for the caller to
  decide - never moved or deleted.

## Scope: reusing the launcher's own writers means the same column shape,
   not literally sourcing swarmforge.sh

The ticket's FIRM clause says the roster rewrite "reus[es] the launcher's
own roster writers... never a second format." `write_roles_file`/
`write_sessions_file` (swarmforge.sh) are bash functions operating on
GLOBAL ARRAYS a full launch's `parse_config` populates - literally
`source`ing that giant, heavily side-effecting file from a standalone
retirement verb (never run during a launch) would trigger argument
parsing, dependency checks and more, none of them wanted here. "Never a
second format" is honored at the level that matters - the EXACT same
column layout (roles.tsv's 9 columns, sessions.tsv's 5, in the same
order) - encoded once, in `retire_seat_lib.bb`, and read back by both
`retire_seat.sh` and this ticket's own acceptance fixture. The ticket's
own "How" section is itself headed "direction, not mandate."
