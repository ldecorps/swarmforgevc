## qa_e2e_procedure walked

1. **Reproduced the live case.** Fixture: a real git repo whose `main`
   carries two commits `swarmforge-QA` does not, both touching a QA-exclusive
   path — two real Article 4.2 findings with sha-derived keys. With no waive
   the sweep nudges, and nudges again once the dedup stamp is backdated
   (scenario 02).
2. **Waive recorded → no nudge** for that key (scenario 01). The finding is
   still printed, and the sweep prints `WAIVED [<key>]`: suppression is an
   overlay on the record, never an erasure.
3. **The negative case that matters most.** With a waive in place for one
   key, the SECOND Article 4.2 finding — same class, different commit — still
   nudges (scenario 03), and invariant 1 generates that pair by construction
   rather than drawing it, because an independently drawn pair would almost
   never be same-class and a class-wide waive would sail through.
4. **The sweep wrote no waive** at any point: measured as a byte-for-byte
   store diff before and after, across repeated sweeps (scenario 04,
   invariant 2 against the REAL sweep).
5. **Unusable store alerts.** Malformed (truncated/garbage) and unreadable
   (a directory in the store's place — no `chmod` failure simulation, and no
   root-user hole) both nudge every finding and print
   `WAIVE-STORE-UNUSABLE <reason>`; invariant 3 adds the two remaining
   corners, an absent store and an entry too incomplete to be accountable.
   The code path is fail-open by construction: `partition-findings` suppresses
   only on `{:ok? true}`, never on the absence of an answer.
6. **Listable** with key, waiver, date and stated reason (scenario 05).

## Two scope readings, recorded rather than assumed

- **Nudge only.** The waive silences the coordinator NUDGE, which is what the
  ticket's invariants, feature and title all speak of. The same finding's
  operator `BABYSITTER_ESCALATION` still fires every cooldown. That is either
  a deliberate boundary or the next slice; it is not decided here, and it is
  the one thing a reviewer should look at before this reads as "the noise is
  gone".
- **Key-generic mechanism.** The store keys on a finding key, so it works for
  any detector's key by construction — that is the shape the ticket's own HOW
  describes ("give the finding key a durable waive"). No per-detector
  behaviour was added, and nothing outside Article 4.2 is exercised or
  claimed; generalizing deliberately (and testing it) stays the follow-up the
  constraints reserve.
