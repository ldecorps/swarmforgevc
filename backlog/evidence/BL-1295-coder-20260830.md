# BL-1295 — coder pass, 2026-08-30

A revert commit does not blame the ticket whose subject it inherited.

## 1. The change

`task_scope_gate_lib.bb`'s `commit-message-names-task?` read the commit
SUBJECT and took the first ticket id in it. `git revert` writes
`Revert "<original subject>"`, so a revert inherits the reverted commit's
ticket id verbatim, and a revert of a MERGE names every path that merge
carried — including other tickets' files. The gate refused the send on the
strength of a commit that only REMOVED content.

Two new functions, both public so the rule is asserted directly on subjects
rather than only through a git fixture:

```clojure
(defn revert-subject? [subject]
  (boolean (and subject (re-find #"(?i)^\s*revert\s+\"" subject))))

(defn subject-names-task? [subject task-ticket-id]
  (and (not (revert-subject? subject))
       (= task-ticket-id (pipeline-stage-lib/extract-ticket-id subject))))
```

`commit-message-names-task?` is now a thin git wrapper over the second.

**The QUOTING is the signal, not the word.** A hand-written subject that
merely begins with "Revert", or one like `BL-1240: revert the fixture change
and redo it`, is a real commit by whoever wrote it and stays attributed.
Exempting on the bare word would let genuine foreign scope through, which is
the failure direction that actually matters in a gate — and it is a break I
ran deliberately (table in §4).

## 2. Verified against the live blocking commit

Not only against a fixture. The commit that has BL-1240 blocked:

## 4. Declared invariants (BL-654) — both executable

`extension/test/bl1295RevertAttributionInvariants.property.test.js`,
`npm run test:properties` lane. 3 properties, all pass.

**Invariant 1** drives the real pure predicate. The generator constructs
COLLISION CANDIDATES rather than drawing independently: the revert subject
is derived from the plain one by the very transformation the gate conflated,
so every generated pair can detect the defect. Drawing two subjects
independently would almost never produce a revert quoting the task's own id.
Reach over all four kinds — plain, revert, revert-of-merge, revert-of-revert
— is asserted every run.

**Invariant 2** builds a REAL git repository TWICE — once with the revert in
range and once without, identical in every other respect — and compares the
real gate's verdicts. That is the invariant's own wording ("a parcel refused
with such a revert in range would have been refused without it") turned into
an executable comparison rather than restated. Both the clean parcel and the
genuinely-foreign parcel are required by the reach floor: the first is the
case the defect breaks, the second is the case that must still refuse.

Non-vacuity, both directions, run and restored:

| deliberate break | properties that FAIL |
|---|---|
| the revert exemption removed (the defect) | invariant 1, invariant 2 (2 of 3) |
| exempt on the WORD `revert` anywhere, not the quoting (over-broad) | the "word alone is not the signal" property (1 of 3) |
| none | 0 of 3 |

The second break matters as much as the first: a fix that exempts too much
passes the ticket's headline scenario while silently disarming the gate.
