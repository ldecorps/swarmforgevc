# BL-1607 — coder, 2026-09-16

## What was wrong

QA's checklist gather (`qa-gather.js`) ran the full unit lane on the BL-1598
parcel commit `771b9cdd6d` the same afternoon BL-1600 landed
(`3e5884b9bc`), and reported (`backlog/evidence/BL-1598-QA-unowned-red-20260916.md`,
QA branch `cd5f3b5e25`):

```
FAIL  test/bl1277UnscopedStepCollisionGuard.test.js > BL-1277 unscoped step-pattern collision guard > the shipped step files register no colliding unscoped pattern
Error: Test timed out in 20000ms.
```

Green alone at the same commit, 6/6 in 7.9 s. BL-1600's own derivation,
`resolveUnitLaneTimeout(20000).effectiveMs`, defaults to
`sampleContentionFactor` = the 1-minute load average divided by the core
count. With 20 cores that factor stays under 1 well past the point real
contention already times these tests out (BL-1579's measurement: idle load
2.3-3.6, a full lane 7-10.8) — the budget always resolved exactly its
20000 ms base on this host, the property lane's `bl1304`/`bl968` files hit
the identical shape (BL-1606, same pass).

## The fix

- `extension/test/helpers/unitLaneContentionBudget.js` (new): exports
  `UNIT_LANE_FORKS_ENV_KEY = 'SWARMFORGE_UNIT_LANE_FORKS'` and
  `unitLaneHeavyContentionFactor(opts)`, which feeds the property lane's
  existing `propertyLaneContentionFactor` its own `forksFn` reading this
  key — no copy of the math, reused through its existing injection point.
- `extension/vitest.config.mjs`: publishes
  `process.env[UNIT_LANE_FORKS_ENV_KEY] = String(resolveLaneForks(process.argv, WORKER_POOL_SIZE))`
  before `defineConfig`, through the same `resolveLaneForks` the property
  lane's own config already uses (one explicit file argument = a genuinely
  solo run = 1 fork, else the pool ceiling) — the unit lane's own real
  concurrency, never a copy of the property lane's signal.
- `extension/test/bl1277UnscopedStepCollisionGuard.test.js`: the scan's
  timeout argument is now
  `resolveUnitLaneTimeout(20000, { factor: unitLaneHeavyContentionFactor() }).effectiveMs`
  — still names `resolveUnitLaneTimeout` and `20000` (BL-1600 invariant 2
  stays green), now also the fork-aware factor.
- Unit test `extension/test/bl1607UnitLaneContentionBudget.test.js`: one
  fork at load 1.8/3.6 stays at the 20000 ms base; nine forks at load 1.8
  resolves the factor to exactly 2.25 (45000 ms); load 10.8 alone (any
  fork count under the quiet ceiling) resolves 2.7 (54000 ms); 40 forks at
  a quiet load crosses the unit lane's own 120000 ms ceiling; an unset
  `SWARMFORGE_UNIT_LANE_FORKS` key reads as one fork.
