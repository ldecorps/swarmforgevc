## D1 — the fix

`swarmforge/scripts/land_step_lib.bb`'s `own-paths`: a new `cond` clause,
positioned immediately before the existing BL-1830 rebuild-attempt clause,
catches a path this ticket owns, shared with an unlanded non-closed
sibling, where `(:any-untagged? attribution)` is true - and refuses by
name (naming the path and every such sibling), rather than falling
through to the ordinary keep-whole-tip + passenger logic at the bottom of
the `cond`. That fall-through was the exact leak: the rebuild clause's own
`(not (:any-untagged? attribution))` guard already refused to ATTEMPT a
rebuild when untagged, but nothing stopped the path from then landing
whole anyway, sibling lines included.

**Deliberately scoped to `:any-untagged?` alone, never `:any-ambiguous?`**
despite QA's own remediation pointer naming both: a pre-existing, already
green test (`"BL-1544 (02): an ambiguous path the landing ticket also
touched is kept, no refusal"`) proves an ambiguous-but-also-self-tagged
path must still ride as an ordinary passenger, not escalate - the landing
ticket's own separate, cleanly-tagged commit on the same path is real
proof of its own stake, so nothing here can be shown to be "only" the
sibling's. Escalating that case too would have regressed BL-1544 (02) for
an incident QA's bounce never named (confirmed empirically: my first
draft checked `(or any-untagged? any-ambiguous?)` and broke exactly that
test; narrowing to `any-untagged?` alone restored it to green while still
catching D1's real shape).
