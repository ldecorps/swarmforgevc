The ticket carries a mid-flight amendment (specifier commit `2f36d2270`,
landed on `main` while the parcel "was already at architect"): invariant 3
+ acceptance scenario 06, closing a real regression — a tile whose last
capture was busy stays green through a whole outage, because

## D1 — invariant 3 is not implemented in production code

1. **Failing command**: direct source read, confirmed by tracing the real
   call path: `refresh()` (residentSpyUiHtml.ts:1044) → `setStatus('err')`
   (:1052/1061/1068) → `updateAllPaneStatusDots('err')` (:846) →
   `updatePaneStatusDot(headEl, pane, 'err')` (:826) →
   `resolvePaneStatusKind(pane, 'err')` (:811).
2. **Commit hash**: `c339946666` (documenter, = the parcel handed to QA).
3. **First error excerpt** (the function itself, `residentSpyUiHtml.ts:798-806`):
   ```
   function resolvePaneStatusKind(pane, aggregateKind) {
     if (pane && pane.activitySignal) {
       return pane.activitySignal;
     }
     if (!pane || pane.available === false) {
       return null;
     }
     return aggregateKind;
   }
   ```
   `aggregateKind` is accepted as a parameter and used only as the
   fallback on the LAST line — never checked before the early return on
   line 799-801, so a truthy `pane.activitySignal` (e.g. `'ok'` from the
   last successful poll) wins regardless of what `aggregateKind` is.
4. **Failure class**: `behavior`.
5. **Expected vs observed**: Expected — per invariant 3 and the ruling in
   `approval_context`, when the whole-poll aggregate is `err`, no tile
   paints `ok`, even if that tile's own last-known `activitySignal` was
   `ok`. Observed — the aggregate is never consulted first; a tile whose
   last real capture was busy keeps painting green for the entire outage.
   This is the EXACT regression the specifier's amendment names, verified
   still live by reading the shipped function, not inferred.
