# BL-1467: the re-point keeps QA bookkeeping and names what it drops — coder

## What changed

1. `swarmforge/scripts/land_step_lib.bb` — `post-land-repoint!` now
   enumerates `origin-main..old-tip` (`ancestry-commits`) before the
   `reset --hard`, classifies each commit
   (`classify-repoint-candidate`/`repoint-bookkeeping-path?`):
   - a merge, a revert/reapply subject (`task-scope-gate-lib/revert-subject?`),
     one naming no ticket, or one naming the just-landed ticket itself
     (already carried by its own replay) → **drop**, reason named.
   - one naming a *different* ticket whose every changed path is that
     ticket's own bookkeeping shape (`backlog/evidence/<id>-*`, a
     `backlog/{active,paused,done,hold,archive}[/<milestone>]/<id>-*.yaml`
     ticket file, or `backlog/topics/<id>.json`) → **keep**.
   - anything else → drop, reason "not bookkeeping".
   After the reset, kept commits are cherry-picked oldest-first onto the
   new tip; a conflict aborts and re-classifies that one commit dropped
   ("conflict"), leaving every earlier successful pick in place and the
   tree clean; an empty pick (content already on the new tip) is kept
   with `:already-applied? true`, never dropped. Returns
   `{:action :repointed :old-tip :new-tip :kept [...] :dropped [...]}`
   (both new keys; `:new-tip` is now "origin-main plus whatever was
   re-applied", not necessarily origin-main itself). New optional
   `:landed-task-ticket-id` key on the opts map — omitted, every
   local-only commit is judged on shape alone.
   An unreadable candidate walk now SKIPS the whole re-point (a new skip
   reason) rather than resetting blind — BL-1438's own "a skip never
   fails the land" promise still holds, since a skip was already always a
   non-fatal outcome for every caller.
2. `swarmforge/scripts/land_step_cli.bb` — `repoint` verb takes an
   optional `<landed-task-name>` 3rd arg (extracted to a ticket id via
   `pipeline-stage-lib/extract-ticket-id`), and now prints one
   `LAND_REPOINT_KEPT <sha>` line per kept commit and one
   `LAND_REPOINT_DROPPED <sha> <reason>` line per dropped one, after the
   existing `LAND_REPOINTED <old> <new>` line.
3. `swarmforge/scripts/land_main_publish.sh` — `run_land` now passes
   `$task` (the landing ticket name it already has in scope) to the
   `repoint` call.

## Invariants (BL-654)

Both of BL-1467's declared invariants have coder-authored, non-vacuous
property tests in
`extension/test/bl1467RepointKeepsBookkeepingInvariants.property.test.js`:

- invariant 1 ("no bookkeeping commit is lost silently"): drives the real
  `post-land-repoint!` over a shuffled fixture carrying all five
  classification shapes at once (a genuine bookkeeping commit, an
  unrelated one, a revert, one for the landed ticket itself, and a
  conflicting bookkeeping one) and asserts every commit is named as
  exactly one of kept/dropped, with a non-empty reason when dropped, in
  BOTH the returned map and the on-disk re-point log. Non-vacuity: made
  the returned `:dropped` list always empty regardless of classification
  and confirmed the property fails, naming a commit accounted for by
  neither list; restored and re-verified green.
- invariant 2 ("the worktree it leaves is always clean"): drives the real
  publish-side cherry-pick loop over four shapes (nothing to keep, a
  clean keep, a conflicting keep, and a mix) and asserts `git status
  --porcelain` is empty and `HEAD` equals the reported `:new-tip` after
  every one. Non-vacuity: removed the `cherry-pick --abort` call on the
  conflict path and confirmed the property fails, catching the
  conflict-marker (`AA <path>`) left in the index; restored and
  re-verified green.

Both restores verified against a clean `bb -e '(load-file ...)'` load and
a full re-run of the property test file (green), plus the full bb-native
and shell-test regression sweep above.

## Notes

- A first draft of the property tests had a fixture bug, not a production
  one: `initRepo` never set repo-level `git config user.email`/`user.name`
  (only per-`commitFile`-call `-c` overrides), so `post-land-repoint!`'s
  own internal `git cherry-pick` call (no `-c` override of its own, as no
  real production worktree ever needs one) failed on missing identity and
  the fixture's own error-handling mislabeled that as a content
  "conflict". Fixed by setting identity at repo-init, matching every
  other fixture builder in this codebase.
- required_wiring names only `bl1467RepointKeepsBookkeepingSteps.js` (the
  ticket's own notes explain why: the publish wrapper only echoes
  `land_step_cli.bb`'s own text, and an anchor on the CLI itself would be
  the parcel's own diff) — landed in this same commit as the feature.
- `docs/how-to` updates (BL-1438's how-to, the QA prompt's repoint bullet)
  are the documenter's/specifier's, per the ticket's own "How" section —
  not touched here.
