# BL-1832 — coder pass, 2026-10-01

## What was built

- `swarmforge/scripts/babysitterd_sweep_lib.bb`: new pure resolver
  `seat-expected-agents` — given `{:rotation-router? :home-role :active-role
  :role-agent->token}`, returns the set of agent tokens a router pack's
  HOME pane may run and still be judged healthy: the home role's own
  roles.tsv agent, plus — only when `rotation-router?` is true and
  `active-role` is a DIFFERENT, honoured role — the active role's own
  agent. With no honoured active role (`active-role` nil, the exact shape
  `babysitter_check.bb`'s own `resident-active-role` already carries for a
  standing pack or an absent/unknown marker — BL-1345 invariant 3), or
  outside rotation router, the set collapses to the home agent alone,
  unchanged from today.
- `swarmforge/scripts/babysitter_check.bb`: `gather-role` runs before
  `resident-active-role` is resolved and judges every role (including the
  home role) against its own agent alone. A new re-judgement step, added
  right after `session-by-role`/`resident-active-role` are both known,
  recomputes `:has-claude-process?` for the resident-home role's row ONLY
  — and ONLY when `rotation-router?` is true and `resident-active-role`
  differs from `resident-home` — against the whole acceptable set
  (`babysitterd-sweep-lib/seat-expected-agents`, the required_wiring
  anchor), re-running `agent-process-line` once per acceptable agent
  against the pane's own pid/ps snapshot. Every other role's row, and the
  home role's row in every other case, is untouched.
- `swarmforge/scripts/test/babysitterd_sweep_lib_test_runner.bb`: six new
  unit cases for `seat-expected-agents` covering all four outline rows
  (mixed-agent rotation in progress, resident at home, outside rotation
  router, no honoured active role) plus an unmapped-role fallback case.
- `specs/pipeline/steps/bl1832RouterResidentActiveAgentSteps.js` (new):
  the acceptance driver, same pattern
  `bl804BabysitterMonoRouterTopologyAwarenessSteps.js` already uses — a
  real tmux server with a renamed child process (`exec -a "<agent> ..."
  sleep 999`) that a real `ps` snapshot picks up, driving the REAL
  `babysitter_check.sh` end to end. Cleanup is a `node:test` `after()`
  sweep (same posture as `bl633InvariantsSectionSteps.js`'s own hardening)
  since scenario 02 ends on a different (later) Then step than scenarios
  03/04, so no single assertion step can safely own cleanup inline.
- `extension/test/bl1832RouterResidentActiveAgentInvariants.property.test.js`
  (new): a coder-authored property test (BL-654) for both declared
  invariants, driving the real `seat-expected-agents` composed with the
  real `check-live-session` via `bb -e` — never a JS restatement of
  either decision. Two cells: `healthy-on-either-agent` (invariant 1;
  fresh, distinct agent-token pairs each run, the "live" agent constructed
  as one of the pair by a boolean draw, so every case is a genuine member
  by construction) and `marker-not-honoured-is-unchanged` (invariant 2;
  `active-role` always nil, the real shape the caller hands in for that
  case). Generator reach asserted via `assertReachFloor`/`runsPerCell`.
  **Non-vacuous, verified by hand**: forced the resolver's `cond->` guard
  to `(and false rotation-router? ...)`, reran — invariant 1's cell failed
  immediately (acceptable set held only the home agent); reverted (clean
  diff after, confirmed via `git diff`/grep for the break marker), reran
  green. Did the same for the acceptance feature's own driver: disabled
  the re-judgement in `babysitter_check.bb` with `(and false
  rotation-router? ...)`, reran the feature — 1 of 6 failed (outline row
  1); reverted, reran 6/6 green.

## Invariants (ticket's `invariants:` list, BL-654 coder-first authorship)

1. "Under rotation router, a home pane holding a live process of the home
   role's agent or of the agent of the role the resident is active as
   yields no proc-<home> finding and no repair." Encoded by the
   acceptance scenario's outline (3 rows), the unit cases, and the new
   property test's `healthy-on-either-agent` cell.
2. "Where the active-role marker is not honoured (a standing pack, or an
   absent or unknown marker), every seat is judged against its own
   roles.tsv agent alone, exactly as today." Encoded by acceptance
   scenarios 03/04, the unit cases, and the property test's
   `marker-not-honoured-is-unchanged` cell.
