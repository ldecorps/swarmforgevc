## QA bounce fix (2026-09-30, second pass)

QA found 2 defects (`backlog/evidence/BL-1815-QA-20260930.md`), both
blamed on coder, both in `request-brief!`'s wait/poll loop:

- **D1**: a `brief.md` already sitting at the path when `request-brief!`
  starts - "left by an earlier boundary" - was returned immediately, no
  request, no wait. Fixed by clearing any pre-existing file
  (`clear-existing-brief!`, best-effort) before the request is ever
  injected, so only a write that happens after the call began can be
  observed at all.
- **D2**: the poll loop classified a file the instant it first appeared
  on disk, racing the outgoing seat's own write-in-progress. Fixed by
  requiring the SAME content on two consecutive polls (`poll-ms` apart)
  before trusting it; absence still polls all the way to the deadline
  (never "stabilizes" on two nil reads - that would break the "no brief"
  timing contract test 01 already asserts).

Fallout from D1 in the tests themselves: every fixture that pre-wrote a
brief.md BEFORE calling the boundary (the property test's `valid` shape,
the shell test's cases 03/04, the acceptance step handler's "writes a
N-character brief" and "empty"/"2001 characters long" problem steps) was
now exercising the exact leftover-file shape D1 removes, and would be
cleared before the poll loop ever saw it. Rewrote each to write via a
detached, unref'd `node -e` process on a delay instead - late enough
(800ms) to safely land after `model_steward_cli.bb`'s own namespace-load
startup has reached the clear (measured empirically at several hundred
ms), decoupled from the parent's own synchronous `spawnSync` call to the
boundary. `MODEL_STEWARD_BRIEF_WAIT_S` bumped accordingly (2-6s
depending on fixture) to leave real margin after the delayed write for
the D2 stability check. Also added a DIRECT regression proof for D1
itself (shell test case 05): a genuinely pre-existing, never-rewritten
brief.md ends the call as "no brief", and its stale content never
appears in the output.
