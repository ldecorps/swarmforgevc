## The change that removed it

The stray-hang probe read every process on the HOST whose command line
carried `sleep 3600` (`pgrep -f '[s]leep 3600' | wc -l`), sampled before
and after each draw's sweep. A peer's hang alive across the two samples -
another copy of the property lane, an acceptance handler, a shell/bb test
runner, any of the 15 files the specifier's census named - flipped the
verdict, never the sweep under test.

Fixed by scoping the probe to the fixture that started it, never the
host:

- `extension/test/helpers/bl1071SweepFixture.js` gains `HANG_SHAPES` (the
  four hang shapes, moved from the property file) and `fixtureHangs(fixture)`.
  Every `sleep 3600` in every shape now runs as
  `exec -a "bl1071-hang:$(dirname "$0")" sleep 3600` - `exec -a` renames the
  process's own argv[0] (a same-PID `execve`, not a fork; the production
  kill path always wraps the command in `setsid` and kills the whole
  process GROUP on a bound hit - `bounded_run_lib.bb`, `:kill-mode :group`
  - so renaming changes nothing the kill reaches). The marker is the
  fixture's own mkdtemp root: unique per fixture, no token to thread
  through, and two fixtures alive at once never share one.
  `fixtureHangs(fixture)` is `spawnSync('pgrep', ['-f',
  'bl1071-hang:<fixture.root>'])` with NO shell wrapper - a `bash -c`
  wrapper whose own argv carries the marker text matches itself (the
  specifier's marker demonstration measured 4 instead of 2 this way);
  `pgrep` never reports itself.
- `extension/test/bl1071RecoveryBoundedInTime.property.test.js` drops its
  own local `HANG_SHAPES` and the host-wide `strayHangs()`, consuming the
  helper's two exports instead. The fixture is built FIRST so its root
  exists for the marker; `before` is read via `fixtureHangs(fixture)` and
  asserted `=== 0` (a guard that the fixture started clean, never
  compared against `after` the way the host-wide probe was); `after` is
  read the same way post-sweep and asserted `=== 0` directly, so the
  message names what happened instead of the amount some other process's
  lifecycle moved the same number by.

No change to `babysitter_check.sh`/`.bb`, the recovery bound or its env
seam, the BL-1071 acceptance handler or feature
(`bl1071BabysitterSweepSurvivalSteps.js` keeps its own inline bare
`sleep 3600` grandchild shape untouched - out of scope, and it never calls
`fixtureHangs`), or `bl1370WorktreeStrayCheck.property.test.js` (names
`sleep 3600` in a fixture table only, spawns nothing).
