## Scope

Route the four stray call sites through `daemon-cycle-guard-lib`:

- `process_table_lib.bb`'s `cwd-from-lsof` — `process/sh` → `daemon-cycle-guard-lib/sh!`.
- `model_factory_store.bb`'s `invoke-launch-seam!` — `process/process` → `sh!`.
- `outage_failover_store.bb`'s `respawn-seat!` — `process/process` → `sh!`.
- `handoff_lib.bb`'s rotation bootstrap (`run-respawn-bootstrap!`) — deliberately
  fire-and-forget, so it takes a new chokepoint verb,
  `daemon-cycle-guard-lib/spawn-detached!`, rather than `sh!` (a bound would
  destroy the bootstrap's tree at the wait). `spawn-detached!` starts the
  child and never waits on it; a spawn failure is swallowed exactly as the
  bare `process/process` call site it replaces did.

Each of the three `babashka.process`-requiring files had its require dropped
along with the direct call — the ban regex (`daemon_api_ban_lib.bb`) matches
the bare namespace token, so a stale unused require would still trip the
gate.
