## Review

`git show a9cadb6484` — `kill_pipeline_swarm.sh`'s new `socket_owned_by_root`
compares the tracked socket's directory and the stopped root's own
`.swarmforge/` physically (`pwd -P` on both sides), so neither a `../`
segment nor a symlinked directory can make a foreign socket read as this
root's own. The lexical fallback (used only when the socket's directory no
longer exists) refuses any path containing `../`. A refusal is logged as
`REFUSED tmux kill-server <sock> — socket is outside $ROOT/.swarmforge`. A
stop of the main checkout still resolves its own `.swarmforge/tmux-socket`
under its own `.swarmforge/`, so `socket_owned_by_root` returns true there
and the kill proceeds — confirmed by reading the function: when `$ROOT` is
the main checkout, `root_p` and the tracked socket's own directory resolve
to the same tree, matching the `"$root_p"/.swarmforge/*` case.

`git show 49fe963c76` — the TypeScript half. `socketOwnedByTarget` in
`swarmStopper.ts` makes the same physical comparison via a new
`physicalPath` helper (`fs.realpathSync`, walking up to the nearest
existing ancestor when the socket's directory is gone, so the check still
holds when a socket was torn down between the pointer being read and the
check running). All four call sites (`drainAgentSessions`,
`clearStaleSwarmState`, `stopSwarm`, `stopSwarmCompletely`) now gate on it;
each refusal path still clears the target's own stale state and reports a
message naming the refusal rather than a silent no-op. A stop of the main
checkout still kills its own server for the same physical-prefix reason as
the shell half.

Both hotfixes match the ticket's "What the hotfixes changed" section
exactly. Neither needs to be re-applied; this parcel is their review only.
