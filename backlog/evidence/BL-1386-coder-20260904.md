# BL-1386 — CODER PASS, 2026-09-04

## The defect, in one sentence

`absorb-with-merge!` discarded `abort!`'s result, so an abort defeated by a
transient `.git/index.lock` went unnoticed — and the NEXT tick read the
leftover `MERGE_HEAD` and, by BL-1120's rule, protected the daemon's own
orphan as a human's merge.

## What changed

**`master_main_reconcile_lib.bb`** (pure, where the decision lives):

- `merge-owner-path` / `read-merge-owner` / `write-merge-owner!` /
  `clear-merge-owner!` — the durable record, at
  `.swarmforge/daemon/master-main-merge-owner.json` (name fixed at mint so
  BL-1387 can read it).
- `owns-merge-head?` — every uncertainty answers NO: absent record, empty
  record, blank sha on either side, or a different sha. A wrong yes aborts a
  merge the daemon did not start, which is the one thing BL-1120 exists to
  prevent.
- `may-abort-failed-merge?` gains a 2-arity: this tick started it (BL-1120,
  unchanged) OR the record positively names this `MERGE_HEAD`. The 1-arity is
  untouched, so every existing caller behaves identically.
- `absorb-with-merge!` stops discarding the abort. On a failed abort it logs
  `merge-abort-failed` with git's own text, KEEPS the record, and returns
  `{:outcome :merge-abort-failed}` **without calling `fallback!`** — a
  rematch/reset on top of a still-open merge is a second hazard stacked on the
  first. On a successful abort it clears the record and logs the OBSERVED
  outcome, so `conflict` is kept only for a merge git actually called a
  conflict (BL-1214's e2e step 2 still holds) and a hook refusal reads
  `merge-failed`.

All three new adapters (`record-owner!`, `clear-owner!`, `log!`) are
**optional**, and a `nil` return from `abort!` still counts as success, so
every pre-BL-1386 call site and its tests are byte-identical in behaviour —
asserted by a row that supplies none of them.

**`handoffd.bb`** (the only side-effecting edits, as the ticket directs):
`master-main-merge-head-sha`, `master-main-origin-sha`, the record
write/clear, and `master-main-merge-abort!` — `git merge --abort` with a
bounded 3-attempt retry through a transient lock, never a spin. `merge!` now
reports `:conflict?` read from git's own output rather than assumed.

### Generator reach, by construction rather than by draw

The defect lives in ONE cell of the outcome grid — merge failed AND abort
failed — which is also the rarest cell if the two are drawn independently.
So the property enumerates the grid: every (merge-outcome × abort-outcome)
pair is built on every run and the run asserts all 12 were reached. A draw
could pass a hundred times having never once failed an abort, which is
exactly how the live defect survived until a human read the index by hand.

### Non-vacuity

Asserted in the runner itself, not claimed here: the pre-BL-1386 ladder — the
one that discarded the abort result and fell through regardless — is
reconstructed and must be caught. It is.

## Cross-boundary constants (BL-897)

Both `required_wiring` anchors are consumer anchors: the literals must live in
`handoffd.bb`, the only process that writes the record or emits the line,
while the lib owns the same two strings. Two copies across a boundary need a
test asserting they agree, so `test_handoffd_master_main_reconcile_wiring.sh`
reads the file name out of the lib and greps the daemon for it, and does the
same for the label. A rename on either side is now a red test rather than a
daemon writing one file while BL-1387 reads another.
