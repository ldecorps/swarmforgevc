## D1 — `acceptance:` was prose, not a feature-file pointer

BL-514 was specced with a two-part prose `acceptance:` block. Since BL-111 the
`acceptance:` field must be a path to a feature file under `specs/features/`,
which is the durable contract; BL-761's acceptance-contract gate additionally
requires every scenario in that file to resolve to a step handler at the cited
commit. A prose block satisfies neither, so the parcel could not pass the
documenter→QA edge no matter how sound the implementation was.

This is the specifier's own defect, not the pipeline's: the ticket ran the full
chain (coder `b09ce9b95`, architect `e7a0fdcbe`, hardener `315e27de5`,
documenter `968eaab05`) against a contract that was never runnable, and the gate
is the first thing in the chain that can mechanically notice.

**Remediation (specifier, this commit):** wrote
`specs/features/BL-514-rc-health-in-swarm-ensure.feature` — six scenarios
covering half (B), the `./swarm ensure` remote-control wiring — pointed
`acceptance:` at it, and added the required `description:` field the ticket was
also missing. Feature file parses clean under `gherkin_lint_gate.sh`; IR-DRY
reviewed (nine medium-confidence near-duplicate/synonym findings, all reviewed
and none accidental drift — distinct report outcomes, distinct subjects, and
setup-vs-assertion pairs; no merge would be meaning-preserving).
