## Declared invariants (BL-654)

- **Invariant 1** ("one notion of a standing red... the register CLI is
  the only reader") — **P1**: generates randomized counts of
  register-covered (lane,file) pairs, allowlist-only (uncovered) files,
  and ledger-only (uncovered) debts, and asserts (a) no (lane,file) pair
  ever appears twice across the combined report and (b) a pair the
  register covers always reports the register's own ticket, never one
  invented by the allowlist/ledger side. Broken by disabling the
  register-coverage filter on the allowlist side (`(remove (constantly
  false))` in place of the real membership check): failed on every
  generated case with at least one covered pair (the generator always
  includes at least one).
- **Invariant 2** ("a commit is judged only by the register rows it adds
  or changes; rows that pre-exist the commit never refuse it") — **P2**:
  builds a real git fixture with a randomized number of pre-existing
  stale register rows (naming a closed ticket, committed on HEAD) and a
  randomized staged change (touching the register with an open or closed
  ticket, or not touching it at all), and asserts the REAL guard's exit
  code depends only on the staged content. Broken by dropping `--cached`
  from the diff command (`git diff -U0` in place of `git diff --cached
  -U0`): failed on every generated case that touched the register with a
  bad ticket — after `git add -A` the working tree and index are
  identical, so an uncached diff reports nothing changed at all and the
  guard goes silently blind, a different failure shape than initially
  anticipated (false-negative-on-everything rather than
  false-positive-on-stale-rows) but an equally real one the property
  catches either way.
- **Invariant 3** ("the property-suite allowlist gate is unchanged in
  what it refuses: this parcel edits the allowlist's rows, never its
  reader") — no separate property test, per BL-654's own allowance for a
  declared invariant with no fresh executable encoding to record a stated
  reason instead: this is a one-time structural fact about THIS parcel's
  own diff, not a property over an arbitrary input domain. Verified by
  `git diff` naming only `property_suite_standing_allowlist.tsv`'s DATA
  rows changed — `property_suite_standing_allowlist_lib.sh` and
  `check_property_suite_drift.sh` are untouched (confirmed: neither
  appears in this parcel's own file list above), and
  `test_property_suite_drift_guard.sh`'s regression run above is unchanged
  apart from the one already-known, already-owned pre-existing red.

**Reachability**: P1/P2 ran 200 cases each; every dimension (has-covered /
