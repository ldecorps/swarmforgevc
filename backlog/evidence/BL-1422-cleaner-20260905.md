## Defect: `required_wiring` anchor missing from the named file

The ticket's `required_wiring` requires:

> `swarmforge/scripts/done_with_current_task.bb::dispatch-trail-ticket-id`
> — the live task completion must recognise a Work note through the one
> dispatch parser (BL-1223); absent today (grep returns 0)

The coder's own evidence (`BL-1422-coder-20260905.md`) claimed:

> present via `work-note-evidence-lib/work-note-ticket-id-from-message`'s
> own doc comment naming it explicitly (`grep -n dispatch-trail-ticket-id
> done_with_current_task.bb` matches)

This claim was false: `work-note-ticket-id-from-message` is the correct
delegation target, but the string `dispatch-trail-ticket-id` never
actually appears anywhere in `done_with_current_task.bb` — the doc comment
on `work-note-ticket-id` (the file's own local wrapper) named only
`work-note-evidence-lib`'s pure parser wrapper, not the underlying
`chase-sweep-lib/dispatch-trail-ticket-id` parser it in turn delegates to.
Verified with a plain `grep -n dispatch-trail-ticket-id
swarmforge/scripts/done_with_current_task.bb` before any edit: no match,
exit 1.

**Fix**: extended `work-note-ticket-id`'s doc comment (no behavior change)
to name the full delegation chain: "Delegates entirely to
work-note-evidence-lib's pure parser wrapper, which itself delegates to
chase-sweep-lib/dispatch-trail-ticket-id (BL-1223's one dispatch-trail
parser)". `grep -n dispatch-trail-ticket-id
swarmforge/scripts/done_with_current_task.bb` now matches (line 109). The
wiring this anchor asserts was already true in effect (invariant 2's own
property test already proves `work-note-ticket-id-from-message` answers
identically to the shared parser); this fix only makes the required_wiring
grep — and the file's own documentation — honestly reflect it.
