# BL-1901 — coder pass, 2026-10-02

## Change
- `swarmforge/scripts/land_merge_path_lib.bb` (new, pure):
  - `line-verdict`: a line from origin/main to the queued commit is clean when every commit
    names the landing ticket and no other (`pipeline-stage-lib/extract-ticket-ids`, so prefix
    collisions like BL-90010 and multi-id subjects are caught), or is a merge whose other parents
    are all on origin/main. An empty line is not a merge-path land.
  - `merge-message`: "Land <ticket>: merge origin/main <sha10>". It names the landing ticket
    only, and does not start with "<ticket>:" so it never reads as a second landing commit.
- `swarmforge/scripts/land_merge_path.bb` (new, the lander's land):
  - A clean line takes the land step's own lock (`land_main_publish.sh --acquire-lock`, same
    bound), then either publishes the queued commit itself (it already contains origin/main) or
    makes ONE `git merge --no-ff` of origin/main on a detached HEAD, so the commit-msg hooks run.
  - The land record (`path: merge`, source = queued commit) is written before the push. The push
    is never forced. A push that loses the race rebuilds once against the fetched origin/main.
  - The lander worktree goes back to its branch and the lock is released in `finally`.
  - Every decline happens before any push and hands the land to `land_main_publish.sh --land`
    unchanged, printing `LAND_PATH land-step: <reason>`. The declines are: an unclean line, a
    dirty lander worktree, the lock not obtained, a merge conflict (merge aborted), or the race
    lost twice.
- `lander_lib.bb`:
  - `land-command` picks the runner. The default is `:merge`; `:land-step` is the old command.
  - `tick!` takes an optional injected `:land-path` (default `:merge`). The `outcome` /
    `LAND_PUBLISHED` reading is unchanged.
- Land record path:
  - `land_step_lib/record-land-approval!` takes an optional `:path`. Its line gains
    `"path":"..."` only when one is given. Every reader (is_qa_ancestor.sh's regexes,
    ticket_close_guard_lib, landed_ticket_autoclose_lib, handoffd) tolerates the extra field.
  - The land step's own record (`land_step_cli.bb`) and its rematch record
    (`land_main_publish.sh` → `record_land_approval.bb`, new optional 5th arg) now say `land-step`.
    No other line of the land step changed.
- BL-1872's handler: its race fixture (`raceOnce`) now sets `:land-path :land-step`. Those
  scenarios test the land step's own push race and rematch, which the merge path, running first
  by default, would otherwise absorb on its own push. Its other scenarios run the default (merge)
  path and still pass. The handler also exports its fixture, which BL-1901's handler reuses
  rather than copying.
