# BL-1820 — coder evidence, 2026-09-30

## What changed

`swarmforge/scripts/local_specifier_battery.py`: five judgment
competencies added to the same battery run BL-1819 built, each a fixed
prompt naming the structured answer shape it wants and a deterministic
grader over that structure (never a second model's opinion):

- `invest-split`: grades a `TICKETS: <n>` line; pass when `n >= 2`.
- `invariants-discipline`: grades an `INVARIANTS: <n>` line; pass only
  when `n == 0`.
- `reality-check`: grades `VERDICT: <word>` (stale/supersede/close) and
  `FILE: <path>`; pass only when both are present and the verdict is one
  of the three.
- `consolidation`: grades a `TICKETS: <n>` line; pass only when
  `n == 1`.
- `deprecator-refuse`: grades a `DECISION: <word>`; pass only on
  `refuse-escalate` - every other decision (amend/retire/split/
  confirm-promote) fails.

`specs/pipeline/steps/bl1820SpecifierJudgmentSteps.js` (new, same commit
as the feature, BL-233) drives the real battery through its stub
provider, covering all ten competencies for scenario 02's "all ten in
one run" check.

`specs/pipeline/steps/bl1819SpecifierBatterySteps.js`'s own scenario-02
Then step (`the JSON sidecar records the same five verdicts and the
count that passed`) is loosened from an exact five-entry/`/5` count
check to "at least BL-1819's own five, each agreeing between evidence md
and sidecar, and the passed-count line matches the sidecar's own total"
- the battery now always runs all ten competencies in one process, so a
run BL-1819's own scenario drives also carries BL-1820's five entries.
Nothing else in that file changed.

`swarmforge/scripts/test/test_local_specifier_battery.sh`: ten new
fixture pairs and ten new cases (13-22) for the five judgment graders,
plus `write_answers_json`'s defaults extended to all ten competencies and
test 11's assertions updated to the new ten-entry/`/10` shape.
