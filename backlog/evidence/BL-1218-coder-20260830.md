# BL-1218 — coder pass, 2026-08-30

`config remote_control off` decides the launched flag, not just auto-inject.

## 1. The change

`swarmforge/scripts/swarmforge.sh` line 723 used to read:

```zsh
if [[ "$agent" == "claude" && "$REMOTE_CONTROL_DEFAULT" == 1 && "$extra_cli" != *"--remote-control"* ]]; then
  extra_cli+=" --remote-control $(remote_control_session_name_for_role "$role")"
fi
```

— an INJECT-only rule. A window line that named the flag itself was never
consulted about the config, and both `swarmforge.conf` and
`packs/full-forge.conf` name it on every Claude window line, so on exactly
the packs a human is most likely to run, `remote_control off` switched
nothing off.

Replaced with one call to a new pure `resolve_remote_control_cli`
(`swarmforge/scripts/remote_control_launch_lib.sh`), sourced at file scope
next to `project_socket_id_lib.sh`:

- agent is not `claude` → unchanged.
- default `1` → today's rule exactly: a named flag stays where the window
  line put it, an absent one is appended the way `extra_cli+=" ..."` always
  appended it.
- default `0` → no remote-control flag survives, and a following session
  name goes with it. A following token starting with `-` is another flag and
  is kept.

The decision is a pure string transform so it is asserted directly, not only
observed through a written script.

**Sourced by zsh, tested under bash.** The lib avoids word-splitting an
unquoted parameter — zsh does not split and bash does, so a token loop would
behave differently in the two and the difference would be invisible in
whichever one was not exercised (BL-801's shape). It uses `sed` instead, and
`test_remote_control_launch_lib.sh` passes under **both** shells.

## 2. Invariant 3 verified byte-for-byte, not argued

Composed a real `coder.sh` from the same fixture before and after the change
for the two on/absent paths, with the temp root normalised out, and diffed:

| path | diff |
|---|---|
| window line NAMES the flag, config absent | **identical** |
| window line OMITS the flag, config absent (auto-inject) | **identical** |

That is why the config-on branch returns `$rc_cli` untouched rather than
stripping and re-appending: re-appending would move the flag to the end of
the line and byte-for-byte would fail. Break 2 in the table below is exactly
that mistake, and the invariant-3 property catches it.

The empty-`extra_cli` case keeps today's leading space — `extra_cli+=" --remote-control X"`
has always produced one — pinned by lib case 08.
