## The invariants

### Invariant 1: The setting changes only what qwen keeps in the history after a compaction, never when qwen compacts, the served window or the provider entry

- `write_local_model_qwen_settings` writes only `model.chatCompression.maxRecentFilesToRetain`
  (and, from 4afdfbb6bf, `memory.enableManagedAutoMemory`); it writes no
  `context.autoCompactThreshold` (BL-1840's comment above the function
  records why that key is inert) and no window key.
- The served window is unchanged: the provider entry's
  `contextWindowSize` is still set by `local_model_qwen_provider_cli.bb`
  from `local_model_window_gate_lib.bb`'s served-window, exactly as before
  the hotfixes (the 427b3a1b1f declared-window logic is a separate stamp-off
  in the same ticket's notes, not one of the five hotfixes reviewed here).
- The provider entry merge (`local_model_qwen_provider_lib.bb`
  `merge-provider-entry`) replaces only the `modelProviders.openai` entry
  sharing the model's `:id`; every other key passes through untouched.
  Verified by the two "provider entry merge keeps" PASS lines below.

### Invariant 2: Every local-model seat's written .qwen/settings.json carries model.chatCompression.maxRecentFilesToRetain 0 and memory.enableManagedAutoMemory false, and the provider entry merge keeps both

- The writer writes both keys (swarmforge.sh, `write_local_model_qwen_settings`).
- `test_bl1949_local_model_precompact_hook.sh` asserts both in the written
  settings and both after the provider entry merge:
  - PASS: the settings stop qwen re-attaching recently read files after a compaction
  - PASS: the settings switch qwen's managed auto memory off
  - PASS: the provider entry merge keeps maxRecentFilesToRetain 0
  - PASS: the provider entry merge keeps managed auto memory off

### Invariant 3: A request the shim does not recognise as qwen's compression side-query reaches Ollama exactly as it did before c44825d8e4

- `is_compaction_request` reads only the system messages and the last
  message; a marker quoted in the history between is not a compaction
  (`test_a_marker_quoted_in_the_history_is_not_a_compaction`).
- A non-compaction request takes the original path: `_shim_chat` ->
  `_respond` -> `_complete`, with no cap, no thinking-off, no
  analysis-rewrite and no salvage applied.
- `test_a_tool_request_keeps_the_clients_thinking_knobs`: a tool request
  carries no `think` or `reasoning_effort` key — the client's own knobs are
  untouched.
