# BL-1447 — coder pass, 2026-09-07

## Implementation

`swarmforge/scripts/land_step_lib.bb`:

- `replay-missing-paths` (new, public, pure): given `cited-blobs`/
  `replay-blobs` (path -> blob-id, `::absent` for a path missing there)
  and `parcel-paths`, returns the sorted vector of paths where the two
  disagree - unit-testable without git, per the ticket's own "How".
- `replay-completeness-offenders` (new, public - not `defn-`, so BL-1447's
  own acceptance handler can drive the exact same check `land-plan` runs
  internally against a deliberately truncated build, never a second
  implementation of it): reads both trees' blobs at each path via the
  existing `blob-at` (`::absent`-on-missing), hands plain data to the pure
  core above.
- `parcel-commit-paths` (new): the WIDE, attribution-independent path set
  - `ancestry-commits root origin-main commit` (== `git log --format=%H
    ^origin/main <cited>`) filtered to commits whose subject names the
    ticket (`commit-ticket-id`, the SAME extractor `entangled-siblings`
    already uses elsewhere in this file), each commit's own `diff-tree
    --name-only` unioned. Never the `own-paths`/`delivered-attribution`
    walk this check exists to cross-check (invariant 2).
- `land-plan`: its `:replay`-bound branch now calls `replay!` itself
  (building the tip-pure commit), then `parcel-commit-paths` +
  `replay-completeness-offenders` against the built commit, BEFORE ever
  returning `:replay` - a build failure or any missing/differing path
  becomes `{:action :escalate :reason "replay-incomplete: <path> ..."
  :unlanded unlanded}` (dropping the now-unpublishable branch first);
  only a verified-complete build returns `:replay` WITH the already-built
  `:commit`/`:branch` embedded.

`swarmforge/scripts/land_step_cli.bb`: the `:replay` case no longer calls
`replay!` a second time (which would collide on the same deterministic
branch name land-plan's own call already claimed) - it publishes
`(:commit plan)`/`(:branch plan)` directly. The `:escalate` case now
prints `entanglement-note` when the plan carries `:unlanded` (a replay was
attempted and failed to build or build complete) - the same context a
direct `replay!` failure printed here before this ticket moved the build
itself into `land-plan`.

## A production behavior consolidation, not just a new check

Because `land-plan` now builds the REAL `replay!` (which already runs
BL-1375/BL-1324's own tree guards whenever a passenger rides) as part of
deciding `:replay`, a tree-guard refusal that used to surface only at a
SEPARATE, later `replay!` call now surfaces as `land-plan`'s own
`:escalate` directly. This is a real strengthening (a `:replay` verdict is
now a GUARANTEE the tip is both complete AND tree-consistent, never merely
"planned"), not a side effect to route around - three existing acceptance
drivers assumed the old two-step "plan optimistically, then discover a
build/guard failure separately" shape and needed updating to the new one:

- `specs/pipeline/steps/bl1446LandWalkNeverCountsLandedHistorySteps.js`
  (BL-1446's own scenario 02): dropped `ctx.plan.branch` before its own
  independent `replay!` verification call, which would otherwise collide.
  Fixture infrastructure extracted to the new
  `specs/pipeline/steps/lib/bl1446LandFixture.js` so BL-1447's handler
  (identical Background) shares it rather than re-implementing it.
- `specs/pipeline/steps/lib/bl1431OneLandPlanOneTipCli.bb`: `comparable-plan`
  now `dissoc`s `:commit`/`:branch` (two independently-built,
  content-identical fixtures each get their own real SHA/branch now, which
  a bare equality check must not read as "the plans differ"); the
  `moved-at-push` driver uses the plan's own already-built result instead
  of calling `replay!` a second time.
- `specs/pipeline/steps/bl1375ApprovedSiblingsCanLandSteps.js`: `decide()`
  now reads `land-plan`'s own build result via a thin `st.replay` shim
  instead of calling `replay!` separately. Scenario 01 (the approval axis
  only, not tree-consistency) incidentally inherited the Background's
  default-inconsistent tree (deliberate, for scenarios 06/07's own tree-axis
  tests) once tree-consistency became part of every `:replay` decision -
  `decide()` now defaults an untested tree-axis (`st.treeShouldBeConsistent
  === undefined`, neither 06's nor 07's own Given ran) to consistent via
  the same `landHandlerOnMain` helper 07 already used, extracted so both
  share it.

## Invariants (BL-654)

Both declared invariants ARE executable property tests here, not a
stated-reason carve-out (unlike BL-1349/BL-1450's own tuning-shape
invariants): `replay-missing-paths` is a genuinely new, pure, testable
function, and the five direct unit tests above encode invariant 1 (LAND_REPLAY
only for a complete carry) exhaustively over its small input space (present/
absent/differing/deleted, singly and combined). Invariant 2 (reads git
objects only, never the attribution) is structural - `replay-missing-paths`
takes plain blob maps as its ONLY input, with no reference to `own-paths`/
`delivered-attribution` anywhere in its signature or body, so it cannot
share their blind spot by construction; the acceptance scenario 01 exercises
this directly by driving the check against a build whose OWN attribution
(via `replay!`'s `:own-paths` argument) was deliberately wrong, proving the
check catches it regardless of what produced the wrong build.
