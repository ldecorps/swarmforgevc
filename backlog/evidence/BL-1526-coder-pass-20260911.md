# BL-1526 — coder pass (2026-09-11)

## What changed

`master_checkout_drift_lib.bb`'s spawn-target resolver
(`resolve-spawn-target` / `extract-spawn-targets`) gains a fourth,
deliberately non-literal shape: a file may declare a bare-symbol spawn
target genuinely dynamic (no literal anywhere) via a top-level
`daemon-spawn-declared-dynamic-targets` map naming the symbol and a reason.
`extract-spawn-targets` now returns a fourth key, `:declared-dynamic`,
threaded through `resolve-daemon-reachability` alongside `:resolved`,
`:unresolved`, `:non-bb`. Declaring one name never resolves another
undeclared bare symbol in the same file (scenario 03 and the new
`master_checkout_drift_lib_test_runner.bb` cases prove this).

The three let-bound sites resolve via the resolver's EXISTING "literal
wrapped in path plumbing" shape — no resolver change needed for them,
matching the `kill_all_swarm.sh` idiom already in `handoffd.bb`:
- `handoffd.bb`'s `defer-handoffd-bounce-after-drift-repair!` (`launcher`)
  and `close-landed-ticket!` (`script`): the `let`-bound path is inlined
  directly into the spawn vector.
- `chase_sweep_lib.bb`'s `park-ticket!` (`cli`): same inlining.

`expedite_cli.bb`'s `runner` (the `EXPEDITE_STAGE_RUNNER` seam — no literal
anywhere, by design) is declared dynamic via
`daemon-spawn-declared-dynamic-targets`, per the ticket's architect-facing
option 2; `stage-cmd`'s production behaviour (spawn `claude -p` directly)
is unchanged.

**Unplanned but required**: resolving `chase_sweep_lib.bb`'s `cli` target
newly brings `commit_integrity_cli.bb` and `commit_integrity_lib.bb` into
the daemon's spawn-reachable closure (`chase_sweep_lib.bb` is load-filed by
`handoffd.bb`, and now correctly resolves its `["bb" cli ...]` spawn) —
both used `babashka.process` directly (`commit_integrity_cli.bb`'s
`record-lean-ledger!`, `commit_integrity_lib.bb`'s `run-git` and
`pid-alive?`), which the walk could not see until this ticket's own fix
made the edge visible. This tripped BL-1031's ratchet (`bl1031:
spawn-reachable subtree carries no banned-API debt`) as a NEW offender —
exactly the ratchet's documented behavior ("a new offender fails"), not a
regression of BL-1524/BL-1525's four already-converted sites. Both files
now self-load-file `daemon_cycle_guard_lib.bb` and route through
`daemon-cycle-guard-lib/sh!`, same convention as every other conversion;
`[babashka.process :as process]` removed from both (the ban scan's regex
matches the require line itself, not just call sites).
