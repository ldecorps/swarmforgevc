# BL-1458: coder pass

## What changed

- `swarmforge/scripts/briefing_generation_schedule_lib.bb`:
  `briefing-due-instruction` now returns `produce the morning briefing for
  <day-key>` - byte-identical to `nightClosingCeremonyLive.ts`'s
  `briefingInstruction(dayKey)` (BL-897 mirror rule). Comments updated to
  describe the documenter-notify route, not the retired coordinator-nudge
  one.
- `swarmforge/scripts/handoffd.bb`:
  - New `instruct-documenter-briefing!` (+ its once-per-day marker
    helpers, `.swarmforge/briefing/instructed-<day-key>`) delivers the
    fallback's instruction as a real mailbox `note` to the documenter via
    `swarm_handoff.bb` (`SWARMFORGE_ROLE=coordinator`), the same outbound
    route `nudge-coordinator-parked!`/`auto-route!` already use. Marked
    instructed only on a successful send.
  - `briefing-generation-sweep!`'s `:notify!` adapter now calls
    `instruct-documenter-briefing!` instead of injecting a pane into the
    coordinator's tmux session.
  - `swarm-handoff-script` now reads `script-dir` (captured once at load
    time) instead of re-reading `*file*` at call time - `*file*` is only
    reliably this file's own path for the dynamic extent of loading/
    running it as one unit; a caller that `load-file`s this file and
    later calls a function (this ticket's own acceptance handler, and any
    future test harness doing the same) saw `*file*` revert to the
    caller's context, resolving to a bare relative `swarm_handoff.bb` and
    failing "File does not exist". `script-dir` has no such fragility;
    behavior in the normal script-execution path is byte-identical
    (same value, computed the same way).
- `extension/src/extension.ts`: `onBriefingDue` no longer looks up the
  coordinator's pane or calls `sendInstructionVerified` - it still
  emits+commits the cost/health sidecar. The dead `socketPath` local
  (used only by the removed block) is removed; every other use of
  `socketPath`/`readTmuxSocket` elsewhere in the file is untouched.
- Tests updated to the new literal:
  `briefing_generation_schedule_test_runner.bb`,
  `test_handoffd_briefing_generation_wiring.sh` (rewritten - asserts a
  real queued mailbox note addressed `to: documenter`, and that the
  retired coordinator wording never reaches tmux),
  `test_agent_runtime_inject_mock.sh` (the old wording was only an
  arbitrary `:text` example - replaced with an unrelated literal per the
  ticket's own direction).
- Docs: `docs/reference/Specification.MD`'s BL-099/BL-258 prose and
  `docs/how-to/BL-658-briefing-trigger-derived-from-closure-schedule.md`
  both now say the fallback instructs the documenter. No registered
  diagram depicts the briefing trigger; none changed.
