# BL-1652 coder evidence

## What was built

- `swarmforge/scripts/chase_sweep_lib.bb`:
  - `heartbeat-beat-ms`/`heartbeat-age-seconds` (new, pure): the one place
    `:last_beat` is parsed for age; `compute-liveness` refactored to reuse
    `heartbeat-beat-ms` rather than a second parse of the same field.
  - `decide-item-action` gains a second arity (`pane-busy?`,
    `lane-running?`, appended at the end) that folds either signal into
    `has-recent-activity?` — a busy footer or a running verification lane
    is treated exactly like tracked pane activity, so the SAME immediate-
    chase / backed-off-chase / skip branch governs it and
    `decide-stale-item-action`'s `"respawned"` branch is never even
    reached while either is true (invariant 1). The original 9-arg form is
    kept, defaulting both to `false`, so BL-852's own property invariants
    (`decide-item-action`'s pre-BL-1652 9-arg contract) needed no edit.
  - `lane-process-pattern`/`lane-process-cmdline?` (new, pure): the
    cmdline signature (Stryker, vitest, `bb test`, `run_acceptance.sh`)
    handoffd.bb's impure process-table read matches against.
  - `sweep-role-inbox!`: reads `:pane-busy?`/`:lane-running?`/
    `:get-heartbeat-age-seconds` ONCE per role per sweep (all three
    optional adapters, degrading to `false`/`nil` for any pre-BL-1652
    fixture), caps `"respawned"` to one per role per sweep via a local
    atom (invariant 2 — a later item that also decided `"respawned"` this
    sweep is left untouched: no wake, no count bump, no telemetry, exactly
    like `"held"`/`"skipped"` already leave every input alone), and builds
    the `{:item-id :liveness :heartbeat-age-s :activity-age-s :busy
    :lane}` context the one respawn's log line and telemetry row both read
    from (invariant 3 — one map, never two independently-assembled field
    sets that could drift apart).
  - `apply-inbox-item-action!` takes the new `respawn-context` (nil for
    every non-respawn action); the `"respawned"` case forwards it to
    `:trigger-respawn!` and merges it into the telemetry event.
- `swarmforge/scripts/handoffd.bb`:
  - `chase-target-busy?` (new): the SAME footer reading
    `chase-poke-and-notify!` gates `chase-wake-skip-busy` on (resident pane
    when the poke would land there, else this role's own wake-session pane
    via the pre-existing private `pane-busy?`) — reused, never a third copy
    of the capture+`actively-processing?` check.
  - `lane-process-snapshots!`/`lane-running-under-worktree?` (new): one
    `process-table-lib/list-processes!` read for the WHOLE sweep (mirrors
    `master_checkout_drift_lib.bb`'s own `list-process-snapshots!` shape —
    cheap cmdline match first, `cwd!` resolved only for candidates), scoped
    to a role's worktree via `process-table-lib/project-scoped-process?`
    (the same path-boundary rule the orphan reapers use — BL-1370's
    prefix-sibling hazard already closed there, inherited here for free).
  - `do-respawn!` gains an optional `log-context` and a new
    `chase-respawn-log-detail` helper: the real `chase-respawn <role>
    item=<id> liveness=<state> heartbeat-age-s=<n> activity-age-s=<n>
    busy=<b> lane=<b> script=<path>` log line (its own internal busy
    recheck is unchanged — belt-and-braces against a decision/action race,
    not the primary guard, which is invariant 1 in the pure decision).
  - `chase-sweep!`: one `lane-process-snapshots!` call per sweep (never per
    role); `:trigger-respawn!` now takes `(role context)` and forwards
    `context` to `do-respawn!`; three new adapters wired
    (`:pane-busy?`/`:lane-running?`/`:get-heartbeat-age-seconds`, the last
    reusing `parse-heartbeat` + `chase-sweep-lib/heartbeat-age-seconds`).

## Invariants (BL-654)

Both declared invariants are encoded, but not as a seeded-generator
property test: the domain (liveness × busy × lane × item-count, at the
exhausted-chase-count gate) is small and finite, not one where a
reachability floor is a live concern, so — matching the SAME specifier's
immediately-prior BL-1649 (also two declared invariants over a chase/claim
ladder) — the encoding is exhaustive case coverage in
`test_chase_sweep.sh` (case 18's 3 combinations, case 19's negative,
case 20's cardinality) plus the real end-to-end wiring shell test, rather
than a `bb` seeded-LCG runner. Non-vacuity for invariant 1 is direct
(`bb -e` sanity calls during development showed `respawned` before the
fix and `chased` after, on the identical inputs); the acceptance step
handler's own vacuity bug (above) is a second, independent non-vacuity
proof for the wiring-level assertions.

## FIRM constraints held

- The chase ladder's shape (chase up to `maxChases`, then respawn a
  genuinely dead role, else dead-letter) and its cooldown/backoff
  (`respawnCooldownSeconds`, `compute-chase-backoff-seconds`) are
  unchanged — `decide-stale-item-action` itself has zero edits.
- A role with a truly dead pane and no running lane is still respawned
  exactly as before (test_chase_sweep.sh case 19; wiring test scenario 02;
  acceptance scenario 03).
- Fixtures throughout are mkdtemp roots with fake tmux/process readings,
  never the live daemon's own real `.swarmforge` root (BL-1390); the one
  real subprocess spawned (the lane scenario's `exec -a vitest sleep 30`)
  is a throwaway, killed at the end of its own scenario, never left
  running.
- `required_wiring`'s step handler lands in this same commit as the
  feature file (which the specifier already committed at mint,
  508c9202bf) — this parcel adds ONLY the handler, never rewrites the
  specifier's Gherkin (an earlier local draft of this parcel accidentally
  overwrote the feature file's own scenarios with hand-authored ones —
  caught via `git status`/`git diff` before commit, reverted with `git
  checkout HEAD --`, never shipped).
