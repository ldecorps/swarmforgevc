# BL-1350 — coder pass (2026-09-03)

The bridge wrote nothing to an idle `/events` connection, so undici's default
300000 ms `bodyTimeout` killed every relay connection after five quiet minutes.
`attemptReplyRelayConnection` could not tell that from a real drop, so a quiet
swarm read as a chronic outage and BL-1111's sustained-outage alert fired on a
phantom one every 2-4 hours.

## The fix, on the server, where the ticket firmly put it

`writeSseKeepalive` — the name is fixed by the `required_wiring` anchor and is
**defined in `bridgeServer.ts` itself**, beside the `sseClients` set and the
poll timer, because a helper that is unit-tested and never reached from the
running server is precisely the BL-1235 shape that would leave this defect
unfixed behind a green suite. A `setInterval` in the same module calls it, and
`stop()` clears it alongside the poll timer.

The frame is an SSE **comment** (`: keepalive`), the conventional carrier and
already inert to every consumer of this stream: a browser `EventSource` ignores
comments natively, and this repo's own reader finds neither an `event: ` nor a
`data: ` line in one.

Two details the ticket did not ask for but the code needs:

- a client that has gone away is dropped rather than written to, and a write
  that throws removes the client instead of escaping the timer — one dead
  socket must not stop the keepalive for every other client;
- the interval is injectable (`keepaliveIntervalMs`, with `pollIntervalMs` as
  the precedent) so the suite drives it on a fake clock. **No real timer and no
  real sleep anywhere in these tests** — the 300000 ms each scenario elapses is
  fake-clock advancement.

`DEFAULT_SSE_KEEPALIVE_INTERVAL_MS = 20000`, kept as the acceptance specifies,
with a comment recording that it is one fifteenth of the undici default chosen
for margin rather than measured — the one number `approval_context` invites a
human to change.

  Invariant 1 is checked structurally (the live module defines the symbol, a

  over keepalive, snapshot and arbitrary-comment frames, each shape its own
  pass, asserting nothing is delivered, nothing acked, and no `seenIds` entry
  added.
- `npx tsc -p . --noEmit` clean; `npm run compile` clean; the bridge's own
  existing suite (`catchUpBridge.test.js`) still passes.

## One export added, and why

`drainBufferedRecords` in `telegramFrontDeskBotCore.ts` is now exported.
Invariant 2 is a statement about the SHIPPED relay loop — a re-implementation
of it in the test would prove something about the test. The export carries a
comment saying so, so it is not later mistaken for an API someone wanted.

## Belt-and-braces the ticket allows but did not require

A client-side `bodyTimeout` override on the relay's fetch is welcome per the
ticket but explicitly "must not be the only" fix. It is NOT in this parcel: the
server keepalive fixes every consumer of `/events` at once (the bot, the
holistic UI, the Bubble host page), which is the reason the ruling put it
there, and adding a second mechanism in the same slice would blur which one is
under test. Worth a follow-up if the operator wants the redundancy.
