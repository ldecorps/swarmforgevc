## Invariants (BL-654)

1. *"Every hook-installing fixture's copy set is a function of the hooks it
   installs and the runner they exec, read at run time through BL-1398's
   helper - never a list in the test..."* — encoded as
   `bl1484HookFixturesDeriveTheirSet.property.test.js::inv1`, which extends
   BL-1398's own add/remove generator across BOTH chain-source shapes
   (`run_guard` and commit-msg's direct call) via an added `directCall`
   boolean dimension, asserting both add and remove reach for both shapes.
   Confirmed non-vacuous: sabotaging `DIRECT_CALL_LINE`'s parse (forcing
   every direct-call match to report a fixed bogus script name) failed the
   test immediately (`AssertionError: the derivation must refuse naming
   check_aaa.sh (directCall=true)`); reverted, back to green.

2. *"Exactly one reader of each hook line shape exists in the repo (BL-1408
   invariant 2 carried forward): the four fixtures consume BL-1398's helper
   and none carries a parse of its own."* — **stated reason, no property
   test**. This invariant quantifies over the repository's own source
   structure (which files contain a line-shape parser), not over a pure
   function's input domain - there is no generator that varies "which files
   exist in the repo" in a way a property test could usefully explore.
   Verified instead by direct grep, matching the ticket's own
   `qa_e2e_procedure` step 4: `grep -rn 'check_[a-z_]+\.sh" "\$1"'
   extension/test specs/pipeline/steps swarmforge/scripts/test` returns no
   matches (the shape exists only inside the helper's own regex literal,
   which the grep's literal string cannot match either); all four fixtures'
   `grep -c commitGuardFixtureSet` is 1 and `grep -cE 'cp
   .*check_[a-z_]+\.sh'` is 0.

3. *"A guard a hook or the runner names but the tree lacks fails the fixture
   loud, naming the guard - never silently skipped..."* — encoded as
   `bl1484HookFixturesDeriveTheirSet.property.test.js::inv3`, extending
   BL-1398's own inv2 (already proves this for the `run_guard` shape) across
   the new `directCall` shape via the same generator (absent guard is a
   member of the named list by construction; non-vacuity re-derives with it
   planted and asserts a clean match). Confirmed non-vacuous by the same
   sabotage run above (the throw's absent-guard name is exactly what the
   sabotage broke).
