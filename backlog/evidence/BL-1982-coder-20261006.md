## Invariants

Both declared invariants are properties of the CLI's cross-process,
cross-tick orchestration (does a SECOND `bb` invocation, reading what the
FIRST one wrote to disk, ask again or consume a mismatched answer) -
process behaviour across multiple real subprocess calls and persisted
files, not a single pure function's input/output relationship. Nothing in
this parcel is a pure module that quantifies over the invariant directly
(the two pure predicates below are its atoms, not the invariant itself),
so per the Invariants contract this is a stated reason, not a property
test:

1. "At most one throttle question is raised per episode." - encoded by
   the acceptance feature's scenario 02 ("a later run while the question
   is pending raises no second question"): two REAL successive
   `effective_backlog_depth_cli.bb` runs against the same fixture, the
   second asserted to leave the coordinator's `role-awaiting` marker and
   the reply outbox exactly as the first left them (one question, same
   `asked_at_ms`). The gating predicate itself,
   `question-already-asked?`, is unit-tested directly in
   `throttle_release_ask_lib_test_runner.bb`.
2. "The depth CLI consumes a coordinator answer only when the
   coordinator's pending question is the throttle question it raised for
   the open episode." - encoded by scenario 03 ("another pending
   coordinator question defers the ask and is left untouched"): a REAL
   run against a fixture carrying an unrelated pending question with its
   own tapped answer on file asserts that run touches neither the other
   question nor its answer, and records no `releaseAskedAtMs` for the
   episode. Scenario 04 is the positive case of the same invariant (a
   matching pending question IS consumed). The comparison itself
   (`role-awaiting-asked-at-ms` read fresh, compared BEFORE calling
   `deliver-role-answer.js`, never after) is the bb CLI's own IO, not a
   pure function - `question-already-asked?`/`episode-awaiting-release?`
   are its pure building blocks, unit-tested as above.
