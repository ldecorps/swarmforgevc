## A real bug the generator caught on its first run (before any deliberate break)

`label-symbol-re` matched a bare `"&"`, but `escape-html`
(markdown_to_html_lib.bb) runs BEFORE `bold-leading-ticket-ids` ever sees
the text - a literal `"&"` from the source markdown always arrives here as
the 5-character HTML entity `"&amp;"`. Consuming only the leading `"&"`
left `"amp;..."` unrecognized, truncating every `"&"`-joined label early:
3 of the first 80 generated cases failed, e.g.
`"BL-2561 (skip BL-3352) & BL-6580 (cannot a) & GH-5709: ..."` bolded only
`BL-2561` instead of all three ids. **None of the eight manually-written
Examples rows happened to use `"&"` as a connective** (only `"and"` is
exercised there), so this was invisible without the generator. Fixed by
matching the whole entity (`#"^(?:&amp;|[/,+])"`) and by advancing the
loop by the ACTUAL matched length rather than a hardcoded single
character (the same bug would otherwise have recurred for any future
multi-character connective).
