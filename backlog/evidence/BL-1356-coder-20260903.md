## One shared helper, not six parallel edits

`extension/test/helpers/stampOff.js` is the single place a stamp-off invariant
now asks its questions, so the seventh stamp-off ticket inherits the fix rather
than repeating the bug (the ticket's own "How" asks for exactly this):

- `assertRunWritesNoDecision(hotfix, work, { ledgerPath })` — captures the row
  BEFORE, runs `work`, and asserts this run neither introduced a decision into
  it nor changed it at all. What the row said beforehand is the expected value,
  whatever it said. A decision this run INTRODUCED is named by field first, so
  the failure says *which* field was written rather than only that two strings
  differ.
- `assertParcelDoesNotEditReviewedSources(ticket, paths)` — the same lesson one
  door down, and it had to be fixed to reach the ticket's own scenario 04 (see
  below).
- `findTicketYaml(id)` — the same lesson a third time.
- `hotfixRow` / `decisionMarkers` — the shared parsing, so six files stop
  slicing the YAML six slightly different ways.

`ledgerPath` is injected for ONE caller only: the proof that the gate still
bites cannot be demonstrated against the live ledger without writing to it.
Every real caller takes the default, so option 1's "keep them on the live
ledger" holds.
