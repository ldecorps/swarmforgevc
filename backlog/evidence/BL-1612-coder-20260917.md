`handoff-lib/handoff-files-with-batches` (BL-1313's own batch-aware
reader), each with a comment naming BL-1313 and this ticket:

  (feeds BL-806's review-forward evidence gate and, via
  `merge_drop_guard_lib.bb`'s own reuse, BL-1576's merge-drop gate).

  (feeds BL-1213's parcel-rollback gate).

top-level file and one inside any `batch_*` subdirectory together, by
filename alone), never re-implemented here.

## BL-654: the one declared invariant

"For both readers, the received commit resolved for a task is the commit
header of the newest git_handoff naming that task anywhere under the
sender's in_process box, at the top level or inside a batch directory, and
nil otherwise - independent of the sender's receive mode."

`swarmforge/scripts/test/bl1612_send_gates_batch_property_runner.bb`: 300
randomized file-layout trials (1-5 candidate git_handoffs for the target
task scattered across the top level and 0-3 batch directories, plus 0-2
distractor notes, random priority/timestamp-shaped filenames so sort ties
are exercised, not just the trivial case) x 2 receive modes (`task`,
`batch` — the readers never consult this field, so holding the layout
constant while flipping it is exactly how the invariant's own
"independent of receive mode" clause is reached) x both readers, checked
against an independently-computed oracle (`(last (sort-by :filename
candidates))`, never the reader's own scan code) — plus 20 trials for the
"nil otherwise" clause (no matching candidate at all). 620 checks total,
zero random-seed flakiness (fixed `java.util.Random. 1612` seed).

Proven non-vacuous by hand before committing: reverting BOTH readers back
to `handoff-lib/handoff-files` fails 580 of the 620 checks (every trial
whose true-newest candidate happened to sit inside a batch directory);
reverted before landing.

## Existing unit-test runners extended with the batch case

Both `review_forward_evidence_gate_lib_test_runner.bb` and
`parcel_rollback_guard_lib_test_runner.bb` already had a "batch role,
several tasks, newest wins" case — but written with the files sitting
FLAT (never inside a `batch_*` directory), which never actually exercised
the bug: a flat file was already visible to the old reader regardless of
the role's own configured receive mode. Added one new case to each,
placing the parcel inside a real `batch_*` directory, and (for the
rollback lib) a full `findings-for-git-handoff` real-git-fixture case
mirroring existing "row 1" exactly but through `seed-batch-parcel!`
instead of `seed-parcel!`. Both proven non-vacuous individually (see
"Runs" below).
