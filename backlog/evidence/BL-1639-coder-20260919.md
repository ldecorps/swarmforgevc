## Bug found and fixed during TDD

The first draft of `babysitterd_census_pids` used bare
`[[ cond ]] && stmt` / `[[ cond ]] || continue` forms inside the function
body under the file's (inherited, at call time) `set -euo pipefail` —
when the condition was false and no `&&`/`||` partner ran, the compound
command's own exit status is non-zero, and since these were bare
top-level statements (not inside `if`/`while`), the calling shell's
`errexit` aborted the whole script the first time a token did NOT match
root, with no error message. Rewritten as explicit `if` blocks. Caught by
the unit test's own scenario 03 (a genuinely non-matching token) going
silently missing rather than failing an assertion — root-caused with
`bash -x`.

## Declared invariants (BL-654) — no property-test framework for shell

Both declared invariants are covered by `test_babysitterd_census_lib.sh`'s
scenario coverage (tracked/operator/other-root/sibling-worktree/empty)
and by construction (the stop, the verify, and `kill_all_swarm.sh` all
call the SAME `babysitterd_census_pids`/`babysitterd_census_signal`, never
a second copy). No property-test file is added: per `engineering.prompt`
("Babashka/Clojure and Kotlin/Android have NO mutation/CRAP/DRY wired")
and this project's own precedent for plain bash
(`test_finish_shift_lib.sh`'s scenario 02 comment — "this repo wires no
property-test framework for plain bash... exhaustive removal of each cell
in turn is a stronger, fully-deterministic encoding... than a sampled/
generated property would be"), shell has no property-test lane to add a
file to; the exhaustive fixture matrix above is the equivalent-strength
encoding for this invariant's small, enumerable input shape (script
location x root-arg presence x root identity).
