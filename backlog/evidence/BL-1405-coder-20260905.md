## A property-test gotcha caught by design

`land_step_lib.bb`'s `shared-target-root` resolves via `git rev-parse
--git-common-dir`. The first property-runner draft used a bare
`fs/create-temp-dir` fixture (not a git repository at all), so every
`record-land-approval!` call inside the property silently refused
("shared target root could not be resolved") and every
`already-recorded?` check then answered false VACUOUSLY — the property
reported "ALL PROPERTIES HOLD" while never having genuinely exercised the
writer at all. Caught auditing the properties' own non-vacuity (a mutant
in `already-recorded?` should have failed and did not on the first
attempt); fixed by `git init`-ing every fixture root before use.

## Declared invariants (BL-654)

Both have a coder-authored, non-vacuous property test, each shown to fail
against a deliberately broken implementation (verified live, then
restored — `diff` against a pre-break backup confirmed byte-identical
restoration every time):

- **Invariant 1** (one writer, no second serializer) — **P1**: an
  arbitrary set of distinct (commit, source) pairs (some deliberately
  sharing a commit with a different source, so a loose match on either
  field alone would be caught) is written through the real writer into one
  shared store; `already-recorded?` must answer true for exactly the pairs
  written and false for every other combination drawn from the same pool.
  Broken by making the reader match on the commit field alone (ignoring
  source): 300/300 cases failed on the very first check (every
  shared-commit-different-source pair, present in 240/300 generated
  inputs, false-matched).
- **Invariant 2** (a record with a missing sha is refused, never written)
  — **P2**: arbitrary invalid sha inputs (nil, empty, <7 chars) crossed
  with an otherwise-valid one. Broken by dropping the nil-check in
  `record-land-approval!` (`(if false ...)` in place of the real
  condition): 300/300 cases failed (every invalid-sha case wrote a file
  where none should exist). The "grants nothing on its own" half of this
  invariant is BL-1334's own predicate behavior, unchanged and out of this
  ticket's scope — proven instead at the acceptance layer (scenario 03)
  against the real `is_qa_ancestor.sh`.

**Reachability floors**: all three coverage buckets (P1's
shared-commit-different-source shape, P2's invalid-commit and
invalid-source cases) measured 141-240 out of 300 — all well above the 30
(runs/10) floor.
