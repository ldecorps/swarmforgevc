### 2. CRAP refactor (no behaviour change)

`npm run crap` flagged `applyAction` (complexity 10) and
`runNightClosingCeremony` (complexity 10) — both ABOVE the gate regardless
of coverage, since CRAP = `complexity² × (1−cov)³ + complexity` floors at
`complexity` itself at 100% coverage. Per the ticket's own "coverage first;
a small refactor only where coverage cannot reach":

- `applyAction`: an 8-case switch's cyclomatic complexity is driven by its
  case count, not by any one case's body complexity. Replaced it with a
  `Record<LiveAction['kind'], ActionHandler>` dispatch table — same shape
  as `telegramCursorBridgeLive.ts`'s `INBOUND_ACTION_HANDLERS` precedent.
  Each per-kind handler is its own trivial (complexity 1) function; the
  `Record` type keeps the table exhaustive at compile time, the same
  guarantee the switch's cases gave. `applyAction` itself drops to
  `if (dryRun) return []` + one ternary lookup.
- `runNightClosingCeremony`: extracted two branch-heavy expressions into
  named pure helpers, same differential-complexity reasoning as the
  existing `withRuntimeLoudCodes`/`landBriefingIfDue` extractions in this
  file: `isContinuingInProgressNight(prev, nightKey)` (the four-clause
  `if (prev && ... && ... && ...)`) and `ceremonyHasAdvanced(actions,
  finalState, prev)` (the final return's `||`/`??`).
- Every existing test (29 pre-existing + 6 new = 35 in this file, 38
  across both ceremony-run test files) stays green unmodified — confirms
  the refactor changes no observable output.
