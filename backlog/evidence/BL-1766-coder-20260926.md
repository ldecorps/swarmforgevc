## What changed

`extension/test/bl1648RegisterCliInjectedDateInvariants.property.test.js`:
the "no date argument reads today" test built its fixture's "first seen
today" row from `new Date().toISOString().slice(0, 10)` (always the UTC
day); `standing_red_register_cli.bb` with no `--now` reads
`java.time.LocalDate/now` (the local day). Added `localDay()` (Node's own
local getters, which respect `TZ` exactly like the JVM does) and used it
in place of the UTC read. A local midnight falling inside the test's own
run (read today, call the CLI, the CLI now reads the next local day) is
handled by reading the local day again after the CLI call and accepting
age 1 only when the two reads differ - never a retry, per the ticket's
own suggested remedy.

New `specs/pipeline/steps/bl1766RegisterTodayLocalDaySteps.js`: runs the
one real test via vitest's own `-t` filter under a real `TZ` override
(`Etc/GMT-14`, `Etc/GMT+12` - always on opposite sides of the UTC date
line from each other, whatever the instant), pinning the run at exactly 1
test (BL-1445: a `-t` filter matching nothing still exits 0 with 0 tests).
