## The fix

`extension/test/helpers/tolerantTreeWalk.js`: added
`DEFAULT_ROOT_ONLY_EXCLUDED_DIR_NAMES = new Set(['.swarmforge', 'tmp'])` and
a new `rootOnlyExcludeDirs` option, checked only when the directory being
recursed into is a DIRECT CHILD OF THE WALK ROOT (`dir === root`) - never a
basename-anywhere exclusion like the existing `excludeDirs` set. This
matches the ticket's own direction ("scope `tmp` to the root: a fixture
root named `tmp` must still be walkable") and the invariant's literal
wording ("the root's runtime directories"): a fixture that legitimately
nests a directory named `tmp` or `.swarmforge` deeper in its own tree is
still walked; only the checkout's own top-level runtime state is skipped.

Neither `bl874PortableTimeInvariants.property.test.js` nor
`tempDirTrapGuard.property.test.js` needed editing - both already call
`walkFilesTolerant(rootDir, { extension: '.js', withContent: true })` with
no `excludeDirs`/`rootOnlyExcludeDirs` override, so the new default applies
to both automatically. Confirmed by running them directly
(`--logHeapUsage`): 62 MB / 61 MB in this worktree (was 894 MB / 1778 MB on
the shared main checkout - this worktree has no `.swarmforge/operator/
vscode-cli/`, matching the ticket's own observation that no role-worktree
refusal log shows a heap death, so the ORIGINAL crash cannot be reproduced
here; what IS verified here is that the walk's behaviour and these two
files' own results are unaffected by the fix).
