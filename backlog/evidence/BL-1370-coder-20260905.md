# BL-1370 — coder evidence, 2026-09-05

Ticket: the per-pass orphan check is a gate with no tool.

## What shipped

**`swarmforge/scripts/worktree_stray_lib.bb`** — the pure decision:
`job-process?`, `stray?`, `strays`, `result-line`, `reap-targets`. It takes
the process list from its caller, so every decision is testable without a
process table.

**`swarmforge/scripts/check_worktree_strays.bb`** — the entry point a role
calls about its own pass: `check_worktree_strays.bb <worktree-root> [--reap]`.
A stray is a **refusal** (exit non-zero), not a warning; `--reap` signals each
stray's process **group** and then re-reads the table rather than assuming the
kill worked.

Three things it deliberately does not do:

- **It does not decide scope.** That delegates to `process_table_lib`'s
  `project-scoped-process?`, the classifier the orphan janitor and the handoffd
  supervisor already share so they "can never disagree" (BL-887). Growing a
  second notion here is the one change that would make this tool dangerous.
- **It does not restate the patterns.** `job-process-pattern` is byte-mirrored
  from `handoffd_supervisor.bb`, which cannot be loaded to read it (that
  script's top level exits with usage), so BL-897 applies: e2e check 11
  compares the two literals and refuses on drift.
- **It never signals its own process group.** A stray started from the role's
  own shell without `setsid` shares that shell's group, and `kill -- -<pgid>`
  would take the role's session down with the stray. Such a stray is reported
  with the pid to kill by hand.

## Three defects found while building it — two of them mine, in this parcel

1. **The first draft read every process's `cwd`.** `cwd!` shells out per pid,
   so a 136-process host cost ~30s per check — a gate slower than the thing it
   guards, and it hung the acceptance runner. The cheap filter (the job
   pattern) now runs first and narrows hundreds of processes to a handful
   before any cwd is read. The check is ~20ms.
2. **`kill -- -<pgid>` killed the caller.** Measured, not imagined: a fixture
   job that `setsid` did not separate shared my shell's group, and the reap
   took the shell down (exit 143). That is now refused in the tool AND in the
   e2e, which computes its own pgid and never signals it — without that guard
   the suite silently killed the `node --test` process running it.
3. **`pgrep -f <path>` matched the suite's own command line** and killed the
   suite mid-run (rc=143 at 548s). The suite no longer uses `pkill`/`pgrep`
   patterns that can match itself.

A fourth, in my own probe: SCI analyses eagerly, so naming
`worktree-stray-lib/...` in a probe fails before its `load-file` runs — BL-1395's
shape, met from the other side. The probes resolve the vars after loading.

## A finding in the SHARED classifier — reported, not fixed here

`project-scoped-process?` asks `str/includes? cmd root`, so a root that is a
**path prefix** of another root claims the longer one's processes: with
`/repo` and `/repo-2` — or `.worktrees/coder` and `.worktrees/coder-2` — the
shorter root's reap would kill the longer root's suite. My invariant-1
generator derives its sibling from the root, which is why it surfaced.

This is the shared classifier's behaviour, inherited by the orphan janitor and
the handoffd supervisor too, and **invariant 1 forbids this tool from growing
its own notion of scope** — so the fix belongs in `process_table_lib`, not
here. It is pinned by a named test ("known boundary: a prefix-shaped sibling
root IS claimed by the shared classifier") so the day it changes, it changes
visibly, and a priority-`00` note went to the specifier (2026-09-04 23:59Z).
Until then, scenarios 03 and 05 hold for sibling roots that are not
prefix-shaped, which is every worktree this swarm actually uses.

## Declared invariants (BL-654) — all three encoded

`extension/test/bl1370WorktreeStrayCheck.property.test.js`, driving the **real**
library through bb. A JavaScript reimplementation of the predicate would be the
second notion of "mine" invariant 1 forbids.

Reach is constructed: each line is built from a root and a shape, so every case
is a genuine own/other and job/not-job decision; all three classes are asserted
reached. Invariant 2 checks that every reap target is a group some stray
reported, deduplicated, and that a stray whose group could not be read is
reported rather than turned into a kill aimed at nothing. Invariant 3 asserts
the refusal line names pid, pgid and the remedy, that the clean line names the
scan size, and that both are byte-stable for a fixed state.
