## A mistake caught and fixed before committing

While manually exploring the pinned blob at the shell (before writing
the step handler), I ran:

```
for entry in swarmforge/scripts/*; do ln -s "$(pwd)/$entry" "$predir/$(basename "$entry")"; done
git cat-file blob 2edd9a17ba... > "$predir/swarmforge.sh"
```

without `rm`-ing the symlink first - the redirect followed the symlink
and overwrote the REAL `swarmforge/scripts/swarmforge.sh` with the
pinned blob's content (1166 lines replaced by 54). Caught by `git
status`/`git diff HEAD` showing an unexpected large modification to a
file this ticket is out-of-scope for; restored with `git restore
--source=HEAD --staged --worktree -- swarmforge/scripts/swarmforge.sh`
and verified clean (`git diff HEAD` empty, `PROPAGATION_MODES` present
at its three call sites) before any further work. The step handler
itself (`writePinnedRow` in the committed file) does `rm` the symlinked
target before writing the blob, so this mistake does not recur in the
shipped code or any test run.
