# BL-1842 — coder pass, 2026-09-30

## What was built

- `swarmforge/scripts/local_seat_report_lib.bb` — pure parsing/summary:
  qwen usage rows (`parse-usage-entries`, `latest-session-id`,
  `recent-session-ids`, `session-usage-summary`), a session's chat file's
  `system` rows (`parse-session-events`: compressions with before/after
  tokens, api errors), the Ollama server log's latest load and generation
  speed (`parse-ollama-load`), whether a generation is in progress
  (`latest-generating-at-ms`), the seat/worktree/qwen-project-key mapping
  (`seat-worktree-path`, `qwen-cwd-key`), and the state decision
  (`seat-state`: generating/idle/down). `summarise` composes all of it into
  one report map.
- `swarmforge/scripts/local_seat_report_cli.bb` — thin wrapper: resolves
  default paths (`~/.qwen/usage`, `~/.qwen/projects/.../chats`, the swarm's
  own `.swarmforge/ollama/serve.log` else `.swarmforge/ollama-serve-operator.log`),
  reads the files, checks the seat's process via `pgrep -f <worktree-path>`,
  and renders the report. Every path is overridable
  (`--qwen-home`/`--qwen-usage-dir`/`--qwen-projects-dir`/`--ollama-log`/
  `--now-ms`) so no fixture or test ever reads the operator's real records.
  `--sessions N` prints the N most recent sessions.
- `specs/pipeline/steps/bl1842LocalSeatReportSteps.js` — drives the real
  CLI over a real mkdtemp fixture (never a reimplementation of the parsing).
- `swarmforge/scripts/test/local_seat_report_lib_test_runner.bb` — unit
  tests for every pure function above, registered in
  `swarmforge/scripts/test/suite-manifest.tsv` (standing).
- `docs/how-to/BL-1052-local-model-seat-launch.md` — new "Judge a seat's
  health from its records, not its pane" section.

## Invariants (BL-654)

The ticket declares one invariant: "The local-seat report is read-only:
running it changes no file, pane or process." First pass wrongly recorded
this as unencodable (a code-shape claim, no `spit`/`kill` call to assert
the absence of by grep). Architect bounce D1 (invariant-unencoded,
`backlog/evidence/BL-1842-architect-20260930-bounce.md`): this is a plain
black-box input/output property over the real CLI, not a claim about its
internal shape - the coder's own grep argument is itself evidence FOR
encodability, not a reason to skip it. Fixed:
`extension/test/bl1842LocalSeatReportReadOnlyInvariant.property.test.js`
builds a generator-drawn mkdtemp fixture (qwen usage/session/log content,
`--sessions`/`--now-ms` args), snapshots the fixture tree (path + content
hash + mtime, recursively) before and after running the real
`local_seat_report_cli.bb` via `execFileSync`, and asserts the two
snapshots are byte-identical. Non-vacuous: a throwaway `(spit
(str project-root "/probe.txt") "x")` added to `-main` failed the property
immediately (named the new file in the tree diff); removed, green again.

## Self-audit finding: two description bullets were missed (fixed before forwarding)

The description's "what is wanted" list also asked for "requests,
**recorded turns**", and "total output and reasoning tokens, **and the
longest request**" - neither was implemented in the first pass, caught by
this ticket's own self-audit before the first `swarm_handoff.sh` call
queued. Fixed: `parse-session-events` now also returns `:turns` (the
session chat file's non-`system` rows - the actual conversation turns,
distinct from `:requests`, a count of qwen usage/telemetry rows, which can
outnumber turns on a retry); `session-usage-summary` now also returns
`:longest-request-tokens` (the max single row's input+output tokens, never
the sum). Both are printed by the CLI (`Turns: N`, `Longest request: N
tokens`) and covered by new unit tests; neither is asserted by the
acceptance feature's own 3 scenarios (they test the request count,
compressions/api-errors, served-model facts, and generating-state only),
so this is unit-test coverage only, re-verified after the fix (see
Verification above - all counts there are POST-fix).
