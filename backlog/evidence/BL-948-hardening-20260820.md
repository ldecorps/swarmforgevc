## D1 — the gate recognised ONE spelling of the long base, so invariant 1 held only by convention

Invariant 1: *"The gate defines the adoption set; no hand-maintained list of file names does… a checked-in roster of paths goes stale on the next step file and reproduces the one-at-a-time patching this ticket exists to end."* The ticket is blunter still: *"The gate is the point: it is what makes the fourth recurrence **impossible** rather than merely unlikely."*

The classifier tested for exactly one syntactic form:

```js
const LONG_BASE_ROOT = /mkdtempSync\(\s*path\.join\(\s*os\.tmpdir\(\)/;
```

That is a hand-maintained list of **spellings** rather than of file names — the same failure one level down. **Measured against the received commit, 1 of 6 realistic long-base spellings was caught:**

| Spelling | at `HEAD` | after |
|---|---|---|
| `mkdtempSync(path.join(os.tmpdir(), …))` | caught | caught |
| base hoisted into a local (`const base = os.tmpdir()`) | **MISSED** | caught |
| `tmpdir` destructured off the module | **MISSED** | caught |
| interpolated into a template literal | **MISSED** | caught |
| concatenated (`os.tmpdir() + '/p-'`) | **MISSED** | caught |
| reached through an inline `require('os')` | **MISSED** | caught |

So the fourth recurrence was not impossible — it only had to be written differently, and hoisting the base into a variable is the most natural way to write it.

**Fix**: `rootsAtLongBase()` now inspects each `mkdtempSync(` call's own argument text (sliced by paren balance) for a `tmpdir()` call of **any** receiver, and resolves a local alias bound from `tmpdir()`. The rule keys on the base itself rather than on how it was spelled.

**Consequence I had to resolve, not ignore**: broadening the rule made the gate read this parcel's own acceptance step file as a violation, because BL-948's example bodies necessarily contain the pattern (the coder had split the literal at `os.` + `tmpdir()` to dodge the narrow regex, and a paren-balanced scan reads straight across that). The principled fix is to blank **quoted-string contents** for the long-base check only — real code never spells `os.tmpdir()` inside a quoted string, and a file that does is carrying an EXAMPLE. Template literals are deliberately left intact, since `` `${os.tmpdir()}` `` is a real spelling whose call is an expression, not text. `SOCKET_REFERENCE` still keeps literals, because real socket paths live in them.

Result: **6/6 long-base spellings flagged, 0 false positives on short-base forms, and the real tree back to 0 violations.**

**Pinned so it cannot narrow again**: 11 new tests in the standing guard suite — one per long-base spelling, one per short-base form, plus the two edge cases (an example inside a quoted string is not a call site; a real call site sharing a line with a literal still is). The pre-existing 200-draw property test proves the *flag-iff-(socket AND long-base)* truth table but hardcodes one `longBase` string, so it could never have caught this — the vocabulary, not the shape, was untested.

## D2 — a second hand-mirrored literal across the same language boundary had no parity gate

The cleaner correctly gated `SOCKET_PATH_GUARD_LIMIT` against `swarm_socket_lib.bb`'s `max-safe-socket-path-len` (BL-897). But `WORST_CASE_SOCKET_SUFFIX = '/.swarmforge/tmux/4294967295.sock'` mirrors the **shape** `primary-socket-path` builds — `(str working-dir "/.swarmforge/tmux/" hash ".sock")` — and was ungated. Rename the socket directory on the `.bb` side and every fixture would measure headroom for a path the swarm no longer builds, while both suites stayed green: the same silent drift the sibling gate's own comment warns about.

Added a parity test parsing the `.bb` source for `primary-socket-path`'s own literals, in the same read-the-other-side's-literal style. **Non-vacuity proven**: drifting the JS constant to `/.swarmforge/sockets/…` failed exactly the new test and nothing else; restored.

The worst-case hash `4294967295` **checks out and is not a guess** — `project_socket_id_lib.sh` derives the id with `cksum` (CRC32), whose upper bound is exactly that. A second test asserts that derivation still uses `cksum`, so the worst case is re-derived rather than assumed if it ever changes.

## D3 — a socket fixture root that BYPASSED the helper leaked, invisibly to the gate

Invariant 2: *"A fixture root is removed in a finally… Moving roots to a shorter base multiplies nothing if a throwing scenario leaks them."*

`bl817FixtureTmuxServersReapedSteps.js:173` built its root with a direct `fs.mkdtempSync('/tmp/sfvc-bl817-loc-')`. Short enough, so the gate never flagged it — but created **outside** `mkSocketFixtureRoot`, so it was untracked and the exit-hook backstop could not remove it. The step `reap()`s the tmux server and never removes the ROOT.

**Not hypothetical — found on disk**: three stranded `/tmp/sfvc-bl817-loc-*` directories, timestamped 06:42, before any of my runs. This is the blind spot between the two mechanisms: the gate only catches LONG-base roots, and the helper only cleans roots it handed out, so a short-base root created directly gets neither.

Routed through `mkSocketFixtureRoot` (same short base, plus tracking). **Verified by before/after measurement on the real run**: the BL-817 acceptance previously stranded 3 directories; it now runs 9/9 with **0** stragglers. The three stale directories — leaked artifacts of the defect just closed, owners long exited — were removed.

### A cooldown-gate reading that looks wrong and is NOT — recorded so nobody re-opens it

Both new lib files report `file_age_days: 20685.31` (~56.6 years), which reads exactly like a bug: a file created 90 minutes earlier presenting as maximally old, hence past cooldown. **It is deliberate.** `mutation_cooldown_gate.bb`'s `last-committed-ms` queries **`main`**, not the role branch (BL-463: querying the current branch would return the parcel's own just-made commit and vacuously reset the cooldown clock on nearly every parcel). Its docstring states the consequence outright: a file with no history on `main` yet "has no integrated baseline to measure against — epoch (0) makes its age enormous, so it is eligible to run… never skip-cooldown." Cross-checked: `swarm_socket_lib.bb` reads 37.14d, `backlog_depth_lib.bb` (committed today, present on `main`) reads 0.13d and correctly returns `skip-cooldown`. I nearly filed a defect against correct behaviour and read the source instead.
