## Window start — which source, and why

Chose **the commit that added the previous `docs/briefings/<day>.md`**
(`git log --format=%aI --follow`, oldest line), not `.sent.json`. Two
reasons: `.sent.json`'s own locked shape (`{"sent": ["<day>.md", ...]}`,
read by `night-closing-ceremony-run.ts`'s `briefingSent`/`SENT_LEDGER_KEY`,
BL-1836) carries no timestamp at all, only day-key names - widening it to
add one would touch a consumer this ticket has no reason to touch; and the
briefing file itself is the one artifact that is unambiguously "the
previous briefing", so reading when IT was committed needs no new state
anywhere. `main()` computes this itself (`findPreviousBriefingSentAtIso`);
the ticket's "the briefing caller may also pass it in" alternative was not
taken; `briefing_email_lib.bb`'s `:qa-bounce-line` call site
(`handoffd.bb`'s `node-tool-line "qa-bounce-line.js"`, no args) is
therefore untouched.

## Invariants (BL-654)

New file `extension/test/qaBounceWindow.property.test.js`, both
coder-authored:

1. "The window counts, the trend and the all-time total are read from the
   same bounce log through the same reader, so a correction (BL-990)
   removes a bounce from every figure at once." — constructed by
   deletion: an arbitrary record set (12 max, roles/offsets spanning
   future, in-window, in-the-7-day-lookback, and well past both),
   `buildBounceWindowReport` built with and without one removed record,
   asserting the all-time total always drops by exactly 1, the window
   total drops by 1 only when the removed record was after the window
   start, and the removed record's own role's 7-day trend (re-derived
   independently via `computeSevenDayTrend` over the same before/after
   sets) drops by 0 or 1 accordingly. Reach floor 15 on
   removed-in-window/removed-outside-window, both hit.
2. "A bounce is in the window exactly when its time is after the window
   start, so no bounce is counted in two consecutive briefings." — pure
   over `recordsAfter`, a shape-selector generator (before/at/after) so
   the exact-boundary case is actually drawn rather than hoped for, reach
   floor 25 on all three shapes.

**Non-vacuity, proven by hand, reverted before this commit**: (a) changed
`recordsAfter`'s `>` to `>=` — the "at" case failed exactly as expected;
(b) changed the window tally's source from `windowRecords` to
`allRecords` — the window-total delta check failed exactly as expected.
Both reverted from a backup; `git diff` shows only the real implementation.
