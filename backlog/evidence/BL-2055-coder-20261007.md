# BL-2055 — coder evidence (2026-10-07)

Two faults in BL-1991's restart, both in `local-seat-restart` plumbing
shared with BL-1992's release. Fixed both; nothing else touched.

## Fault 1 — the launch script served whichever override sorted first

`swarmforge.sh`'s `local-model)` case (`write_role_launch_script`'s
relaunch loop) picked `pending_msgs[1]` - the first `.msg` file in
`.swarmforge/local-seat-restart/` by NAME - regardless of whose parcel
wrote it. An override outlives its parcel (a respawned pane leaves one on
disk, read only at the next qwen exit, on another parcel); an older
parcel's name sorting first served its stale override instead of the
held parcel's own.

Fixed: the loop now computes the seat's CURRENT held-parcel name from
`.swarmforge/handoffs/inbox/in_process/` (excluding sidecars - see Fault
2), discards every OTHER pending `.msg` file outright, and serves only
`<held name>.json.msg` if present - matching
`local_model_repeat_guard.bb`'s own `restart-state-file` naming exactly.
Two new zsh functions (`__bl2055_held_name`, `__bl2055_discard_stale_overrides`)
inside the generated script, no change to its escaping discipline (every
baked-in path stays single-quoted at generation time, every runtime
variable stays `\$`-escaped, matching the existing `$restart_dir`/
`$prompt_file` convention). Smoke-tested the raw generated zsh (`zsh -n`)
before touching the official test, then drove the real extracted case
block end to end against a fake qwen.

## Fault 2 — a released parcel's sidecar read as a new parcel

`local_model_repeat_guard.bb`'s `in-process-handoff-name` picked the
FIRST file in `in_process/` by name, sidecars included. BL-1992's release
moves only the handoff file, never its `.claim-progress.json` sidecar, so
a sidecar left behind after a release was read as a brand-new parcel with
zero restarts - restarting the seat on the ticket it had just released.

Fixed: `in-process-handoff-name` now removes any name ending in one of
the four known sidecar suffixes before picking the first remaining file.
The suffix list is copied from `handoff_lib.bb`'s own `sidecar-suffixes`
rather than `load-file`'d (measured: loading `handoff_lib.bb` costs ~100ms
more than this hook's own baseline - `bb -e "(load-file ...)"` - and this
hook runs on EVERY qwen tool call); `test_bl1971_local_model_repeat_guard.sh`
now asserts the copy agrees with the original (BL-897).

## Invariants (BL-654)

New file `extension/test/bl2055RestartOnlyOnHeldParcelInvariants.property.test.js`,
both coder-authored:

1. "A restart's fresh turn only ever carries the override written for the
   handoff that is in the seat's in_process when qwen exits." — drives the
   REAL extracted `local-model)` case block under zsh against a fake qwen,
   generated over an arbitrary held-parcel-name suffix, 0-3 stale overrides
   named to sort first, and whether a parcel is held at all; asserts the
   relaunch (when one occurs) always carries the held override alone and
   every stale override is discarded. 30 runs, floor 10 on each of
   held/noHeld.
2. "A seat whose in_process holds no handoff file (sidecars do not count)
   is never restarted and sends no release note." — drives the REAL
   `local-model-repeat-guard/answer` with in_process holding ONLY one of
   the four known sidecar suffixes (never a real handoff), crossed with
   whether that sidecar's own would-be restart count is already at the
   release cap; asserts neither the kill-fn nor the release-fn ever fires.
   64 runs, floor 2 on each of the 8 suffix×restart-state cells.

**Non-vacuity, proven by hand, reverted before this commit**: (a) restored
the pre-fix `swarmforge.sh` loop (`git show HEAD:...` of the unmodified
file) and reran invariant 1 alone — failed exactly as expected (the
relaunch served the stale override); (b) removed the `(remove
sidecar-name?)` line from `local_model_repeat_guard.bb` and reran
invariant 2 alone — failed exactly as expected (`killed` was `true` for a
sidecar-only `in_process`). Both restored from backup copies; `git diff`
shows only the real implementation.

## Pre-existing test maintenance (not scope creep)

`test_bl1991_local_seat_restart_launch.sh`'s own scenario 1 fixture named
its override `parcel.json.msg` with NO corresponding `in_process` file -
exactly the shape Fault 1 now correctly discards as stale. Updated it to
create a matching `in_process` entry (`held_parcel.handoff` /
`held_parcel.handoff.json.msg`), preserving the scenario's real intent
(surviving `set -e` on a killed qwen, relaunching once with the pending
override, consuming the file) under the corrected matching rule. Also
updated its "builds a launch_body" grep from the now-renamed `pending_msgs`
token to `__bl2055_held_name`.

## A BL-968 catch mid-flight

The first cut of the step handler read `swarmforge.sh` at module load
time (`const CASE_TEXT = extractLocalModelCase()`), which
`bl968StepRegistryMaterializedTreeGuard.test.js` correctly caught: that
guard materializes the step registry into a tree with no `swarmforge/` at
all, and failed loading my file with an `ENOENT`. Fixed by computing the
case text lazily, memoized, the first time a scenario actually needs it -
confirmed by rerunning that guard test standalone (green) before the full
lane.
