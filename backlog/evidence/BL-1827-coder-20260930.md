# BL-1827 — coder evidence, 2026-09-30

## What changed

`extension/test/bl1754PeerQuestionInvariants.property.test.js` invariant
1's leak check snapshotted every `bl1754-peer-question-*` entry in the
shared `os.tmpdir()` before and after its own CLI call. `peer_question.bb`
creates its run-dir under `java.io.tmpdir` (which babashka honours, and
which is `/tmp` by default, ignoring `TMPDIR`), so any concurrent
creator — a sibling run of this same file, or a live role asking a peer
question now BL-1754 has landed — lands in that diff and fails the check
at random, even though nothing leaked.

Each of invariant 1's four outcome calls now gets its own fresh
`mkTmpDir('bl1754-run-parent-')` temp parent, passed to `peer_question.bb`
as `-Djava.io.tmpdir=<dir>` ahead of the script on the `bb` command line
(verified: `bb -Djava.io.tmpdir=<dir>` makes `fs/create-temp-dir` create
under `<dir>`). Since that parent is fresh per call, there is nothing to
snapshot beforehand — any `bl1754-peer-question-*` entry found under it
afterward was made by that call alone. The directory is removed in a
`finally` (BL-971). `peer_question.bb` itself, the four outcomes, the
git-status diff, and invariant 2 are unchanged.
