# BL-874 — coder pass (2026-08-11)

Implements: replace the six inline GNU-only relative-time backdating
invocations under `swarmforge/scripts/test/` with one shared portable
helper, plus a standing guard in the extension Vitest suite.

## Changes

- `swarmforge/scripts/portable_time_lib.sh` (new): `portable_touch_relative
  <amount> <unit> <file...>`, mirroring `portable_stat_lib.sh`'s
  try-BSD-then-GNU shape. Tries `date -v-<N><letter>` (BSD); falls back to
  `date -d "<N> <unit> ago"` (GNU) when `-v` fails. Both reduce to one
  `touch -t` call, matching `test_handoffd_supervisor.sh:172`'s already-
  working precedent.
- `specs/pipeline/steps/lib/portableTimeGuard.js` (new): pure per-file
  classifier + directory walk, mirroring `tempDirTrapGuard.js` (BL-459/
  BL-872) exactly — flags any inline `date -d`/`touch -d` with a relative
  time word (ago/seconds/minutes/hours/days/weeks); an absolute spec
  (`touch -d "2026-...`, `touch -t ...`) is not flagged; the shared lib
  file itself is exempt (its GNU fallback branch legitimately contains the
  pattern).
- `extension/test/portableTimeGuard.test.js` (new): standing zero-violation
  gate in the suite every parcel runs, mirroring
  `extension/test/tempDirTrapGuard.test.js`.
- `extension/test/bl874PortableTimeInvariants.property.test.js` (new): all
  three declared invariants, coder-authored per BL-654 (details below).
- The five sites named in `required_wiring`, plus
  `test_operator_runtime_fixture_reaper_sweep_bounded_progress.sh` (same
  `old_mtime` shape, not separately named in `required_wiring` but sharing
  the identical defect) now source `portable_time_lib.sh` and call
  `portable_touch_relative` instead of the inline GNU-only form. No test's
  own assertions changed — only the mtime-setting mechanism moved.

## Invariants (BL-654)

1. "One shared helper, no inline reimplementation" — generative property:
   any inline `date -d`/`touch -d` with a relative-time word is always
   flagged (fuzzed over cmd/spec/quote-style/surrounding noise); the
   shared-helper shape is never flagged (fuzzed over amount/unit/noise).
2. "A new violation turns the gate red in the introducing parcel" —
   structural/non-generative, mirroring `tempDirTrapGuard.property.test.js`'s
   own treatment of its analogous invariant: `findPortableTimeViolation` is
   defined in exactly one file repo-wide, and the zero-violation assertion
   is confirmed to live in the standing per-parcel suite (not a suite
   nothing runs).
3. "Same relative input -> same resulting mtime on BSD and GNU" — this host
   has no GNU coreutils (constraint: don't add the dependency), so the GNU
   branch cannot be executed here to compare directly. What's verifiable on
   this host is that the BSD branch (the one this host actually takes)
   computes the mathematically correct epoch offset for arbitrary
   amount/unit (1-500, seconds/minutes/hours) — driving the real shared
   lib via a real bash subprocess, reading the real resulting mtime back.
   The GNU branch forwards the exact syntax the six original tests already
   used verbatim, so the risk this property actually covers (the BSD `-v`
   arithmetic and unit-letter dispatch) is what BL-874 newly adds. Noted in
   the test file itself.
