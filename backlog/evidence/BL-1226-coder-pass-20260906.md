# BL-1226 — coder pass, 2026-09-06

## What was implemented

Widened the /pilot land mkTmpDir convention check
(`assessPilotMkdtempConvention`, `extension/src/tools/pilotMkdtempConventionCheck.ts`)
to also scan touched `specs/pipeline/steps/**/*.js` paths, per the ticket's
own direction:

- **New scope classification** (`classifyMkdtempConventionPath`): returns
  `'in-scope' | 'exempt' | 'out-of-scope'` for any repo-relative path, used
  by both lanes. `isStepsHandlerJsPath` mirrors the existing
  `isExtensionTestJsPath` shape test for the steps directory.
- **Route-based detection for the steps lane**, deliberately NOT
  spelling-based: `RAW_MKDTEMP_ANY_BASE_PATTERN` /
  `findRawMkdtempLinesAnyBase` (`extension/src/tools/rawMkdtempDetector.ts`)
  matches any direct `mkdtempSync(` call site regardless of what expression
  sits inside its parens. The extension/test lane keeps BL-743's original
  narrow, spelling-anchored pattern completely unchanged — the two lanes now
  load and use independent detectors, loaded lazily and only for the lane
  that actually has a path in scope.
- **Required-helper exemption**: `specs/pipeline/steps/lib/socketFixtureRoot.js`
  (the steps lane's required route) and this ticket's own acceptance step
  handler (which legitimately builds scratch fixture text containing the
  literal pattern as test DATA) are both added to `EXEMPT_REPO_PATHS`.
- **Acceptance**: `specs/pipeline/steps/bl1226StepHandlerMkdtempGateSteps.js`
  (new), driving the real `assessPilotMkdtempConvention` /
  `classifyMkdtempConventionPath` against scratch fixture roots — never a
  reimplementation. The feature file
  (`specs/features/BL-1226-mkdtemp-convention-gate-covers-step-handlers.feature`)
  was pre-minted by the specifier and was NOT modified; checked first per
  standing practice.
- **Unit tests**: extended `extension/test/pilotMkdtempConventionCheck.test.js`
  with the scope-classification table (mirrors scenario 05's own table),
  the steps-lane route-based detection cases (mirrors scenario 04's outline,
  all five example base expressions plus the clean route), the
  untouched-legacy-file case (scenario 03), self-exemption for the steps
  lane's own helper and this ticket's step handler, a regression check that
  the extension/test lane's narrow detector stays unaffected by an exotic
  spelling, and a detector-independence check (the steps detector loads
  without ever loading the test-lane one, for a call with only a steps path
  in scope).

## BL-654 invariants — non-vacuous property tests

`extension/test/bl1226MkdtempConventionGateStepsInvariants.property.test.js`
(new), both declared invariants:

- **P1 (invariant 1)**: for a randomly generated mixed set of touched/
  untouched files across both lanes (every draw guarantees at least one
  untouched-and-raw file by construction), an untouched file is never in
  `scannedPaths` and never named in `violations`. 200 runs.
- **P2 (invariant 2)**: for a randomly generated base expression (drawn
  WIDER than the ticket's own five examples — arbitrary identifier-like
  method-call and property-access shapes, never the five canonical
  spellings verbatim) fed into a touched steps-lane file's `mkdtempSync(`
  call, the check always reports exactly one violation naming that file —
  and, the other direction, a file routed through the shared helper is
  always clean, whatever it is named. 200 + 100 runs.

**Non-vacuity, two separate deliberate breaks, both restored and reverified
byte-identical via diff against a saved backup:**

1. Widened the scan to also sweep every sibling `.js` file in the touched
   steps directory (a plausible "catch more of the leak class"
   over-widening). Caught by P1 (an untouched sibling was reported scanned)
   and, as a side effect, by P2 (duplicate scan of the same file). Restored.
2. Reverted the steps lane's detector selection to the narrow, spelling-based
   one (`loadStepsDetector = loadRawMkdtempDetector` instead of the any-base
   one) — directly targeting invariant 2's own claim. P2 caught it
   immediately: a randomly generated base expression (`aa.tmpdir()`, not one
   of the five canonical spellings) went unreported. Restored, confirmed
   byte-identical via diff, re-verified all three property tests green.
