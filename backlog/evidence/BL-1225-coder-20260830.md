# BL-1225 — coder pass, 2026-08-30

A sync-initiated restart leaves a readable trail.

## 1. The two changes

**Log truncation.** `restart-operator-group!` spawned the replacement with
`{:out (str log-file) :err (str log-file)}`. A path STRING in
babashka.process's `:out` truncates — reproduced here before changing
anything, not taken from the ticket:

```
(spit f "PRE-EXISTING\n")
@(p/process {:out f :err f} "bash" "-c" "echo NEWLINE")
;; => "NEWLINE\n"     ← PRE-EXISTING gone

@(p/process {:out :append :out-file (File. f) ...} ...)
;; => "PRE-EXISTING\nNEWLINE\n"
```

The opts map now comes from a new pure `build-freshness-lib/operator-log-spawn-opts`,
which returns `:out :append` with an `:out-file`, stderr pointed at the same
file, `:dir` unchanged. Matches what the project's own normal entry point
`start_operator_runtime.sh` already does with a plain `>>`.

**Caller attribution.** `restart-handoffd-group!` now passes
`:extra-env {"SWARMFORGE_DAEMON_START_CALLER" build-freshness-lib/daemon-start-caller}`.
`start_handoff_daemon.sh:48` has always interpolated that variable into its
start-audit line and fallen back to `unknown`; nothing had ever set it.

Nothing else moved. Which groups a sync restarts, and in what order, is
untouched; BL-433's stop-file, its `status.json` deletion and its bounded
settle-wait are byte-for-byte unchanged.

## 2. required_wiring

`swarmforge/scripts/build_freshness_cli.bb::SWARMFORGE_DAEMON_START_CALLER`
— the literal variable name is in the CLI, inside `restart-handoffd-group!`'s
own form, which is where the declaration puts it. Only the VALUE lives in
the lib, so it has one source and is testable. Parsed rather than assumed:
the lib test runner asserts (a) that the text between `(defn- restart-handoffd-group!`
and its next blank line contains `SWARMFORGE_DAEMON_START_CALLER`, and
(b) that the CLI takes the value from `build-freshness-lib/daemon-start-caller`
rather than repeating the literal. An earlier draft put the whole env map in
the lib and would have left this anchor unmatched in the CLI — caught before
committing, which is exactly what the anchor is for.

## 4. Declared invariants (BL-654) — both executable

`extension/test/bl1225SyncRestartTrailInvariants.property.test.js`,
`npm run test:properties` lane. 3 properties, all pass. Each drives a real
production artefact: invariant 1 spawns through the lib's own opts map,
invariant 2 runs the REAL `start_handoff_daemon.sh` and reads the REAL audit
log it writes.

Generator reach, asserted every run:
- invariant 1 must produce a NON-EMPTY prior log — append and truncate agree
  on an empty file, so a generator that only drew empty content would pass
  against the defect. Both the empty and non-empty cases are required.
- invariant 2 is an "if and only if", so all three start kinds are required:
  sync-initiated, direct (no caller set), and a different caller entirely.
  Generating only the sync side would prove half the invariant.

Non-vacuity, run and restored:

| deliberate break | result |
|---|---|
| opts map back to `{:out (str log-file)}` (the defect) | both invariant-1 properties FAIL |
| `daemon-start-caller` set to `"unknown"` | invariant-2 property FAILS |
| none | 3 of 3 pass |
