# BL-1461 — coder pass

Commit: this parcel · 2026-09-07 · worktree `swarmforge-coder`

## The fix

`land_step_lib.bb`'s `land-plan`: the entanglement candidate walk
(`entangled-siblings`' own internal walk, and the local `candidates`/
`lines-of` that feeds it as an optional cache) now always runs
`origin-main..commit`, never `:base`/`walk-base` — matching what BL-1446
already restored for `own-paths`/`delivered-attribution`. `:base` is still
accepted (the `own-paths` call site keeps its existing arity) but decides
nothing now; the docstring is rewritten to stop promising a bound it no
longer provides and to record why (BL-1438's re-point keeps the
never-landed range short, so the wide walk this restores is cheap again).

## Why the fix is exactly this narrow

Traced the actual defect to one line: `land-plan`'s `candidates` (used to
build `lines-of`, an optional performance cache fed into
`entangled-siblings`) and the `entangled-siblings` call itself both took
`walk-base` (defaulting to `parcel-own-base`, the last hop) as the
candidate range's lower bound. A sibling's commit absorbed before that hop
sits outside `walk-base..commit` and was never visited — regardless of
whether it was ever landed. `own-paths` was already fixed the same way by
BL-1446; this ticket is the same fix for the OTHER consumer of the same
narrowing.

`own-paths`'s own trailing `walk-base` parameter is untouched — its own
comment already says it "is accepted for arity/call-site compatibility...
but is never used as the diff boundary here" since BL-1446, so there was
nothing left to fix there.

## Unit tests — updated and extended, non-vacuous

Two pre-existing `land_step_lib_test_runner.bb` tests asserted the OLD
(buggy) behavior directly (`:base` hides a pre-base sibling) and are
updated to assert the new one (a pre-base sibling is entangled regardless
of `:base`); a third pre-existing test's expected `:entangled` set is
widened to include the pre-base sibling it previously missed. Six new
tests cover both new positions (`:before-first`, `:between`) x both
landed/unlanded, plus own-paths correctness for the unlanded case.

Reverting `land_step_lib.bb` to its pre-fix (`HEAD`) content and re-running
reproduces the exact reported defect: **9 failures**, all and only in the
updated/new assertions (the "still names the pre-base sibling" pattern) —
every other pre-existing test stays green. Restored; **ALL PASS** again.
