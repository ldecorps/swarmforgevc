# BL-1608 — coder, 2026-09-16

## What was wrong

`specs/features/BL-1185-work-note-missing-task-header-defers-hard-seat.feature`
scenario 02 failed on main:

```
Scenario "the hard seat claims an ambulance patient Work note when easy is idle" failed at step "Then the Work note is claimed rather than skipped as defer-better-fit": hard should claim Work note; out=NO_TASK
```

BL-1185 (2026-08-27, 8fa2a5c2fb) fixed this with `task-name-for-difficulty`:
prefer the `task:` header, else the `Work BL-...` slug from a note's
message. BL-1167's land the same afternoon (ccc63d8cfd, "bypass tier
routing when stage seats share the same model") rewrote
`difficulty-allows-claim?`'s signature and replaced that call with a bare
`(handoff-lib/header-field handoff-file "task")` read, silently reverting
BL-1185 — a Work note carries no `task:` header (task is git_handoff-only),
so a hard seat with an idle easy sibling deferred every Work note and
printed `NO_TASK` while the ambulance patient's mail sat in `new/`.
`apply-effort-for-task!` (BL-1316) read the same bare header at the claim
moment, so a claimed Work note also applied no ticket-specific effort.

## The fix

`swarmforge/scripts/ready_for_next_task.bb`:
- Restored the `supersede_lib.bb` require.
- Restored the shared attribution as `claim-task-name` (public, not
  `defn-`, so the unit test runner can drive it directly): prefers the
  `task:` header, else `supersede-lib/task-name-from-content` on the
  note's own message, else `nil` — never invents a task header on a
  `type: note`.
- Both claim-time cost readers now resolve the task through it:
  `apply-effort-for-task!` and `difficulty-allows-claim?` — exactly 2
  call sites, verified by the acceptance feature's own source census.
  Line 248's `claim-task` (the rework-claim decision, BL-1004,
  git_handoff-only) is untouched — it was never a cost reader.
- Guarded the script's own trailing `(-main)` with
  `(when (= *file* (System/getProperty "babashka.file")) (-main))` — the
  same idiom `apply_shift_schedule.bb`/`babysitter_waive.bb` already use.
  Without this, `load-file`-ing the script (required to unit-test
  `claim-task-name` directly, and by the acceptance step handler) fired
  the real claim loop against whatever mailbox state the loading process
  happened to be sitting in — a live hazard, not just a test-isolation
  nicety. Necessary to test the function safely at all; not itself part
  of BL-1185/BL-1167's attribution fault.
