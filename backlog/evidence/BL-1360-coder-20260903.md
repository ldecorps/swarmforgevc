| # | Invariant | Property | Non-vacuity: broken implementation → failures |
|---|-----------|----------|-----------------------------------------------|
| 1 | every ceremony is sent through `swarm_handoff.sh` | **P1** — a delivered copy carries the envelope headers only the tool stamps (`id`/`from`/`recipient`/`created_at`/`enqueued_at`); `--dry-run` reaches no mailbox; a refusal delivers nothing | made the CLI write a recipient inbox directly → **60 FAIL P1** |
| 2 | a composed message is one line within the cap and never truncates the ticket or the commit | **P2** — over generated ceremonies/tickets/commits, compose either refuses or yields one line ≤80 chars containing both facts verbatim | replaced form-selection with `subs` truncation → **148 FAIL P2** |
| 3 | recipient list and priority have ONE definition, pinned to `handoff-protocol.md` rather than restated (BL-897) | **P3** — parses the document's `QA → worktree roles` / `QA → coordinator` steps and the stated cap, and asserts the lib agrees | dropped `hardender` from the lib's list → **FAIL P3** |

**Generator reach is asserted, not hoped for.** P2 draws ticket-id *lengths*
across the cap boundary and then fails the run outright unless all three
outcomes — roomy form chosen, prose shortened, composition refused — were each
observed. Without that floor the property would have sampled the roomy form
forever and proved nothing about shortening, which is the exact failure shape
BL-654 names.

## A real defect the acceptance driver caught

Scenario 03 ("composing never bypasses a send-time gate") failed on first run
with `exitCode 2` and **empty stderr**: the gate's refusal was swallowed whole.
Cause: the wrapper printed the captured stderr inside `(binding [*out* *err*] …)`
but called `(flush)` *after* the binding had been popped, so it flushed stdout
twice and never stderr. `print` does not flush on newline the way `println`
does, which is why the composer's own `println` refusals were visible and the
passed-through one was not. Each stream is now flushed inside its own binding,
and `test_ceremony_handoff_cli.sh` §3 pins it.
