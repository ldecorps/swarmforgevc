# BL-1602 — coder evidence, 2026-09-16

## The fix

`specs/pipeline/steps/lib/sendGitHandoffTwoCall.js` (new): the shared
two-call sender, `sendGitHandoffTwoCall(bb, args, opts, spawnFn =
spawnSync)`. Runs the sender once; if the result is non-zero AND its
combined stdout+stderr contains `AUDIT_REQUIRED`, runs the identical
invocation exactly once more and returns THAT result; otherwise returns
the first. Never a third call, never an env bypass — the audit protocol
(Article 2.3, BL-1529) and nothing else. `spawnFn` is injected so
scenario 01 drives the protocol itself over a fake sender thunk.

Nine JavaScript drivers now send through the helper (each a one-hunk
`spawnSync(...) -> sendGitHandoffTwoCall(...)` swap at their real
`swarm_handoff.bb` call site, keeping their own assertions unchanged):
`bl1001DifficultyAwareSeatRoutingSteps.js`, `bl1004ReworkClaimSteps.js`,
`bl1167SameModelSeatRoutingSteps.js`,
`bl1185WorkNoteMissingTaskHeaderSteps.js` (both its call sites, for
population consistency — see the BL-1185 note below),
`bl1317AdaptEffortSteps.js` (this one's OWN prior "fix" was the actual
defect: it called `sendOnce()` twice unconditionally and asserted
`status === 0` on the FIRST call too, which fails outright since a fresh
draft's first call is exactly the non-zero `AUDIT_REQUIRED` challenge —
replaced with the helper, which asserts only on the one real result),
`bl606RequiredStagesRoutingSteps.js`, `bl623RoutingSkipTrailSteps.js`
(both share the `SWARM_HANDOFF` constant + `sendHandoff`/`send` pattern),
`bl983StageQueueSteps.js` (both its call sites — the initial send and the
seat's own forward).

The two bash drivers, `specs/pipeline/steps/lib/bl1192TaskScopeGateCli.sh`
and `specs/pipeline/steps/lib/bl1276AcceptanceExemptionCli.sh`, adopt
`bl1240UnregisteredTestGateCli.sh`'s own `send_once` idiom verbatim
(lines 118–138 there): wrap the single `bb "$SWARM_HANDOFF" "$DRAFT"`
call in a `send_once` function, call it once, and call it again only if
`AUDIT_REQUIRED` appears in the captured stdout/stderr.

`corruptHandoffNeverDispatchedSteps.js` needed no change: it writes a
deliberately corrupt handoff FILE directly into the fixture inbox (to
exercise handoffd's own quarantine), never spawning `swarm_handoff.bb` as
a subprocess at all — there is no audit call site in it to protect. It
is still part of the eleven-member population (the census matches it),
answering the population check by construction (verified below).

No feature file or step text changed anywhere — invariant 2.
