# Two unowned reds found while verifying BL-1447's qa_e2e_procedure step 1

Both confirmed pre-existing and unrelated to this parcel's diff: reproduced
identically against the pre-BL-1447 `land_step_lib.bb`/`land_step_cli.bb`
(commit `a0a97bee67`), with no code from this parcel present at all.

## 1. `specs/features/BL-1272-a-landed-sibling-is-not-reported-as-entangled.feature`

Scenario "A sibling is reported as entangled only on positive evidence it
is unlanded", Example row 4 (`unreadable` state) fails:

```
the unreadable sibling was not named as entangled: LAND_ESCALATE
land-step: could not read own.txt's attribution
```

The real `land_step_cli.bb` prints `LAND_ESCALATE` and the raw `own-paths`
warning, but never an `entanglement-note` naming the sibling - so
`namedAsEntangled`'s fallback text search (`entangled tip - sibling
ticket(s)...`) finds nothing. Identical output, byte for byte, against
both the pre- and post-BL-1447 library. Cause (not fixed here, out of
this ticket's scope - BL-1447 is about a REPLAY's completeness, not this
escalate path): `land-plan`'s `(if (nil? paths) {:action :escalate
:reason ...} ...)` branch (own-paths returning nil on an unreadable
attribution) has never included `:unlanded` in its return map, so the
CLI's `entanglement-note` printing (gated on `:unlanded` being present)
never fires for this specific escalate path - only for one reached via a
successful `entangled-siblings` call carrying a real unlanded set through
a LATER branch. This "nil paths" branch is the FIRST cond clause in
`land-plan`, upstream of where `:unlanded` starts getting threaded.

## 2. `specs/features/BL-1297-a-merge-commits-own-paths-are-not-empty.feature`

Scenario "A parcel whose only attributed commit is a merge still has
content to replay" fails:

```
the land step did not reach its replay: {:action :escalate, :reason
"land-step: refusing to replay BL-1174 - every delivered path was
attributed to an unlanded sibling, leaving nothing of this ticket's own
contribution to land: extension/src/parcel.ts -> BL-9999;
extension/src/trunk.ts -> BL-9999"}
```

`own-paths`'s BL-1343 "nothing left to replay" refusal (every delivered
path excluded to an unlanded sibling) fires for this fixture on both the
pre- and post-BL-1447 library, identically - the scenario's own fixture
(a merge commit as the parcel's only attributed commit) no longer produces
what the scenario's title expects ("still has content to replay").
