- `merge-authored-paths` reads `git diff-tree --cc -r <commit>` and keeps only
  paths with a `diff --cc`/`diff --combined` header — the DENSE combined-diff
  header, which git only emits for a path where the merge result differs from
  every parent's own resolution of a real conflict, not merely from each
  parent individually. This is the correct discriminator: `--cc --name-only`
  (what the ticket's own `required_wiring` anchor names, and what the coder's
  own audit flags as satisfied "for the wrong reason") would have reinstated
  the exact over-report this ticket fixes, per the coder's own measurement
  against the live `5d4486eb08` tip. Confirmed by re-reading that measurement
  table rather than taking the claim on faith.
- The `reduce` in `path-owner-tickets` treats an unreadable combined diff as
  `(reduced nil)` — propagating blindness through `attributing`, so the outer
  `when attributing` makes the whole path unaccounted-for rather than silently
  reading "the merge wrote nothing." Matches this file's existing fail-open
  convention (the same posture `own-paths`' `blocking-for` already takes) and
  invariant 1's requirement that a genuine entanglement is never silently
  waved through.
- The one case a merge CAN legitimately author — a resolved conflict — still
  counts, because `merge-authored-paths` reports the path whenever the
  combined diff produced a patch for it, regardless of merge/non-merge origin
  further back. Cross-checked against the coder's own fixture 05 (a resolved
  merge conflict still owns its path) and the property runner's
  `:resolved-merge` shape, both green.
- `merge-authored-paths*` (memoized per `(root, commit)`) is safe: a commit
  sha addresses immutable content, so memoizing on it cannot go stale within
  one process run — same reasoning as `own-paths`' existing `blocking-for`
  memo, which this parcel's self-audit explicitly modeled it on.
