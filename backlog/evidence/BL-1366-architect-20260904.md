## Invariants — verified in the actual code, not from evidence alone

1. **Never force-push, at most one rematch.** `land_push_ff_only()` is a plain
   `git push origin "$sha:refs/heads/main"` with no `-f`/`--force` anywhere —
   the ref-update itself is what enforces fast-forward-only. `run_land()`
   rematches (`git rebase origin/main "$land_sha"`) exactly once on a
   rejected push (lines ~170-191); a second rejection returns 5 without a
   second rematch and without forcing.
2. **Lock released on every exit path.** `trap land_release_trap EXIT INT TERM`
   is installed at the top of `run_land()`, before the lock is ever taken.
   `LAND_LOCK_HELD` is set only once `land_acquire_with_deadline()` actually
   holds the lock, and the trap releases iff that flag is set — so an
   entanglement return before acquisition is a correct no-op, and every other
   return (rejected push, timeout, success) is released via the trap, not an
   enumerated call at each return site.
3. **`LAND_ESCALATE` never auto-resolved.** Checked and returned (exit 3)
   *before* `land_acquire_with_deadline()` is even called — the lock is never
   taken on an escalation. Message states main is untouched and nothing was
   pushed.

Grepped the implementation for `-f`/`--force` on any push path: none.
