(`49fe963c76`) added the identical shape — one `||`/`&&` guard condition

(`drainAgentSessions`, `clearStaleSwarmState`, `stopSwarm`,

Split out `socketRefusalOrAbsent(socketPath, refusedMsg, noneMsg)`: the
shared two-way ternary every `socketOwnedByTarget` call site needs,
extracted once instead of inlined four times (also closes a potential
DRY clone the four near-identical ternaries would otherwise have
become). This removes exactly the ternary's +1 complexity from each of
the three sites still over 5 complexity, leaving only the necessary
`||`/`&&` guard condition — the irreducible cost of the fix itself, not
an avoidable regression. Post-split: `stopSwarm` complexity=6, CRAP=6.00
(back at the threshold, not over); `stopSwarmCompletely` complexity=10,

## Coverage gap closed: physicalPath's unreachable-ancestor fallback

`physicalPath`'s `if (parent === head) { return path.resolve(p); }` (the
"no existing ancestor resolves at all" terminal case) had 0% coverage —

so no real-fixture test can walk this branch. Added

## Hand-mutation of the security-critical boundary check

`socketOwnedByTarget`'s comparison is
`(sockDir + path.sep).startsWith(ownedPrefix)` where `ownedPrefix =
path.join(root, '.swarmforge') + path.sep`. Hand-mutated the compiled
`out/swarm/swarmStopper.js` at the exact line, ran `npx vitest run
test/stop.test.js test/swarmStopper.test.js` (44 tests) against each
mutant, restored from a saved original afterward (confirmed
`git status --short` clean throughout — `out/` is gitignored, so no
tracked-file risk regardless):

- Dropping `+ path.sep` from `ownedPrefix` (the classic bare
  string-prefix bug: a sibling directory like `.swarmforge-evil/` would
  satisfy `startsWith('.../.swarmforge')` without ever being under the
  real `.swarmforge/` tree): **survived** — a real gap, no existing
  fixture in either test file ever tried a text-prefix sibling. Closed
  with the new test `socketOwnedByTarget refuses a sibling directory
  that only shares ".swarmforge" as a text prefix`; re-mutated and
  confirmed this test alone catches it (1 failure, the others
  unaffected).
- Dropping `+ path.sep` from the `sockDir` side of the comparison
  (`sockDir.startsWith(ownedPrefix)` without ever closing the socket
  directory's own path to a boundary): killed by the same new test
  (the sibling-prefix fixture also discriminates this half).
- The physicalPath hand-mutation above (stubbed `fs.realpathSync`
  throwing always) is itself the hand-mutant for the unreachable-ancestor
  branch — see "Coverage gap closed" above; both of its new tests pass
  against the real code and would fail if the terminal `return
  path.resolve(p)` were replaced with e.g. an infinite loop or a thrown
  error, since the function would then throw/hang instead of returning a
  boolean.

Zero silent survivors among the mutants actually tried: every one found
is either killed by a new test (confirmed by re-running the mutant) or
not applicable here (no equivalents were found among the ones checked).
