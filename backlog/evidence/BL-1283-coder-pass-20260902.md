## Scenario 05 — the failure direction, stated rather than assumed

`probeSwarmLiveness` has a recorded false-green history on this host, so the
review states what a WRONG answer costs in each direction, driving the real
tick with the probe lying:

- probe says asleep while the pack works → **frozen-while-working**: board and
  pin untouched, so the board goes stale but is never wrong-by-writing.
- probe says awake while the pack idles → **reposting-while-idle**: the exact
  waste the hotfix exists to stop; costs noise, not correctness.

Both directions are recoverable and neither corrupts state, which is what
makes the gate safe to depend on a probe with this history. The Outline
validates `<reality>`/`<probe>`/`<outcome>` against explicit KNOWN_VALUES
tables and throws on an unknown value — no passthrough.
