  `record-verification` (keyed on `category::ticket`, invariant 1),

- `swarmforge/scripts/verification_debt_ledger_update.bb` — the recorder
  CLI: `--record <category> --ticket <id> --role <role> --description
  "<text>" [--evidence <path>] [--on YYYY-MM-DD]`. Refuses (exit 1, naming
  the field, nothing written) a non-kebab-case category, a non-`BL-`/`GH-`
  ticket, or a blank description. A redelivered (category, ticket) is a
  no-op: exit 0, `VERIFICATION_DEBT_ALREADY_RECORDED <category> <ticket>`.
  A successful record commits via `commit_integrity_lib.bb`'s
  `commit-with-integrity!`, pathspec-scoped to the ledger file alone,
  "By <role>." in the body; a commit failure reverts the on-disk file to
  its pre-write content and exits non-zero. When the record leaves the
  category at/over threshold with no open-ticket owner, also prints
  `VERIFICATION_DEBT_UNOWNED <category> count=<n> threshold=<t>`.
- `swarmforge/scripts/verification_debt_ledger_read.bb` — the reader CLI:
  one JSON object, `categories.<name>` = `{count, threshold,

  Read-only; never touches the ledger file.

## A bounce-shaped fix caught before it shipped

The recorder's first commit-message draft led the subject with the
ticket the row is ABOUT (`verification-debt: record land-path-ownership
for BL-1711`). Seeding the real four rows hit the BL-1544 merge/commit
guard immediately: BL-1711 is closed (`backlog/done/`), and the guard
refuses a commit whose subject leads with a closed ticket's id. Fixed by
moving the category/ticket into the commit BODY and keeping the subject
untagged (`verification-debt: record a hand-verification row`) — the
guard's own suggested fix. This is a real design point for a
general-purpose recorder: the ticket a row is ABOUT is very often
already closed by the time it is being seeded or re-recorded, so the
subject must never name it.
