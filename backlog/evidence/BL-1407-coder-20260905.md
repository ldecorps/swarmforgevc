316-file property suite. A non-allowlisted failing file is now re-run once,
alone, before the guard decides: if it passes alone it is a load flake
(recorded, commit allowed); if it fails alone it is a genuine regression
(refused exactly as before, naming the file). This is the guard that
refused five unrelated BL-1370 commits across 2.5 hours on 2026-09-04, a

## Addendum: `run_bounded` gains its own BL-1124 canary and kill-reap

The ticket's own "How" direction says "Keep BL-1124's HEAD-unchanged canary
around the re-run as around the main run" — the first pass above did not do
this: `run_bounded` (the function every re-run goes through) had no canary
of its own and no signal trap, so (a) a re-run that itself mutated the
shared checkout would go undetected (the main run's `BEFORE`/
`report_canary_once` machinery is single-shot — `CANARY_DONE` latches true
right after the main run, per its own comment — so it never re-arms for
the re-run phase), and (b) killing the guard while a re-run's subprocess
was alive had no trap to reap that subprocess's process group, unlike the
main run's `on_interrupt`.

Fixed by making `run_bounded` self-contained for both concerns: it now
takes its own `bl1124_snapshot` before launching its subprocess and asserts
`bl1124_assert_unchanged` after (refusing and naming BL-1124 on a mismatch,
same message shape as `report_canary_once`'s), and installs its own
INT/TERM/HUP trap (saved via `trap -p` and restored after, never leaking
into the rest of the script) that reaps the subprocess's process group via
a new `run_bounded_kill_group` helper — the same grace-then-force sequence
`report_canary_once` uses for `SUITE_PID`, factored out so the ceiling-
overrun branch and the trap share one copy instead of drifting apart.

Two new scenarios cover this:

- **23**: a fixture re-run command that itself commits to the fixture repo
  (simulating a re-run mutating the shared checkout) is refused, naming
  BL-1124 in the output — the same way a main-run mutation already is.
- **24** (BL-1202 parity): a re-run fixture that backgrounds a child and
  sleeps is killed via `kill -TERM` on the guard process mid-re-run; both
  the fixture's own process and its backgrounded grandchild are confirmed
  gone (not just the immediate subprocess) within a 5s deadline, and the
  guard itself exits non-zero.

No change to the three declared invariants or their property test — this
addendum is a re-run-phase parity fix (matching machinery the main run
already had), not new observable behavior the ticket's invariants
quantify over.

## Declared invariants (BL-654)

All three have a coder-authored, non-vacuous property test in this parcel,
each shown to fail against a deliberately broken implementation (verified
live, then restored — `diff` against a pre-break backup confirmed exact
restoration):

- **Invariant 1** (a deterministic red is always refused) — broken by
  forcing the post-rerun branch to always take the "flake" path
  (`if (( 1 == 1 ))` in place of `if (( rc == 0 ))`): every `:det-red` draw
  failed (incorrectly allowed, wrongly named as a flake) — 2/2 in a 20-run
  sample.
- **Invariant 2** (every cleared flake is recorded durably) — broken by
  skipping `record_flake` on the passing branch: every `:flaky` draw failed
  (commit still correctly allowed, but no record) — 4/4 in the same sample,
  both `touches: true` and `touches: false` represented.
- **Invariant 3** (the re-run is bounded; overrun counts as failure) —
  broken by replacing `run_bounded`'s ceiling check with an unreachable
  threshold (`waited >= 999999`): every `:hang` draw failed BOTH the
  verdict check (the guard incorrectly allowed the commit once the 30s
  fixture sleep finally finished) and the wall-clock check (~30.1-30.2s
  measured, `> 15` threshold) — 2/2 in an 8-run sample; the property
  catches the defect two independent ways.

**Reachability floors**: all three kinds, and for `:flaky` both
touched-by-commit booleans, at least a few times each in the default
45-run configuration (measured 11/11/7/16 across `:det-red`,
`:flaky-touched`, `:flaky-untouched`, `:hang` — well above the 5/2/2/5
floors).
