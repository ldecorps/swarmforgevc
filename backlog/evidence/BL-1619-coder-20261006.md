## Invariants

1. "Every completed property-lane run, pass or fail, appends exactly one
   row; a run that did not complete appends none." - this is a single
   deterministic branch (`runRecorder`'s own `if
   (fs.existsSync(reportPath))`), not a state space wide enough to need a
   generative property test: BOTH its outcomes are exercised directly,
   deterministically, by real subprocess fixtures - `recordPropertyDuration.test.js`
   (pass, fail, killed) and the acceptance feature's scenarios 01/03 (the
   SAME three cases, end to end through the real CLI wrapper). A stated
   reason, not a property test: there is no wider reachable-state space
   here for a generator to explore beyond the three cases already covered
   deterministically.
2. "The recorder changes nothing vitest does: same files, same order,
   same result, same exit status - observation only." - a cross-process
   comparison (a direct vitest invocation vs. one routed through the
   recorder), not a property of any single pure, in-process module - a
   stated reason, not a property test. Encoded instead by
   `recordPropertyDuration.test.js`'s own direct-vs-through-recorder
   check and acceptance scenario 04, both comparing two REAL subprocess
   runs of the same fake-vitest stub.
