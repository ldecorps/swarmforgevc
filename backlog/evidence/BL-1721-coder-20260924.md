# BL-1721 — coder pass, 2026-09-24

## What landed

- **`extension/scripts/recordTestDuration.js`** (`confirmPoleAlone`, the
  ticket's own Scope): returns `{ms}` on a real measurement or
  `{failed: reason}` - never a bare `null` - naming which of four
  distinct failure modes actually happened: a spawn error (`result.error`),
  a timeout (`result.signal` set - the child killed after the 3x-budget
  wait; a timeout does NOT reliably set `result.error`, only `signal`, so
  the two are checked separately), a missing report file, or a report
  with no entry for the file.
- **`extension/src/tools/check-suite-file-budget.ts`** (the ticket's own
  Scope): new `PoleConfirmation` type (`{ms: number} | {failed: string}`);
  `BudgetOffender` gains two optional fields, `aloneMs` (the confirmation
  eventually succeeded but still measured at/over budget) and
  `confirmFailures` (every attempt's own failure reason, in order - set
  only when EVERY attempt failed). `confirmOffendersAlone` retries a
  failed confirmation exactly once before it counts as over budget (the
  FIRM: two failures still refuse) - a retry that succeeds under budget
  is contention exactly like a first-try success; `formatBudgetOffenders`
  now names whichever of `confirmFailures`/`aloneMs` the offender carries,
  never the bare in-suite duration alone when a confirmation was
  attempted (the 4-argument, no-`confirmAlone` callers are unaffected -
  no failure field is ever set for them, so their line is byte-identical
  to before).

   report: every new-pole line names the alone duration or each

   this small) over every confirmation-outcome shape: a first attempt
