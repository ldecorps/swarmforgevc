## Declared invariant (BL-654)

> "Exactly one number is enforceable as the boot-prefix budget, and it is the
> number the failing report names."

Encoded executably in `extension/test/bl1300SingleEnforceableBudget.property.test.js`
(`npm run test:properties`), two properties:

1. every verdict's exit code is decided by the budget read from
   `boot_prefix_budget_gate_lib.bb` itself (never a literal copy), the report
   names that number and the measured size, and names **no** second budget;
2. nothing in 42001..budget is refused — the band the retired ceiling used to
   guard in secret.

**Generator reach** is asserted by construction, not hoped for: sizes are
DERIVED from the budget (`budget + offset`, with `-1/0/+1` always drawn) and
from the 42000..44000 gap, so every run is a boundary candidate. An independent
draw over 5-digit integers would spend nearly every run far from the edge where
the property holds trivially.

**Non-vacuity proven.** With `:exit-code` changed to `(if (> size 42000) 1 0)`
in the gate lib — the literal two-live-numbers defect, one number enforced and
another reported — both properties fail:

  boot_prefix_budget_gate: FAIL — measured 43999 chars, budget 44000, ...

The lib was restored immediately (`git diff` clean for that path).

## Self-audit corrections (commit 2)

The handoff self-audit found three defects in the first commit, all in the new
pinned-tree machinery. Fixed and re-verified:

- **D1 — the pre-run sweep would eat a concurrent run's tree.** `sweepStaleFixTrees`
  removed *every* `bl1227-fix-commit-*` dir in `os.tmpdir()`. Every role worktree
  shares one tmpdir and several run this feature at once, so a sibling run's
  pinned tree could vanish mid-scenario. The sweep is now age-bounded (1 h,
  `STALE_FIX_TREE_MS`) — still collecting what a killed run left behind, which is
  all BL-971 asks — and a new unit test proves it spares a fresh dir and collects
  an aged one.
- **D2 — `git -C` on a Stryker sandbox path.** The archive used the bare
  `__dirname`-joined `REPO_ROOT`; under a mutation sandbox this module is reached
  through a sibling symlink and that path is not inside a work tree. Now
  `fs.realpathSync(REPO_ROOT)`, the same reason `bl643NonPipelineAgentsStepsGuards.test.js`
  realpaths its own root.
- **D3 — a silent failure mode with a misleading remedy.** If the pinned commit
  is unreachable (a shallow clone, a fixture tree) the step died on a bare
  non-zero exit that reads like a budget regression. It now throws naming the
  commit and the cause.

Re-verified after the corrections: acceptance **7/7**;
`bl1300HeadroomProofIsPinned.test.js` **4/4**; `tmpDirMigrationGuard` green.
