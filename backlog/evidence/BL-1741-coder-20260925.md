## The fix

`extension/test/emitLifecycleSnapshotCli.test.js` test 4 ("the compiled CLI
runs against the real repo...") ran `main()` (from
`out/tools/emit-lifecycle-snapshot`) with `process.cwd()` stubbed to the
LIVE worktree root - `main()` calls `resolveProjectRoot(process.cwd())`
then `ensureLifecycleSnapshot(projectRoot)` with no injected
`runGitLogFn`, so this did a REAL git log walk of whichever checkout ran
the suite, and only wrote/deleted/restored the live
`.swarmforge/briefing/lifecycle-snapshot.json` in its `finally`. Rewrote
it to build a REAL fixture git checkout instead (`mkFixtureCheckout`): git
init under mkdtemp, proven isolated via `rev-parse --git-common-dir`
before any further git write (BL-1390), a `.swarmforge/roles.tsv` file
(content irrelevant - `resolveProjectRoot`'s `hasRolesTsv` only checks
presence) so `resolveProjectRoot` resolves the fixture instead of
throwing, and one commit under `backlog/` so the real walk has something
to find. `runCli` (unchanged) then points `process.cwd()` at the fixture
instead of the live worktree.

Since the fixture is always brand-new with no pre-existing snapshot, the
`walked` assertion could be tightened from `typeof parsed.walked ===
'boolean'` to the actual expected value `true` - deterministic now, where
it depended on which checkout ran the suite before. The whole
preexisted/priorContent/restore dance is gone: `mkTmpDir` (already used by
the other three tests in this file) registers the fixture for the
standard per-test afterEach sweep, so no manual cleanup is needed and the
live worktree is never touched at all.
