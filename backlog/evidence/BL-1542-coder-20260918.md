## Declared invariant - encoding

"The strip's collapsed or expanded state changes only on a human tap or
on loading a stored preference - never on a pane-data refresh, a claim-age
tick, or a layout re-check." Encoded two ways:

- **By construction**: `ticketStripCollapsed` is assigned in exactly two
  places in `residentSpyUiHtml.ts` - the click handler and
  `loadTicketStripCollapsed`'s fetch `.then`. `updateTicketStrip` (the
  pane-data refresh) and the 1s claim-age tick both rewrite ticket-strip
  TEXT only and never reference `ticketStripCollapsed` or
  `applyTicketStripCollapsed` - confirmed by grep (see evidence below).
- **Property test** (coder's first authorship, BL-654):
  `extension/test/bl1542TicketStripCollapseInvariant.property.test.js`
  drives the real page under jsdom with a generated stored preference
  (boolean) and a generated tap count (0-5), asserting the final
  collapsed state is exactly `initialStored XOR (tapCount is odd)` -
  nothing else can move it. The acceptance feature's scenario 04 covers
  the refresh/tick half of the invariant directly (two REAL 4-second poll
  cycles against the real page, a single fixed case); this property
  covers the tap/load half generatively, over many tap counts and both
  starting states, not just the one the acceptance scenario 02/03 fixes.

**Non-vacuity** (staged-first restore, run 2026-09-18, recorded in this
commit): the click handler's toggle line temporarily changed from
`ticketStripCollapsed = !ticketStripCollapsed` to unconditionally
`ticketStripCollapsed = true`. The property failed on its first generated
case (seed 1237194375, counterexample `[initialStored=true, tapCount=1]`:
expected `false`, got `true`). Restored byte-for-byte (`git status
--short` showed no diff on the file after restore); the property holds
again.

## What was built

**The control**: a `▾`/`▸` button (`#ticket-strip-collapse-btn`) inside
`.ticket-strip`, its own element - never inside `#fs-font-ctrl` (the
BL-609 pane text-size control, which changes font size, not visibility,
and is untouched). Toggling adds/removes `.is-collapsed` on
`#ticket-strip`; the collapsed CSS clamps `.ticket-strip-title` to one
ellipsized line while the id and meta line stay visible (both are
siblings/children outside the title span, untouched by the rule).

**The preference** (`webUiFontSizePreference.ts`, "beside fontSizePx" per
the ticket's own direction - one store, not a second file): a new
`ticketStripCollapsed: Record<surface, boolean>` sibling top-level key in
the SAME `web-ui-font-size-preferences.json` file. Both
`writeWebUiFontSizePreference` (font size) and the new
`writeWebUiTicketStripCollapsed` now explicitly preserve the OTHER
section on every write (`readFontSizeMap`/`readTicketStripCollapsedMap`
helpers), so a font-size change never clobbers a stored collapse state
and vice versa - verified directly (unit tests "a font-size write
preserves..." and "a collapse write preserves...").

**The routes** (`webUiTicketStripCollapseRoutes.ts`, new,
`GET`/`PUT /web-ui-ticket-strip-collapsed`): byte-for-byte the same shape
`webUiFontSizeRoutes.ts` already uses (auth gate, surface-from-query,
validated-body write), wired into `bridgeServer.ts` beside
`webUiFontSizeRoutes` (same `writeRoute` array - GET and PUT both live
there since each route's own `matches` checks its method) and added to
`QUERY_TOKEN_ELIGIBLE_PATHS` (the Mini App JSON-poll query-token
allowlist, same reason `isWebUiFontSizePath` is there: the fetch cannot
set an Authorization header).

**No browser storage, ever** (Architecture Rule 3): confirmed by the
acceptance handler's storage-write wrapper (scenario 05's own check) and
the property/unit tests - nothing new touches `localStorage`/
`sessionStorage`.
