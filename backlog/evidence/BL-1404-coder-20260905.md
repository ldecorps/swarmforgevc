# BL-1404 — coder pass, 2026-09-05

`babysitter_check.bb` decided the coordinator nudge from the post-waive
`nudgeable` set but the operator escalation from the raw `findings` list —
a recorded waive stopped the nudge and left the (more expensive)
`BABYSITTER_ESCALATION` channel deciding as if nothing had ever been
waived. An Article 4.2 finding keys on an immutable commit sha, so this
was permanent: the operator was re-summoned every escalation cooldown
forever, waive or no waive.

## Declared invariants (BL-654)

Both have a coder-authored, non-vacuous property test, each shown to fail
against a deliberately broken implementation (verified live, then
restored — `diff` against a pre-break backup confirmed byte-identical
restoration every time):

- **Invariant 1** (a waive is applied once, before both channels decide;
  waived key never nudges, never escalates, still recorded suppressed) —
  **P1**: broken by reverting the property runner's own pipeline call to
  feed `decide-escalations` raw `findings` (the exact pre-fix defect) —
  412/500 cases failed (every one with at least one waived CRIT key still
  escalating). Confirms the property genuinely encodes the fix, not just
  the lib's own pre-existing correctness.
- **Invariant 2** (BL-1344's three bounds unchanged for the escalation
  channel: one key one waive, only a recorded decision waives, an unusable
  store escalates everything) — **P2**: broken by making `partition-findings`
  waive EVERY finding once ANY key is waived (a class-wide waive) — 385/500
  cases failed. **P3**: broken by making an unusable store return `:to-nudge
  []` instead of `(vec findings)` — 473/500 cases failed (every case with
  at least one CRIT finding silently dropped instead of escalating).

**Reachability floors**: all three coverage buckets (has a waived CRIT,
has an unwaived CRIT, has zero waives at all) measured 206-409 out of
500 — all well above the 50 (runs/10) floor. The "zero waives" bucket
needed a dedicated coin flip in the generator (a per-key coin alone makes
it vanish geometrically as finding count grows) — noted directly in the
property runner's own comments.
