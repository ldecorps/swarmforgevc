## What landed

- **`swarmforge/scripts/ollama_ancillary_lib.sh`** (new): the whole
  start-and-probe contract, `ollama_ancillary_ensure_ready_for_launch`.
  Portable across POSIX sh / bash 3.2 / zsh (no arrays, no bash-4-only
  builtins) since it is sourced by zsh (`swarmforge.sh`) but must also run
  standalone under bash for tests. Probes the same two paths
  `local_model_endpoint_ready` already uses (Ollama's native `/api/tags`,
  then the OpenAI `/models` path); on silence, starts `<binary> serve`
  detached (models dir / context length only set when the caller passes
  them - never guessed), waits up to a bounded, overridable interval; on
  success writes `.swarmforge/ollama/serve.json` (`owner`, `pid`,
  `startedAt`, `endpoint`); on failure, stops the process it started and
  writes no record.
- **`swarmforge/scripts/swarmforge.sh`**: new `ensure_ollama_ancillary_for_launch`,
  called right after `parse_config` - before `create_role_session` (the
  first seat-related call, line 2582) and `launch_role` (line 2638) - so a
  refusal (`exit 1`) happens before any seat exists. Detection reuses two
  things `parse_config` already resolved, never re-deriving the pack conf:
  the `AGENTS` array (`local-model` agent keyword, the
  `local-model-mono-router.conf` shape) **and** `EXTRA_CLI_ARGS` (an aider
  seat instead names the endpoint on its own window line via
  `--openai-api-base`, the shape every `ollama-*-mono-router.conf` pack
  actually uses today) - the same substring-match convention this file
  already applies to `EXTRA_CLI_ARGS` for perplexity.ai /
  dashscope.aliyuncs.com / api.b.ai. `SWARMFORGE_OLLAMA_BINARY` /
  `_MODELS_DIR` / `_CONTEXT_LENGTH` / `_WAIT_SECONDS` /
  `_POLL_INTERVAL_SECONDS` are the swarm.env keys; defaults reproduce
  today's hand-run `ollama serve` shape.
- **`specs/pipeline/steps/bl1703OllamaLaunchProbeSteps.js`** (new,

## Discovered while wiring: the agent-keyword-only detection misses every real ollama pack

My first pass detected "uses the local endpoint" via `AGENTS[i] ==
"local-model"` alone (mirroring the existing
`require_local_model_endpoint_ready` per-seat gate). Checking the actual
pack confs (`swarmforge/packs/*.conf`) before calling this done: `grep -l
openai-api-base` names eleven `ollama-*-mono-router.conf` /
`*-mono-router.conf` packs, every one an `aider` agent naming
`--openai-api-base http://127.0.0.1:11434/v1` directly on its window
line - none of them use the `local-model` agent keyword at all. Only
`local-model-mono-router.conf` does. BL-1703's own "What is wrong" section
is literally about aider seats failing at their first request - the
agent-keyword-only check would have shipped a feature that misses the
exact packs it was written for. Widened `ensure_ollama_ancillary_for_launch`
to also match `EXTRA_CLI_ARGS[i]` against the resolved endpoint URL, per
the ticket's own direction ("a window line ... naming the local endpoint
... read the pack conf the launch path already resolved").

This is wiring inside `swarmforge.sh` itself, which the acceptance feature
(driving the lib directly, per its own Background) and the property test's
lib-level check cannot observe - so `test_ollama_ancillary_launch_gate.sh`
exercises it through the real `parse_config` + `ensure_ollama_ancillary_for_launch`
call, with a fixture pack conf shaped exactly like the real
`ollama-qwen2.5-coder-mono-router.conf` window line. Non-vacuity: before
the widening, this same test failed at "01" (the stand-in ollama binary
was never invoked) - restored after the fix, both cases green.

## Invariant (BL-654)

"No seat of a pack that uses the local model endpoint is started unless
the endpoint answered the launch's probe." Two parts, each tested where it
is actually observable:

1. **The lib's own contract** (a pure, testable module):
   `extension/test/bl1703OllamaLaunchProbe.property.test.js`'s second test
   sweeps a never-answering endpoint across every (wait_seconds,
   poll_interval) combination in a small, fully enumerated space (2x2,
   constructed exhaustively rather than fc-sampled - too small a space for
   random sampling to reliably reach every value, confirmed empirically
   when an earlier fc.assert draw of 4 runs missed one of two values).
   Every combination: refused (exit 1), no record, and the process it
   started is confirmed stopped. Non-vacuity: disabled
   `ollama_ancillary_stop_pid`'s own kill - the property immediately caught
   the still-running pid; restored, diff empty, re-verified green.
2. **The call-site ordering that actually keeps a seat from starting**
   (this parcel's own diff, not a reusable module a generator can drive):
   the same file's first test reads `swarmforge.sh`'s own source and
   asserts the probe/start call's line precedes both seat-creation call
   sites (`create_role_session`, `launch_role`). Non-vacuity: removed the
   call entirely (caught: no call found), then moved it to just before
   `start_ancillary_services` - after `create_role_session` - (caught:
   line 2588 not before line 2581); both restored, diff empty, re-verified
   green.
