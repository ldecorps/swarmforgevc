## D1 — `nowMs` DI seam not wired at its one production call site (behavior)

**File:** `extension/src/bridge/bridgeServer.ts:1550`
**Class:** behavior (wiring gap, not a design change)

`captureMonoRouterLiveScreen` was changed to accept an injected clock
(`nowMs: number = Date.now()`), explicitly following — per the coder's own
evidence file — "this codebase's existing `nowMs?: number` injection
convention (`buildStageDwellState`, `buildBurnRateState`,
`capturePipelineGridLive`)". Those three sibling functions are called from
the *same* `buildJsonRoutes(targetPath, runLogPath, nowMs?)` table, and each
call site threads the enclosing `nowMs` through:

```
compute: () => buildStageDwellState(targetPath, nowMs),      // line 1534
compute: () => buildBurnRateState(targetPath, nowMs),        // line 1542
compute: () => capturePipelineGridLive(targetPath, nowMs),   // line 1554
```

`captureMonoRouterLiveScreen`'s call site, sitting between two of those
three in the same table, does not:

```
compute: () => captureMonoRouterLiveScreen(targetPath),      // line 1550
```

It silently falls back to real `Date.now()` regardless of what `nowMs` (in
turn `options.nowMs`, a bridge-server-construction-time frozen clock used
for deterministic testing — see line 1777 `buildJsonRoutes(targetPath,
runLogPath, options.nowMs)`) was supplied.

**Concrete failure scenario:** a test (or future caller) starts the bridge
with a fixed `options.nowMs` — the established pattern this codebase uses
to get deterministic `/stage-dwell`, `/burn-rate`, `/cost-rank`,
`/pipeline-board` responses — then hits `/resident-pane` twice expecting
the same frozen-clock cache semantics the sibling routes get. Because this
route ignores the injected clock, its TTL cache is driven by real wall-clock
time instead, so its behavior diverges from every other route on the same
server and cannot be tested deterministically through the server's own
established seam. No existing test exercises this (`bridgeServer.test.js`'s
three `/resident-pane` tests all call `withBridge(target, {}, ...)` with no
`nowMs` override), so nothing currently fails — but the gap is real,
unguarded, and inconsistent with the exact convention this parcel's own
evidence cites as its justification for the parameter shape.

**Remediation:** thread the enclosing `nowMs` through, matching the sibling
routes:

```
compute: () => captureMonoRouterLiveScreen(targetPath, nowMs),
```

(`nowMs` is `number | undefined` in `buildJsonRoutes`'s scope;
`captureMonoRouterLiveScreen`'s own default parameter already handles
`undefined` by falling back to `Date.now()`, so no other signature change
is needed — TypeScript will accept `nowMs` directly since the parameter
type is `number` with a default, which is assignable from `number |
undefined` at a call site... confirm via `npm run compile`; if the
optional/default interaction doesn't typecheck cleanly, an explicit
`nowMs ?? Date.now()` at the call site is the fallback.)

This is a one-line, narrowly-scoped fix — not a redesign of the draft — so
it does not conflict with the ticket's stamp-and-land posture.
