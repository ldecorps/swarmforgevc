Every test in `extension/test/telegramFrontDeskBotCli.test.js` after the
coder's own BL-1620 change passes a fake `runHandoff`, so no test in the
unit lane exercised `enqueueRoleAnswerNote`'s own DEFAULT `runHandoff`

`out/tools/telegram-front-desk-bot.js` (swapping `[cli, draftPath]` to
`[draftPath, cli]` in the default arrow) and re-running: every test in
this file, plus `deliverRoleAnswerCli.test.js` and
`bl1201DeliverRoleAnswer.test.js` (both call the default path but only
assert on state written *before* the seam fires), stayed green. The
mutant is caught by `telegramFrontDeskBotCli.property.test.js`'s
invariant 1 (real outbox-file count), but `vitest.config.mjs` — the
config Stryker mutates against — excludes `**/*.property.test.js`, so
under real mutation scope this default arrow had zero coverage.

Commit `b2dbead3d7` closes it with an isolated `node` subprocess (no
Babashka) that monkey-patches `child_process.execFile` before requiring
the compiled module, asserting the default arrow's own `[cli, draftPath]`
argument order and shape. Cost: ~150-340ms (a bare node process start),
confirmed to kill the hand-applied mutant.
