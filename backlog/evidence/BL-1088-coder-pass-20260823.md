# BL-1088 — coder pass

Commit: this parcel · 2026-08-23 · worktree `swarmforge-coder`

## The fix

`check-one!`'s `gave-up` branch read:

```clojure
(or (cooldown-elapsed? …) (and (:pid entry) (not (pid-alive? (:pid entry)))))
```

The second disjunct is gone. A child reaches `gave-up` by crash-looping until
its budget is spent, so its recorded process is **always** dead — the `or`
short-circuited true on the very next tick and the cooldown six supervisors
declare never applied to the one case it exists to bound. Liveness of the
corpse is not new information; it is the definition of the state.

BL-403's guard is untouched: the re-arm still `kill-pid!`s whatever is recorded
before spawning, because a `gave-up` entry's pid can still be alive (`stalled`
is entered from `running` without ever checking liveness).

## Measured, both directions

| | spawns |
|---|---|
| with the defect, one full 900000ms window at the real 2000ms cadence | **104 spawns across 449 ticks** |
| after the fix, same window | **0** |

Not 449, because after each re-arm the child runs, crashes back through its
budget, and gives up again — a cycle, which is what an unbounded restart loop
actually looks like from outside.

`test_front_desk_supervisor_tick.sh` — *"bl-303 supervisor-recovery-02 [not
elapsed]: still gave-up, not restarted"* — **now passes**. It has been red on
main for weeks and I reported it as a pre-existing failure three separate times
in this session's earlier parcels before it turned out to be this ticket.

## Two contradictory contracts — and a third the ticket did not know about

The ticket named two. There were **three**:

| assertion | verdict |
|---|---|
| `test_front_desk_supervisor_tick.sh` — "still gave-up, not restarted" | **kept** (the declared design) |
| `cursor_bridge_supervisor_test_runner.bb` — "gave-up with dead pid should re-arm immediately" | **retired** |
| `front_desk_supervisor_lib_test_runner.bb` — "re-arms to running without waiting for cooldown" (3 assertions) | **retired** — not named in the ticket |

Both retirements are replaced rather than deleted. The cursor-bridge runner now
checks the intent its retired assertion was really reaching for — *recover
faster than 15 minutes* — through the lever it already has:
`CURSOR_BRIDGE_GIVEUP_COOLDOWN_MS`. A shorter configured cooldown re-arms
sooner; the default one holds the child down. That serves the cursor bridge
without removing the bound for the other five supervisors.

A sweep for any further contradicting assertion found none.

## BL-303's own feature could not see this — worth someone's attention

`specs/features/BL-303-supervisor-giveup-recovery.feature` scenario 2 is
literally *"a given-up child is re-armed only once the cooldown has passed"* —
the exact contract. It passes **with the defect restored** and without it, so
its rows never exercise the dead-pid case. The acceptance feature that names
this contract was blind to its violation, which is part of why the defect
survived a year of green runs. Surfaced, not fixed: widening BL-303's rows is
not this ticket's scope, and minting is the specifier's.

## Declared invariants (BL-654) — all three encoded, non-vacuity measured

`swarmforge/scripts/test/bl1088_giveup_cooldown_property_runner.bb`, 200 runs.
The cooldown is a **free variable**, because a supervisor lowering its own is
the sanctioned lever — the fix has to hold for every configured value, not just
the 900000ms default. The clock is **derived** from it rather than drawn: a
uniform draw lands on the boundary essentially never, and the boundary is where
an off-by-one lives.

| property | invariant | breaks that kill it |
|---|---|---|
| P1 | 1 | dead-pid disjunct **93**; never re-arm **260**; always re-arm **210** |
| P2 | 2 (timed, never terminal) | never re-arm **400** |
| P3 | 3 (one contract per behaviour) | — see note |
| P4 | armed-ness | dead-pid disjunct **30**; always re-arm **68** |
| P5 | BL-403's kill guard | never re-arm **200**; drop the guard **200** |

P1 is stated as an **equivalence** — re-armed *iff* elapsed — with liveness a
free variable, because *"whatever the liveness"* is the whole clause. One-way
it would be satisfied by a function that never re-arms, which is BL-303's
sticky give-up. P2 is stated as **reachability**: for every entry there exists
a later instant at which it re-arms with a fresh budget. P4 exists because P1's
"not before" half and P3 are both satisfied by a child never respawned at all.

**P3 is a claim about the source tree**, so no break to the lib trips it — the
only thing that does is reinstating a contradictory assertion in a test file.
It scans every test file for an assertion demanding a re-arm justified by a
dead pid.

**It found three offenders on its first run, and all three were prose** — two
of them this ticket's own retirement notes explaining why the contract is gone.
A source scan that cannot tell code from a comment greens on prose, which is a
trap this repo has already been bitten by. Comments are now stripped before
scanning, and what survives is assertion text — which is exactly where both
retired contracts announced themselves.
