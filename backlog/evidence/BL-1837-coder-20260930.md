## What was built

- `swarmforge/scripts/swarmforge.sh`:
  - New `role_prompt_card_path role agent` helper: for `agent == local-model`
    it maps every `@` in `role` to `-` before joining `$PROMPTS_DIR`; every
    other agent is unchanged. The single source of truth for "where does
    THIS role/agent's card live" - `write_agent_instruction_file`'s three
    callers (`generate_dormant_role_launch_artifacts`, `launch_role`,
    `run_agent_bootstrap`) and `write_role_launch_script`'s own
    `prompt_file` now all compute the path through this one function
    instead of four separate inline `$PROMPTS_DIR/${role}.md` computations.
  - `local-model)` branch: the qwen prompt now says `(your card)` instead of
    the generic `(constitution, pipeline, role, pack)` (scenario 02) -
    every other agent's wording is untouched.
- `specs/pipeline/steps/bl1837LocalSeatCardPathSteps.js` - drives the real
  `write_agent_instruction_file` + `write_role_launch_script` (the same two
  calls `launch_role` makes) over a real mkdtemp fixture via `zsh -c`, the
  same invocation shape `test_local_model_seat.sh` already uses.
- `extension/test/bl1837LocalSeatCardPathInvariants.property.test.js` - the
  ticket's declared invariant ("no local-model seat's launch prompt
  contains an '@' character") as an executable property, driving the real
  script against generated `coder@<variant>` role names. Non-vacuous:
  reverting `role_prompt_card_path` to the bare pre-fix path failed it
  immediately (`expected no "@" ... coder@A-0.md`); restored, green again.
