## A fixture gap found while building case 1 — committer identity

Every PRE-EXISTING case in this test file that exercises a cherry-pick
only reaches a `:refused`/no-reapply outcome, so `take-up!`'s own internal
`git cherry-pick` (which auto-commits with no `-c` override, unlike this
file's `commit!` helper) never actually had to complete a commit before.
Case 1 is the first in this file where a cherry-pick must SUCCEED, and
the host's git has no usable default identity (`fatal: empty ident name
(for <user@HOST.>) not allowed`) — confirmed by reproducing the bare
`git switch` + `git cherry-pick` sequence directly against a throwaway
fixture, isolated from the project's own code. Fixed by setting a
persistent `user.email`/`user.name`/`commit.gpgsign false` on the fixture
repo before any case that can genuinely re-apply, matching the BL-2044
property runner's own existing fixture-setup convention (lines 89-91 of
`bl2044_seat_commits_survive_line_move_property_runner.bb`) rather than
inventing a second way to do it.
