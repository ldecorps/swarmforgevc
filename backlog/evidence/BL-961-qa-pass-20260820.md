## G4 — invariant 1, measured across every role

By construction the exported value cannot disagree with the `--pack` selector: `launch_pack_name="$(basename "$CONFIG_FILE" .conf)"` (`swarmforge.sh:1519`) derives it from the conf the launcher actually loaded, so the env var and the selector are the same fact read once.

Measured as well, generating a full 7-role pack through the harness pattern the ticket names:

```
   7 export SWARMFORGE_PACK='full-forge'
  scripts generated: 7
```

Every generated role script carries the identical value, and it equals the loaded conf's basename. Under the default conf the same generation yields `'swarmforge'` (G6), so the value tracks the conf rather than being hardcoded.

## A harness failure that was mine, not the code's — and is already ticketed

The first two attempts at steps 1–2 reported the export MISSING. That was a false alarm from QA's own fixture: `mktemp -d` produced a root whose derived tmux socket path was 101 characters, one over the OS limit, so `resolve_swarm_socket.bb` aborted and `write_role_launch_script` never ran — the launch directory was empty rather than the export being absent. Re-running with a short root produced the correct export immediately.

Worth recording because **this exact failure mode is minted in this very parcel** as `BL-974` ("shell fixtures overrun socket guard and fail silently", `backlog/paused/`). A fixture that fails this way looks indistinguishable from a missing feature, which is how it nearly became a spurious bounce here.
