# BL-1359 — CODER PASS, 20260903

## The defect, re-measured before changing anything

The ticket asks for measurement rather than reading, so the two commands were
run on live history first:

| commit | `-m --first-parent` | `-m` alone | two-tree vs first parent |
|---|---|---|---|
| `15dc336877` | 54 | 54 | **7** |
| `e3ce579112` | 38 | 38 | **7** |
| `f8dc07963` (BL-590's case) | 38 | 38 | **20** |

The first two columns being byte-identical IS the defect: `--first-parent` is a
revision-traversal option, so on a single named commit it does nothing and `-m`
alone decides the output — one diff section per parent, i.e. the union of the
diffs against every parent.

## What changed

`swarmforge/scripts/babysitter_check.bb`:

- `commit-first-parent` (new) resolves `<sha>^1`, answering nil on git failure.
- `commit-touched-paths` asks the TWO-TREE diff `diff-tree ... -r <p1> <sha>`
  for a merge — what the file's comment always claimed and the command never
  did. Non-merge commits are untouched (invariant 3).
- Both comments that stated the false claim are corrected in this parcel, as
  the ticket requires: `babysitter_check.bb`'s own paragraph and the one in
  `babysitterd_sweep_lib.bb` that restated it for the classifier.

**The fix reached `offender-row`, and the ticket asked for that to be said out
loud rather than done quietly.** `commit-touched-paths` answers nil when a git
call could not run, and `offender-row` folded that into `(or touched [])` — i.e.
into CLEAN. A read that failed and a commit that touched nothing are the two
answers a safety gate must never conflate, and narrowing the merge charge adds
one more call that can fail (resolving the first parent), so leaving it would
have converted a git failure into a silent pass on exactly the path this ticket
touches. `(nil? touched)` now yields `::adjudication-failed`, which
`assemble-offending-commits` already turns into a whole-sweep
ancestry-unavailable. This is invariant 2, and it was NOT reachable before.

`merge-parent-facts` and `adjudicate-merge-paths` are unchanged, as the ticket
predicted.
