## Declared invariant - no new property test, and why

"The count reads only tool-result records stamped at or after the
origin, and counts a record only when a line of its output starts with
the guard's note text."

Both halves are already pinned directly by the acceptance feature's own
scenarios - scenario 01 (`notes-at-or-after-the-origin-are-counted`)
exercises the origin-stamp half, scenario 02
(`a-quoted-phrase-is-not-a-note`) exercises the line-start half - not
merely incidentally, but as each scenario's whole stated purpose.

This ticket's own "What is wanted" is explicit the only files to change
are the lib and the step handler (a deliberate scope lock, after three
same-day loop-halts on this code area), and architect is skipped for
this slice (`stage_skip_reasons.architect`: "a pure counter and a file
lookup... no boundary moves"), so there is no downstream check expecting
a `*.property.test.js` file here. Adding one would mean a third file
outside that lock for an invariant the acceptance scenarios already
prove directly. If QA or a future pass wants a generalized property
beyond the two pinned scenarios, that is a follow-up, not a gap in this
slice's own declared invariant coverage.
