## A live flake found and fixed in the ACCEPTANCE DRIVER (not production code)

`run_bb_suite.sh --list | grep -Fxq "$FILE"` measured roughly 1-in-5 to
1-in-8 false negatives on this host under its own live-swarm contention
(load average 7-10 during authoring, several concurrent bb/JVM processes
from other roles). Isolated by elimination:
- The manifest file itself is stable (`md5sum` unchanged across every
  repeat).
- `suite_inventory_cli.bb` run directly: 10/10 exit 0, consistent output.
- `run_bb_suite.sh --list` redirected to a FILE first, then grepped: 0/20
  and 0/30 misses across two separate runs.
- The SAME command PIPED directly into `grep -Fxq` (which stops reading as
  soon as it finds a match, closing its end of the pipe early): reproduced
  misses at roughly the rates above, repeatedly.
- Switching to `grep -Fxc` (reads the full stream, no early close): 0/30
  misses, then 15/15 and 10/10 clean on the two files this ticket adds.

This is a pipe-closure race under host contention in the ACCEPTANCE
DRIVER's own shell plumbing, not a defect in `run_bb_suite.sh` (out of
scope to touch per the ticket) and not a defect in the manifest rows
(stable and correct throughout). Fixed by reading the full `--list` output
rather than early-exiting on first match, in the new driver file only.
