## What changed, and the one design call the ticket left open

The ticket said the short arity "should still GET one, or should not compile.
Which of those it is, is the architect's call" — but acceptance scenario 05
("a staleness check that was never asked for a grace still applies one")
settles the first half, so the choice was only about the second. **Both**, in
the end:

| | before | after |
|---|---|---|
| grace-less call | `(poll-heartbeat-stale? hb now stall)` — silently no grace | **arity error** |
| grace-length omitted | did not exist | `(… hb now stall started-at)` → `default-startup-grace-ms` (90000) |
| explicit | `(… hb now stall started-at grace)` | unchanged |

`default-startup-grace-ms` is 90000 — the value `cursor_bridge_supervisor.bb`
had already chosen, not a third number.

The 3-arity is retired rather than repaired because it could not be repaired:
it has no spawn time to measure a grace from. Its dead third argument
(`stall-ms` passed into the grace slot) is what made it read correct to a
reviewer, so leaving a grace-less form reachable under any spelling keeps the
trap. Omitting the spawn time is now loud.

One residual door is closed too: `(:started-at-ms entry)` reads **nil** on an
entry that has not started, and both supervisors compute the staleness check
eagerly for every entry each tick. Under the defaulting arity a nil spawn time
answers *not stalled* — never the immediate stall that was the defect. The
explicit 5-arity keeps nil meaning "no spawn time to measure from", which is a
statement rather than an accident, and is what the BL-370 assertions use.

Both supervisors now pass `(:started-at-ms entry)` with their own env-tunable
grace (`ONBOARDER_HEARTBEAT_STARTUP_GRACE_MS`,
`NEGOTIATION_RELAY_HEARTBEAT_STARTUP_GRACE_MS`, both defaulting to the library
value) and clear their heartbeat file at spawn, as the reference does.
`cursor_bridge_supervisor.bb` is untouched.

## Declared invariants (BL-654) — both encoded, non-vacuity measured

`swarmforge/scripts/test/bl1043_startup_grace_property_runner.bb`, 400 runs.

The extra quantifier over BL-1035's runner is the **call form**: BL-1043 is not
a defect in the timestamp arithmetic BL-1035 fixed, it is a defect in which
call shape a supervisor reaches for, and the shipped bug lived entirely in the
arity that runner never calls.

| property | invariant | what it holds |
|---|---|---|
| P1 | 1 | never stalled inside the grace, at every call form |
| P2 | 1 ("by accident") | the defaulting form answers **identically** to an explicit default grace |
| P3 | 2 | a pre-spawn heartbeat is indistinguishable from none |
| P4 | — | armed-ness backstop: P1–P3 are all satisfied by `false` everywhere |
| P5 | 1 ("by accident") | the grace-less form does not resolve |

Non-vacuity proven by four deliberate breaks, each restored, counts measured:

| break | kills |
|---|---|
| restore the grace-less 3-arity and route the defaulting form through it (the shipped defect) | P1 40, P2 85, P3 2, **P5 3** |
| default the grace to `stall-ms` (the dead code the old third argument pretended to be) | P2 92, **P4 50** |
| return `false` unconditionally | P4 176 |
| drop the pre-spawn comparison | P1 85, P3 85 |

Two of those are the argument for the design. The shipped defect is caught 85
times by P2 and only twice by P3 — because the arithmetic was never the bug.
And a grace defaulted to the 120000ms stall window trips **P4**: it leaves a
child unstalled through the 30000ms between the real grace ending and that
window closing. A longer grace than anyone asked for is a hole in the guard.

Generator reach, asserted not hoped for: `defect-shape 85, inside-grace 137,
past-grace 137, at-boundary 126, own-heartbeat 131, no-heartbeat-at-all 176,
form-defaulted 192, form-explicit 208` — all above their floors.
