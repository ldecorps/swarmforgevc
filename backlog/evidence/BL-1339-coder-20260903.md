# BL-1339 — coder pass (2026-09-03)

BL-1334 shipped fully gated and inert: its record was written into the running
role's own worktree, while every consumer resolves the store from the target
root. Built to the human's ruling — **option 2, writer plus the land-approval
store read, both resolved from the shared root.**

## Writer

`record-land-approval!` now writes at the **shared target root** —
`git-common-dir`'s parent, via a new `shared-target-root` helper. That is the
resolver already used twelve lines below to place the replay worktree, and it
answers the same from either checkout, which is exactly the property this
record needs. No third resolver invented.

**Fail closed, as invariant 3 requires**: an unresolvable root writes NOTHING,
returns `{:ok? false}` with a reason naming the problem, and lets the land
succeed on the sanctioned override. It never falls back to the caller's
directory — that silent fallback IS this defect.

The append-vs-truncate discipline is unchanged and now lives in one small
helper rather than inline, so "append, never truncate" has one place to be
true.

## Reader (the second half of the ruling)

`is_qa_ancestor.sh` resolves `LAND_DIR` from `git rev-parse --git-common-dir`'s
parent, so the grant half answers the same wherever it is asked from. It falls
back to the relative path when git cannot answer — the pre-existing behaviour
for a caller outside a repository, where "no store found" is "no record ever
written", the same fall-through as today.

The **bounce** stores deliberately stay on the caller's directory. Moving them
is ruling option 3, which the human did not pick and which the ticket says
wants its own evidence.

## The fixture shape the ticket demanded

The ticket's diagnosis is that six stages went green because every test built
ONE root, so writer-root and reader-root were the same directory by
construction and the defect could not be expressed. So **every fixture here
has a main checkout AND a linked worktree**, and the land step runs from the
worktree.
