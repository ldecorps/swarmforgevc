# Unowned red: BL-1061's own feature, exposed by the BL-1974 fix (2026-10-05)

`specs/features/BL-1061-tunnel-ownership-fixture-binds-a-live-tunnel-name.feature`
scenario "a fixture leaked by an earlier run is swept before the table is
read" now fails deterministically (3/3 reruns) with:

```
Scenario "a fixture leaked by an earlier run is swept before the table is
read" failed at step "Then the leaked fixture is no longer alive": the
sweep did not select the leaked fixture pid <N>
```

## Root cause (not a BL-1974 regression - a pre-existing fixture flaw it unmasked)

`specs/pipeline/steps/bl1061TunnelFixtureIsolationSteps.js`'s
`spawnFixtureTunnel` names its fixture via
`fixtureTunnelName('leaked-earlier-run')` - but `fixtureTunnelName()`
always encodes the CALLING process's own `process.pid` as the creator
(`sfvc-test-<process.pid>-...`). Called from inside the running test
itself, the "creator" it encodes is the test process, which is
self-evidently alive for the scenario's whole duration - there is no
earlier, now-dead run involved at all, whatever the scenario's own name
claims.

Reproduced directly (read-only, isolated from this ticket's own fixture
root): built the exact same fixture, confirmed `creatingPidFor` correctly
reads the creator pid as the live test process's own pid, and confirmed
`leakedFixtureTunnelPids` now correctly refuses to select it - i.e. this
scenario was previously passing only because BL-1974's own bug (a
spawner's pre-exec bash -c line reading as "no known creator", hence
selected unconditionally) was riding to a false-positive "selected". With
that bug fixed, the fixture is read correctly as owned by a live run (the
test itself) and is - correctly - never selected.

## Not this ticket's fix

BL-1974's own `required_wiring` names only its own new step handler and
`extension/test/helpers/fixtureTunnelName.js`; BL-1061 is a different,
already-closed ticket. No `backlog/standing-reds.tsv` row names it, so
this is unowned. The fix (not mine to apply) is almost certainly for
`spawnFixtureTunnel`/the scenario's own setup to use
`bl1287FixtureSweepFixture.js`'s `nameWithCreator(deadPid())` pattern -
an EXPLICIT dead creator pid - instead of the implicit, always-alive
`fixtureTunnelName()` default, the same fixture shape
`bl1287FixtureSweepScopingInvariants.property.test.js`'s own invariant 2
already uses for exactly this "leaked by a gone run" case.
