# BL-1361 — CODER PASS, 2026-09-04

Human ruling honoured: **tell for every reason, wake only for a dirty
worktree.**

## What was built

`swarmforge/scripts/post_qa_branch_sweep_lib.bb` (pure additions)

- `wake-for-reason?` — true only for `:dirty-worktree`. That is the one reason
  that does not resolve itself; a branch that merely cannot fast-forward is
  merged the next time its role receives a parcel anyway, because a forwarded
  commit must carry the received commit as an ancestor. Waking is the
  exception, so an unknown reason never wakes.
- `surface-notice` — the one-liner: landed commit, the sweep's own reason text,
  and what the role must do. Kept inside the 80-char note cap on purpose: an
  oversized note quarantines silently as `.dead`, which would reproduce this
  ticket's own defect in a new way.
- `sweep!` now calls a `:tell!` adapter for each NEW surfacing. The dedupe is
  the existing `surface-already-recorded?` record — actions are only produced
  for a new surfacing — so a per-tick sweep is silent (invariant 2). A `tell!`
  that fails OR throws is logged as `post-qa-branch-sweep-tell-failed` and the
  reduce carries on, so one unreachable mailbox never withholds the rest
  (invariant 3). A caller with no `:tell!` adapter still sweeps.

`swarmforge/scripts/handoffd.bb`

- `post-qa-branch-sweep-tell!` sends through `swarm_handoff.bb` — the send this
  daemon already uses — never by writing a mailbox directly. The deferred case
  rides `SWARMFORGE_SKIP_SYNC_INJECT`, a switch that already existed: the
  parcel lands in the role's mailbox and it reads it on its next
  `ready_for_next`, costing no turn.
- `--post-qa-sweep-once`, mirroring the file's existing `--chase-sweep-once`
  and `--reconcile-sweep-once`. This is why: `post_qa_branch_sweep_cli.bb` is
  BL-668's acceptance seam with FAKE adapters and cannot reach a send at all,
  so the only honest way to prove a role was TOLD is to run the sweep inside
  the real daemon.

Invariant 1 is untouched: the sweep is still fast-forward-only and still never
merges, resets, rebases or stashes, and the e2e asserts both surfaced
worktrees are exactly as they were.
