### Two real gaps found and closed

1. **Quality-floor boundary was untested.** `<` vs `<=` in
   `candidate-verdict`'s `:below-quality-floor` arm survived — no fixture
   candidate scored exactly at the profile's floor, so a mutant that treats
   "at the floor" as failing (rather than passing, the correct minimum-bar
   semantics) went undetected. Added a candidate scoring exactly 0.5 against
   a 0.5 floor, asserting it is staffed.
2. **"No cast entry for an unstaffable seat" was checked by `nil?`, not by
   key absence.** A mutant that kept the key with a `nil` value
   (`(map ...)` instead of `(keep ...)` in `generate-cast-from-profile`)
   survived: `(nil? (get-in ... "QA"))` reads true either way, and the JS
   acceptance step's `!st.result.cast.roles[st.subjectRole]` has the same
   blind spot (a JSON `null` is also falsy). A downstream consumer iterating
   `(:roles cast)` would see a `"QA": null` entry that has no business
   existing. Added a `(not (contains? ... "QA"))` assertion, which
   discriminates key-absent from key-present-nil where the `nil?` check
   cannot.
3. **CLI's fail-closed default for an unrecognised provider had no test.**
   `host-reachable?`'s docstring claims "a provider this map does not know
   is NOT assumed reachable," but every fixture provider is one of the
   handful `provider-credential-env` names, so the `else -> false` branch
   was never reached and a mutant flipping it to `true` survived. Loaded the
   CLI file directly in the bb test runner (its exported adapter function,
   not the argv/process boundary — CLI thin-wrapper rule) and asserted both
   the fail-closed case and the `local`-provider (no credential requirement)
   case.

All three additions are in `swarmforge/scripts/test/bl1337_profile_cast_test_runner.bb`;
no production code changed by this pass.
