# BL-1822 — coder pass, 2026-10-01

## What was built

- `swarmforge/scripts/recruiter_score_table_lib.bb` (new): the pure
  rendering core. `render-model-scout-section [table previous-briefing-date]`
  returns one of three literal shapes exactly as the ticket's outline
  requires — `"Model scout: no scout has run yet."` when `table` is nil,
  `"Model scout: no new scout since the previous briefing."` when the
  table's `updated_at` is not strictly after `previous-briefing-date`
  (fails closed on a missing/malformed `updated_at` too — never a crash,
  never a false "fresh"), or every row (highest `passed` first, naming
  the model, its passed/total, and "(incumbent)" when flagged) followed
  by the table's own `recommend.specifier` text verbatim when fresh.
  `previous-briefing-date [filenames today briefing-date-label-fn]` finds
  the latest `docs/briefings/<date>.md` label strictly before `today`,
  injecting `briefing-date-label-fn` (the CLI passes the real
  `briefing-email-lib/briefing-date-label`, BL-1811 — this file holds no
  second copy of that filename pattern).
- `swarmforge/scripts/recruiter_score_table_cli.bb` (new): the thin I/O
  wrapper — `recruiter_score_table_cli.bb <project-root> --briefing
  [--today <YYYY-MM-DD>]`. Reads `.swarmforge/recruiter/score-table.json`
  (BL-1821's own output) and lists `docs/briefings/`, resolves `today`
  (real UTC date by default, overridable for deterministic fixture runs,
  same `--today` convention `model_factory_cli.bb` already uses), and
  prints `render-model-scout-section`'s output. Manually confirmed
  against this host (qa_e2e_procedure item 2): with no score table yet,
  prints exactly `"Model scout: no scout has run yet."`.
- `swarmforge/scripts/test/recruiter_score_table_lib_test_runner.bb`
  (new): unit cases for both pure functions — the three render outcomes
  (no table, stale-on-the-boundary-date, stale-before, missing
  `updated_at`, fresh-with-no-previous-briefing-at-all), and
  `previous-briefing-date`'s own filtering (mixed filenames, today's own
  briefing excluded, no qualifying file). Registered in
  `swarmforge/scripts/test/suite-manifest.tsv`.
- `specs/pipeline/steps/bl1822ModelScoutSectionSteps.js` (new): the
  acceptance driver. Every scenario drives the REAL
  `bb recruiter_score_table_cli.bb <root> --briefing --today <date>` over
  a disposable `mkSocketFixtureRoot` fixture (a fixture score-table.json
  and fixture `docs/briefings/*.md`), never a reimplementation of the
  rendering/date logic.
