| # | Invariant | Property | Non-vacuity |
|---|-----------|----------|-------------|
| 1 | a record excuses only a red it names, at the same base sha and config hash; the cache shrinks a run, never widens an excuse | **P1** — nothing is excused unless the record matched the key AND names the red AND the red was observed; `new`/`vanished` are exactly the set differences; every new red reaches the evidence and no "same set" claim survives beside one | excused the recorded set unconditionally and stopped forcing the second run → **244 FAIL P1** |
| 2 | absent, unreadable or config-mismatched record falls back to two runs; no path turns a missing baseline into a green | **P2** — every non-matching record shape yields a second run, an empty `excused`, no `new` claim, a stated reason, and a baseline to write | treated any present record as usable → **593 FAIL P2** |

**Generator reach is asserted, not hoped for**, and in the shape BL-654 names:
the observed set is **derived from the recorded one** by the transformation
each case is about (same / added / removed / both / empty), never drawn
independently — two independent draws would agree essentially never, so the
exact-match case, the only one that can skip a run, would be vanishingly rare
and P1 would pass forever on mismatches. The run fails outright unless all six
record shapes, all five observed shapes, and specifically the `[:match :same]`
pair were generated.

## Decisions worth the reviewer's eye

- **The base run happens in a throwaway worktree at the base sha**, never by
  checking out the stage's own tree. A helper that moved a role's HEAD to
  measure something would cost far more than the minutes it saves. `07`
  asserts HEAD does not move and that the worktree is removed; the prefix is
  swept before the run as well as in a `finally` (BL-971).
- **A record filed for the same suite at another key is reported on, not
  ignored.** It is never usable — `decide` refuses it either way — but handing
  it to the decision is what lets the refusal say *recorded at base X, not Y*
  rather than the flat *no baseline record*, which an operator cannot act on.
- **One unparseable line makes the whole record file unreadable**, rather than
  being skipped. Silently dropping a line is how a record shrinks into a
  smaller excuse — invariant 1's failure mode.
- **A missing config file contributes its absence to the hash.** Deleting a
  config must move the hash, or an old record would keep applying to a suite
  that no longer has one.
- **The suite→config-paths registry is written down, not discovered.** A suite
  whose config moved without being listed would keep matching an old record.
  `properties` includes `property_suite_standing_allowlist.tsv`, because what
  the allowlist tolerates changes the observable set.

## Self-audit (Article 2.3)

Three findings, all fixed before forwarding:

1. **The evidence sentence did not name who recorded the baseline**, though
   the ticket's own expected wording does ("baseline `<sha>` recorded by
   `<stage>`"). A reader who cannot tell which stage observed it cannot judge
   how old it is or go and ask. `decide` now carries `recorded-by` through and
   the sentence names it.
2. **An unreadable suite run could have read as a green one.** The default
   (unstubbed) path parsed failures out of the command's output and returned
   whatever it found — so a command that could not run at all (`vitest: command
   not found`) yielded an empty set, which beside an empty record looks like a
   clean cache hit and skips the base run. That is invariant 2's failure mode
   arriving by the back door. Parsing moved into the lib as the pure
   `parse-failures`, which returns **nil** for output it cannot read (as
   distinct from `[]` for a genuinely green suite), and the CLI refuses on nil.
   Covered by seven unit assertions and shell check `01b`.
3. **The config hash was a 32-bit `hash`.** It is a cache key, and a collision
   there silently reuses the wrong failure set. Now a SHA-256 digest of each
   config file, truncated to 16 hex characters.
