## Cleanup applied

**C1 — a hand-mirrored cross-language constant had no gate (BL-948).**
`specs/pipeline/steps/lib/socketFixtureRoot.js` defines
`SOCKET_PATH_GUARD_LIMIT = 100`, a hand-mirror of
`(def max-safe-socket-path-len 100)` in `swarmforge/scripts/swarm_socket_lib.bb`
— two literals for one bound across a boundary no import can bridge, tied
together by a comment only. The engineering rules name this case exactly:
*"needs a test asserting both literals agree — a 'kept in sync' comment is not
a gate, and drift fails silently (BL-897)."* Nothing in the repo read the `.bb`
literal.

Added `extension/test/bl948SocketGuardLimitParity.test.js`: it parses
`swarm_socket_lib.bb` for its own `(def max-safe-socket-path-len N)` and
asserts equality with the JS constant, failing loudly if the definition is
renamed rather than passing vacuously.

Placed in `extension/test/` deliberately — `specs/pipeline/test/` is run by no
standing gate (the BL-872 lesson, which `tempDirTrapGuard.test.js`'s own header
records), so a parity gate parked there would have been decorative.

**Non-vacuity measured, not assumed**: temporarily set the `.bb` literal to
`108`; the gate failed with
*"SOCKET_PATH_GUARD_LIMIT (100) has drifted from … (108)"*. Restored, and the
file verified byte-identical afterwards.

Why this matters here specifically: drift would be silent in the worst
direction — the fixtures would compute headroom against a bound the guard no
longer enforces, and the scenarios BL-948 exists to rescue would quietly start
dying on the guard's refusal again. That is the **third** recurrence of this
exact shape, which is why BL-948 was minted.
