# BL-1312 — coder pass, 2026-09-05

## What was wanted

`mkSocketFixtureRoot`'s cleanup (`specs/pipeline/steps/lib/socketFixtureRoot.js`)
promised to remove every fixture root it hands out through a bare
`process.on('exit', removeStragglers)` hook. Node does not run `'exit'`
handlers on SIGTERM/SIGINT — the default action terminates immediately
without unwinding — so on the signal paths the cleanup never ran at all. It
appeared to work only by accident: whenever some OTHER step file in the
same process also called `fixtureReaper`'s `track()`/`onAbnormalExit()`,
that file's own SIGINT/SIGTERM handlers called `process.exit(1)`, which
THEN unwound the `'exit'` hook. A process using the helper alone leaked its
root (and any tmux server under it) on every signal.

Human ruling: option 1 (fix the shared helper for all 96 current callers,
not just the two BL-1305 step files that were directly observed leaking).

## What landed

- **`specs/pipeline/steps/lib/socketFixtureRoot.js`**: `installExitHook`
  now routes `removeStragglers` through `fixtureReaper`'s `onAbnormalExit`
  instead of a bare `process.on('exit', ...)`. `onAbnormalExit` installs
  the process-wide `exit`/`SIGINT`/`SIGTERM` listeners exactly once
  (`installGlobalHandlersOnce`) regardless of how many callers register,
  which is what keeps invariant 2 (one listener, not one per root) true.
  No private SIGTERM listener was added — the ticket's own direction
  explicitly warns against that, since two independent listeners
  reintroduce the ordering question the shared helper exists to settle.
- **`specs/pipeline/steps/roleLifecycleParkUnneededSteps.js`**: closed the
  secondary caller-side race the ticket's description names — `mkFakeBin`
  now calls `liveFakeBinDirs.add(dir)` immediately after
  `mkSocketFixtureRoot` returns, before writing the stub/`.zshenv` files,
  rather than after. This is this file's OWN redundant BL-1305 cleanup
  path; `mkSocketFixtureRoot`'s own `trackedRoots` already covers `dir`
  from birth regardless, so this closes a real but secondary window, not
  the ticket's main defect.
- **`specs/features/BL-1312-fixture-root-signal-cleanup.feature`** (renamed
  from `.feature.draft`, in-parcel per the ticket's own notes) +
  **`specs/pipeline/steps/bl1312FixtureRootSignalCleanupSteps.js`** (new,
  registered by discovery per BL-1371 — no `index.js` edit needed) +
  **`specs/pipeline/steps/lib/bl1312FixtureRootSignalProbeCli.js`** (new):
  the two-mode probe qa_e2e_procedure describes, run as a real child
  process so the step handler can observe the defect from OUTSIDE the
  process it affects (a bare `'exit'` hook not firing is invisible from
  inside the very process it fails to protect). `idle` mode creates N
  roots, prints them, and waits to be signaled; `count` mode creates N
  roots, prints `SIGINT`/`SIGTERM` listener counts, and exits normally.
- **`backlog/active/BL-1312-...yaml`**: `acceptance:` repointed at the
  `.feature` path (was `.feature.draft`).
