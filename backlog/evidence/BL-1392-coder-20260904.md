# BL-1392 — CODER PASS, 2026-09-04

Two halves, because either alone is blind. The install-time probe is green at
start and says nothing afterwards (the BL-1235 shape); the runtime heartbeat is
what catches cron dying LATER, which is what happened here — cron stopped on
2026-08-30 and every start since printed "Installed".

## What was built

**Install-time** — `swarmforge/scripts/install_swarmforge_crons.sh`

- After the lines are written (never instead of them, invariant 1), probes for
  a live daemon with `pgrep -x cron || pgrep -x crond` — Debian/WSL, RHEL and
  BusyBox names, and the same probe answers on macOS where launchd keeps
  `/usr/sbin/cron` running whenever a crontab exists.
- With none: prints `CRON_DAEMON_DOWN` naming what is not firing and the host
  fix (`sudo service cron start`, and the `/etc/wsl.conf` `[boot]` line), and
  exits non-zero. The launcher invokes the installer with no redirection, so
  the marker reaches the launch output unchanged — proved by running the real
  launcher, not asserted in a comment.

**Runtime** — `swarmforge/scripts/cron_heartbeat_lib.bb` (pure) plus a
`cron-heartbeat` sweep in `handoffd.bb` on the shared cadence

- The freshness cron writes its log every 2 minutes, so that log's age is a
  heartbeat cron itself keeps, and the daemon — which cron does not run — is
  the one process that can read it.
- `cron-heartbeat-verdict` escalates ONCE per episode past a 10-minute bound,
  stays quiet while stale, and re-arms when the log goes fresh (BL-920
  self-healing). An absent log is the same symptom at its starkest and gets its
  own verdict name. An unreadable mtime answers `:unknown` — never an
  escalation and never a clear, because a watchdog that guesses is the thing
  that needs watching.
- It never starts cron (invariant 3): the lib is pure — no process, no shell,
  no filesystem — and the message names the fix as the host owner's.

### Non-vacuity, one mutation per rule

- escalate every tick (drop the already-escalated branch) → "escalated twice in
  one episode".
- never re-arm (a fresh log leaves the flag set) → "a fresh log did not clear
  the episode".
- treat an absent log as fresh → "a dead cron went unreported".

## One fixture trap worth recording

`fixture_root` declared `name` with `local`, so the helper that wrote the
installer's output to `"$WORK/$name.out"` referenced an unset variable under
`set -u`: every run produced NO output and a non-zero exit, which read exactly
like a broken installer. The installer was correct throughout. The variable is
now deliberately global with a comment saying why.
