## Read, not just evidence-trusted

- `sibling-path-verdict`: pure over `{:changes :main-lines :tip-lines}`,
  three-valued (`:landed`/`:unlanded`/`:vacuous`). `surviving-added`/
  `surviving-removed` net out lines that were both added and removed by the
  sibling's own commits before scoring — correct, avoids self-contradiction.
  Fails closed (`:unlanded`) whenever any of `changes`/`main-lines`/
  `tip-lines` is falsy.
- `sibling-own-line-changes`: filters candidates to the sibling's own commits,
  explicitly excludes merge commits (`merge-commit?`, 2+ parents via
  `rev-list --no-walk --parents`) — the exact mechanism that stops a merge's
  passenger content (its first-parent diff = everything the second parent
  brought in) from being mis-charged to whichever ticket the merge subject
  names. `nil` propagates when any candidate commit's diff can't be read —
  never scored as if empty.
- `landed-siblings`: `changes` nil → every path verdicts `:unlanded` (fails
  closed on an unread sibling). `:vacuous` paths are dropped before scoring;
  a sibling whose every attributed path is vacuous still has an empty `paths`
  set, so `sibling-landed?`'s own empty-paths fail-closed row catches it —
  matches the ticket's explicit "every path vacuous still reports unlanded"
  contract. Traced this by hand against the code (not just the docstring
  claim) for: nil-changes, all-vacuous, and mixed landed/vacuous cases.
- Verified independently that a sibling reachable only via a merge naming it
  (no own non-merge commits among candidates) still reports unlanded, not a
  crash or a silent pass — `sibling-own-line-changes` returns `{}` (real
  answer) for that sibling, every path then verdicts `:vacuous`, all dropped,
  empty `paths` fails closed.

## A design-latitude note, not a defect

`sibling-path-verdict` compares SETS of added/removed lines per path, so two
distinct non-blank lines with identical text in the same file would be
indistinguishable. The ticket explicitly leaves the comparison granularity
open ("Whether the per-sibling comparison is done on attributed hunks... is
open. What matters is that the verdict depends on that sibling's lines
alone") and this is within that latitude, not a violation of either declared
invariant. Recording it here for visibility, not as a bounce.
