# BL-871 — coder pass (2026-08-11)

Implements: cap the property lane's worker pool and per-worker heap to the
same shared budget module the unit lane already uses
(`extension/out/tools/vitest-worker-memory-budget.js`), so the property
lane's verdict for a file stops depending on how many other property files
happen to run alongside it.

## Changes

- `extension/vitest.properties.config.mjs`: reads `resolveWorkerPoolSize`
  and `PER_WORKER_HEAP_MB` from the shared budget module (same
  `createRequire` ESM->CJS bridge `vitest.config.mjs` already uses), sets
  `pool: 'forks'` with `poolOptions.forks.maxForks`/`execArgv`. No literal
  worker count or heap size in this file.
- `extension/test/helpers/propertyLaneFixtureRunner.js`: added
  `runManyAsPropertyLaneFixtures` — spawns N real fixture files through the
  real config in one `vitest run` invocation, needed to observe pool sizing
  across files (the existing single-file runner cannot).
- `extension/test/helpers/maxConcurrentSpans.js` (new): pure sweep-line
  helper, max overlapping `{start,end}` spans.
- `extension/test/helpers/workerPoolConfigGuard.js` (new): pure source-text
  guard — does a config import the shared budget module vs. hardcode either
  number.
- `extension/test/bl871PropertyLaneWorkerPoolCapInvariants.property.test.js`
  (new): both declared invariants, coder-authored per BL-654. Invariant 1
  drives the real config with real subprocesses; invariant 2 fuzzes config
  source-text shapes over the pure guard.
- `specs/pipeline/steps/bl871PropertyLaneWorkerPoolCapSteps.js` (new) +
  `specs/pipeline/steps/index.js`: step handlers for
  `specs/features/BL-871-property-lane-worker-pool-cap.feature`
  (pre-existing, not authored this pass).
