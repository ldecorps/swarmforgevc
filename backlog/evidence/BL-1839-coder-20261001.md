## Probes (ticket's "Review goals" 2)

- **2a (credential leak via env forwarding)**: `test_local_model_seat.sh`
  scenario 05 ("local endpoint credential reaches the pane via env, never
  the launch file") already covers this generically for the local-model
  launch path and passed clean on this parcel's tree. No new forwarding
  in 2cdb259806/7f38e5d7fe writes a credential value into a generated
  launch script, prompt file, or commit — `PACK_STAFFING_SKIP_GATE`,
  `SWARMFORGE_PACK`, `SWARMFORGE_OLLAMA_CONTEXT_LENGTH` and the
  OPENAI_*/OLLAMA_* vars forwarded by `nohup ... key=val` (start-swarm.sh)
  are process environment, never written to a file the launch script
  reads back from. No finding.
- **2b (BL-1711 crash restart keeps the two defaults)**:
  `ollama_ancillary_restart_if_crashed` (ollama_ancillary_lib.sh) calls
  `ollama_ancillary_start_server` for the actual restart (verified by
  reading the function body) — the same function scenario 04 drives, so
  a restarted server gets `OLLAMA_FLASH_ATTENTION=1` /
  `OLLAMA_KV_CACHE_TYPE=q8_0` the same way a fresh launch does.
  `test_handoffd_ollama_crash_restart_sweep_wiring.sh` (ALL PASS on this
  tree) exercises this restart end to end through the real daemon loop.
  No finding.
- **2c (loopback substring match)**: `start-swarm.sh`'s check is
  `[[ "$OPENAI_API_BASE" == *127.0.0.1* || "$OPENAI_API_BASE" == *localhost* ]]`
  — a plain substring match, not a URL-authority parse. A base whose
  hostname is NOT loopback but whose string happens to contain
  `127.0.0.1` or `localhost` elsewhere (e.g. a path segment) would match
  and get `OPENAI_API_KEY` set to the Ollama placeholder (`ollama`,
  never a secret) instead of the real cloud key already in the
  environment. The failure mode is a broken connection to that remote
  (wrong, non-secret credential sent), not a credential leak — no secret
  value is exposed either way. **Finding, low severity, reported to the
  specifier by note**: tighten the match to the base's actual authority
  (e.g. parse the host out before comparing) if this is worth hardening;
  not blocking, since no credential leaks and the one real pack
  (`full-forge.conf`'s `coder@iq3`) never constructs such a base.
