**First error excerpt** (actual ledger output from the repro above):

```yaml
- commit: 091369a2e3
  subject: "Emergency fixture fix."
  detected_at: 
  state: pending
  stamp_ticket: null
```

**Failure class**: `behavior` (the sweep writes structurally-correct output — right commit, right `state: pending` — but the wrong VALUE for a required field; not a compile/unit/integration/acceptance failure).

**Expected vs observed**: Expected `detected_at: <YYYY-MM-DD>` (today's date), matching R2's own documented ledger schema (`detected_at: 2026-08-07` in the ticket body), the ledger's committed seed entries, `docs/how-to/BL-848-certify-an-operator-hotfix.md`, and `hotfix_ledger_update.bb`'s own `--new` mode (which correctly defaults `detected-at` to `(today)` when omitted, per its test `hotfix_ledger_update_test_runner.sh`: "ok - new: ..."). Observed: `detected_at:` renders **blank** for every commit the automated sweep itself detects and appends, forever — not `null`, not a real date, just an empty scalar.

**Root cause** (traced, not guessed):
- `operator_runtime.bb`'s `git-log-main` (`resolve-main-commits`'s source) uses format string `"%H%x1f%s%x1f%b%x1e"` — hash/subject/body only, no commit date (`%cd`/`%ad`) is ever captured.
- `resolve-main-commits` enriches each commit with `:functional? :hotfix-declared? :cited-ticket-done?` only — never a `:detected-at` key.
- `hotfix_certification_lib.bb`'s `assemble-report` builds `:new-ledger-entries` via `(new-entry c)` directly from that enriched commit map, so `(:detected-at c)` is always `nil`.
- `new-entry` passes `:detected-at` straight into the entry with no default (unlike `stamp-ticket`/`human-decision`/`decided-at`, which `render-entry` explicitly falls back to the string `"null"` via `(or stamp-ticket "null")` etc. — `detected-at` has no such fallback and no upstream default either), so `render-entry`'s `(str "  detected_at: " detected-at "\n")` renders Clojure `nil` as an empty string.
- Every existing test (`hotfix_certification_lib_test_runner.bb`, `bl848_hotfix_certification_property_runner.bb`, the acceptance runner, `test_operator_runtime_hotfix_certification_sweep.sh`) only ever supplies/asserts `detected_at` on ledger entries that are hand-seeded in the FIXTURE (parse path) or checks `state:`/ledger-membership for sweep-appended entries — none constructs a fresh `main-commits` entry through `resolve-main-commits`/`assemble-report` and checks the resulting `detected_at` value, so the gap is invisible to green tests.

**Why this matters for BL-848 specifically**: this ledger is the ticket's own core deliverable — "a durable, greppable hotfix certification ledger" whose purpose is exactly the kind of audit trail a blank detection date undermines. It is silent and permanent: every commit the recurrent check ever autonomously detects from here on gets no detection date, with no error, no test failure, and no visible symptom short of reading the raw YAML.

**Remediation pointer**: `swarmforge/scripts/operator_runtime.bb::git-log-main` needs to capture a commit date (e.g. add `%cI`/`%cd` to the format string) and thread it through `resolve-main-commits`'s enrichment; `hotfix_certification_lib.bb::new-entry` (line ~170) should receive that value as `:detected-at` (or fall back to the sweep's own `now-ms` formatted as `YYYY-MM-DD`, matching `hotfix_ledger_update.bb::today`'s existing convention) rather than passing through an always-nil field.

**Blamed role**: coder (introduced in `2a1ecc3c`, BL-848's own coder commit — the sweep's core wiring). Not caught by cleaner (`3d5c1e7b`, clean-pass-only) or hardener (`9481f436`, which hardened `hotfix_ledger_update.bb` and `process_table_lib.bb` but not this gap in the sweep's own `new-entry` call path).
