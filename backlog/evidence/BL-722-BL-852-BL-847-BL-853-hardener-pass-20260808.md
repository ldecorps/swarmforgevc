## Findings and fixes

### BL-853: untested fallback branch, now covered (real gap, fixed)

`promote_and_route_next.sh`'s CAP-resolution has two branches: a primary
call to `effective_backlog_depth_cli.bb`, and a FALLBACK (only reached when
the primary is unavailable/malformed) that this ticket rewrote to fix the
actual live-incident root cause — the fallback used to pass
`backlog_depth_cli.bb` the project ROOT where it expects a CONF-PATH file,
silently degrading to the library default (5) and reproducing the incident
this ticket fixes. `test_promote_and_route_next_no_limit_depth.sh`'s
existing case resolves CAP via the PRIMARY path only (confirmed by direct
invocation: `effective_backlog_depth_cli.bb` degrades its throttle-refresh
gracefully in a fixture with no compiled `extension/out/` and still prints
the configured `-1`) — the fallback branch, where the actual bug lived, was
never exercised end-to-end.

Added a second case to the same test file that removes
`effective_backlog_depth_cli.bb` from the fixture (forcing the
`[[ -f ... ]]` guard to fall through), and proved it non-vacuous two ways:
(1) run against the PRE-BL-853 `promote_and_route_next.sh` — reproduces the
exact live incident (`exit 2`, "active count 5 >= cap 5"); (2) hand-mutated
the CURRENT script's fallback to pass `$ROOT` instead of `$CONF_PATH` (the
exact pre-fix bug) — the new test catches it (exit 2), then restored clean
(confirmed via `git diff` showing no residual change to the script).
