2. Manual fixture, run live: `FRESHNESS_ANNOUNCE_CMD='echo ANNOUNCE'`, 5 ticks
   120s apart on a stale handoffd log: `ANNOUNCE` printed exactly once (tick

   `suppressed_ticks=14` — the ticket's own illustrative "15" counts the

## Declared invariants (BL-654)

- **Invariant 1** (suppression is announce-only; the incident log is never
  thinner) — **P1**: runs the REAL checker over a random-length run (2-6)
  of consecutive violation ticks against a fixed-stale handoffd log with
  babysitterd refreshed every tick (isolating the daemon under test), and
  asserts the incident log gains exactly one record per tick regardless of
  how many announces were suppressed. Broken by removing the
  `append_incident` call in the escalate branch: failed 200/200 (every
  multi-tick case under-recorded).
- **Invariant 2** (the first tick of a transition is never suppressed) —
  proven together with invariant 3 by **P2**: every `announce_transition_only`
  call runs in its own `env -i sh -c` subprocess (no shared shell, no
  inherited env — the strongest available proof that "every cron tick is a
  fresh process" does not matter to the decision, invariant 3's literal
  claim). For a random sequence of violation/fresh ticks per a random
  (daemon,reason) key, asserts the first violation tick after a
  fresh-or-never state always decides `announce`, a repeat violation tick
  (digest window pinned unreachably large) always decides `suppress`, the
  first fresh tick after a violation always decides `recovered <secs>`, and
  a repeat fresh tick always decides `none`. Broken by deleting the
  first-tick-in-violation special case (defaulting to the "already exists"
  branch with fabricated `announced_epoch=now`, which computes
  `elapsed=0 < digest_secs` and answers `suppress`): failed 278/200-run-
  pairs (every first violation tick across every daemon key).
- **Invariant 3**: no separate property — proven jointly by P2 above (see
  invariant 2). A declared invariant that is genuinely inseparable from
  another in its own executable encoding is documented here rather than
  padded with a second, redundant test asserting the same subprocess
  boundary a second way.

**Reachability**: P1/P2 ran 200 cases each; every branch (announce,
suppress, digest never fires in P1 by design since the window is pinned
unreachable, recovered, none) is exercised by construction every run except
digest, which the unit tests (BL-1414-03) and the live qa_e2e_procedure #2
cover directly instead — P1/P2 exist specifically to encode invariants 1-3,
not to re-prove the digest arithmetic already covered elsewhere.
