### Invariant 1: A GPU pause is always bounded

`pause-active?` requires `active` to be true AND `untilMs` to be a number
AND `untilMs > now-ms`. A marker with no `untilMs` is not active. The
duration table maps only `30m`, `1h`, `2h`; any other token returns nil
and the CLI prints usage and exits 1. Verified by
`gpu_pause_lib_test_runner.bb` (assertions: "missing until is not an
open-ended pause" → false; "unknown duration" → nil).

### Invariant 2: The marker is not the intake pause

`gpu-pause.json` is a different file from `control-pause.json`. The
gatherer reads `gpu-pause.json` in `read-gpu-pause`; the intake pause is
read separately in the existing `read-pause`. The two are independent:
arming the GPU pause does not set `control-pause.json`, and clearing it
does not touch intake. Verified by the file paths in
`babysitter_check.bb` (`read-gpu-pause` reads `operator/gpu-pause.json`;
the existing `read-pause` reads `operator/control-pause.json`).

### Invariant 3: While active, no half-launch, stuck-parcel, frozen-pane, or claim-risk

- `check-live-session`: `gpu-quiet?` → `nil` (no finding, no repair).
- `check-stuck-in-process`: `:when (and (not owner-busy?) (not gpu-quiet?))`.
- `check-busy-frozen`: `(when-not gpu-quiet? ...)`.
- `assemble-findings`: `claim-findings` filters out roles in
  `gpu-quiet-roles`.
- `check-seat-ticket-stuck`: `(remove :gpu-quiet? (or held-tickets []))`.

Verified by `babysitterd_sweep_lib_test_runner.bb` (four gpu-quiet
assertions) and `telegramControlCore.test.js` (five /gpu cases).

### Invariant 4: The marker is written before qwen is stopped

`gpu_pause_cli.bb` `arm` branch: `(write-marker! ...)` is called BEFORE
`(quiet!)`. The marker is on disk before any process is killed, so a
babysitter sweep that lands in the gap sees an active marker and does not
relaunch the seat.
