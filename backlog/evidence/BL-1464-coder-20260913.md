## 1. The change — fixture only, no production line changes

`specs/pipeline/steps/bl1297MergeCommitOwnPathsSteps.js`: added
`mergeOwnParcelIn`, a SEPARATE helper for BL-1297 scenario 03's step alone.
`mergeParcelIn` (shared by scenarios 01 and 05) is untouched — scenario 05's
whole premise is a branch commit authored under the FOREIGN id, so that
helper cannot change without breaking it (the ticket's own direction).

`mergeOwnParcelIn`:
- Authors `TRUNK_PATH` on main and folds it into `origin/main` itself
  BEFORE the branch forks — genuinely pre-existing content, not merely a
  same-range commit under a foreign subject. Measured: leaving it in-range
  (the old shape) still puts it in the land step's own full
  `origin-main..tip` delivered diff, attributed solely to the foreign
  subject — a real "delivered path owned solely by an unlanded sibling"
  that never blocked scenario 03's replay but does violate BL-1464's own
  scenario 02. Moving it before `origin/main` removes it from that diff
  entirely.
- Authors the branch commit that becomes `PARCEL_PATH` under the TASK's OWN
  subject (`BL-1174-fixture: ... arriving through the merge`), not the
  foreign `BL-9999-other`. `land_step_lib.bb`'s `path-attributing-commits`
  credits a delivered path to whichever commit actually introduced it
  (a path-scoped `git log`, not the merge's own subject) — so the path now
  survives BL-1389's unlanded-sibling exclusion.
- Keeps the "old invocation stays suppressed" premise assertion, same as
  `mergeParcelIn`.

BL-1297's scenario 03 step now calls `mergeOwnParcelIn` instead of
`mergeParcelIn`. Its own assertions (the merge is the walk's only
task-tagged first-parent commit; the land step reaches `:action :replay`
with the parcel's own path in `:own-paths`) are byte-identical, unmodified.

Both helpers, plus `git`/`bb`/`initRepo`/`cleanup` and the shared
constants, are exported from the file so BL-1464's own handler drives the
SAME fixture builders rather than a second copy of them.

New file `specs/pipeline/steps/bl1464MergeOnlyFixtureOwnContentSteps.js`
implements BL-1464's own 4 scenarios (detail in §3).

**Not touched**: BL-1297's, BL-1343's and BL-1389's `.feature` files
(constraint); `land_step_lib.bb` / `task_scope_gate_lib.bb` (no production
line changes — the defect was the fixture, not the walk).
